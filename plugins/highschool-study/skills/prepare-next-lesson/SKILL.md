1. Select one eligible Plan from its dependencies and the student's chosen order. Call `highschool-study:recall-study-memory` for preparation.
2. Read `references/classroom-templates.md` and `references/reveal-policy.md`. Choose a primary template from the Lesson target, prior summaries, active evidence, confirmed profiles and preparation-only planner attention. Explain the proposed activity roles, materials and reveal modes; do not force another confirmation when the student asked for direct preparation.
3. For Plan-scale or cross-card retrieval, delegate one focused source-retrieval task to `Agent(highschool-study:lesson-designer)` instead of preloading the parent with a full Trace/card result. Ask it to return real card paths, selection reasons, active Trace references, findings and missing roles. For one known card or a small local question, search directly.
4. Derive problem-role slots before card search. Search authentic candidates for each needed role, deduplicate paths, and use their included active `traceHistory`. An unseen assessment uses a card absent from earlier Lesson aliases and prior Trace. A same-card retry is practice, not unseen transfer. If no real card fills a role, report the gap and adjust the Lesson.
5. Apply the Plan's observable test literally. Card metadata describes reference structure; active Trace describes student evidence. Do not infer attainment from Lesson prose, method labels or Task state.
6. Prefer local materials. Include an external video only after `lesson-designer` verifies its title, canonical URL, relevant segment, teaching purpose, follow-up question and local fallback. A video that solves a target comes after its first attempt or uses a different example.
7. Draft flexible Blocks with Node State and separate Student View/Teacher Control. Student View contains the next activity without recognition spoilers. Teacher Control keeps the role, evidence target, reveal mode, card-step references and ordered help. Mark dependencies and safe skip, repeat or reorder choices. Each card attempt is one problem Block whose `Uses` contains exactly one real Lesson alias; split a question set into multiple problem Blocks, then compare them in dialogue or reflection.
8. Write the next indexed Lesson as `prepared`, with top-level `## Aliases`, `## Reflection`, `## Lesson Summary`, and `## Traces`. Every nonempty Block `Uses` value must have a declared alias resolving to a real problem card, and exactly one Block must explicitly declare `Kind: reflection`. If no real card fills a problem role, use material/dialogue or report the content gap instead of fabricating an alias. Reread the file before reporting it prepared. These are executability requirements, not teaching-quality scoring. Preparation does not append classroom evidence, claim attainment, edit profiles, or close the Lesson or Plan.
9. When the primary template is `assessment`, report successful preparation with only readiness and the number of problem Blocks, for example: “考察课已备好，共两道题。准备好就可以开始。” Keep its stems, formulas, problem types, methods, recognition targets, traps and card IDs inside the Lesson until `run-lesson` activates the corresponding Block. Other templates may summarize their activity roles.
