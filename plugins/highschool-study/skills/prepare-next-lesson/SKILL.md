description: Prepare a source-grounded, flexible next Lesson for one eligible Plan.
allowed-tools: Read, Glob, Grep, Write, Edit, Skill, Agent(highschool-study:lesson-designer), mcp__plugin_highschool-study_study-markdown__card_search, mcp__plugin_highschool-study_study-markdown__trace_search, mcp__plugin_highschool-study_study-markdown__source_resolve

1. Select one eligible Plan from explicit dependencies and the student's approved order. Call `highschool-study:recall-study-memory` with purpose `preparation` before searching for new material.
2. Read `references/classroom-templates.md` and `references/reveal-policy.md`. Choose one primary template from the Lesson capability target, prior Lesson Summaries, active Trace, both confirmed profiles, and preparation-only planner attention. Explain the reason, proposed problem roles, materials, and reveal modes. Let the student adjust them; if the student says to prepare directly, do not force another confirmation turn.
3. Collect every card path from prior Lesson aliases in this Plan as `usedCardPaths`. Derive the problem-role slots before the first `card_search`. Treat result fields literally: problem category = card_search.goal (graph.goal.primary); method shell = card_search.methods (graph.method). Search separately for the required slots and deduplicate by real `cardPath`. When the Plan Test requires another problem category, exclude already covered goal values before selecting another authentic card. Do not stop at the first suitable card. Every card_search candidate already includes its complete active traceHistory. Do not call `trace_search` to refetch a candidate's history; use it only for a cross-card evidence question or evidence not scoped to one card.
4. For an unseen assessment slot, reject a candidate when its `cardPath` is in `usedCardPaths` or its `traceHistory` is non-empty. After supported or contaminated assessment, search again for a different real card. A same-card retry is practice, not unseen transfer. If no fresh authentic card exists, expose the missing role and do not write a fake validation Lesson. Bind every adopted slot to a real Lesson-local alias and card path; never invent a card, problem, alias, source, or session ID.
5. Before proposing the next target, call `trace_search` once for the current Plan's prior evidence and use only active Trace plus `cardsByPath`. For prior rows, copy every non-empty category cell from `cardsByPath[cardPath].goal.primary` and every method cell from the card's method fields; for new candidates, copy the corresponding literal `card_search` fields. Never infer or paraphrase a category from Lesson prose, solution route, method, or surface wording. If the card or goal is missing, write `unknown` and do not qualify that row for a category requirement. Build a temporary evidence matrix: `criterion | lesson/block | cardPath | problem category (graph.goal.primary) | method shell (graph.method) | first exposure | assessment | current support | prior support | qualifies`. The chronology rule is that consecutive means adjacent evidence-bearing attempts; do not skip a supported, failed, or conflicting attempt. The category rule remains: method structure is not a problem category. Compare exact non-empty goal values; two different method shells with one goal value still count as one problem category. A correct answer may inform discussion, but missing active Trace blocks attainment. Apply the original Plan Test wording to every qualifying row.
6. Prefer real local `materials/`. If an external video has a necessary instructional role, delegate verification to `Agent(highschool-study:lesson-designer)`. Keep it only when the returned draft includes its real title, URL, segment, purpose, follow-up question, and fallback. External URLs remain ordinary links; use `source_resolve` only for learning-set-local references. Never place a video that solves a target before that target's first attempt.
7. Delegate additional preparation to `Agent(highschool-study:lesson-designer)` only when direct evidence is insufficient. Optional Agent/Dynamic Workflow remains subject to the recall Skill's parallel-search gate, and raw JSON remains in the current session.
8. Draft every problem-bearing block with `### Student View` followed by `### Teacher Control`. In Teacher Control, record the role, evidence target, reveal mode, card-step references, and ordered hints without copying a full solution when stable step references suffice. When recognition is the evidence target, Student View says only “new-structure transfer check”; do not reveal the method name, comparison object, or direction. Mark required and optional blocks, dependencies, and safe skip or reorder choices.
9. Use 2–4 deduplicated unseen cards only when the Plan Test requires consecutive or cross-problem evidence. A one-card long-form lesson remains valid for explanation but cannot prove a multi-problem criterion.
10. Write the next indexed Lesson as prepared, with its Plan link, capability target, primary template and reason, direct sources, blocks, aliases, and empty Reflection, Lesson Summary, and Trace areas. Every prepared Lesson ends with the exact top-level headings `## Reflection`, `## Lesson Summary`, and `## Traces`, in that order, even when initially empty. A Block named reflection does not replace these sections. Reread the new Lesson and verify these headings before reporting it prepared. Preparation does not append classroom evidence, assert attainment, edit either profile, or close the Lesson or Plan.
