# M1c 真实模型验收协议

## 冻结身份

- 产品行为冻结点：`2a1788c`。
- 主对话：`openai-codex/gpt-5.6-sol` + `high`。
- Material Scout：`openai-codex/gpt-5.6-terra` + `high`。
- 三个情境各用独立学习集、独立 Pi 配置目录和独立原生 Session。
- 同一次 acceptance run 中不得修改产品代码、Skill 或协议；失败 run 原样保留，修复必须另起提交与运行根。

每轮记录学生原话、完整 HTTP 事件、首个学生可见反馈、最终回复时间、工具活动、原生 Pi JSONL、
provider 可见 usage、最终 canonical 文件清单与前后快照。凭据、完整私有工具载荷和临时学习集只留在
`/tmp/studyforge-m1c-validation-*`，不提交仓库。

## 学生输入边界

学生只根据当前可见对话自然回答。学生消息不得出现工具名、文件路径、schema、revision 或预期调用顺序。
“可以”只在老师已经展示完整提案时表示确认；模型若提前保存或物化，按首击失败记录，不能靠后续提醒洗白。

## 情境 A：有资料的 Ksp 自由学习与 Meta

导入一份短教材原文，从其中准确片段进入自由学习。学生问为什么溶度积表达式中纯固体不出现，
先真正参与解释，再自然提出保存为笔记。检查 Note 的标签和固定 Material 来源；漂亮 Note 本身不等于掌握证据。
随后学生从“我不知道怎么长期学化学反应原理”进入 Meta。老师应讨论长期变化，公开完整 Roadmap 级方案，
明确确认后只创建 Roadmap，把第一个 Plan 留给新的 Roadmap Session。

## 情境 B：空白的阿伦尼乌斯自由讨论

不带任何资料，从“温度高一点为什么反应会快很多”开始。教师通过解释和比较帮助学生形成一个有边界的看法；
学生自然提出保存笔记。产物应有语义标签但没有伪造来源，教学解释和 Note 成熟度都不能自动成为掌握判断。

## 情境 C：正式课程与旧题库召回

在带旧题库与既有对象记忆的课程学习集中，由 Roadmap/Plan 形成一节真实训练课。Coach 的选材 brief 要两道题；
Scout 只看安全索引与浅层题面，达到 Coach 要求的数量即停，Coach 自己深读并负责教学核验。Lesson 以当前表现为准，
只有学生看到并确认资产内容后才保存。足迹可以串起课程、资产与对象历史，但不得暴露教师私有判断正文。

## 判定

按设计验收表逐项填写 `PASS / FAIL / NOT OBSERVED`，并给出 Session、事件或文件证据路径。至少观察：

- 是否先教学再谈保存，确认门是否首击守住；
- Session 类型与写入层级是否稳定；
- Material 来源是否固定到实际读到的位置；
- Meta 是否只创建 Roadmap；
- Scout 是否适可而止且父对话不被候选全文污染；
- 学生是否在等待期持续看到真实进展；
- 足迹是否只投影现有事实。

自动报告只提供证据和建议，最终发布判断权属于项目负责人。
