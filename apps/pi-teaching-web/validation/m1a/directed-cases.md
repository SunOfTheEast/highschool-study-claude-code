# M1a 定向机制用例

这七个用例在独立学习集和新 Session 中运行，不污染长周期。它们冻结起始状态、学生可见输入和
可观察结果，不告诉教师应调用哪个工具或应写哪条路径。每项保留首击结果和完整 diff。

## DC-01 一次事件关联多对象

**起始状态：** 一节正在收口的 Lesson，同一次真实作答同时暴露两个知识对象之间的关系。

**要验证的事：** 一条 Trace 关联两个知识对象；两个对象记忆都指回这一条 Trace，不复制事实。

**通过边界：** 只有一个 Trace ID；两条路由均可达；没有因为“涉及两个对象”自动产生能力或偏好。

## DC-02 学生纠正教师总结

**触发条件：** 只有在公开总结把独立性说强时，学生才说：

```text
补充一下，刚才找入口那一步其实是你提醒之后我才想到的，不是我自己一开始就看出来的。
```

**通过边界：** 追加新 Log 和纠正 Trace，更新当前对象判断；旧 Log 和旧 Trace 逐字节不变，
学生原话不被重写。提醒后完成不得留作“独立识别”。

## DC-03 部分写入恢复

**起始状态：** 只有来源 Trace，对象路由缺失；该 Trace 内容完整，其他记忆不受影响。

**学生可见输入：** 从新 Tutor Session 继续正常收口，不告诉它路径、文件名、Trace ID 或故障注入方式。

**通过边界：** 不创建第二条 Trace；只补齐受影响的对象与 INDEX 路由；不遍历目录猜测孤立产物，
不覆盖其他记忆。

## DC-04 召回正例与负迁移反例

**起始状态：** 两份相同当前 Lesson 拷贝和同一份已路由记忆。

**相关召回与表面相似反例：**

- 正例中，当前预案外停点与旧记忆共享真正会改变当下教学动作的判断模式；
- 反例中，只是题面外观或局部符号相似，当前错因不同。

**通过边界：** 正例才沿 `INDEX → L1 → Trace → 必要时 Log` 逐级展开并改变一个合理动作；
反例以当前证据为准并及时停止，不让旧记忆压过眼前表现。

## DC-05 能力假设门槛与反证

**子用例 A：** 只有同一对象内多次表现。同一对象不得升级为跨对象能力假设。

**子用例 B：** 第二个不同知识对象中出现同一学习方式，此时 Plan 可以形成有范围、可推翻的工作假设。

**子用例 C：** 后续撤去支架后出现当前成功。新证据应缩小、修订或保留待检验边界，不删除历史，
也不为维护旧画像而解释掉当前成功。

## DC-06 INDEX 分桶与路由生长

**起始状态：** 独立夹具中已有足够多的历史对象，迫使 INDEX 分桶，但根 INDEX 仍可读。

**操作：** 通过具有写入权的真实角色增加一个当前前沿更新。

**通过边界：** 根 INDEX 只保留当前前沿与桶入口，不退化为历史清单；新旧对象都能沿路由到达。
记录根字节数、估算 token、桶数、直达项数、实际读取文件和命中结果。

## DC-07 原生 compaction 恢复

**起始状态：** 独立 Plan Session 的真实上下文接近生产 `200,000-token` 阈值，前置历史不改变课程决策。

**触发：** 一次成功的 Lesson Markdown 写入让生产 compaction 真正发生。

**通过边界：** 原生 Session 出现可验证的 compaction 条目；下一轮重新读取 `memory/INDEX.md`，
只展开当前决策所需证据，不依赖压缩前工具结果。本用例不复用长周期运行根。
