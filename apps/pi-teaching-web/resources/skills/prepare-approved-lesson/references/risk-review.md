# 课堂内容风险核验

只在 Coach 已经点名准备采用的题目或活动，并发现一个会改变数学结论或课堂可用性的实质
风险时读取。常见入口是教师新拟题、改变数学关系或路线的实质改编，以及定义域、参数范围、
分类讨论、等号条件或证明闭环仍不确定。

原样采用的可信题卡、普通课堂编排、措辞微调和排版不进入本流程。Reviewer 不是每课必经
步骤，也不负责寻找更优材料。

## 一次有界核验

给 `lesson-risk-reviewer` 一份自足的短 brief：

- 候选题目或活动的完整公开内容；
- 它在本课中的教学作用；
- Coach 预期的结论与主要路线；
- 预计工作量；
- 本次需要核对的具体风险点。

只调用一次，使用 fresh context，并直接按名称调用，不先做能力列表查询。这个任务不写文件、
不运行命令，也不需要代码式验收证据；显式使用以下 acceptance，避免通用子代理把正确的短核验
误判为“缺少命令证据”：

```json
"acceptance": { "level": "none", "reason": "bounded read-only lesson risk review" }
```

不要改成 `attested`、`checked` 或 `verified`。不要要求完整答案、候选比较、整课重写或题库
搜索。Reviewer 信息不足时，Coach 补齐决定性信息后自行处理；调用失败不视为通过，也不自动
重试。

Coach 读取短核验后承担最终判断：可做最低必要修正，或改用已经核验的材料。若修正会改变
学生已批准的目的、活动形态、处理深度、提示方式或工作量，停止备课并返回
`plan-dialogue` 重新讨论。
