# 材料准备协议

仅在已确定的 Block 使用学习集内既有素材、但当前授权上下文尚未绑定其唯一精确相对路径时
读取。进入本文件前，Coach 已经确定素材的教学意图；本文件只负责把这份未绑定的学习集
资产交给 Scout 召回，不负责师生协商、教学目标、Lesson 结构或素材来源选择。

学生持有材料、教师内联材料和已绑定学习集资产不进入本文件。一个 problem Block 本身也不
自动触发 Scout；触发条件是它已经选择学习集资产作为来源，而且精确路径尚未绑定。

## 建立临时材料槽位

为每份未绑定的学习集资产建立一个临时槽位：

- 一个使用未绑定学习集题卡的 problem Block 通常对应一个 problem-card 槽位；
- video 或 reading Block 可以各自形成槽位；
- 没有选择学习集资产作为来源的 Block 不形成槽位。

槽位只服务于当前备课调用，不写入 Plan 或 Lesson，也不成为新的持久对象。

每个槽位 brief 包含：

- 槽位名称；
- 公开教学目的；
- 材料种类与工作量；
- 当前需要的候选数量，可以是确定数量或范围；未写时默认 1 个，范围按下限满足；
- 应避免的结构，以及需要避开的既用材料精确路径或 ID；
- 会改变适配判断的学生事实；
- 可选的建议检索词；
- 只有精确组合可能过窄时才提供的放宽顺序。

Coach 已经沿当前 Plan Tree 读取了可用课程证据。把真正会改变选材的结论和既用材料压进
brief；不要把 Plan/Lesson 路径交给 Scout，让它重新解释父子文档或扩大证据范围。

建议检索词只负责召回，不代表最终适配。优先给出少量、平坦的核心词和相关词；旧题库的
冻结词表仍可帮助 Coach 选词。自由文本使用短而不特殊的字面入口，并可列出常见符号变体：

```text
建议检索词（只用于召回）：
- core: [求参数范围, 自由度与主元]
- related: [三次函数, 绝对值, |]

放宽顺序：先去掉 text；仍为空时再放宽 method。
```

非题卡材料可以只写素材类型和自由文本，不为满足格式编造 `goal`、`method` 或
`structure`。候选数量只反映当前槽位的真实需要，不使用全局固定数量；brief 不要求完整
路线、数学结论、穷尽证明或搜索起点，这些旧要求会与 Scout 的浅召回边界冲突。

学生或已批准设计点名了某本原书的具体页码 / 连续页段时，brief 直接写人能读懂的书名与
精确页码，不再附加 `core / related` 语义词组。页码负责定位，主题只说明这一页在课堂中的
用途；语义资产索引里搜不到页码不代表原书页不存在。只有精确分页投影确实不存在或存在
多本书歧义时，才把这个来源缺口返回师生讨论，不能先用相似题替换。

Scout 会优先使用学习集的 `semantics/indexes/asset-recall.tsv` 做召回；它只把资产路径、类型、
平坦标签和公开题面或标题排在同一行，不是选材证据，也不替代 Coach 对正式资产的完整核验。
旧学习集尚无统一索引时，题卡仍可退回 `graph/card-recall-index.tsv`。

## 调用材料 Scout

每个槽位启动一个全新上下文的 `study-material-scout`。不要为同一槽位预先建立第二种
“搜索视角”，也不要用固定任务数代替真实材料需要。

父 Session 不得先发现候选：不要以目录、索引、关键词、模式或文件集合为输入，通过
`ls`、`find`、`grep` 或读取候选文件取得素材路径。

所有槽位使用一次前台并行 `subagent` 调用：

- `concurrency: 3`；
- `context: "fresh"`；
- `async: false`；
- `includeProgress: false`；
- `artifacts: false`；
- `agentScope: "user"`；
- 不设置 `timeoutMs` 或 `maxRuntimeMs`。

调用对象恰好使用七个顶层字段：

```text
tasks
concurrency
context
async
includeProgress
artifacts
agentScope
```

每个 `tasks` 项恰好包含：

```json
{
  "agent": "study-material-scout",
  "task": "当前槽位的完整 brief",
  "acceptance": {
    "level": "none",
    "reason": "read-only candidate recall"
  }
}
```

结果保持 inline：省略 `output` 和 `outputMode`。

## 合并、选择与核验

等待所有槽位任务结束。按 `asset_path` 合并和去重浅候选，再由 Coach 根据当前 Plan、
closed Lesson 和学生对话确定每个槽位实际采用的候选。

Coach 完整读取准备采用的每个候选，并分别核验：

- 来源真实且路径存在；
- 数学内容正确；
- 预期完整路线确实走得通；
- 定义域、隐零点、端点、取等条件没有遗漏；
- 难度、计算量、结构、来源陌生度和教学作用适合；
- 不会泄露本课需要学生独立作出的关键判断；
- 与其他槽位不形成无意义重复。

某个准备采用的候选未通过核验、使可用数量不足时，可以在原批准边界内，根据
`search_boundary` 只补检缺少的数量，并把刚刚淘汰的精确路径列入“应避免”；不要让 Scout
为每项预先寻找备用，不要把路线核验重新下放给 Scout，也不要自动重跑整个 fan-out。材料
图谱帮助定位，题卡 metadata 描述材料；二者都不能替代数学核验和对学生的教学判断。

## 失败边界

一个任务失败时，保留其他槽位中可用的结果。如果任何必需槽位仍没有合适真实材料：

- 不创建 Lesson；
- 不静默减少活动数量；
- 不自动重复 fan-out；
- 不回到父 Session 做批量兜底搜索；
- 只告诉学生哪个公开条件无法满足，在后续回合讨论应改变哪个条件。

Scout 不决定学生能力、教学顺序、Lesson 结构、提示策略、Plan 完成与否或任何持久事实。
课后复盘也不是 Scout 任务；Coach 直接读取已经关闭的 Lesson。
