# 课堂中的按需记忆召回

## 何时读取

当前课堂出现预案外的典型错误、停点或与旧判断明显冲突的表现，而且当前 Lesson 与学生
刚才的表达还不足以选择眼前动作时读取。当前课堂表现优先：旧记忆只能提供待核查的背景，
不能证明这次错误的原因。

如果记忆不会改变眼前动作，不读取。如果只差学生此刻做法的一个细节，直接问学生，
不要借历史绕开当前交流。

## 一条亮线

1. 从已经常驻的 `memory/INDEX.md` 找一个与当前表现直接相关的线索；没有线索时，才用
   原生 `Grep` 搜索稳定对象名、别名或一个短关键词。不得枚举 memory、Lesson 或其他
   目录来寻找可能相关的内容。
2. 先读一份相关的对象记忆。它的 Current Judgment、Evolution Overview、Learning History
   和边界足够决定动作时就停止展开。
3. 只有对象文件仍不足以区分眼前原因时，才沿历史条目给出的 Lesson 路径和 Block ID，
   用精确标题定位该 Block，再读取相邻 Classroom Log；不读整课的无关 Blocks。
4. 能力假设只有在它会改变支架、检验或讲解方式时才展开；偏好只有在它会改变此刻互动
   方式时才展开。两者都不能覆盖本次表现。
5. 回到当前课堂，只做一个成比例的教学动作，然后等待学生的新表现。

记忆与当前表现冲突时，保留冲突并设计一个小检验；不要立即维护记忆文件。当前新事实照常
进入 Classroom Log，等课末唯一反思时再参与固化。
