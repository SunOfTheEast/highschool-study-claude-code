# Coach Study

1. Read `ROADMAP.md`, the current Plan, both confirmed profiles and source-linked earlier Lesson summaries. Read `memory/planner-attention.md` only during preparation.
2. Before card search, collect every card path from earlier Lesson aliases in this Plan as `usedCardPaths`. Treat result fields literally: problem category = card_search.goal (graph.goal.primary); method shell = card_search.methods (graph.method). Search separately for each problem-role slot; every `card_search` hit already includes its active Trace. For unseen assessment, reject candidates in `usedCardPaths` or with non-empty `traceHistory`. A same-card retry is practice, not unseen transfer. If no fresh authentic card exists, say the slot is unavailable instead of fabricating validation.
3. Before a post-Lesson review or final audit, call `trace_search` once with the current `planId` and `limit: 100`. Use only its active Trace and `cardsByPath`; copy every non-empty category cell from `cardsByPath[cardPath].goal.primary` and every method cell from that card's method fields. Never infer or paraphrase a category from Lesson prose, a solution route, a method name, or surface wording. If a traced card is absent from `cardsByPath` or has no goal value, write `unknown` and do not let that row satisfy a category requirement. Then build a temporary evidence matrix: `criterion | lesson/block | cardPath | problem category (graph.goal.primary) | method shell (graph.method) | first exposure | assessment | current support | prior support | qualifies`. This table is reasoning context, not a new file or schema.
4. Apply the original Plan Test literally: consecutive means adjacent evidence-bearing attempts; never skip supported, failed, or conflicting attempts. The category rule remains: method structure is not a problem category. Compare exact non-empty `goal.primary` values for a problem-category requirement; method names never establish a second category. In particular, two different method shells with one goal value still count as one problem category. A correct answer may inform discussion, but missing active Trace blocks attainment. Do not pass a criterion until every required matrix row qualifies.
5. Agree on the next Lesson direction with the student. Derive its problem-role slots before search and use 2–4 distinct unseen cards only when the Plan Test actually requires consecutive or cross-problem evidence; one long authentic problem is valid for explanation but cannot prove a multi-problem criterion. When the Plan Test requires another problem category, exclude already covered goal values before selecting another authentic card.
6. Write a flexible sequence of dialogue, problem, material and reflection Blocks with Node State, Student View, Teacher Control and real aliases. Show only a no-spoiler outline. When recognizing a structure or method is the target, say only “new-structure transfer check” in Student View; keep the method, comparison object and direction in Teacher Control.
7. A `prepared` Lesson may be revised in place. Never overwrite an `active`, `paused`, `closed` or `abandoned` Lesson. After a Lesson closes, read its Lesson Summary and source-linked active Trace before discussing the next step. Long-term profile changes happen only after Plan completion and student confirmation.
8. After a final audit chooses `active`, `complete`, or `replan`, persist that decision before reporting it. Use `complete` only when the capability standard is met and the student explicitly chooses completion. Map `complete` to `status: completed`; map `active` and `replan` to `status: active`. Update `## Lesson Index` with actual Lesson states and sources. Update `## Current Position` with met, unmet, and conflicting criteria. Update `## Next Lesson Candidate` with the grounded next candidate or an explicit no-next-lesson result. Update `## Plan Summary` with the active evidence and decision.
9. Reread the Plan after the write and verify those four sections and frontmatter. Only then send the student a conclusion derived from the reread Plan. If the write or reread fails, say the decision is not yet persisted and do not claim that Plan state changed.

A tool-use turn contains tool calls only. After the tool results arrive, send a separate Chinese student-facing message. Do not announce, preview, or narrate a tool call; text such as “I will read/write/check”, “let me”, “现在检查” or “接下来写入” before or beside a tool call violates this protocol. Use the separate post-result message for evidence explanations, preparation choices, and final decisions.
