# 课后复盘与下一课共备

只在"最新 Lesson 已 closed，且没有 prepared/active 的下一课"时读取。

顺序只有一条亮线：**读固化结果 → 接住学生主动补充 → 公开判断 → 讨论下一步需要 →
生成草案 → 走统一批准门。** 在上一步完成前不进入下一步；未讨论出下一步需要前不
生成草案，未确认前不搜索材料、不读取模板、不创建 Lesson。

## 1. 读固化结果

读取当前 Plan，并沿 Lesson Tree 定位刚关闭的 Lesson。先读其
`Consolidated Learning Traces`，再重新读取 `memory/INDEX.md`，沿 Trace 与根索引中的精确链接按需读取
相关对象记忆；只有会改变阶段判断时才展开已有能力假设；只有会改变互动与负担时才展开
当前偏好。压缩结果足够时到此停止。

只有固化结果缺失、冲突，学生提出具体纠正，或一个高影响判断取决于帮助前后的细节时，
才下钻相关 Block 与 Classroom Log。不要默认读取完整 Lesson，也不要为了保险重建整堂
课。此时只形成初步判断，不生成下一课草案。

## 2. 接住补充，不重复采访

课末反思已经在 Tutor Session 完成。学生回到 Plan 时若主动补充、纠正或改变需求，先听
完并把它纳入判断；否则直接使用固化结果，不重复进行整课反思，不例行再问一遍哪里顺、
哪里不踏实。只有上述缺失、冲突或高影响条件成立时，才问一个针对性问题。

## 3. 公开判断

综合固化结果与学生此刻新增的信息，用普通教师语言公开说明并区分：

- 课堂中实际发生的作答、停止点和帮助；
- 学生现在报告的理解感、困难、兴趣和负担；
- 教师基于两者作出的暂定解释；
- 还没有被独立表现证明的部分。

两类证据冲突时保留冲突，把它转化为下一课需要检验的问题，不改写原始课堂事实。
同时说明对初始弧线的调整判断：按原方向继续、加快、放慢、调整阶段内顺序或负担，
或把超出本 Plan 的路线问题交回 Roadmap。

## 4. 局部维护阶段记忆

先看根索引是否存在 `Deferred Object Routing`。只有本阶段证据已经足以说明某个待分桶
对象应进入哪些既有或新 bucket 时，Coach 才明确给出这些 bucket 并调用
`memory_route_resolve`。若仍无法判断，保持 deferred 条目原样，不为了文件完整而猜一个
分类。这个窄工具只处理 deferred 出口；对象合并、别名和普通重分桶仍由 Coach 先完成
语义判断，再按下面的低频维护边界处理。

只有同一模式已经跨不同对象出现时，才创建或修订 `memory/capabilities/` 中的一份工作
能力假设。单一对象内重复出现仍属于对象记忆，不升级。能力文件保持：

- `Current Hypothesis`：暂定解释；
- 适用范围、不适用边界与 `Evolution Overview`；
- 来自不同对象的 Trace 链接、冲突或反向证据；
- 追加式 `Calibration History`。

若本阶段看清了对象同义、重复或分桶问题，可以补别名、更新多对多 bucket；合并时保留
旧对象文件并改为指向规范对象的重定向，不移动稳定文件，不改写旧 Trace。学生在 Plan
中明确表达或撤回偏好时，更新相应 preference 的原话、时间、范围与当前判断。最后只
局部更新受影响的 INDEX 路由。下一课检验、练习和安排都是教学待办，留在 Plan。

## 5. 再生成草案

师生讨论出下一步真正需要解决的问题后，教师才生成第一版下一课草案，说明为什么
这样安排及主要取舍。学生修订或拒绝后，教师整合为完整但不泄题的公开 Lesson 提案：
本课为何现在进行、目标、与 Plan 的关系、大致学习过程、预期参与方式、课末完成
标志，以及会实质影响学生选择的负担或取舍。

学生否定的是本课时，在阶段内重做草案；否定整个阶段时，停止创建 Lesson 并返回
Roadmap。

提案经学生明确确认后，按根 Skill 的统一批准门写入 `Next Lesson Arrangement` 并
调用 `prepare-approved-lesson`，一次只物化当前下一节 Lesson。讨论收敛后，可以把
共同确认的真实进展和边界更新到 Plan 的 Current Position。初始弧线只是可调整假设，
不是学生对未来 Lesson 的预先批准。
