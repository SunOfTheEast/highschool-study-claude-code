# 首次进入与第一课共备

只在"Lesson Tree 为空且没有当前 Lesson"时读取。

## 简短交接

首次进入不是重新审批 Plan：Stage Goal、Observable Capability Standard 与 Test 已
在 Roadmap 确认。先用自然语言完成一次简短交接：这个阶段为什么现在做、主要希望
发生什么变化、怎样看出阶段已经完成、第一课为什么可能从当前位置开始。教师可以
澄清学生的理解，但不把整个 Plan 再读一遍，也不要求学生重新批准已经确认的阶段。

学生此时明确反悔或提出超出当前 Plan 的目标时，解释冲突并把路线问题交回
Roadmap；只涉及阶段内先后、强度、学习方式或第一课重心的变化，留在本 Session
共同调整。

## 草案先行

第一课缺少本 Plan 内的既往课堂经验，教师先根据已确认 Plan、现有证据与初始弧线
形成一份可放弃的暂定 Lesson 草案，再把它作为有理由的建议交给学生讨论。草案不是
定案；备课投入不能成为说服学生继续的理由。学生理解关键收益与代价后仍拒绝，就
重新开始共同思考。

以草案为起点说明建议和真实取舍，与学生讨论：本课推进 Plan 的哪一步及为什么先做
它、学生对相关内容的现有经验与准备状态、本课重点、难度、节奏、参与方式、学习
活动与材料类型、课后负担，以及课末应能表现出什么。这些不是逐项盘问的表单；
对话持续到教师能够整合一份有依据的课程方案，且学生能够理解它将怎样进行并作出
决定。

具体题目、答案、提示阶梯、误区分支和备用路线属于教师的私有备课，不提前泄露，
也不在学生确认前物化为正式 Lesson。

## 确认与交接

教师把修订结果整合为完整但不泄题的公开 Lesson 提案：本课为何现在进行、目标、
与 Plan 的关系、大致学习过程、预期参与方式、课末完成标志，以及会实质影响学生
选择的负担或取舍。

提案经学生明确确认后，按根 Skill 的统一批准门写入 `Next Lesson Arrangement` 并
调用 `prepare-approved-lesson`，一次只物化当前一节 Lesson。学生仍认可 Plan 只是
不接受这节课时，在阶段内放弃或重写草案；学生不再认可阶段目标时，停止创建
Lesson 并返回 Roadmap。
