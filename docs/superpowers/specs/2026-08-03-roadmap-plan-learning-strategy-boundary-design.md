# Roadmap 与 Plan 的分层学习策略设计

状态：基于 2026-08-03 已确认讨论整理，待书面复核
日期：2026-08-03

## 一、结论

StudyForge 的三层学习树不只是在不同时间尺度上保存目标，也在不同层次上保存
“怎么学”。

```text
Brief       介绍这是一栋什么楼，里面有什么
Roadmap     学生想爬到哪里，并与 Agent 共同决定总体怎样爬
Plan        到达当前这一层需要形成什么能力，以及这一层具体怎样学
Lesson      脚下这个台阶在真实课堂中怎样走
```

Roadmap 和 Plan 都拥有学习策略与学习偏好，但二者不是重复关系：

- Roadmap 保存整个学习周期的上位学习方针；
- Plan 将上位方针与当前数学内容、近期课堂事实结合，翻译成这一阶段的具体教学
  策略；
- Lesson 将 Plan 策略实例化为本节目标、活动、素材、帮助方式和真实课堂记录。

本文所称 `Brief.md` 严格只承担内容简介。当前 M0 最接近它的文件是
`LEARNING_GUIDE.md`，但该文件目前还混合了承担教研提示；是否改名或拆分不属于本
设计范围，不能因此把 Brief 的目标职责重新扩大。

## 二、这次问题是怎样暴露的

此前真实验收中的单节课大多可以正常完成，题目、Session、Markdown 记录和父子
读取也能工作，但整段课程的节奏仍显得奇怪。

导数学习集明确面向已经掌握基础、希望提升综合题结构识别和方法选择的学生。这样
的学生常见诉求是：

- “我想学点高级的技巧。”
- “我做导数综合题经常没有思路。”
- “答案看得懂，但自己想不到该用什么方法。”

他们通常不是希望重新检查每一个基础环节，而是希望较快认识同构、切线放缩、参
变量分离等高级方法的本质、识别信号与迁移方式。

此前课程并非每个台阶都走错了，而是上游没有充分确定学生想采用什么学习方式。结
果是学生希望“先坐电梯看到高级方法地图”，课程却默认“从第一阶楼梯逐步排查”。
Lesson 可以执行得认真，整体节奏仍然不对。

这说明 Roadmap 的重要性一直被低估。它不能只被当成长期目标、Plan 索引和当前位
置；它还是学生与 Agent 共同确认的长期学习契约。

## 三、四层文档的职责

### 3.1 Brief：介绍内容

Brief 是学习集作者准备的内容说明。它回答：

- 这个学习集覆盖什么内容；
- 适合怎样的学生；
- 有哪些主要方法、题型或资料；
- 学完大致可能获得什么。

Brief 不替某个具体学生决定目标，不保存个体学习策略，也不根据课堂结果更新。

### 3.2 Roadmap：共同确定长期能力与总体学法

Roadmap 由学生和 Roadmap Agent 通过真实对话共同制定。它回答：

- 学生希望通过这一段长期学习获得什么能力；
- 学生目前为什么想学；
- 整体希望以怎样的节奏和方式推进；
- 什么表现意味着这段长期学习已经达到目的；
- 当前从哪里进入最合适。

Roadmap 中的“怎么学”是上位学习方针，例如：

- 先快速获得方法全景，再选择关键方向深入；
- 先由老师讲清方法原理和识别信号，再练发现与迁移；
- 通过困难问题探索方法，老师尽量延后介入；
- 稳扎稳打，从必要基础开始逐层建构；
- 节奏较快，基础内容只在确实造成阻碍时回补。

这些方针只约束当前 Roadmap，不自动升级为永久学生画像。学生可以在后续复盘中改
变它们。

### 3.3 Plan：当前能力阶段与局部学法

Plan 对应“到达当前这一层需要什么”。它拥有：

- 一个有边界的阶段能力；
- 一个可观察标准和直接检验；
- 当前这一层具体采用的教学策略；
- 与本阶段内容相关的学习偏好；
- 根据已关闭 Lesson 继续、回补、重排或检验的安排。

Plan 不是复制 Roadmap 的偏好，而是进行一次具体翻译：

```text
Roadmap 总体学习方针
＋ 当前阶段的数学内容
＋ 本 Plan 已发生的真实课堂
＋ 学生此刻的时间、兴趣与感受
→ 当前 Plan 的具体学习策略
```

学生可以总体偏好“快速看全景”，但某个概念确实陌生时，当前 Plan 仍可选择较慢
的建构；也可以总体偏好探索，却在考试临近时要求当前 Plan 更直接。局部调整不是违
背 Roadmap，而是把上位方针应用到真实楼层。

### 3.4 Lesson：实际走过的台阶

Lesson 不再重新决定长期学习方式。它把 Plan 已确定的局部策略变成本节真实课堂：

- 这一节保持不变的目标；
- 使用哪些问题、解释、图像、视频或讨论；
- 哪些活动做透，哪些只做判断、比较或关键一步；
- Tutor 何时观察、提示、换一种解释或收口；
- 学生实际怎样开始、停顿、修正和完成。

Lesson 的 Block 日志是后来 Plan 调整策略时读取的原始事实。

## 四、Roadmap 不是让学生自己做专业诊断

学生通常不会用课程设计语言表达自己的需求。Roadmap Agent 不能要求学生直接说：

> “我要先建立高级方法地图，而不是进行基础补弱。”

真实学生更可能说：

> “我想学点高级技巧。”
>
> “导数题我经常没有思路。”

Roadmap Agent 的专业责任是通过自然追问理解这些话，而不是把制定路线的工作推回
给学生。一次合理的首次交流可以是：

```text
学生：我想学点导数里高级一点的技巧。

老师：可以。你现在做导数题，最难受的是求导算不下去，
      还是拿到综合题不知道从哪里开始？

学生：主要是不知道从哪里开始，答案看了又觉得能懂。

老师：最近哪种题最容易出现这种感觉？

学生：有 x、ln x、e^x 混在一起的时候，我经常不知道要干什么。

老师：听起来你不是基础求导不会，而是还不太会从表达式里认出方法。
      我建议先把几种常用的高级方法快速认识一遍，每种先讲清它在
      做什么、题目会给什么信号，再练怎么自己发现。先从同构开始，
      过程中真有基础环节挡路时再回头补。这样安排合适吗？

学生：可以。
```

学生提供愿望、困难和具体经历；Agent 负责提出有洞见的解释与建议；学生用普通语
言确认或修正。Roadmap 保存的是双方确认后的教学判断，不是学生原话的机械转录，
也不是 Agent 单方面猜出的画像。

## 五、“爬楼”比喻下的三种总体学法

同一个学习集可以支持完全不同的 Roadmap：

| 总体学法 | 学习体验 | 典型用途 |
|---|---|---|
| 走楼梯 | 从必要基础开始，逐层建构、练习和检验 | 基础不稳或希望系统重建 |
| 坐电梯 | 先快速看到方法全景和关键洞见，再在重要楼层练识别与迁移 | 基础较好，希望高密度扩充方法库 |
| 徒手攀岩 | 以困难任务和探索为主，从受阻、猜想与比较中发现方法 | 喜欢挑战、发现式学习或竞赛探索 |

这些是理解 Roadmap 层级的比喻，不应实现为枚举字段或固定模式。真实 Roadmap 可以
混合使用，也可以在学习中改变。

Roadmap 规定的是默认攀登方式。Plan 面对具体楼层时，可以基于内容和课堂事实临时
采用另一种方式，但应让学生知道为什么这样安排。

## 六、同构学习的完整分层示例

### 6.1 Brief 层

Brief 只需介绍：本学习集包含同构变形、切线放缩、参变量分离、数形结合和局部逼
近等高级导数方法。同构是其中一种重要方法。

### 6.2 Roadmap 层

经过学生与 Agent 对话，双方确认：学生基础求导大致具备，希望快速熟悉高级方法，
先理解方法本质与识别信号，再训练独立发现和迁移；不默认从基础补弱开始。

这是整个学习周期的总体路线，不是同构 Plan 的逐课安排。

### 6.3 Plan 层

当当前楼层是同构时，Plan 将总体路线具体化：

- 先从复合映射解释同构的本质；
- 理解将表达式整理成同一个严格单调函数不同输入的意义；
- 把“跨阶”作为高价值识别信号；
- 从显式结构进入需要代数整理的隐藏结构；
- 最后在陌生外壳中检验能否主动发现和迁移；
- 若暴露的是局部代数整理问题，只局部回补，不将整个阶段改成基础课。

“跨阶”指 `x`、`ln x`、`e^x` 等不同复合层级的对象同时出现。它是提醒学生检查能
否升阶、降阶或配成共同外层函数的信号，不是看见这些符号就自动判定同构。最终仍
需核对定义域、值域与单调性。

### 6.4 Lesson 层

某节 Lesson 才决定本节实际使用一张映射图、哪些题用于直接识别、隐藏整理或迁移，
以及哪些完整书写、哪些只做口头判断。Tutor 根据学生当场表现推进并写入 Block 日
志。

## 七、信息继承而不是语义复制

三层之间的关系不是把同一句学习偏好复制三次。

```text
Roadmap：上位学习方针
        ↓ 结合当前阶段内容
Plan：本阶段具体学法
        ↓ 结合本节目标与素材
Lesson：本节课堂路径
        ↓
Block Classroom Log：实际发生的事实
```

父节点提供方向，子节点只写本层需要的具体化和变化。Plan 需要读取 Roadmap，但不
必重复全部 Roadmap；Lesson 需要服从 Plan，但不再解释整段长期路线。这样既保持连
续性，也避免重复语义上下文不断膨胀。

## 八、对下一轮验收的影响

下一轮真实课程验收不能直接复用一份含糊的通用 Roadmap，否则无法判断 Lesson 模
板和 Plan 周期是否真的改善教学质量。

验收前应先模拟一次自然的首次家教交流，让学生只说普通学生会说的话，由 Roadmap
Agent 完成追问、教师判断、建议和确认，并形成同时包含“目标能力”与“总体学法”的
Roadmap。

随后再观察：

- Roadmap 是否使首个 Plan 的目标与节奏符合学生来意；
- Plan 是否将总体学法具体化为当前能力阶段的教学策略；
- Lesson 模板是否在该策略下产生合适的题组、处理深度与课堂节奏；
- 课堂事实是否促使 Plan 作出有理由的局部调整，而不是机械重复 Roadmap。

## 九、非目标

本设计当前不要求：

- 为“楼梯／电梯／攀岩”增加枚举或模式字段；
- 新增 Roadmap 或 Plan schema；
- 把学习方式写成永久学生画像；
- 让学生回答抽象的教学策略问卷；
- 预先物化所有 Plan 或 Lesson；
- 修改记忆、BKT、闪卡或复习调度系统；
- 用防御性运行时代码判断 Agent 的教学措辞。

当前结论首先是一项提示词与文档写作原则。更深入的记忆和复习机制应在真实课程验
收证明这条主链路有效之后再讨论。
