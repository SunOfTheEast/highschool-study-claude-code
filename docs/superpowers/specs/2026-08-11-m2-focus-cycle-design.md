# M2 现实时间第一阶段：专注周期设计

**状态：** 已讨论定稿，等待实施计划

**日期：** 2026-08-11

**适用范围：** `apps/pi-teaching-web` 的 macOS 桌面端、Free Learning 与 Lesson

## 一、问题与目标

StudyForge 的教师目前能够读取学习内容、Session 历史和学生记忆，却不知道现实中一段学习
实际经过了多久。若把时钟交给模型轮询，既不准确，也会持续消耗推理和上下文；若只在浏览器
显示倒计时，退出应用、电脑休眠或页面切换后又无法可靠恢复。

本阶段先实现一个最小专注周期：学生在真实学习 Session 中直接启动、暂停、继续或结束计时；
Runtime 掌握权威时间并在开始和结束两个节点把最小事实写入原生 Pi Session；老师只在结束时
结合学生实际反馈决定下一步。

它不是学习效果测量，也不是完整的生产力系统。本阶段明确不做：

- 日历、复习排程和资产遗忘算法；
- 番茄统计、连续打卡、积分、排行榜和历史报表；
- 依据计时长度推断专注、掌握、努力程度或认知变化；
- 模型工具式计时、自然语言控制计时和模型持续读取时钟；
- 后台常驻守护进程、应用退出后的准点 Agent 回复；
- 多窗口、多进程或多个学习集同时运行多只计时器。

## 二、学生闭环

### 2.1 启动范围

计时入口只出现在正在进行的 Free Learning 或 Lesson 对话中。Roadmap、Plan、Meta、已经结束
的 Session 和单独的资产阅读页不显示入口。学生想围绕一张题卡或笔记专注学习时，先沿现有
“问老师”路径把它带入 Free Learning，再启动计时。

入口是聊天页头中的安静按钮“开始专注”。点击后只提供 15、25、45 分钟三个预设，25 分钟
为默认的一键选择；首版不提供任意数字输入。

开始、暂停、继续和结束都是普通界面操作。它们不调用模型工具，不要求学生对老师说固定
口令，也不让模型判断按钮是否可以执行。

### 2.2 运行中

计时开始后，聊天页内的启动入口收起，当前学习集顶栏显示紧凑倒计时、暂停和结束。该位置
采用已经确认的“顶栏常驻”方案：学生切换到题卡、笔记、学习首页或课程脉络时仍能看见同一
只表；开始前不长期占据顶栏空间。

暂停与继续只改变机械计时状态。页面重渲染、前后台切换和普通导航都不重建计时，也不向
Session 追加事件。

### 2.3 到时与提前结束

自然到时或学生提前结束时，界面先立即播放本地提示音并显示“本次专注时间已到”或“本次
专注已结束”。窗口在后台时，同时使用 macOS 系统通知。模型延迟不能承担闹钟职责；老师的
回复是随后发生的独立交互。

结束事件进入 Session 后，老师先简短询问学生实际完成了什么、哪里卡住。如果学生正在做题，
先听学生讲当前过程；之后可以建议休息、继续当前讨论或再开一轮，选择权留给学生。到时不会
自动结束 Free Learning、关闭 Lesson Block、提交记忆或开始下一只计时器。

学生主动结束整个父 Session 时，绑定的计时也随之结束并从顶栏消失，不再额外开启一轮教师
追问。不存在单独的“取消但不算结束”状态。

## 三、责任边界

| 事实或行为 | 唯一负责人 | 边界 |
| --- | --- | --- |
| 当前计时状态、权威时间、暂停累计、到期恢复 | Runtime | 不判断学生是否真的专注 |
| 开始、暂停、继续、提前结束 | 学生界面 | 机械命令，不经过 Agent 语义判断 |
| 开始与结束历史 | 当前 Pi Session | 只保存两类 Custom Message，不另建统计表 |
| 到时提示音、页内提示、系统通知 | 前端与桌面壳 | 只提示机械到时，不等待模型 |
| 结束后的教学回应 | 当前老师 | 先询问真实进展，再建议下一步 |
| 学习效果、对象记忆和课堂进度 | 既有教学与记忆机制 | 不从计时事件自动派生 |

Runtime 可以说“计时器在未暂停状态下累计运行了 25 分钟”，不能说“学生专注学习了 25
分钟”。电脑休眠期间没有按下暂停，墙上时间仍计入计时；这仍然只是计时器事实，不是行为
监控。

## 四、唯一活动状态

当前学习集只保存一份 Runtime 私有状态：

`<learning-set>/.studyforge/time/focus.json`

最小结构为：

```ts
type FocusCycleState = {
  cycleId: string;                 // Runtime 生成
  sessionKey: SessionKey;          // 绑定 Free Learning 或 Lesson
  sessionId: string;               // 防止投递到同名但不同的原生 Session
  targetSeconds: 900 | 1500 | 2700;
  startedAt: string;               // Runtime ISO 时间
  status: 'running' | 'paused';
  runningSince: string | null;      // paused 时为 null
  accumulatedSeconds: number;      // 只累计未暂停的计时器运行时间
};
```

剩余时间、预计到期时间和是否已经到期都从这组字段计算，不持久化第二份派生值。状态中没有
页面位置、暂停次数、应用切换、统计归属、学生评价或教师建议。

正常结束后删除活动状态；结束事实已经进入 Pi Session，不为已结束的周期保留第二份 Runtime
历史。状态写入使用同目录临时文件与原子替换，避免只写入半份 JSON。

当前桌面产品一次只打开一个学习集，并在本阶段改为单实例，因此这一份状态也就是学生唯一
活动计时。若启动入口发现已有周期，只恢复并展示原周期，不创建第二个。未来若产品真正引入
多学习集并行窗口，再把计时所有权提升为桌面服务；本阶段不预建跨进程同步协议。

设置页切换学习集会更换整个 Runtime 工作区，不属于普通页面导航。存在活动计时时，首版直接
阻止切换并提示先结束当前专注；不让旧学习集留下一只后台表，也不为这一罕见操作增加新的
结束原因或跨学习集注册表。

## 五、两种 Session 时间事件

历史只使用原生 Pi Custom Message，不伪装成学生消息，不增加 Tool Call，也不另建番茄 Log。

### 5.1 `studyforge.m2.focus-started.v1`

```ts
type FocusStarted = {
  cycleId: string;
  sessionKey: SessionKey;
  sessionId: string;
  targetSeconds: 900 | 1500 | 2700;
  startedAt: string;
};
```

Runtime 在 Session 中持久化类似以下事实：

> 专注计时已开始。目标 25 分钟，开始时间由 Runtime 记录。本事件不要求回复。

该消息显示为一条轻量时间标记，`triggerTurn=false`。老师不会因为学生按下开始按钮而说一段
鼓励话或重复安排任务。

### 5.2 `studyforge.m2.focus-ended.v1`

```ts
type FocusEnded = {
  cycleId: string;
  sessionKey: SessionKey;
  sessionId: string;
  targetSeconds: 900 | 1500 | 2700;
  elapsedSeconds: number;
  endedAt: string;
  reason: 'elapsed' | 'manual' | 'session-ended';
};
```

其中 `elapsedSeconds` 是排除明确暂停后的计时器运行时间。自然到时的 `endedAt` 是计算出的
到期时刻，而不是学生几小时后重新打开应用的时刻；此时 `elapsedSeconds` 截止于目标时长。
提前结束和父 Session 结束则使用停止时实际累计值。

普通自然到时或提前结束时，Custom Message 携带一条紧凑的协议说明：这是计时事实而非专注
证明；请先询问实际进展，再根据学生回答讨论休息或继续。父 Session 结束产生同类历史事件，
但 `triggerTurn=false`，不追加一轮教师对话。

两个事件使用同一 `cycleId`，既表达一对开始与结束，也承担崩溃恢复时的幂等键。事件字段由
Runtime 绑定；模型不填写 ID、时间、时长或结束原因。

## 六、状态转换与投递

活动状态只有三种可见位置：

```text
不存在
  └─ start ─→ running
running
  ├─ pause ─→ paused
  └─ elapsed / manual end / parent Session end ─→ 结束事件后删除
paused
  ├─ resume ─→ running
  └─ manual end / parent Session end ─→ 结束事件后删除
```

开始顺序为：验证当前 Session 与唯一活动约束，生成 `cycleId`，落活动状态，再持久化开始消息。
若进程在两步之间退出，恢复时沿 `cycleId` 检查 Session；缺少开始消息就补写一次，已有则不
重复。

若进程仍在而开始消息写入明确失败，启动操作失败并回滚刚创建的活动状态；只有回滚过程中
再次异常时，才交给同一恢复逻辑收敛，不能留下界面显示为成功但 Session 不知情的计时。

结束顺序为：先向界面发布本地到时状态，再计算并持久化结束消息，确认消息存在后删除活动
状态。若进程在结束消息写入后、状态删除前退出，恢复时发现同一 `cycleId` 已有结束消息，只
删除旧活动状态，不再次投递。

正常到时与提前结束使用 Pi 原生 Custom Message 触发老师：

- Session 空闲时立即开始一个 turn；
- 老师正在回复时使用 `deliverAs='followUp'`，排在当前回复结束之后，不中断当前推理；
- 时间事件已经持久化但模型调用随后失败时，计时仍保持结束，沿现有公开错误与继续对话路径
  处理，不重新启动计时，也不循环重投同一事件。

为此，`StudySession` 的窄接口需要暴露 Pi 原生 `sendCustomMessage`，而不是用普通 `prompt`
伪造用户输入。`WorkspaceRegistry` 仍负责 Session 打开与 turn 串行化。

## 七、退出、休眠与恢复

- 应用在运行而窗口位于后台：Runtime 正常到期，前端发声并由桌面壳显示系统通知；老师按
  正常事件投递规则随后回复。
- 应用退出：不维持后台 Agent，也不保证到期时发声。活动状态留在学习集。
- 运行态重新打开：按 `runningSince` 与当前墙上时间重算；尚未到期就恢复顶栏，已经到期就
  结算到真实到期时刻并只投递一次结束事件。
- 暂停态重新打开：保持暂停，不把关闭期间算入累计时间。
- 父 Session 已经结束但留下旧活动状态：补齐不触发回复的 `session-ended` 结束事实并清理
  状态，不复活已经结束的课堂。

macOS 通知权限被拒绝时，页内提示与本地提示音仍然工作；权限失败不影响时间事实和 Session
事件。浏览器 `setInterval` 只负责刷新显示，所有剩余时间都从 Runtime 快照和当前时间推导，
不能把刷新次数当成计时来源。

## 八、单实例边界

同一个学生不能通过重复启动应用得到两只互相冲突的计时器。macOS 桌面壳使用 Tauri 单实例
能力：第二次启动只唤醒并聚焦已有主窗口，不生成第二个 Runtime。当前学习集已有活动周期时，
所有入口都展示或恢复同一 `cycleId`。

这是一条桌面生命周期约束，不向 Agent 增加“多开判断”，也不建立文件锁租约、主从选举、
跨窗口广播协议或多计时器合并规则。

## 九、界面与文案

### 9.1 未开始

Free Learning 和 Lesson 的聊天页头显示“开始专注”。点击后就地展开三个时长；选择后立即
收起。Roadmap、Plan、Meta 和结束后的对话不渲染这组控件。

### 9.2 运行或暂停

采用已确认的顶栏 A 方案：

- 紧凑显示“专注中 24:37”或“已暂停 12:08”；
- 运行态提供“暂停、结束”，暂停态提供“继续、结束”；
- 不显示百分比、火焰、积分、完成环或夸张动画；
- 顶栏控件不挤压学习内容，窄窗口可以缩成计时数字，展开后操作。

开始和结束消息在对话中投影成细线分隔的轻量时间标记，而不是“你”或“老师”的气泡。内部
custom type、`cycleId`、`sessionKey` 和秒数 JSON 不暴露给学生。

本地到时文案只描述事实，例如“25 分钟计时已到”；不使用“太棒了，你专注完成了一个番茄”
一类无法由系统证明的评价。

## 十、老师的结束回应

结束事件只需要一条亮线：

```text
读到计时事实
→ 简短询问学生实际完成了什么、哪里卡住
→ 先听学生回答
→ 再结合当前 Session 建议休息、继续或另开一轮
```

老师不得仅凭事件：

- 声称学生一直专注或已经完成目标；
- 自动提交自由学习记忆或 Lesson 对象记忆；
- 自动完成课堂 Block、Lesson、Plan 或 Free Learning；
- 自动开始下一轮计时；
- 输出固定番茄钟鸡汤或长篇复盘模板。

这份协议随 `focus-ended` 在行为发生时注入，不新增模型计时工具，也不把一大段时间规则常驻
所有 Session。开始事件明确不要求回复。Roadmap、Plan 与 Meta 不会收到这两类事件。

## 十一、实现改动面

后续实施计划应限制在以下切片：

1. 新增 Runtime 专注周期模块，负责状态文件、时间计算、恢复、幂等与 Session 资格验证；
2. 为 `StudySession` 暴露窄化的原生 `sendCustomMessage`，在 `WorkspaceRegistry` 中接入开始、
   结束和父 Session 关闭路径；
3. 增加查询、开始、暂停、继续、结束的机械 HTTP 契约，以及现有事件流中的状态刷新；
4. 在 `ChatPanel` 增加未开始入口，在 `AppShell` 增加已确认的顶栏活动控件，并投影两类时间
   标记；
5. 在 macOS Tauri 壳接入系统通知与单实例能力；本地提示音和页内反馈保持可降级；
6. 增加少量基于可控时钟的状态、恢复、投递和界面测试，并完成真实模型小闭环。

不修改学习资产 schema、Session Key、Lesson Block、对象记忆、足迹或课程树，不引入新的
Agent Tool、数据库、后台 daemon 和番茄历史页面。

## 十二、验收

### 12.1 自动化

1. 只有 active Free Learning 与 Lesson 可以启动；重复启动、其他 Session 和已结束 Session
   被机械拒绝。
2. 15、25、45 分钟的运行、暂停、继续与提前结束计算正确；暂停时间不计入
   `elapsedSeconds`。
3. 开始只产生一个不触发 turn 的 Custom Message；暂停与继续不产生消息。
4. 自然到时和提前结束各自产生一个结束消息；老师正在回复时结束消息成为 follow-up，不
   中断当前回复。
5. 开始落盘中断、结束落盘中断、运行态重启、暂停态重启和过期重启均沿 `cycleId` 恢复且
   不重复投递。
6. 父 Session 结束会清理计时，不触发额外老师回复，也不改变既有结课语义。
7. 顶栏在学习集页面间持续显示同一状态；内部 ID 和原始事件不泄露到学生界面。
8. 第二次启动桌面应用只聚焦已有窗口；通知权限失败不影响计时结束。
9. 活动计时存在时不能切换学习集；普通学习集内导航仍不影响计时。

测试使用可注入时钟推进时间，不在测试中真实等待 15 或 25 分钟；只为独立硬不变量编写测试，
不为每个秒数和同义文案复制用例。

### 12.2 真实模型

使用发布配置中的真实老师模型验收三条链：

1. **正常到时：** 学生围绕一个真实困惑学习，结束事件后老师首击先问实际进展，不声称学生
   已专注或已掌握，不自动结课。
2. **提前结束：** 目标 25 分钟但计时器较早结束；老师能看见目标与实际计时时长，先理解原因
   和现状，不进行道德评价。
3. **随 Session 结束：** 活动计时期间结束 Free Learning 或 Lesson；计时安静消失，Session
   正常关闭，不多出一轮番茄追问。

真实模型验收可以通过测试时钟快速触发事件，但不得为此给发布界面增加任意短时长入口。

首击合格门是：开始时保持安静，到时后证据措辞准确、回应简短、先问真实进展，并守住记忆、
课程状态和学生决策权。

## 十三、后续复用

日历将在下一份独立设计中复用已经验证的 Runtime 权威时间、桌面通知和 Pi Custom Message
投递通道，但不会扩宽 `FocusCycleState`。资产级遗忘复习再使用日历式到期事件，不把复习
排程塞入专注周期文件。

这样三类机制共享可靠的“现实时间 → Runtime 事件 → Agent 决策点”，同时继续各自拥有最小
数据结构和事实边界。
