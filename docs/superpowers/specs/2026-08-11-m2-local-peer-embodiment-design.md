# StudyForge M2 Peer 数字人薄切片设计

**状态：** 已讨论定稿，实施中
**日期：** 2026-08-11
**范围：** 只为自由学习中的 `peer-axia` 增加本地立绘、轻量说话动画与 MiMo 自动语音
**上位约束：** `2026-08-10-m2-free-learning-peer-first-loop-design.md`、
`2026-08-10-studyforge-m2-m4-milestone-outline.md`

## 一、目标

文字 Peer 首闭环已经证明学生、Peer 和教师可以在同一个原生 Pi Session 中公开对话，且
Peer 发言不会被误记成学生表现。本切片只回答下一个产品问题：当阿夏说话时，能否用一种
不打断学习、不另造聊天事实、也不依赖按分钟云端渲染的方式，让学生真正感到一个同龄伙伴
来到了对话中。

首版成功形态是：学生在自由学习中明确邀请阿夏，阿夏的文字回复先按真实 actor 落盘；页面
边缘随后出现一个轻量角色形象，MiMo 语音自动朗读同一条回复；教师可以同时在后台继续生成，
但其公开续接在阿夏说完后再出现。任何表现层失败都只退化为已经成立的文字三方对话。

本切片把早期文字原型中的显示名“阿澄”和 actor ID `peer-acheng` 一次性替换为“阿夏”和
`peer-axia`。该角色尚未作为稳定产品接口发布，因此不保留双写或别名分支；历史测试消息即使
无法匹配新角色资源，也仍按普通文字消息投影。

本切片优先验证私人环境中的真实体验。目标机器是 Apple Silicon M4、24 GB 内存；不同时
建设角色编辑器或跨平台安装流程。

## 二、承重边界

### 2.1 一个发言事实，一套可替换表现

原生 Session 中 `ask_peer` 的成功 `toolResult` 仍是阿夏发言的唯一事实。立绘、表情、语音、
播放进度和动画都是这条消息的派生表现：

```text
同一条 actor 消息
→ Markdown / KaTeX 文字投影
→ 数学口播转换
→ actor 对应的本地声音
→ actor 对应的立绘与说话状态
```

表现层不得生成或持久化第二条回复，不得修改原文，不进入对象记忆、学习足迹、Note、题卡
或 Material。音频可以作为可删除的本地派生缓存存在，但不能成为恢复会话所需的事实。

### 2.2 不是第二个 Agent

数字人没有自己的模型调用、Session、记忆、工具或人格副本。阿夏仍由现有 Peer Runner
生成；教师仍由当前自由学习 Agent Loop 主持。正常说话不经过 MCP，也不增加一次情绪分类
或口播改写模型调用。

### 2.3 首版只有阿夏，表现层不写死 Peer

第一版只为 `peer-axia` 启用数字人，不启用教师数字人。但数学口播、TTS、播放控制与立绘
投影都以 `actorId` 消费已经落盘的消息，不以 `peer-message` 写死实现。以后教师获得自己的
角色配置后，可以复用同一表现层，不迁移 Session，也不重写公式朗读和播放节奏。

## 三、角色视觉与界面位置

### 3.1 视觉形态

阿夏采用可辨认本人特征、但经过插画化处理的半身形象。首版准备三个固定状态：

- `neutral`：平静、明亮，用于联想、头脑风暴与旧调用兜底；
- `curious`：轻微好奇，用于追问；
- `skeptical`：认真审视，用于质疑、反例和假设攻击。

当前私人参考只用于生成插画化角色，不直接截帧成为产品画面。已经生成的三个状态、眨眼帧
及后续嘴型帧只存放在本机私有角色目录；公开仓库与公开 DMG 继续使用无身份特征的占位资源。

### 3.2 页面边缘短暂出场

角色采用已经确认的 C 布局：阿夏说话时从自由学习页面边缘轻微进入，语音结束后安静退场。
它沿用 StudyForge 的纸张、朱砂与墨绿色主题，不形成常驻数字人面板，不挤窄对话正文，也不
改变为将来侧栏预留的页面骨架。

学生全局静音后角色仍可作为安静的 actor 标识出现，但不播放声音。

### 3.3 轻量说话动画

首版不运行神经口型模型，也不为每条回复生成视频。角色资源只增加少量可直接组合的帧：

- 三个固定表情；
- 一个闭眼帧，用于低频眨眼；
- 闭口、半开与张口三个嘴型。

前端从自己正在播放的 TTS 音频取得音量包络，经过简单平滑后在三个嘴型之间切换；停顿时
回到闭口。它只需要让二次元角色呈现自然的“正在说话”，不做音素识别、viseme 对齐或逐字
精确口型。轻微呼吸、进退场和眨眼也只由 CSS / 前端时间轴完成，不增加模型调用、边车推理
或网络请求。

音频分析或任一动画帧不可用时，角色仍以当前静态表情出现；不能为了补动画重新合成语音或
重新生成 Peer 回复。MiniMax 视频、MuseTalk、LiveTalking、Live2D 与 VRM 均不进入实时链路。

## 四、语义动作驱动表情

Runtime 不从阿夏文本或学生文本中用关键词、正则或情绪模型猜表情。教师调用 `ask_peer` 时
已经知道这次邀请的学习动作，因此工具输入增加一个可选的紧凑字段：

```ts
type PeerMove = 'question' | 'association' | 'challenge';
```

稳定映射为：

- `question` → `curious`；
- `association` → `neutral`；
- `challenge` → `skeptical`；
- 旧调用、缺失值或无法识别值 → `neutral`。

该字段只表达教师已经作出的教学意图，不携带情绪标签、Session ID、图片路径或运行时状态。
它不改变 Peer 消息的证据边界，也不要求 Peer 生成时再次判断自己的表情。

## 五、语音栈

### 5.1 后端选择

试听本地 Qwen3-TTS 后，真实音色没有达到产品体验要求，因此首版收敛为：

1. **主要后端：** Xiaomi MiMo `mimo-v2.5-tts`，使用固定中文女声音色与紧凑风格指令；
2. **系统退路：** macOS 系统语音，只在 API Key 未配置、网络不可用或本次合成失败时使用；
3. **文字底线：** 系统语音也不可用时，保留已经成立的三方文字对话。

Pi 已原生支持 Xiaomi Provider。学生在设置页“阿夏的声音”中配置 API Key，凭证仍写入
StudyForge 自己的 `auth.json`，不另造账户表、语音配置文件或浏览器端密钥。桌面 Runtime
每次只从凭证层解析 Key，并由受保护的本地接口请求固定的 MiMo HTTPS 地址；浏览器不能指定
URL、模型、音色或请求头，也看不到 Provider 失败正文。

### 5.2 首版声音与后续声音克隆

没有本人录音时，首版使用 MiMo V2.5 的中文女声音色“冰糖”，并用一句自然语言把风格限制
为年轻、自然、清晰、松弛且不过度表演。获得本人明确同意和一段干净、自然、无背景音乐的
录音后，只需放入固定私有槽位 `actors/peer-axia/voice.mp3` 或 `voice.wav`；Runtime 随即改用
`mimo-v2.5-tts-voiceclone`。克隆分支使用单独的风格指令：保留参考音频里的非母语中文发音、
声调、重音与停顿，不把它校正为标准普通话；在此基础上只增加甜软、明亮、亲近的同龄交流感，
并明确排除幼态、嗲声、耳语、播音腔和夸张模仿。该风格已经过本人声线试听确认，不与预置音色
共用提示词。原始录音、声纹和克隆结果不进入 Git 或公开 DMG；由于 MiMo 的克隆协议会在每次
合成时把样本随请求发送给云端，这项使用必须取得本人知情同意。

声音替换只修改 `peer-axia` 的本地表现配置，不改变显示名、人格内核、actor ID、历史消息
或记忆边界。

## 六、数学与化学公式口播

### 6.1 公式不是原始 LaTeX 字符串

MiMo、系统 TTS 或未来其他 TTS 都只消费准备好的中文口播文本。Runtime 不把
`\frac`、上下标标记或 Markdown 分隔符直接交给语音模型。现有 KaTeX 继续负责可见公式，
其 MathML 结构可以供确定性符号朗读使用，但现成 Speech Rule Engine 没有中文规则，不能
直接承担自然中文教学口播。

### 6.2 共用口播输出契约

所有启用数字人语音的 actor 共享一条短输出契约：

> 当回复包含公式时，先用自然语言说明这一步做了什么、得到什么，再展示公式；不要为了
> 朗读重复无关内容。

这是一项输出接口约定，不是学习方法 Skill。第一版放入阿夏的人格输出边界；以后教师启用
数字人时复用同一段约定。它不能要求模型另交一份 `spokenText`，也不产生第二条可持久事实。

“如下所示”只能出现在已经说清运算动作、关键关系和结论之后，不能替代推导。例如：

```markdown
所有分压都变为原来的 α 倍后，分子得到 α²，分母得到 α⁴，所以反应商整体变为
原来的 α⁻² 倍，并且大于平衡常数：

\[
Q'_p=\alpha^{-2}Q_p>K_p
\]
```

### 6.3 两种朗读深度

- **自动播放：** 以自然语言中的运算动作、关键关系和结论为主；简单行内公式由确定性规则
  读出，展示公式本体统一跳过，不由 Runtime 猜测附近文字是否已经完整解释。
- **详细朗读：** 学生点击公式时，Runtime 根据 KaTeX / MathML 结构读运算符、上下标、
  分式、幂和括号，例如把 `Q'_p=\alpha^{-2}Q_p>K_p` 读成
  “Q 撇下标 p，等于阿尔法的负二次方乘 Q 下标 p，大于 K 下标 p”。

学生在对话中自然提出“把这个公式再念一遍”时，由被询问的角色在正常回复中口头说明，
而不是让 Runtime 判断这句话指向哪个公式。

确定性朗读只描述符号结构，不自作主张把 `p_{NH_3}` 解释成“氨气分压”；这种学科含义由
发言者已经写出的自然语言承担。首版覆盖真实验收会出现的高中数学与化学常用结构，不把
完整中文数学读屏器当成本切片完成条件；无法安全解析时保留自然语言解释和可见公式，不把
原始 LaTeX 念给学生。

### 6.4 模型负担实验

口播契约只有一条条件性写作规则，预计不会显著增加模型负担，但不凭直觉宣称成立。真实
模型验收用相同模型和 thinking 配置比较原人格与口播人格，至少覆盖：普通闲聊、简单行内
公式、连续数学推导、带上下标的化学表达。记录响应时间、reasoning / output tokens，并检查
是否出现无公式也啰嗦、重复解释、口语化破坏严谨性或公式含义漂移。该比较用于修正文案，
不建立脱离真实体验的复杂基准。

## 七、实时节奏与中断

### 7.1 正常链路

```text
学生明确邀请阿夏
→ 教师调用 ask_peer，并给出本次 PeerMove
→ Peer 文字完成并先作为唯一事实落盘
→ 教师在同一 Agent Loop 中继续生成
→ UI 启动阿夏立绘、轻量说话动画与 MiMo TTS
→ 教师续接暂存在表现层，不提前覆盖阿夏
→ 阿夏语音结束并退场
→ 已生成的教师续接公开出现
```

教师生成不等待 TTS，TTS 也不阻塞 Session 写入。等待只发生在前端展示顺序上，因此学生
听阿夏说话时，后台时间仍被用来准备教师的下一步。

### 7.2 学生掌握节奏

- 学生在 Session 已允许继续输入时发送新消息，或随时点击停止：立即中止当前音频与角色
  说话状态；教师续接已经生成时立即公开，尚未生成时回到现有教师等待状态，完成后再公开；
- 学生全局静音：之后不自动播放，但不改变任何消息事实；该偏好在本机持久；
- 页面刷新、历史恢复或再次打开线程：不自动重播旧消息；
- 同一条 live Peer 消息最多触发一次自动播放，历史水合不得被误认成新消息。

首版不要求学生等待一段固定时间，也不以音频播放完成作为工具成功或 Agent Loop 完成条件。
停止语音不创建第二个并发 Agent turn，也不改变原生 Session 何时允许下一条学生消息。

## 八、失败与隐私退化

- 私有立绘不存在：保留现有文字 Peer 样式，不显示破图；
- MiMo API Key 未配置、网络不可用或合成失败：使用系统退路；退路也失败时只显示文字；
- 合成中途失败：停止说话状态并公开教师续接，不重新生成 Peer 文本；
- 学生中断：取消本次派生音频，不取消已经落盘的 Peer 发言；
- 云端语音不可用：当前 Session、记忆与学习资产均不受影响；
- 公式无法确定性解析：读已经存在的自然语言解释，不朗读原始标记；
- 私有角色素材只从固定 actor 槽位读取，不能把任意本地路径暴露给前端或 HTTP 调用者。

当前参考视频、后续照片、录音、克隆声音和生成立绘全部属于私人本地素材。本切片的提交、
公开源码与公开 DMG 只包含接口、占位资源和文字退路，不包含可识别本人身份的素材。

## 九、实现边界

预计改动只跨越以下现有接缝：

1. 将文字原型的 `peer-acheng` / 阿澄改为 `peer-axia` / 阿夏；
2. `ask_peer` 增加可选 `PeerMove`，旧调用保持 `neutral`；
3. 新增按 `actorId` 解析的本地表现配置与严格槽位资源读取；
4. 桌面端增加固定 MiMo TTS 适配、StudyForge 凭证解析和系统语音退路；
5. Markdown 投影增加共用口播转换和公式详细朗读入口；
6. 对话投影区分 live 新消息与历史水合，并维护当前播放 / 中断状态；
7. `ChatPanel` 增加页面边缘角色舞台、音量驱动嘴型、自动播放、停止和全局静音；
8. 阿夏人格增加共用口播输出契约；
9. 私人环境提供不进入 Git 的角色素材；语音 Key 进入既有私有凭证层。

不新增统一多 actor 消息总线、第二个 Peer Session、数字人专用记忆、图数据库、云端媒体
管线或 Runtime 情绪判断。若现有组件需要抽出小型 actor-agnostic 接口，只抽取本切片实际
使用的能力，不预建插件平台。

## 十、验收

### 10.1 确定性检查

- 开启或关闭表现层都投影同一条 `peer-message`，Session 不增加镜像文本；
- 三种 `PeerMove` 稳定映射表情，缺失值为 `neutral`；
- TTS 播放时嘴型随音量在三帧间平滑变化，停顿闭口；缺帧时退化为静态表情；
- 只有 live 新消息自动播放，刷新与历史恢复不播放；
- 停止、发送新消息、静音和 TTS 失败都不删除或重写文字；
- 教师续接可以在后台完成，并在语音结束或中断后只公开一次；
- 本地资源服务拒绝固定角色槽位之外的路径；
- 常用行内公式与详细朗读得到稳定中文，原始 LaTeX 不进入 TTS；
- 无 API Key、无网络、无立绘时既有文字自由学习完整可用。

### 10.2 本机真实体验

在真实 DMG 中用 Sol 教师、Terra Peer 和 MiMo TTS 至少走查：

1. 普通阿夏短回复：边缘出场、自动说完、轻量嘴型可接受、教师自然续接；
2. 追问、联想与质疑：三种表情符合教师已经给出的学习动作；
3. 学生在语音中途发送消息：音频立即停止，教师回复不丢失、不重复；
4. 页面刷新与重新进入：旧语音不自动播放；
5. 简单公式、连续推导和化学下标：自然解释成立，详细朗读不念 LaTeX；
6. 移除 MiMo Key、断开网络或移走私有立绘：安静退化为系统语音或文字；
7. 对比加入口播契约前后的模型响应时间、tokens、严谨性与啰嗦程度；
8. 记录 Peer 文字完成到首段音频开始、完整语音时长和教师公开续接时间，判断学生等待感。

首轮以“愿不愿意继续听”和三方节奏是否自然为最终体验判断，不以表情数量、声音拟真度或
公式读屏覆盖率替代真实使用感受。

## 十一、明确延期

- 教师数字人的视觉与声音配置；
- 第二个 Peer、角色选择器、人格编辑器和群聊；
- 语音克隆与私人录音授权流程；
- Live2D、VRM、精确口型、视频流与摄像头驱动；
- 其他语音 Provider 与音色选择界面；
- Roadmap、Plan、Lesson 中的数字人；
- 完整中文数学无障碍读屏系统；
- 私人角色素材的公开授权与分发。

教师数字人虽在本切片延期，但不是架构外事项：它将直接复用这里的 actor 表现配置、数学
口播、TTS、播放与中断能力，只新增教师自己的合法角色素材和启用策略。
