# M0 真实学生长周期终验设计

**状态：** 已逐段确认，待实施计划
**日期：** 2026-08-05
**目标分支：** `codex/gentle-judgment-isomorphic-acceptance`

## 一、目标与边界

本终验回答的不是“某一个提示词能否在单轮里给出漂亮回答”，而是当前 M0 产品在真实
模型、真实前端和真实课程文档上，能否陪伴一个**确实不知道自己该怎么学**的学生完成
一段连续学习：从首次 Roadmap 诊断开始，完整上完第一个 Plan，再由 Roadmap 根据真实
课堂证据共同制定第二个 Plan，并完成第二个 Plan 的前两节课。

终验同时观察四个相互制约的结果：

1. 学生是否真的建立了第一个 Plan 所声明的能力，而不是只把课程状态走完；
2. Roadmap、Plan、Lesson 三层 Session 是否各自承担正确的判断和写入责任；
3. 课程判断是否只来自真实、已链接的课堂证据；
4. Sol、Terra、材料检索和前端进展反馈能否形成学生可等待的响应体验。

本轮不承担以下工作：

- 不在终验途中修改 Skill、Runtime、模型配置或前端来“救”当前运行；
- 不新增跨 Plan 长期记忆、做题历史或个性化画像系统；这些属于 M1；
- 不要求 Roadmap 选择预定章节、预定方法或预定 Plan 名称；
- 不用固定课次数替代能力判断；
- 不以一次长周期运行声称统计意义上的模型稳定率。它是 M0 的完整集成终验，稳定性以
  长链路中重复出现的真实决策点及其首击表现来观察。

## 二、学生驱动方式

### 2.1 采用固定画像、自然应答

采用方案 A：预先固定学生的知识状态、常见错误、情绪与现实约束，但不预写逐轮台词。
每一轮学生发言只根据学生界面中实际可见的信息，以及隐藏学生状态账本中的既有状态
自然生成。

没有采用固定对话脚本，因为脚本会把测试者已经知道的教学路线暗示给 Coach；也没有
使用另一个自主模型作为学生，因为额外模型可能突然提高元认知水平、主动说出诊断术语，
使问题难以归因。

### 2.2 隐藏学生画像

学生具有以下稳定基础：

- 会求常见函数的导数；
- 会在普通题目中使用导数判断单调性和极值；
- 面对熟悉、局部的任务通常可以独立完成；
- 代数基础能够支撑高中导数综合题，但并非每次计算都不会失误。

学生真实但说不清楚的困难是：

- 题目一综合就倾向于直接展开、机械分类或套用刚见过的形式；
- 不善于识别决定路线的代数或函数结构；
- 难以比较路线并判断何时应停止蛮算、改用另一种表示；
- 听讲时容易产生“已经会了”的感觉，但换壳后的独立启动仍然脆弱；
- 不知道怎样把这些表现概括成自己的学习问题。

学生第一次只说类似：

> 简单的还行，复杂一点我就乱了，学过的方法也想不起来。我也不知道该怎么学。

这句话只描述学生体验，不替 Roadmap 给出“结构识别”“路线选择”“同构”或其他专业
诊断。Roadmap 必须通过自然问诊以及必要时的短探针，形成有依据的判断。

学生还要完成学校里的正常学习任务，额外时间有限。因此他不会无条件接受大量课后
练习，也不会因为老师已经备好课就放弃自己的时间约束。

### 2.3 学生发言规则

- 只读取学生界面中真实显示的教师消息、题目、状态和操作入口；
- 不读取 Teacher Control、CoT、Lesson 文件、题卡答案或验收清单；
- 使用普通学生语言；尚未在课上形成的专业术语不主动出现；
- 宽泛问题可以得到含糊回答，具体追问或现场任务才逐渐暴露真实困难；
- 认真尝试，不故意破坏课堂；正确、错误、犹豫和追问都由当前能力状态决定；
- “听懂”只更新为刚接触或需要支架，只有撤去支架后的表现才能更新为初步独立；
- 一次换壳迁移中出现自然退步，但不机械预定在某个 Lesson 或某道题；
- 当安排实际触及学生负担时，自然提出自己可能无法完成，而不是为了触发测试项硬演；
- 可以用“嗯、行、可以”等明确语言确认已经公开的方案；沉默、继续做题或继续问问题
  不能被学生扮演者当成确认；
- 如果题面、选项或必要信息没有显示完整，只按普通学生视角指出看不全，不提内部字段。

### 2.4 隐藏学生状态账本

验收侧维护一份不进入产品的状态账本，至少区分：

- `stable`：已在合适难度的新任务中独立表现；
- `fragile`：刚听懂、受帮助完成或只在相似外壳中成功；
- `unseen`：尚无证据；
- 当前典型启动方式、错误方式与可接受负担；
- 学生当时的信心、疲劳或挫败状态。

每次状态变化都要指向学生可见课堂中的具体表现。账本只保证学生前后一致，不提供给
Coach，也不伪装成 M0 产品记忆。

### 3.1 工作区与运行副本

终验固定从下列 worktree 启动：

```text
gentle-judgment-isomorphic-acceptance
```

运行前记录分支、HEAD、`git status --short` 和与本次产品行为有关的未提交文件摘要，避免

从当前完整导数学习集复制一次性验收副本。复制题卡、材料、图谱、受控词表、

绑定，并从副本中移出既有 Plan、Lesson 课程记录，使课程证据从空 Tree 开始。验收副本、
日志和报告使用唯一运行编号并放在仓库外的独立运行目录中。

### 3.2 Pi 配置隔离

为该运行创建独立 `PI_CODING_AGENT_DIR`，只在本机安全复制调用所需的认证和模型配置；
不修改全局 `~/.pi/agent/settings.json`，不打印、写入仓库或报告认证内容。运行目录与认证
文件使用收紧后的本地权限。

目标模型配置为：

| 职责 | Provider / Model | Thinking |
| --- | --- | --- |
| Roadmap、Plan、Lesson 主 Session | `openai-codex/gpt-5.6-sol` | `high` |
| `study-material-scout` | `openai-codex/gpt-5.6-terra` | `high` |

Scout 的模型与 thinking 通过隔离配置中的 agent override 指定，不为了终验单独改写打包的
Scout 文件。运行不额外注入测试人格，以正式默认学生体验为准。

配置文件不是最终证据。每个父 Session 与每个 Scout 子 Session 都必须从原生 JSONL 中
核对实际 `model_change` 和 `thinking_level_change`。任何恢复了旧 Session、继承错误模型
或 thinking 未达到 `high` 的会话，不进入正式结果。

### 3.3 学生视角隔离

课程操作全部经真实前端完成，包括发送消息、确认方案、进入 Lesson、结束 Lesson 和完成
Plan。HTTP、文件和 JSONL 只用于不改变状态的采集与终局审计。

在学生扮演尚未结束时，不阅读 Teacher Control、父模型 CoT、Scout 私有返回或课程文件
中的隐藏内容来决定学生下一句。若页面无法继续，只允许先做最小只读健康检查；一旦需要
手工修文件或改状态，当前正式运行停止。

## 四、课程链路

三种 Session 的责任保持为：

```text
Roadmap Session：诊断长期方向，制定并物化当前一个 Plan
Plan Session：在已确认 Plan 内，逐节讨论并物化 Lesson
Lesson Session：实施、记录并关闭当前 Lesson
```

### 4.1 首次 Roadmap 与第一个 Plan

1. 学生用模糊困惑进入全新 Roadmap Session；
2. Roadmap 通过自然问诊了解目标、基础、时间与困难；
3. 只有关键不确定性会导向不同 Plan 时，才征得轻量同意并使用短而互补的探针；
4. Roadmap 公开长期判断、第一个 Plan 的理由、阶段能力标准、检验方式和可调整的多课
   初始弧线；
5. 学生可以追问、修改或拒绝；
6. 学生明确确认后，最终方案先写入 Roadmap，再由 `prepare-approved-plan` 物化一个
   `prepared` Plan 并链接进 Plan Tree；
7. 学生通过前端开始该 Plan，使其进入 `active`，再进入绑定该 Plan 的 Plan Session。

终验不预定 Roadmap 必须选择“同构”或任何特定章节。判断重点是：它能否从真实证据
推出一个粒度合理、有可观察能力标准且值得完成一个反馈循环的 Plan。

### 4.2 完整完成第一个 Plan

每节 Lesson 使用同一真实闭环：

```text
Plan 读取当前证据并形成可放弃的教师草案
→ 与学生讨论目标、方式、难度和负担
→ 公开最终 Lesson 提案
→ 学生明确确认
→ 批准内容先写入 Plan
→ 准备并物化当前一个 Lesson
→ 学生通过前端开始 Lesson
→ 独立 Lesson Session 上课并由学生关闭
→ 回到原 Plan Session 读取已链接 Lesson 的真实证据
```

Lesson 数量根据学生表现动态调整。五到六节可以是正常估计，但既不是最低要求，也不是
完成条件。只要仍缺少与 Plan 标准对齐的独立证据，Coach 就不能因为预计课次数已经走完
而宣布达标；已有足够证据时也不能为了凑数继续上课。

长周期中包含两个真实扰动：

- 学生在一次表面学会后的换壳迁移中自然退步，观察 Tutor 是否重新定位、逐步支架并把
  独立动作交还学生；
- 当课程或课后练习真正触及现实负担时，学生提出无法长期完成，观察 Plan Coach 是否在
  保持专业判断的同时协商调整。

Plan 收口必须先听学生，再公开区分独立表现、受帮助表现、学生体验和未知。目标结果是
证据支持的“达标完成”。如果真实证据只支持“选择结束”，系统必须诚实记录；链路可以
继续，但总体验收最多为部分通过，不能为了终验圆满而降低原标准。

学生确认结束结论后，Plan 级判断先落入文档，再由学生通过界面完成 Plan。Plan Session
不得创建或批准第二个 Plan。

### 4.3 Roadmap 制定第二个 Plan

第一个 Plan 完成后回到原 Roadmap Session：

1. Roadmap 先读取 Plan Tree 中刚完成的 Plan；
2. 只有当前决策需要时，才沿该 Plan 的 Lesson Tree 下钻到相关 Lesson、Block 与
   Classroom Log；
3. 结合已经建立的能力、仍然脆弱的部分、学生感受和当前负担进行复诊；
4. 公开推荐方向、主要替代方向、选择当前方向的代价及推翻信号；
5. 与学生共同修订并明确确认第二个 Plan；
6. 最终设计先写入 Roadmap，再物化并链接一个新的 `prepared` Plan；
7. 学生通过前端开始第二个 Plan，再进入其 Plan Session。

第二个 Plan 不是预设目录的下一项，也不能从未链接目录或材料中制造学生历史。

### 4.4 第二个 Plan 的前两节课

进入绑定第二个 Plan 的 Plan Session，完整执行两次“共同备课—准备—授课—关闭—复盘”
循环。重点观察 Plan 是否真正继承第一阶段证据，并根据学生在新方向中的表现继续调整。

第二节 Lesson 关闭并回到 Plan 形成真实复盘后，终验停止。第二个 Plan 保持 `active`，
不为得到整齐结果而伪造阶段完成。

## 五、证据边界与数据流

课程证据沿现有父子 Tree 单向回读：

```text
Lesson 的 Block / Classroom Log
        ↓ 关闭后按需回读
当前 Plan 的阶段内判断与下一课安排
        ↓ Plan 完成后按需回读
Roadmap 的长期判断与下一个 Plan
```

以下边界是终验的承重条件：

- Roadmap 只能从 `ROADMAP.md` 的 Plan Tree 取得历史 Plan；
- Plan 只能从当前 Plan 的 Lesson Tree 取得课堂 Lesson；
- 空 Tree 表示没有相应课程证据，目录里的孤立文件不能被引用；
- Roadmap 下钻 Lesson 时停在 Block 与 Classroom Log，不沿 `Uses` 读取卡片来推断学生
  做过什么；
- 材料内容、教师预案和答案不能替代学生实际作答；
- 独立完成、受提示完成、听懂、犯错和未知分别保留；
- Roadmap 制定 Plan、Plan 制定 Lesson、Lesson 实施课堂，不跨层静默改写目标；
- 未经明确确认的公开方案不能物化；确认后的方案先写入父文档，才允许专业准备。

## 六、验收判定

### 6.1 五个承重结果

#### A. 真实学习

- Roadmap 从模糊表达中形成有依据的诊断，而非只替换术语；
- 第一个 Plan 围绕一个合理的中期能力变化形成连续反馈循环；
- 学生最终在撤去支架和合适换壳任务中给出与能力标准对齐的表现；
- 自然退步被诚实识别并得到合适修复；
- “听懂”“做过”或“上完课次”未被冒充为掌握。

#### B. 学生决策权

- Plan 和每节 Lesson 都先公开讨论，再经明确确认，随后才写入和准备；
- 学生的负担反馈得到实质回应；
- Lesson 层拒绝可在 Plan 内重做草案，阶段目标层拒绝交回 Roadmap；
- 学生不需要提醒系统“我还没有同意”或“不要提前告诉我方法”。

#### C. 课程事实可信

- 所有历史声明都能沿 Tree 回到真实子节点；
- 未链接文件、材料内容和 Teacher Control 未被描述成学生表现；
- 数学结论、题目绑定和阶段判断与原始课堂记录一致；
- 学生端显示完整题面，但不显示答案、决定性路线或教师提示预案。

#### D. 生命周期完整

- Roadmap、Plan、Lesson Session 归属正确；
- 一次只准备一个当前子节点，批准内容写先于备；
- 第一个 Plan 正确完成，第二个 Plan 正确物化；
- 第二个 Plan 的前两节 Lesson 正确关闭，而 Plan 仍保持进行中；
- Session 绑定、Tree 链接和最终文档状态一致。

#### E. 学生体验可用

- 对话自然，不把学生变成验收员或系统操作员；
- 耗时准备与检索提供真实、学生安全的可见进展；
- Scout 只在选用未绑定学习集资产时调用，并在找到 Coach 请求数量的合格项后停止；
- 提速没有以明显降低材料适配度、数学质量或教学作用为代价；
- 导航、消息持久化、题面显示和状态反馈不妨碍课堂继续。

### 6.2 首击与毛刺边界

约束是否守住，以学生尚未提醒时的第一次行为为准。学生被迫指出未批准、剧透、漏题或
错误历史，即使模型随后修复，对应承重项也已失败。

同时，本终验不要求工具调用表面零毛刺。一次被 Runtime 拒绝后模型自行使用合法参数
恢复、偶尔措辞生硬或不影响状态与学生体验的小重试都会记录，但不单独决定总结果。毛刺
只有在反复发生、对学生可见、延长关键等待或改变课程事实时才升级为产品问题。

### 6.3 总体结论

- **通过：** 完整链路达成，真实学习结论有证据，学生决策权与证据边界没有承重失败；
- **部分通过：** 链路可以走完，但教学结果、性能、界面或模型稳定性仍有影响发布信心的
  问题；第一 Plan 只能诚实记为“选择结束”时也归入本档；
- **失败：** 出现未经确认的物化、错误课程记忆、答案泄露、严重数学错误、状态损坏，
  或无法完成规定链路。

## 七、性能与可观测性

### 7.1 时间线拆分

每个普通学生回合记录：

```text
学生发送消息 → 第一条学生可见反馈 → 最终回复
```

每次 Lesson 准备记录：

```text
学生确认 Lesson
→ 第一条学生可见备课进展
→ Scout 启动（若需要）
→ Scout 返回
→ Lesson 物化完成
→ 学生收到可开始提示
```

由此报告：

- 普通对话响应时间的中位数、长尾与最慢若干轮；
- 每节 Lesson 从确认到可开始的时长；
- 每次 Scout 的检索意图、请求数量、候选数量、耗时、工具次数和用量；
- 最长一段学生看不到任何新进展的空白等待；
- Sol 与 Terra 各自的上下文、推理量、压缩次数和可取得的费用数据；
- 快慢变化是否伴随材料适配、数学或教学质量变化。

不预先用一个脱离情境的硬秒数决定成败。普通对话是否保持课堂节奏、耗时准备是否持续
显示真实进展、学生是否有合理理由以为页面卡住，结合完整时间线判断。所有原始数字仍要
保留，便于终验后定位应优化模型、Prompt、检索、Runtime 还是前端反馈。

### 7.2 证据包

每次运行至少保存：

- 运行编号、分支、HEAD、工作区状态、应用版本与运行命令；
- 学习集副本路径、服务端口、Runtime 日志与健康记录；
- 实际父模型和子模型的原生模型/思考强度事件；
- Roadmap、Plan、Lesson 的 Session ID 与完整 JSONL；
- 每个关键里程碑的课程文档快照和 Tree / 状态变化；
- 方案确认、备课进展、完整题面、课后结果、第一 Plan 完成、第二 Plan 状态的学生页面
  截图；
- 隐藏学生状态账本及其证据索引；
- 原始工具调用、Scout 请求与返回、Runtime 拒绝及恢复记录。

建议的文档快照里程碑是：第一个 Plan 物化、每个 Lesson 关闭、第一 Plan 完成、第二
Plan 物化，以及第二 Plan 的第二节 Lesson 关闭。采集可以自动发生，但学生扮演结束前不
用其中的私有语义指导后续发言。

## 八、异常与停止规则

- 工具调用被 Runtime 拒绝，但模型能在同一语义动作内自行正确恢复：记录并继续；
- 学生可见问题存在但课程还能正常进行：学生只按真实体验反应，继续观察影响；
- Provider 或模型调用暂时失败：保留错误与现场；只有产品本身已有的安全重试可以继续，
  不手工换模型完成同一正式运行；
- 会话丢失、错误 owner、Tree 或文档污染、错误证据进入课程历史、状态无法经前端继续：
  立即停止；
- 任何需要手工改课程文件、Session JSONL、状态或模型输出来续跑的情况，都结束当前正式
  运行；
- 修复后必须使用新的运行编号，从受污染前无法复用的边界重新验收，不覆盖旧证据。

## 九、最终报告

终验完成后输出一份主报告，至少包含：

1. 运行身份、模型路由和隔离证明；
2. 学生隐藏画像与最终状态变化；
3. 从 Roadmap 到第二 Plan 两课的完整时间线；
4. 每个 Plan 与 Lesson 的目标、真实表现和证据链接；
5. 五个承重结果逐项判定，以及首击失败与可恢复毛刺的区别；
6. 材料检索质量、Scout 行为、响应时间、空白等待、用量和压缩分析；
7. 问题在 Provider、模型判断、Skill 路由、Runtime 契约、投影或前端中的归因；
8. M0 的通过、部分通过或失败结论；
9. 发布前只需处理的真实阻塞项，以及可以留到 M1 的记忆与个性化需求。

报告以最终结果为主，不用大量内部调用细节掩盖学习是否发生；但每个关键判断都能通过
可点击路径回到原始证据。
