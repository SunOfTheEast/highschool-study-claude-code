# StudyForge M2–M4 里程碑总纲

**状态：** 方向草案，用于约束后续快速迭代；不是任何单一功能的实施规格  
**日期：** 2026-08-10  
**基线：** M1 已建立教师式课程周期、自由学习、教师记忆、学习资产、平坦语义索引、
来源关系、知识关系投影与学生界面

## 一、为什么先写总纲

StudyForge 后续有三类性质不同的工作：一类机制清楚、能够快速实现和验证；一类涉及对学生
认知状态的解释，必须由真实使用证据支撑；另一类把原本私有的学习世界连接成开放生态，
必须先建立清楚的发布、来源、身份与隐私边界。三类工作不能为了形成一套看似完整的闭环而
同时建模。

因此先确定三个里程碑：

- **M2：丰富学习活动，并让学习进入现实时间。**
- **M3：在真实行为与长期数据上建立更周全的学生模型。**
- **M4：把独立的学习世界连接成开放的 AI 网校与学习共同体。**

M2、M3、M4 下的每个子功能仍需独立完成小设计、垂直实现和真实验收。本总纲不预先决定全部
数据结构或交互细节；只有已经由承重产品风险决定的实施优先级才在此记录，后续仍可由真实
验收结果调整。

## 二、M2：学习方法、资产互动与现实时间

### 2.1 核心目标

M2 把 StudyForge 从“能够进行并保存一次学习”推进为“能够组织多种有效学习活动，并在
现实时间中持续使用既有学习资产”。

它不以估计掌握度为前提。M2 只依赖已经存在的 Session、资产、对象记忆、语义索引、
来源关系和 Runtime 时间事实。

### 2.2 学习方法 Skill 树

扩充现有 Skill 树，使备课、正式课堂和自由学习不只会选择内容，还能按真实情境组织不同的
学习动作。候选方法包括但不限于：

- 联想与语义邻居探索；
- 学生提问、教师追问与问题生成；
- 头脑风暴与发散收束；
- 类比、对照与边界辨析；
- 自我解释与知识重组；
- 反例探索与假设攻击；
- 检索练习与延迟回忆；
- 陌生外壳下的迁移检验。

M2 同时加入透明的 AI 同龄伙伴。每个 Peer 可以具有稳定、紧凑的人格内核，以自己的思考
习惯参与提问、联想、比较、共同解题、代表性错误审查和头脑风暴，让学生通过解释、质疑和
共同探索参与学习。Peer 只在学生点名、教师建议并被接受，或当前学习方法确实需要时按需
进入，不在每条学生消息后固定插话。

确认的基本链路是：学生消息与当前公开上下文交给被调用的 Peer；Peer 的公开回复成为会话
中的一等消息；教师随后可以读取包含该回复的更新上下文继续教学。Peer 不是新的知识事实
主人，也不自动形成另一种 Session。具体人格格式、调用入口、模型分工和教师是否必须立即
接话，留给后续小设计决定。

Peer 可以具有本地角色形象与声音，但角色身体只是公开消息的表现层，不是第二套 Agent。
StudyForge 仍负责人格内核、回复生成、actor 身份、对话记录、教师续接和记忆边界；Runtime
先持久化 `actor=peer:<id>` 的公开回复，再把同一条回复投影为角色出场、表情、语音和口型。
动画、语音或插件失败时保留文字回复并安静降级，不得丢失、重写或重新生成 Peer 的发言。

默认表现层应能在学生本机运行，不产生按分钟的视频渲染费用。可参考
Open-LLM-VTuber 已验证的浏览器 Live2D、WebSocket 和本地 TTS 组合，但具体复用须先核对
许可证；默认优先独立实现表现层或把它作为可选本地边车，不直接搬入整套前端，也不引入
它自己的 LLM、人格、记忆和聊天事实。普通话语音优先采用能够在 CPU 上运行的本地 TTS
或系统语音；云端实时数字人作为可关闭的实验后端，仅用于验证更高拟真度是否确实改善
学习体验，不能成为使用 StudyForge 的前置条件。

M2 的原创本地角色视觉资产可以由 `gpt-image-2` 生成，包括透明背景的半身或全身立绘、统一
设定下的表情变体和角色视觉参考。首版允许用这些资产做静态立绘、轻量表情和音频驱动的
口型；若升级为 Live2D 或 VRM，仍需合法的模型文件与相应绑定过程，不能把一张生成图片
当成已经完成的可动画模型。默认角色使用原创资产；产品不内置未经授权的商业角色形象、
声音或完整人格。

数字人能力可以作为本地插件或适配器存在，但正常发言不依赖模型额外调用一次工具：
Runtime 根据已落盘的 Peer 消息自动驱动表现层。MCP 只适合暴露按需的出场、退场、表情、
打断和状态查询等控制动作；实时音视频留在本地渲染器或其流媒体通道中，不经过 MCP 传输。

Peer 在 M2 中先作为可关闭的实验能力。不同模型、上下文长度和消息模板对多角色身份的保持
能力可能不同，不能只凭提示词设计宣称稳定，也不预先把失败归因于某一种注意力算法。验收
需要直接观察 Peer 是否保持自己的人格与身份、教师是否正确识别发言者，以及长对话、上下文
压缩和不同模型组合下是否发生角色串台。

身份混乱的承重风险不是措辞难看，而是证据归属错误：Peer 的观点、错误、解题表现或自述
不得被记成学生表现，也不得据此更新学生对象记忆。Runtime 必须保存公开消息的真实 actor
身份；任何模型组合不能稳定守住这一点时，关闭该组合的 Peer 能力，而不是继续叠加提示词
掩盖失败。

这些 Skill 描述“怎样学习”，不建立新的知识事实，也不自动宣称学生掌握。它们可以利用
现有文本索引和关系投影寻找材料；只有真实讨论形成明确内容并经过现有确认流程，结果才
成为 Note、题卡或资产 revision。

备课系统需要同时考虑两条轴：采用什么内容，以及让学生对内容执行什么认知动作。授课时
仍以学生眼前表现为准，可以对预案中的学习动作作小幅、可逆调整。具体路由与粒度留给独立
Skill 设计。

### 2.3 结构化资产固化互动

让 Note、回忆块和题卡的形成、预览、修改、确认与保存成为清楚的学生交互，而不是隐藏在
模型输出或工具调用中的副作用。资产仍然只是可继续使用的内容；资产成熟、数量增加或关系
丰富都不等于学生已经掌握。

### 2.4 日历、番茄钟与时间事件

现实时间第一次成为 Agent 可以使用的环境事实：

- 日历表达学生准备在什么时候学习、复习或上课；
- 番茄钟表达一段真实专注时间的开始、经过和结束；
- Runtime 负责权威时间、到期、恢复和一次性事件；
- Agent 在有意义的时间节点收到事件，结合真实学习进度提出收口、休息、延长或继续建议；
- 时间到不自动结课、不自动写认知判断，最终行动仍由学生决定。

模型不持续轮询时钟。倒计时属于界面与 Runtime；模型只在开始、到期、恢复或其他必要决策
点获得最小时间事实。

### 2.5 资产级遗忘复习

M2 可以根据题卡或 Note 的真实复习事件安排下一次出现，并与日历、番茄钟形成复习闭环。
含回忆块的 Note 可以直接自助复习；纯正文 Note 由老师依据正文生成检索问题。排程仍以完整
资产为单位，不为每个回忆块建立独立队列。
这一层只回答“这项资产何时值得再次出现”，不回答“学生对某个 Topic 掌握了多少”。

允许记录卡片级的复习时间、结果、提示使用和下一复习窗口；具体间隔算法在独立设计中选择。
不得因为生成、打开或保存了资产就增加任何掌握度，也不得把到期状态解释为认知退化结论。

### 2.6 M2 明确不做

- 不建立强制 Topic 本体或让所有资产必须挂到一个 Topic；
- 不引入 BKT、统一 mastery 分数或全局学生能力评分；
- 不从资产数量、对话长度、教师讲解或一句“懂了”推断掌握；
- 不让自动调度器替学生决定完整学习路线；
- 不把完整关系图、词表或所有学习方法同时注入每个 Session；
- 不为了复习排程回写或篡改既有对象记忆与历史事实。
- 不在 M2 实现真实同学加入、多人同步或群聊；AI 同龄伙伴不冒充现实中的具体同学。
- 不承诺所有模型都支持 Peer；角色归因未通过行为验收的模型组合不开放这一实验能力。
- 不要求学生订阅按分钟计费的数字人服务，也不让角色渲染器拥有独立人格或学习记忆。

### 2.7 M2 成功后的体验

学生可以从一个真实问题开始，选择或接受老师建议的学习方法，也可以与 AI 同龄伙伴互问、
解释或共同探索；围绕已有资料、题卡、笔记和语义关系进行联想、提问、比较、发散或检索；
把值得保留的结果确认成资产；再在日历和专注周期中重新遇到这些资产。老师知道现实中过了
多久、这次停在哪里以及什么内容到达复习窗口，但不会因此伪造学生掌握度。

### 2.8 M2 实施优先级：先验证学生是否愿意使用

M2 不按功能在文档中的出现顺序实施。当前产品已经证明教师式课程、自由学习、资产和记忆
可以工作，下一项承重风险是学生是否愿意主动进入并持续使用。因此先完成 Peer 与本地角色
表现组成的采用闭环，再扩展其余 M2 能力。

第一批垂直闭环只需要一个原创 Peer：

1. Runtime 持久化独立 Peer actor，Peer 发言成为公开消息，教师能读取更新后的上下文续接；
2. 学生可以自然点名 Peer，Peer 不在未被邀请时固定插话；
3. `gpt-image-2` 提供一致的原创立绘和少量表情，本地 TTS 提供声音；
4. 前端清楚呈现角色出场、发言归属、打断和退场，表现层失败时退回文字；
5. 首批只实现追问、联想、质疑和头脑风暴所需的最小 Peer 学习动作；
6. 用真实学生观察主动点名、解释意愿、对话深度、次日回访和新鲜感消退后的继续使用。

在这次真实采用验证之前，不以增加角色数量、完整 Live2D 绑定、复杂角色编辑器或云端拟真
数字人替代闭环验证。验证显示角色确实改善使用意愿后，再加入多个预设人格、可编辑的形象、
声音、关系语气、思考风格和出场规则，并扩展完整学习方法 Skill 树。

据此，M2 当前实施顺序是：

1. Peer actor、身份隔离与三方公开对话；
2. 单个原创角色的本地立绘、语音和轻量表现；
3. 首轮真实学生采用验收；
4. Peer 预设、有限编辑和核心学习方法；
5. 结构化资产固化互动与完整学习方法 Skill 树；
6. Runtime 时间事实、日历和番茄钟；
7. 资产级遗忘复习；
8. 可选云端数字人和更高规格动画仅在前述结果支持时继续。

## 三、M3：Topic、掌握度与学生模型

### 3.1 启动条件

M3 在 M2 的学习方法、资产互动和时间复习经过真实使用并产生足够数据后启动。它要研究的
不是怎样再增加一个仪表盘数字，而是哪些表现可以支持怎样的教学判断，以及这些判断在多长
时间、多少帮助和多少迁移之后仍然成立。

涉及学习效果的设计必须使用真实学生数据评估；模拟学生可以校准工具使用和流程稳定性，
不能单独证明学生模型有效。

### 3.2 Topic 的位置

M3 的 Topic 首先是 M1 文本索引中反复出现、具有稳定教学意义的特殊语义锚点，而不是预先
规定所有内容归属的强制实体。

Note、题卡、Material、对象记忆和来源关系仍是各自的事实主人。Topic 可以帮助聚合、召回、
比较与观察跨资产变化，但不得取代原始资产、对象记忆或证据来源。是否需要显式 Topic
revision、归并、层级或其他治理机制，必须由 M2 的真实索引增长问题决定。

### 3.3 学生模型要回答的问题

M3 逐步研究：

- 某个知识对象目前有哪些直接表现与认知流变；
- 学生在无提示、不同帮助强度和不同外壳下分别能做到什么；
- 延迟之后保留、遗忘或重新学会了什么；
- 哪些模式跨多个知识对象反复出现，足以形成能力假设；
- 何时可以形成掌握判断，怎样表达不确定性和证据范围；
- 教师怎样利用这些判断建议下一步，同时把决策权留给学生。

现有对象记忆继续保存带来源的教师判断和认知流变。未来的统计模型、掌握度或 Topic 聚合
只能建立在这些真实表现与活动事件之上，不能反向改写历史证据。

### 3.4 可能的研究与实现面

以下均为 M3 的待研究方向，不在本总纲中预选算法：

- Topic 级证据聚合与跨时间保持；
- 帮助程度、迁移距离和首次表现的表示；
- mastery、BKT、IRT 或其他不确定性模型的适用边界；
- 对象记忆、统计估计与教师公开判断之间的所有权；
- 基于真实学生数据的 benchmark、校准与长期效果评估；
- 学生可理解、可质疑和可修正的模型展示方式。

### 3.5 M3 明确不做

- 不先规定一个数字，再把所有行为强行折算进去；
- 不把卡片数量、资产覆盖度或自动生成内容当作能力证据；
- 不把提示后完成冒充独立掌握；
- 不把一次对话总结直接变成跨对象能力结论；
- 不让 Topic 成为所有内容、记忆与课程节点的唯一挂载点；
- 不用模拟学生的高分替代真实学习效果验证。

## 四、M4：StudyForge Commons——AI 网校与开放学习生态

### 4.1 产品位置

M4 连接此前各自独立的学习世界。它可以被理解为一所开放的 AI 网校，但不是把固定课程、
教师直播和题库搬到线上，也不是围绕关注、动态、点赞和积分建立普通内容社区。

每个学生仍拥有自己的 StudyForge：私人教师、Peer、课程周期、学习资产、对象记忆和学生
模型都以本地学习世界为中心。Commons 只连接学生明确选择公开的资产、角色、学习方法和
共同学习空间，使别人能够把有价值的内容加入自己的学习集，再按自己的情况继续修改和学习。

### 4.2 私人世界与公开内容的边界

原始会话、对象记忆、能力假设、偏好、掌握判断、教师私人判断和未公开的学习资产默认始终
留在私人世界。加入 Commons、使用公开资产或参加共同学习，都不等于同意公开这些内容。

能够进入 Commons 的是学生或作者明确预览并发布的独立 revision，例如题卡、Note、Material、
学习集、部分语义关系、原创 Peer 角色包和学习方法包。别人导入后得到自己的本地版本；其
后续学习表现不会自动回传给原作者。社区参与也不构成研究数据授权。

### 4.3 可改编的学习资产

Commons 首先支持学习集和单个资产的发布、搜索、加入、改编和来源追踪：

- 界面使用“加入我的学习集”“改成自己的版本”“查看它从哪里来”等学生可理解的表达；
- 每个公开资产保留原始来源、版本关系、许可范围和 AI 生成说明；
- 后来的版本可以修正错误、增加联系或适配新的学生，而不覆盖原作者版本；
- 公开资产的数量、热度或被改编次数不构成任何学生的掌握证据。

社区价值主要来自真实使用后的改编、纠错和重新组织，而不是点赞榜、连续签到或付费积分。

### 4.4 角色与学习方法生态

作者可以分享原创 Peer 角色包，包括合法的视觉资产、声音配置、人格内核、思考风格、适用
学习活动和出场规则；也可以分享追问、联想、反方辩论、头脑风暴等学习方法包。角色包不得
携带创建者或使用者的私人记忆，导入之后仍受本地 actor 身份、证据归属和教师主持边界约束。

StudyForge 因而不需要独自编写所有角色和 Skill，但公开生态中的内容必须可查看来源、独立
更新和安全停用，不能把未知提示词直接注入所有会话。

### 4.5 真人共同学习

M2 建立的多 actor 对话可以在 M4 扩展为邀请制共同学习空间：真实学生、AI Peer 和教师 Agent
可以围绕同一问题讨论、比较路线或共同形成公开资产。AI 可以主持轮次、澄清分歧、邀请沉默
成员表达和整理共同结论，但不能把群聊中的他人表现写进某个学生的私人模型。

真实多人空间涉及未成年人身份、骚扰、冒充、私聊、内容审核和记录归属，必须单独设计并通过
安全验收后开放；不能因为 AI 群聊已经可用，就直接把陌生人加入同一房间。

### 4.6 研究与后训练轨道

Commons 可以在独立、明确同意的研究轨道中支持匿名化 Benchmark、教学 Skill 评估、真实
学习效果研究和 Agentic 后训练。只有按相应许可明确发布的公共资产才可用于研究，资产公开
也不代表资产使用者的私人行为可以被收集；社区服务、研究授权和模型训练授权必须分别表达、
分别撤回。

这一轨道的目标是让不同学科都能逐步形成可验证、可蒸馏的教学方法，而不是把社区变成未经
说明的数据采集器。

### 4.7 M4 分阶段落地

1. **M4a：学习资产 Commons。** 发布、搜索、加入、改编、版本和来源关系；
2. **M4b：角色与 Skill 生态。** 分享原创 Peer 和学习方法包；
3. **M4c：真人共同学习。** 邀请制讨论空间与 AI 主持；
4. **M4d：研究协作网络。** 独立授权的 Benchmark、评估和后训练数据合作。

M4a 即使用户数量不多也能提供价值，因此先于依赖网络效应和复杂安全治理的真人共同学习。
M3 形成的 Topic 与学生模型可以改善资产发现、适配建议和共同学习匹配，但私人学生模型不因
此成为社区资料。

### 4.8 M4 明确不做

- 不自动发布对话、记忆、学生模型或学习结果；
- 不公开学生掌握度、能力排名或跨学生排行榜；
- 不把推荐流、点赞、积分或连续签到作为社区的核心价值；
- 不允许公共资产覆盖已经导入的私人版本；
- 不把加入学习集等同于接受原作者的完整课程安排；
- 不在缺少未成年人安全与记录归属设计时开放陌生人私聊或公开群聊；
- 不把加入社区、公开资产和参加研究合并成一次笼统授权。

## 五、四个里程碑怎样衔接

```text
M1：学习可以发生、留下资产和记忆，并通过语义词语建立联系
 ↓
M2：学生以更多学习方法使用这些内容；现实时间、复习和专注周期进入系统
 ↓
真实活动逐渐形成可追溯的长期数据
 ↓
M3：围绕 Topic、保持、迁移、帮助程度和掌握判断建立可校准的学生模型
 ↓
M4：不同学习世界通过公开资产、角色、Skill 和共同学习空间形成开放 AI 网校
```

M1 的文本索引不是等待 M3 替换的临时品。M2 直接在它上面工作；M3 只在真实需要时把其中
部分稳定语义锚点提升为 Topic。M2 的卡片级复习也不是简化版 mastery，它是独立有用的时间
机制。即使 M3 最终不采用某一种掌握度模型，M1 和 M2 仍然完整可用。M4 连接的是学生主动
公开的资产和空间，不把前三个阶段建立的私人事实所有权改成中心化社区所有权。

## 六、后续迭代方式

后续不编写一个覆盖整个 M2 的巨型实施计划。学习方法 Skill、结构化资产固化、日历、
番茄钟和资产级复习分别形成小设计与垂直闭环，完成一个就用真实模型和学生体验验收一个。

M3 也不以“补齐架构”为理由提前开工。先观察 M2 的真实索引增长、复习事件、迁移表现和
教师判断，再决定第一个可证伪的学生建模问题。

M4 从不依赖大量用户的 M4a 资产闭环开始。只有发布、导入、改编、来源和私人边界在小规模
真实使用中稳定后，才扩展角色生态、真人共同学习和研究协作；不能以“社区建设”为理由一次
引入完整社交平台。
