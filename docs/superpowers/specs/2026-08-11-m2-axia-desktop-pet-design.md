# StudyForge M2 阿夏桌宠设计

**状态：** 已讨论定稿，待实施
**日期：** 2026-08-11
**范围：** macOS 桌面端中的常驻阿夏窗口、本地 Live2D 皮套与既有 Peer 表现链路复用
**上位设计：** `2026-08-11-m2-axia-live2d-companion-design.md`、
`2026-08-11-m2-local-peer-embodiment-design.md`

本设计把上位文档中的“自由学习页面边缘长伴随”改为“StudyForge 进程内的独立桌宠窗口”。
上位文档关于 Peer 消息事实、教师主持、TTS、公式口播、隐私和失败退化的边界继续有效；关于
模型只在自由学习页面挂载、离开页面即卸载，以及页面内同时显示阿夏立绘的决定由本文取代。

## 一、目标

阿夏成为随 StudyForge 进程存活的桌面同学，而不是自由学习页面里的一个组件：主窗口打开、
最小化或隐藏时，桌宠都继续存在；退出 StudyForge 时桌宠一起退出。学生仍在原来的对话时间线
中阅读阿夏的完整消息，桌宠只承担形象、说话状态、短气泡和重新唤起 StudyForge 的作用。

桌宠不新建 Agent、Pi Session、记忆、消息、TTS 请求链或独立后台服务。它消费现有
`peer-axia` 消息和播放状态，是同一条学习事实的第二个界面投影。

首版只做 macOS，并使用用户已经下载的“水色小狗”Live2D 皮套作为本机默认外观。该皮套只在
私人环境中加载，不进入公开仓库或公共 DMG。

## 二、复用而非另造运行时

调研后的复用边界如下：

| 项目 | 可复用经验 | 不直接采用的原因 |
| --- | --- | --- |
| [OpenPet](https://github.com/X-T-E-R/OpenPet) | Tauri 透明副窗口、始终置顶、拖动、动态点击穿透、位置记忆、随应用退出 | GPL；使用精灵图；另起完整运行时会重复 StudyForge 已有能力 |
| [Utsuwa](https://github.com/The-Lab-by-Ordinary-Company/utsuwa) | 同一应用内 `main + overlay`、一个状态源、多个窗口只做投影 | AGPL；使用 VRM；包含超出本切片的伴侣系统 |
| [Open-LLM-VTuber](https://github.com/Open-LLM-VTuber/Open-LLM-VTuber) | Live2D 透明桌宠、置顶、拖动与点击穿透的真实产品行为 | Electron；前端有额外商业授权条件；直接嵌入会引入第二套桌面框架 |
| [Pi Desktop](https://github.com/justhil/pi-app) / [Pi](https://github.com/earendil-works/pi) | 同一 Pi Runtime、认证、模型和 Session 是唯一真相源 | Pi 没有可复用的透明桌宠窗口实现 |

因此不安装或打包第三方桌宠应用，也不复制 GPL/AGPL 实现。StudyForge 继续使用现有 Tauri、
Live2D、Peer Runner、TTS 与 Session 投影，只借用已经验证的窗口和交互模式。不可约的新代码
只有一个透明 Tauri 窗口和一条窄的进程内状态桥。

## 三、一个阿夏，两个界面投影

### 3.1 唯一事实不变

```text
ask_peer 成功 toolResult（唯一 Peer 发言事实）
├─ 主窗口：完整 Markdown / KaTeX 消息
└─ 桌宠窗口：表情、口型、短气泡与 TTS 播放
```

桌宠不复制消息正文到另一种持久结构，不回写 Session，不进入记忆、足迹或学习资产。短气泡
只是当前 Peer 消息的临时截断投影，不调用模型另做摘要，消失后也不留下第二份记录。

### 3.2 视觉单实例

桌宠启用后，自由学习页移除原有 `PeerEmbodiment` 立绘，只保留“阿夏 · AI 同学”的文字消息、
等待态与必要的声音控制。任何时刻屏幕上最多只有一个阿夏模型，避免双模型、双口型和重复
GPU 占用。

教师与 Peer 的语义职责不变。桌宠常驻只代表形象在场，不代表阿夏持续监听、推理或主动读取
当前页面。

## 四、窗口与生命周期

StudyForge 在同一 Tauri 进程中创建两个 WebView 窗口：

- `main`：现有 StudyForge 主窗口；
- `companion`：透明、无边框、无阴影、始终置顶、不单独显示在 Dock 或任务切换器中的桌宠窗口。

生命周期固定为：

```text
启动 StudyForge
→ 创建 main 与 companion
→ companion 加载本地皮套并进入 calm
→ main 打开、最小化或隐藏：companion 不受影响
→ 点击主窗口红色关闭键：隐藏 main，不销毁应用
→ 双击阿夏：重新显示并聚焦既有 main
→ ⌘Q 或“退出 StudyForge”：两个窗口与同一进程一起退出
```

桌宠位置在本机保存。重新启动时优先回到上次位置；显示器布局变化时只把窗口收回当前可见
区域，不建立复杂窗口恢复系统。首版不承诺覆盖 macOS 全屏空间，也不把“跨所有桌面出现”
作为完成条件。

## 五、交互

- 拖动阿夏身体可以调整位置；透明区域保持点击穿透，不阻挡下面的应用；
- 双击阿夏只唤起既有 StudyForge 主窗口，不创建新 Session，也不自动发消息；
- 右键菜单首版只有“静音 / 开声”“隐藏桌宠”“退出 StudyForge”；
- “隐藏桌宠”只改变本地表现偏好，主窗口与文字 Peer 继续工作；主窗口设置中可以重新显示；
- 阿夏说话时显示一条短暂气泡，最多承载简短纯文本提示；完整推导、Markdown、表格和公式仍在
  主窗口阅读；
- 气泡与说话结束后回到安静陪伴，不周期性弹话、不主动制造提醒。

右键菜单和拖动属于窗口控制，不进入学习 Session。桌宠点击不能绕过教师直接调用 `ask_peer`。

## 六、状态桥与播放所有权

### 6.1 窄投影契约

两个窗口不各自订阅和解释 Pi Session。主窗口沿用现有对话投影，检测到一条新的 live Peer
消息后，只向桌宠发布本次表现所需的紧凑状态：

```ts
type CompanionPresentation = {
  messageId: string;
  actorId: 'peer-axia';
  text: string;
  expression: 'neutral' | 'curious' | 'skeptical';
  phase: 'thinking' | 'speaking' | 'calm';
};
```

该契约不携带模型路径、Provider Key、Session 私有上下文、教师 thinking 或记忆。Tauri 的
进程内事件与一个可查询的当前快照负责窗口间同步，不新增 localhost 控制服务、MCP 或磁盘
队列。快照只用于窗口晚于事件就绪时恢复当前表现，应用重启后从 `calm` 开始，不重播历史。

### 6.2 一个播放主人

桌宠窗口是阿夏 TTS、音频包络、嘴型和自动播放的唯一主人。它复用现有
`peer-speech` 接口、MiMo / 系统语音退路与 `usePeerPlayback` 逻辑。主窗口只消费桌宠返回的
`loading / speaking / idle` 状态，用来保持已经验证的展示节奏；主窗口不同时播放第二份音频。

学生发送新消息、点击停止、静音或离开当前自由学习时，主窗口向同一个播放主人发送中断意图。
播放完成或中断后，桌宠回到 `calm`。若桌宠窗口不可用，主窗口立即取消表现等待并继续公开
文字，不让桌宠故障卡住教师续接。

学生在主窗口点击公式的“详细朗读”时，也只向同一个播放主人发送一次确定性口播意图；不能
在主窗口和桌宠窗口各播放一遍。

## 七、本地“水色小狗”皮套

### 7.1 已确认的格式

下载目录中的皮套是完整 Cubism 运行时包，包含：

- `水色小狗.model3.json` 与 `水色小狗.moc3`；
- 五张纹理、`physics3.json`、`cdi3.json`；
- 一段待机 `motion3.json`；
- 举手、生气、脸红、星星眼、眼泪等多个 `exp3.json`；
- VTube Studio 的 `水色小狗.vtube.json`；
- 可由现有渲染器驱动的 `ParamMouthOpenY`。

因此不依赖 VTube Studio、摄像头或外部 VTuber 进程。现有
`untitled-pixi-live2d-engine`、Cubism Core 和 `PeerLive2D` 渲染路径继续使用。

### 7.2 规范化而非修改原包

原始 `model3.json` 没有登记外置表情和待机动画；VTube Studio 热键表才保存这些关系。导入时
生成一个只供 StudyForge 使用的本地运行副本：

1. 复制必需的 Cubism 文件到受 Git 忽略的 actor 槽位；
2. 从 `vtube.json` 读取真实的表达式文件名；
3. 生成现有严格加载器需要的 `manifest.json` 与规范化 `model3.json`；
4. 只启用经过实际预览确认的少量表情映射，未知热键不自动承担教学语义；
5. 保留原下载目录完全不动。

首版可以通过一次本地准备命令完成导入，不建设通用皮套商店、云同步或复杂角色编辑器。文件
布局仍保留以后从设置页选择另一套合法 Live2D 包的接口。

### 7.3 纹理运行副本

原包包含一张 8192 与四张 4096 纹理。桌宠显示尺寸不需要该分辨率，直接常驻会带来明显的
解码与 GPU 内存浪费。导入时把运行副本统一限制到 2048 边长；Cubism 使用归一化 UV，等比
缩小纹理不改变模型绑定。原始高清纹理继续保留在下载目录，不被覆盖。

若 2048 预览在真实 Retina 桌宠尺寸下出现肉眼可见的细节损失，再根据实测提高单张纹理，
而不是默认把全部高清纹理常驻显存。

### 7.4 私有与授权边界

当前皮套目录未发现可核验的再分发授权文件，因此它只作为用户本机私有资产：

- 不提交 Git；
- 不写入测试夹具、截图资产或公开示例；
- 不打进公开 DMG；
- 缺失时使用 StudyForge 自带占位形象，教学和文字 Peer 不受影响。

未来若要公开分发某套模型，必须同时确认模型作者授权与 Cubism Publication License，不能把
本机能加载解释成可以再发行。

## 八、失败退化

- companion 窗口创建失败：主窗口正常启动，文字 Peer 与教师链路继续；
- 私有模型、Cubism Core 或纹理缺失：桌宠显示本地占位形象，不显示破图；
- 模型或 WebGL 运行失败：只卸载表现层，不重跑 Peer、不重试生成消息；
- TTS 失败：保留气泡与文字；系统语音也不可用时安静回到 calm；
- 状态桥短暂断开：重新读取当前快照；不能据此重播已经完成的 Peer 发言；
- 主窗口隐藏：当前桌宠播放继续；应用退出：立即停止音频与动画；
- 桌宠被用户隐藏：不影响 Agent、Session、记忆或学习资产。

## 九、验收

### 9.1 确定性验收

1. StudyForge 启动后只创建一个 Pi/Peer 运行链，但同时存在 main 与 companion；
2. 主窗口打开、最小化和隐藏时，桌宠均保持可见；`⌘Q` 后两个窗口同时退出；
3. 自由学习页不再挂载第二个 Live2D 模型，Peer 文字消息仍完整可读；
4. 一条 live Peer 消息最多产生一次 TTS，历史恢复不自动重播；
5. 双击桌宠只聚焦原主窗口，不创建新线程、Session 或消息；
6. 透明区域可点击下面的应用，角色本体可拖动，重启后位置恢复到可见区域；
7. 静音、停止与隐藏偏好不修改 Session；
8. 移走私人皮套后，占位形象、文字 Peer、教师续接和整个课程系统仍可用；
9. Git diff 与公共 DMG 中不存在“水色小狗”模型、纹理、热键和其他私人资源。

### 9.2 真实体验验收

1. 2048 运行纹理在真实桌宠尺寸下没有可见糊边，模型加载与待机不造成明显卡顿；
2. calm 的眨眼、呼吸和物理摆动自然，不像网页中一张被固定的立绘；
3. TTS 播放时口型跟随音量，中断后立即闭嘴；
4. 主窗口同时打开时，桌宠不会遮住主要输入区域，也不会让页面出现第二个阿夏；
5. 连续使用一段真实自由学习后，内存和 GPU 占用没有持续增长；
6. 短气泡有存在感但不承担长公式与完整教学内容；
7. 最终位置、尺寸、表情映射和“是否足够生动”由用户真实体验决定，不以测试通过代替。

## 十、明确不做

- 独立桌宠进程、独立 Pi Agent、Peer 私聊 Session 或持续后台推理；
- VTube Studio、OpenPet 或 Open-LLM-VTuber 的整套嵌入；
- 摄像头追踪、真人驱动、舞蹈、复杂点击动作或自动闲聊；
- 通用角色商店、云皮套同步、公开上传平台；
- 在正式 Roadmap、Plan、Lesson 中自动邀请 Peer；
- 把短气泡变成第二个聊天界面；
- 为理论上的跨设备并发、皮套热更新或多角色群聊预建框架。

本切片只验证一件事：同一个 StudyForge、同一条 Peer 发言和同一套教学边界，能否拥有一个
真正随应用存在、但不反过来支配学习流程的桌面形象。
