# 自适应课堂模板与防剧透策略设计

状态：书面复核通过，进入实施

日期：2026-07-21

## 一、问题

当前备课质量尚可，但有两个直接影响真实课堂的问题：

1. `prepare-next-lesson` 只要求搜索“合适候选题卡”和编排一个小型 ActivityBlock 序列，没有先按教学目的定义题目角色。Designer 因此容易找到一张主题卡后就围绕它完成整节课。
2. 备课 Lesson 把学生首次应看到的内容、教师观察点和解题关键路线混在同一 Block 中。导数试用集 Lesson 003 虽然声称“不给完整推导”，但已经提前给出了合并方式、同除正量、同构函数、单调区间、参数边界和正确选项，实际上泄露了解题主干。

这不首先是题库或 MCP 问题，而是备课提示词缺少“按需求选课堂模板”、“按角色找多道题”和“分级揭示”三类约束。

## 二、目标与非目标

### 目标

- Planner 根据 Lesson 目标、历史 Trace 和当前证据选择合适的课堂模板，说明理由，并允许学生调整。
- 不同需求使用不同的默认 ActivityBlock、题目角色、材料倾向和揭示策略。
- 专项训练、诊断、验收和复习课不再围绕唯一一张题卡，而是按教学角色准备题组。
- 备课可以知道答案，但 `run-lesson` 只能按当前模板和提示级别向学生揭示。
- 本地材料优先；确有价值时，备课侧可以加入经核验的外部视频及文字替代。
- 保留现有的积木式课堂、Task List 投影和学生暂停、跳过、重排、结束课程的主动权。

### 非目标

- 不建立固定的统一课堂流水线。
- 不要求每节课固定相同题量或时长。
- 不为每一种课堂模板新建 Agent 或 Skill。
- 不修改四个 MCP 工具、题卡格式、Trace 格式、知识图谱或长期记忆协议。
- 不保证学生无法自行打开 Lesson Markdown 查看 Teacher Control。本设计防止的是 Coach 未经请求主动剧透，不是做权限隔离。

## 三、方案选择

考虑过三种方案：

1. 把全部模板写进 `prepare-next-lesson/SKILL.md`。文件最少，但会迅速膨胀，且诊断、新授和验收规则容易互相污染。
2. 每种模板建立独立 Skill。边界清晰，但把课堂积木变成了多个僵硬工作流，增加路由和维护成本。
3. 保留单一 `prepare-next-lesson`，使用轻量 Markdown 模板目录和共享揭示策略。Planner 先选一个主模板，再根据学生需求增删积木。

采用方案 3。只有某个模板未来真正形成独立、多步且可复用的工作流时，才单独升级为 Skill。

```text
skills/prepare-next-lesson/
├── SKILL.md
└── references/
    ├── classroom-templates.md
    └── reveal-policy.md
```

## 四、课堂模板目录

模板是 ActivityBlock 的默认组合，不是强制流程。题量是默认范围，Planner 可以根据目标、学生状态和可用真实素材调整，但需说明理由。

| 模板 | 适用需求 | 默认积木 | 默认题目角色 | 默认揭示 |
| --- | --- | --- | --- | --- |
| 诊断课 | 确认当前真实起点 | 简短说明、连续作答、追问思路、诊断总结 | 3–5 道不同结构短题 | `zero` |
| 概念新授课 | 引入新概念或方法 | 视频/材料、互动讲解、已讲示例、独立目标练习、退出小测 | 示例与目标题分离；通常 2–3 道学生作答题 | `worked-example` + `ladder` |
| 专项训练课 | 稳定方法和迁移 | 热身、核心题组、变式、迁移、可选挑战 | 通常 4–8 道，按难度与方法变化组题 | `ladder` |
| 错因修复课 | 针对历史 Trace 中的稳定错因 | Trace 回看、正反例对比、针对练习、无提示再测 | 对比题 1 组、修复题 1–2 道、再测题 1 道 | 前半 `ladder`，再测 `zero` |
| 能力验收课 | 判断能力标准是否达成 | 标准说明、未见题连续测试、必要追问、证据总结 | 2–4 道代表性未见题 | `zero` |
| 复习整合课 | 跨知识点调取与方法比较 | 混合检索、交错题组、方法比较、总结 | 4–6 道跨知识点混合题 | 以 `zero` 开始，需要时转 `ladder` |

模板选择规则：

1. Planner 先从 Plan 能力缺口、最近 Lesson Summary、active Trace 与 `planner-attention.md` 判断主要需求。
2. 向学生说明拟采用的主模板、原因、题目角色与材料组合，允许自然语言增删、重排或替换。
3. 学生明确说“直接备课”时，Planner 可以直接生成并展示理由，不强制新增一次确认轮次。
4. 需要混合时，必须指定一个主模板和少量调整，不建立第七种临时模板类型。

## 五、题目角色与多卡检索

备课不再从“搜一道合适题”开始，而是先从模板得到题目槽位：

- 热身/调取；
- 核心教学或核心练习；
- 变式；
- 迁移/验收；
- 补救；
- 挑战或额外小测。

Planner 按需要为不同槽位分别执行 `card_search`，而不在第一张合适卡后停止。每个采用的槽位必须：

- 绑定真实、去重的 `cardPath` 与 Lesson-local alias；
- 读取候选卡自带的完整 active `traceHistory`；
- 说明该卡在本课的角色，不把同一道题伪装成多个独立槽位；
- 验收或迁移槽位优先使用无该学生 active Trace 的题；若有 Trace，必须明确它是复习而非未见迁移。

真实卡片不足时，Planner 显示缺失的题目角色，然后在三种动作中选择：缩减题组、换用真实材料/互动、请学生确认后改变课堂目标。不得编造卡片、题目、别名或来源。

## 六、材料与视频

备课优先使用 `learning-set/materials/` 中的真实材料。当本地材料不足且视频有明确教学价值时，只给备课侧 `WebSearch` / `WebFetch` 能力；上课侧不在现场搜索或替换外部材料。

一个外部视频 Block 必须记录：

- 真实标题与 URL；
- 建议观看片段或时间范围；
- 观看目的；
- 学生看完后要回答的问题；
- 视频失效、不可访问或学生跳过时的文字/图示替代。

无法核验标题、URL、相关片段或教学相关性时，不加入该视频。视频如果完整讲解某道目标题，必须改用不同示例，或移到学生完成首次尝试之后。

本地材料仍使用学习集内的相对路径或别名，并按现有来源解析流程定位；经核验的外部视频 URL 作为普通外部链接保存在 Lesson 中，不交给 `source_resolve`，也不伪装成学习集文件。

## 七、Lesson 表示与防剧透边界

每个题目型 ActivityBlock 分成两个明确小节：

```markdown
## Block practice-02

### Student View

- 题目或题卡引用
- 当前任务
- 首次尝试前允许知道的信息

### Teacher Control

- 题目角色
- 证据目标
- 揭示策略：zero / ladder / worked-example
- 题卡评价步骤引用
- 分级提示
```

`run-lesson` 一次只向学生展示当前 Block 的 `Student View`，不得转述整个 Block、Teacher Control、题卡解答或观察答案。Teacher Control 尽量引用稳定题卡步骤，不在 Lesson 里重复拷贝完整解法。

这一分区是 Coach 的输出约束，不是文件访问控制。学生拥有 learning set，因此始终可以主动打开 Markdown 查看。

## 八、揭示策略

### `zero`

诊断和验收使用。首次作答前不提供方法名、关键变形、中间结论、答案或选项排除理由。学生要求帮助时：

1. 先将该次尝试按真实支持状态记录为 `incomplete` 或相应评价；
2. 再进入教学或分级提示；
3. 如果仍需验收无提示能力，后续使用另一道未见题，不把获得支持后的原题当作无提示证据。

### `ladder`

专项训练和错因修复使用。学生必须先尝试。卡住后，Coach 询问是否需要提示，并每次只揭示一级：

1. 只提醒检查哪个对象、条件或已知信息；
2. 指出应关注的结构，但不给出具体变形；
3. 给出一个关键步骤；
4. 只在学生明确要求后展示完整解答。

现有 Trace schema 不新增提示级别字段。有必要时，在 Trace `note` 中简短记录实际给到的提示层级，`support` 仍按现有 `none` / `tutor` / `external` 语义写入。

### `worked-example`

概念新授使用。Coach 可以完整讲解一道示例，但随后的学生目标练习必须是另一道真实题。示例可以教方法；不能在讲示例时附带报出目标题的关键变形、中间结论或答案。

### 全局首轮禁止内容

在学生对目标题完成首次尝试前，除非当前模板明确允许，Coach 不得泄露：

- 正确选项或最终答案；
- 决定性代换、同除量、因式分解或关键构造；
- 完整单调区间、参数边界或关键中间表达式；
- 能直接排除选项的理由；
- 当“识别方法”本身是证据目标时，直接告诉学生应使用的方法名。

## 九、完整数据流

1. `prepare-next-lesson` 调用 `recall-study-memory` 读取当前 Plan、前序摘要、相关 Trace、两份画像和仅备课可见的 `planner-attention.md`。
2. Planner 判断课堂需求，选择主模板并提出题目角色、材料与揭示策略。
3. 学生可以调整；明确要求直接备课时则跳过额外确认。
4. Planner 按槽位调用一次或多次 `card_search`，去重并读取每张卡的 active `traceHistory`。
5. 按需读取本地材料；外部视频仅在备课侧核验。
6. Designer 生成带 Student View、Teacher Control、必做/可选、依赖、安全跳过与重排关系的 Lesson Markdown。
7. `run-lesson` 只投影当前 Student View，按揭示策略逐步提示，并在证据性活动后通过现有 `trace_append` 记录真实支持条件。
8. 学生仍可随时跳过、重排、暂停或结束；Task 完成、题组做完和能力达标仍是三件不同的事。

## 十、最小失败处理

- **真实题卡不足：** 指出缺失槽位，缩减题组、换真实材料或与学生调整目标，不编卡。
- **视频无法核验：** 删除视频 Block，使用文字/图示替代，不伪造 URL、标题或时间码。
- **模板不完全匹配：** 组合少量积木，但记录主模板和调整理由，不新建临时类型。
- **活动过多：** 补救题、挑战题、视频或额外小测必须可标为可选，不把所有准备内容强制转成必做。
- **学生在 `zero` 题上要求提示：** 真实记录支持后转教学；后续换未见题完成无提示验收。

## 十一、验收与回归测试

### 静态 contract

- `prepare-next-lesson` 必须在搜卡前选择主模板和题目槽位。
- `classroom-templates.md` 包含六类已确认模板、默认题目角色与揭示策略。
- `reveal-policy.md` 包含 `zero`、`ladder`、`worked-example` 和首轮禁止内容。
- `lesson-designer` 只在备课侧获得 `WebSearch` / `WebFetch`；`run-lesson` 不获得这两个工具。
- `run-lesson` 必须包含“只展示 Student View”和“不转述 Teacher Control”的明确约束。
- MCP 工具名与数量保持不变。

### 回归样例

重写导数试用集 Lesson 003：

- 不再在 Student View 提前给出合并式、同除量、`ln t/t` 的完整单调区间、`a ≥ 1/e` 或正确选项；
- 把必要评价点放入 Teacher Control，优先引用真实题卡步骤；
- 根据该 Lesson 的“连续性核验 + 同构迁移”需求，采用主模板并加入多题角色，不再只有一道学生作答题。

### 真实 Claude Code smoke

1. 给 Planner 诊断、新授、专项训练和能力验收四种需求，确认生成结构、题目角色和揭示策略明显不同。
2. 专项训练生成热身、核心、变式、迁移等多个去重真实题卡槽位，并保留各自 `traceHistory`。
3. 新授课只在能核验真实视频时添加 Video Block，且同时写入文字替代。
4. 运行诊断或验收课的第一道题，Coach 只展示 Student View，不泄露方法、关键变形或答案。
5. 运行 `ladder` 题，确认学生未尝试时不提示，同意提示后每轮只揭示一级。
6. 运行概念新授，确认完整讲解的示例和随后的学生目标题不是同一张卡。

## 十二、完成标准

以下条件同时满足时，本设计实现完成：

- Planner 能根据需求选择六种主模板之一，允许学生调整，且不把模板当作固定流水线。
- 多题课堂从题目角色出发搜索多张去重真实卡，不在第一张合适卡后停止。
- 外部视频只在备课侧核验，并具备真实链接、相关片段、教学目的和替代方案。
- Lesson 明确分开 Student View 与 Teacher Control，Coach 不主动泄露教师区。
- `zero`、`ladder` 和 `worked-example` 在真实会话中符合已定义的证据与揭示语义。
- 重写后的 Lesson 003 不再首轮剧透，并且根据它的真实课堂需求编排多个题目角色。
- 全部 contract、插件严格验证、现有 MCP 测试与上述真实 smoke 均通过。
