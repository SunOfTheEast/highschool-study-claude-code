# 高中数学教学质量 Frame 设计

状态：已实施；真实模型 A/B 验收结论为 `INCONCLUSIVE`
日期：2026-07-27

验收报告：[高中数学教学 Frame 真实模型 A/B 验收](../../audits/2026-07-27-high-school-math-teaching-frame-ab.md)

## 一、结论

StudyForge 的教学质量采用“数学骨架 + 动态教学”路线：

- 方法图谱、题卡和材料提供可靠的数学内容；
- 通用教学 Prompt 沉淀资深高中数学教师的判断方式；
- 每个学习集用自己的教研要领说明怎样学得更快；
- Coach 根据学生跨课证据备课；
- Tutor 根据学生现场思路授课；
- 真实课堂用于持续改进 Prompt，但单次失误不会立即变成新规则。

最终新增或重写的教学资产只分四块：

```text
共享数学教学内核
Coach 备课 Frame
Tutor 授课 Frame
学习集 LEARNING_GUIDE.md
```

Trace、Block 状态、Session 绑定、工具参数和 Markdown 编译继续由现有协议负责，
不重复写入教学 Prompt。

## 二、问题

当前运行时已经能够保存真实题卡、课堂 Trace、Plan/Lesson 状态和带来源的摘要。
近几轮真实课程中，剩余质量问题逐渐从“事实写不进去”转向：

- Coach 是否抓住真正值得改变的数学认知；
- 题目是否形成有效的教学序列；
- Tutor 是否听懂学生的实际路线；
- 提示和讲解是否出现在合适的时机；
- 课堂结果是否在陌生任务中得到验证；
- 下一课是否依据跨题、跨课的模式调整。

历史上若把每次失败直接追加到 Skill，Prompt 会越来越长，并把资深教师的判断
退化为机械规则。因此本设计不继续扩张工具、防御性代码或枚举，而是把稳定的
教学判断与具体的运行时协议分开。

## 三、范围

### 目标

- 覆盖所有高中数学学习集，不只服务于导数示范课。
- 给 Coach 一套通用但不僵化的备课判断 Frame。
- 给 Tutor 一套能跟随学生思路的现场教学 Frame。
- 允许每个学习集提供自己的高效学习原则和教研经验。
- 保留不同课型、不同学生和不同数学内容所需要的自由度。
- 用真实 Plan 周期验证行为，不用字符串断言评价 Prompt 文本。

### 非目标

- 不建立完整名师教案库，也不为每个知识点预写专用 Prompt。
- 不让模型只凭未经组织的长 Context 自由生成课程。
- 不新增评审 Agent、教学状态机、提示门、规则引擎或教学 schema。
- 不让展示人设影响数学判断。

## 四、方案选择

### 方案一：名师教案驱动

预先编写完整例题顺序、讲解、提示梯度和典型回答分支。它稳定、易复制，但主要
根据教案适配学生，难以吸收未预料的合法思路，也需要持续生产大量完整课程。

### 方案二：模型自由生成

把 Roadmap、Plan、题卡、Trace 和历史尽量装入 Context，只提供宽泛的教师角色。
它适应性高，但例题梯度、重点和课堂节奏会随模型与 Context 波动。

### 方案三：数学骨架 + 动态教学

学习集提供可靠的数学骨架与教研经验；Coach 依据学生证据组织本课；Tutor 依据
学生现场思路选择介入。该方案同时保留教学质量下限和真实个性化，因此采用。

## 五、总体架构

```text
数学内容资产
├── 方法图谱
├── 题卡与题卡步骤
├── 材料
└── LEARNING_GUIDE.md

稳定教学 Frame
├── 共享数学教学内核
├── Coach 备课 Frame
└── Tutor 授课 Frame

动态学生 Context
├── Roadmap / Plan
├── 学生画像与教学偏好
├── 前课摘要
├── active Trace / planner attention
├── 当前 Lesson / Block / 题卡
└── 当前 Session 对话

运行
├── Coach：证据 + 教研经验 → LessonBlueprint
├── Tutor：Lesson Frame + 现场思路 → 教学动作与 Trace
└── Lesson Summary / Trace → 下一次 Coach 备课
```

数学内容决定可以教什么；教学 Frame 决定怎样作判断；学生 Context 决定这一次
实际怎么教。

## 六、共享数学教学内核

共享内核不规定固定课堂步骤，只要求 Coach 和 Tutor 在关键决策中完成五个教师
判断：

1. **目标判断**：这次学习主要想改变学生的哪一种数学认知。
2. **起点判断**：学生当前怎样理解问题，真正的困难或机会在哪里。
3. **任务判断**：什么任务最容易推动目标认知发生。
4. **介入判断**：此刻怎样介入才能推进思考而不替学生思考。
5. **证成判断**：什么新的独立表现能够说明学习真正发生。

内核只保留三条全局原则：

- 数学事实服从真实题卡、材料和课堂证据；
- 学生答对不自动等于学会，答错也不自动等于完全不会；
- 单题表现影响当前判断，跨题、跨课重复出现的模式才影响长期画像。

“一节课一个目标”解释为一个主要学习目的，不禁止相关能力的自然巩固。

## 七、Coach 备课 Frame

Coach 备课只承担四项教学职责。

### 7.1 看清学生当前怎样想

依据 active Trace、前课摘要和学生表达，辨认学生已经能独立完成的内容、习惯
路线、尚未解决的困难，以及仍缺少证据的判断。概念、表征、方法、运算和验证
只是可用观察角度，不是必须填写的标签。

### 7.2 确定本课主要学习目的

用认知变化描述目的，例如“从看到参数就分类讨论，转向先检查能否分离参变量”，
而不是简单写“掌握参变量分离”。

### 7.3 组织推动认知变化的任务

每个任务必须有明确教学功能。诊断、原型、对比、反例、变式和迁移只是可选
手段，不要求每节课集齐。若多个任务承担相同作用，Coach 应删除重复或改变角色。

Teacher Control 重点记录学生可能怎样想、教师何时等待或介入，以及课堂如何
调整；它不应退化为标准解堆积。

### 7.4 预判反应并确定结束证据

Coach 预想合理路线、典型困难和意外合法路线，并为提前掌握、基础断裂或目标
偏离准备调整方式。结束任务需要检查本课主要学习目的，而不是机械重复例题。

这些判断继续写入现有 LessonBlueprint、Block 和 Teacher Control，不新增持久
字段。

## 八、Tutor 授课 Frame

Tutor 使用“听懂—判断—介入—再观察”循环：

1. **听懂学生**：还原学生已经表达的数学内容和选择当前路线的原因。
2. **判断当下**：找到当前最关键的障碍或可继续发展的机会。
3. **选择介入**：采用最适合当前学生和课型的主要教学动作。
4. **再观察**：根据下一次回应继续、调整、换题、加深或结束。

等待、复述、追问、对比、换表征、提示、讲解、示范和迁移都只是可选动作，
不组成封闭枚举，也不要求固定顺序。

Tutor 遵守以下教学边界：

- 提问、提示和直接讲解都只是教学手段，由学生需要和课型决定；
- 沿学生实际路线寻找最接近的教学切入点，保留正确部分，不强迫改走标准路线；
- 每次回复保持一个主要教学意图，并随学生表现调整练习量、难度和介入深度。

Tutor 可以在当前 Lesson 内跳过、重排或加深 Block，但 Plan 的长期方向仍由 Coach
与学生共同决定。

## 九、学习集教研要领

每个学习集在根目录提供：

```text
LEARNING_GUIDE.md
```

它是版本控制下的学习集资产，不属于 Roadmap、学生记忆或通用 Skill。

### 9.1 文档结构

```markdown
# <学习集名称>学习指南

## Student Learning Principles

面向学生的高效学习原则。

## Internal Teaching Notes

### Learning logic

本学习集最重要的理解顺序、结构联系和高杠杆原则。

### Learner difficulties

常见误解、虚假熟练和快速诊断方式。

### Teaching choices

例题组织、迁移检验、取舍与避免过度教学。
```

该结构刻意保持短小。具体题目路线、答案和隐藏条件继续留在题卡与 Lesson 的
Teacher Control 中。

### 9.2 可见范围

- 学生只看到 `Student Learning Principles`。
- Coach 在建立或修订 Plan、准备 Lesson 时读取全文。
- Coach 把本课真正相关的内部教研原则写进 Lesson Frame。
- Tutor 默认只读取 Lesson 中已选入的原则。
- 学生出现与本课相关但备课未预料的路线时，Tutor 可以按需读取指南中的相关
  小节，不必强行拉回预设路线。

指南缺失时保持为空，由通用教学 Frame 继续工作；Agent 不自行编造学习集原则。

## 十、Context 与 Frame 装配

### 10.1 Coach Session

```text
固定 Frame
├── Coach 身份
├── 共享数学教学内核
├── Coach 备课 Frame
└── 现有工具契约

动态 Context
├── LEARNING_GUIDE.md
├── ROADMAP.md 与当前 Plan
├── 已确认的学生画像和教学偏好
├── 同一 Plan 内前课摘要
├── active Trace / planner attention
├── 聚焦召回的方法节点与题卡
└── 学生当前请求

输出
└── 现有 LessonBlueprint
```

### 10.2 Tutor Session

```text
固定 Frame
├── Tutor 身份
├── 共享数学教学内核
├── Tutor 授课 Frame
└── 现有工具契约

动态 Context
├── 当前 Lesson Frame
├── 当前 Block 与绑定题卡
├── Coach 选入的学习集教研原则
├── 当前 Lesson 的 active Trace
├── 与本课有关的已确认偏好
├── 当前 Tutor Session 历史或压缩摘要
└── 学生当前消息
```

共享 Frame 应保持短而稳定，便于缓存和长期维护。Guide 与学习事实按职责进入，
不把全部历史、全部题卡或重复摘要预塞给 Tutor。

## 十一、冲突处理

教学 Prompt 只保留三个冲突原则：

1. 数学事实服从真实题卡、材料和课堂证据；
2. 学生意图决定互动方式，本课目的决定什么算学会；
3. 本课具体设计优先于通用建议，展示人设只影响表达。

工具调用顺序、Trace 更正、Block 状态、文件路径、Session 绑定和 Markdown 格式
继续由现有 Agent、工具 schema、运行时和编译器负责，不复制进教学内核。

## 十二、教研迭代闭环

每完成一个 Plan，或积累 3–5 节真实课后，抽取少量关键片段复盘：

1. Coach 是否选对了最值得改变的数学认知；
2. 任务是否真正促成了该变化；
3. Tutor 的介入是否接在学生真实思路上；
4. 陌生任务是否证明独立迁移并正确影响下一课。

问题按实际归属修改：

```text
数学内容问题
→ 题卡、图谱或 LEARNING_GUIDE

备课反复选错重点或任务序列
→ Coach Frame

课堂反复出现错误介入
→ Tutor Frame

模型偶发失误
→ 保留案例，暂不修改 Prompt
```

升级范围遵循：

- 同一学习集反复出现的问题进入 `LEARNING_GUIDE.md`；
- 跨学习集、跨课型反复出现的问题进入 Coach 或 Tutor Frame；
- 所有高中数学课堂都成立的原则才进入共享教学内核；
- 单次问题不直接升级为共享规则。

复盘可以由开发者或临时审计 subagent 离线完成，不进入学生的 Coach/Tutor
Session，也不写入学生长期记忆。

## 十三、实现边界

首轮实现只做 Prompt 与学习集资产调整：

- 添加共享数学教学内核；
- 精简并增强现有 Coach/Tutor Skill；
- 在学习集模板和导数学习集中添加 `LEARNING_GUIDE.md`；
- 让学习集入口只展示学生可见部分；
- 让 Coach 读取全文，并让 Tutor 获得 Lesson 选入的原则；
- 保留 Tutor 对相关内部小节的按需读取能力。

现有工具、schema、前端路由、Trace 投影和 LessonBlueprint 编译不因本设计改变。
若加载共享内核需要调整资源注册，只做最小资源路径接入，不扩张业务协议。

公共 Claude Code 插件与 Pi 教学运行时应表达同一教学原则；具体文件组织可按各自
现有 Skill 结构实现，但不允许形成两套相互矛盾的教学 Frame。

## 十四、验收

Prompt 教学质量不用逐行字符串测试。自动化只验证必要的资源装配，例如模板是否
包含指南、学生入口是否只读取公开部分、Coach/Tutor 是否能够访问各自需要的
资源。

最终行为验收必须是一次真实模型 A/B 对照，而不是只观察新版能否完成课程：

- A 组使用实施前的教学 Prompt 和学习集资产；
- B 组使用新的四层教学 Frame；
- 两组使用同一 Provider、模型、采样配置、干净学习集起点、学生设定和课堂目标；
- 验收者只依据学生可见内容作答，不用隐藏答案引导结果；
- 评分前隐藏 A/B 身份，按相同标准比较，不把工具是否成功等同于教学质量；
- 完整转录保留在隔离运行目录，仓库只提交去敏后的对照报告。

至少运行两组配对短课，覆盖备课与现场授课。对照观察六件事：

1. Coach 是否选中真正值得改变的数学认知；
2. 任务之间是否形成推动认知变化的关系，而不是同类题堆叠；
3. Tutor 是否准确还原并利用学生的实际路线；
4. 介入是否出现在合适时机，且没有替学生完成决定性思考；
5. 是否用新的独立表现检查迁移；
6. 课堂是否自然、聚焦，并保留学生的选择权。

只有 B 组在两组配对中都呈现可定位到具体回合的整体改善，且真实性、学生可见
边界、Trace 和关课事实没有回归，才可以称为教学质量有明显改善。若结果混合或
模型波动无法排除，则结论必须是 `INCONCLUSIVE`，不能为了完成计划宣称通过。
验收期间不修改 Prompt；先保存证据，再按教研闭环决定下一步。

首轮通过不代表所有高中数学内容已经完成覆盖；它证明四层教学 Frame 能在真实
学习集中协同工作。后续学习集通过各自 `LEARNING_GUIDE.md` 承载领域经验。
