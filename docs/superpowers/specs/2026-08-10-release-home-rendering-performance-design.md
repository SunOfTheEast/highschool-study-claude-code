# StudyForge 发布前首页、渲染与读取性能修复设计

日期：2026-08-10
状态：已确认，待实施

## 一、问题与目标

真实 DMG 验收暴露了三个彼此独立、但适合在同一轮发布修复中收口的问题：

1. 首页把 `LEARNING_GUIDE.md` 全文和 Roadmap 的 `Current Position` 直接展示给学生，
   因而出现教研术语、诊断结论和教师工作语言。
2. 打开高阶导数学习集时，首页为了显示题卡数量而完整解析 519 张 YAML 题卡；前端
   又把 Home 请求当成所有路由的前置请求，造成约 4 秒的无意义等待，并让资料、关系
   和足迹页面重复支付扫描成本。
3. 多行引用块中的 `\[...\]` 在 Markdown 建立引用结构前被数学占位器截取，引用前缀
   `>` 被一同送入 KaTeX，最终显示成公式两侧多余的大于号。

本轮目标是修复学生实际看见的结果，不引入新的持久化摘要、索引协议或兼容层。

## 二、首页只接收学生投影

### 2.1 内容所有权

`LEARNING_GUIDE.md` 继续同时服务学生和教师，但遵守既有文档结构：

- H1 后、第一个 H2 前的引言：学习集的学生可见简介；
- `## Student Learning Principles`：学生可见的学习方式；
- `## Internal Teaching Notes`：只供 Agent 和教师读取。

Home API 不再返回完整 `LearningSetGuide`，而返回从原文机械提取的学生投影：

```ts
guide: {
  title: string;
  introduction: string;
  principles: string;
}
```

这三个字段不是新的教学判断，也不写回文件。若没有学生原则，只展示引言；绝不把
其他章节当作兜底内容。完整 `body/raw` 仍留在课程与 Agent 使用的原始指南读取路径。

### 2.2 课程信息边界

Home 的课程摘要删除 `currentPosition`。首页只展示可以从课程树机械确认的事实：

- 学习路线标题；
- 是否存在正在进行的 Lesson；
- 活跃 Lesson 与所属 Plan 的标题和路径。

Roadmap 的 `Current Position` 仍是教师规划所需的正式内容，但不会进入 Home 响应，
因此前端没有误展示它的机会。

### 2.3 首页层级与文案

首页从上到下保持四层：

1. 学习集标题和一句简短引言；
2. 一个主行动：有活跃 Lesson 时“继续上课”，否则“问老师”；
3. 正式课程、学习资料与学习足迹等安静入口；
4. 较低位置的“这个学习集怎么学”，只渲染学生原则。

正式课程入口只写“进入正式课程 · 路线标题”。无活跃 Lesson 时可以补一句中性的
“和老师一起决定接下来学什么”，不得显示掌握判断、能力缺口或诊断过程。

高阶导数示例学习集同步改为规范标题，并把学生原则改写成学生能直接照做的短句；
现有教研内容移入 `Internal Teaching Notes`，不丢失教师信息。

## 三、移除无意义的整库读取

### 3.1 Home 轻量统计

Home 只需要资产数量，不需要题干、答案、评分细则或图谱。题卡数改为枚举当前
`cards/` 下、排除 `.revisions` 的规范 `*.card.yaml` / `*.card.yml` 文件；笔记和资料
同样只走各自的轻量清单。Home 不调用 `readKnowledge()` 或 `listProblemCards()`。

首页统计是导航投影，不承担完整文档校验。某张题卡损坏时，首页仍可打开；真正进入
题卡读取路径时继续由现有严格 reader 报错。

### 3.2 路由按需加载

`App.loadRoute()` 不再把 `api.home()` 作为所有页面的串行前置条件：

- Home 路由读取 Home；
- Course、Assets、Knowledge、Footprint 和单项资产路由只等待自己的数据；
- App 外壳使用已经缓存的 Home 信息，深链接初次打开时可暂用课程标题或通用标题；
- 只有确实依赖自由学习会话摘要的路由才读取相应摘要，且不再造成题库深扫。

因此一次导航最多支付目标页面自身需要的整库读取，不再先深扫一次 Home 再深扫一次
目标页面。本轮不增加数据库、持久化缓存或第二份资产索引；首次打开 519 张题卡的完整
资料架仍可能执行一次严格解析，但首页和课程路线不再为此付费。

## 四、多行引用公式

数学预处理器在识别到 `\[...\]` 位于 Markdown 引用块内时，只从公式内部各后续行
剥离与外层一致的引用容器前缀。公式占位符前保留原始引用前缀，让 Markdown 仍然建立
正确的 `<blockquote>`。

该处理不能全局删除 `>`：公式本身的 `x>0`、以 `>` 开头的关系式，以及非引用文本
都必须原样保留。无法明确识别为引用容器时保持现状，不猜测性改写数学内容。

## 五、失败边界

- 指南没有 `Student Learning Principles`：显示引言，不泄漏其他章节。
- 指南没有引言：标题和主行动仍可独立显示。
- Home 的轻量计数发现候选文件但文件实际损坏：Home 不阻塞，打开该资产时由严格
  reader 报错。
- 引用公式结构不完整：沿用现有 Markdown 文本表现，不做破坏性清洗。

## 六、验收

只增加对应真实缺陷的回归：

1. Home 投影测试：学生引言和学生原则可见，Internal Teaching Notes 与
   `currentPosition` 不出现在响应和 HTML 中。
2. 路由测试：打开 Course/Assets 等页面不会串行等待 Home；Home 统计不触发完整题卡
   reader。
3. Markdown 测试：多行 blockquote display math 保留引用结构、正确生成 KaTeX，且
   不出现容器 `>`；真实关系符号仍保留。
4. 运行完整 `bun run check` 和现有 E2E。
5. 用最终 DMG 打开高阶导数学习集复测：首页可迅速出现、课程导航不再因 519 张题卡
   阻塞、学生首页无教师诊断文字、引用公式无多余大于号。

## 七、明确不做

- 不生成第二份“学生版 Current Position”；
- 不把教师指南改成学生口吻；
- 不用前端关键词过滤或截断来掩盖教师文本；
- 不新增持久化数据库、通用缓存服务或题卡索引格式；
- 不全局清理 Markdown 中的 `>`。
