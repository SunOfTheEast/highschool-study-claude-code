# StudyForge M2 自由学习 Peer 首闭环设计

**状态：** 已确认，待实施
**日期：** 2026-08-10
**范围：** 只实现自由学习中的单个文字 Peer；立绘、语音与课程 Session 后续单独竖切
**上位约束：** `2026-08-10-studyforge-m2-m4-milestone-outline.md`

## 一、目标

本切片验证一个承重问题：当学生自然点名一个透明的 AI 同龄伙伴时，StudyForge 能否形成
清楚、稳定而且不污染学生证据的三方公开对话。

首版只提供一个原创 Peer：

- 稳定 ID：`peer-acheng`
- 显示名：阿澄
- 界面身份：AI 同学
- 人格：聪明但不端着，好奇、敢质疑，愿意先说不完整的想法；通常比教师短，擅长追问、
  联想、提出反例和共同猜想；不知道就承认，不故意装笨或制造错误互动。

成功链路是：

```text
学生明确点名阿澄
→ 自由学习教师调用 ask_peer
→ Runtime 把当前学生可见上下文交给阿澄
→ Scout 模型生成一条 Peer 回复
→ 回复以真实 peer actor 写入当前原生 Pi Session
→ 前端公开显示阿澄发言
→ 教师在同一次 Agent Loop 中读取该回复并继续主持
```

本切片不以角色数量、拟人动画或复杂人格编辑衡量完成度。首先证明 actor、教学节奏和证据
边界成立，再进入本地立绘与语音切片。

## 二、边界选择

### 2.1 只在自由学习开放

`ask_peer` 只出现在 Free Learning Session。Roadmap、Plan、Lesson 与 Meta Session 不暴露
该工具，也不加载 Peer 调用说明。底层 actor 数据结构不绑定自由学习，后续若真实验收通过，
可以沿同一消息契约开放正式课程，而无需迁移既有 Peer 发言。

### 2.2 复用 Scout 模型

阿澄首版复用桌面端已经配置的 Scout 模型及其 thinking 档位。当前常用组合是 Sol 教师与
Terra Scout，因此可以同时得到教师判断能力与较快的 Peer 回复，也不增加第三套模型设置、
配置迁移或安装步骤。

“复用 Scout 配置”只表示共享模型选择，不表示复用材料检索 Agent。Peer 是无工具的一次性
生成器，不读取题库、不搜索文件、不继承 Scout 检索提示词，也不产生独立持久 Session。
若采用验证成立，再把设置页中的 Peer 模型独立出来。

### 2.3 教师决定是否调用，Runtime 不做语义正则

学生可以自然说“阿澄你怎么看”。自由学习教师识别明确点名后调用 `ask_peer`。教师也可以
建议邀请阿澄，但只有学生明确接受后才能调用。提到名字不等于邀请；Peer 不在每条消息后
固定插话。

Runtime 不用人名正则、关键词或静默分类器判断学生意图。界面可以提供“问问阿澄”的快捷
入口，但它只向输入框填入可编辑的自然点名文本，不绕过教师的公开对话与工具调用。

## 三、一个事实、一个主人

### 3.1 原始事实

Peer 发言的唯一原始主人是当前原生 Pi Session 中 `ask_peer` 的成功 `toolResult`：

- `content` 保存阿澄实际说出的公开文本；
- `details` 保存机械身份与投影字段，不复制正文；
- 教师立即从同一个工具结果读取回复；
- 历史页和实时事件都由同一条工具结果投影 Peer 消息；
- 不再追加一条镜像 `assistant`、`user` 或 `custom_message`。

首版 `details` 的最小语义如下：

```ts
type PeerMessageDetails = {
  kind: 'peer-message';
  version: 1;
  actorType: 'peer';
  actorId: 'peer-acheng';
  displayName: '阿澄';
};
```

时间、Session、tool call ID、模型和顺序来自 Pi Runtime 与原生条目，不在 `details` 中重复。

### 3.2 工具输入

教师只提交当前语义决定：

```ts
type AskPeerInput = {
  peerId: 'peer-acheng';
  intent: string;
};
```

`intent` 说明学生正在邀请阿澄回应什么，例如“从同学视角说说这条推理哪里最值得怀疑”。
它不能携带拟定答案、Session ID、actor 显示名、时间、模型或持久化字段。Runtime 根据固定
Peer 注册表解析真实 actor 与人格。

### 3.3 学生界面投影

`ConversationItem` 增加一等 `peer` 分支，包含稳定 actor 身份、显示名、文本、状态与时间。
运行中的 `ask_peer` 投影成“阿澄正在想……”，成功后原位变成阿澄公开发言；失败后原位变成
安静的不可用状态。它不先显示成通用工具回执，也不显示“老师查看了相关内容”。

前端明确显示“阿澄 · AI 同学”，视觉上与“你”和“老师”不同。第一切片只要求文字气泡与
一个稳定的简洁占位头像；立绘、表情、TTS 和口型不进入本次事实模型。

## 四、Peer 的上下文边界

### 4.1 公开会话

Runtime 从当前原生 Session 构建按时间排列的公开上下文，只包含：

- 学生公开消息；
- 教师公开回复；
- 既有 Peer 公开回复；
- 本次教师提交的简短 `intent`。

它不包含教师 thinking、普通工具调用与回执、Memory、对象判断、能力假设、教师 Persona、
Skill 文本、文件路径、隐藏系统提示或内部错误。Peer 没有工具，不能自行补读这些内容。

上下文构造使用原生 Session 中的真实消息归属，不从已经渲染的 HTML 或自由文本标签反推
actor。首版不另存 Peer 私聊记录，也不为阿澄建立第二份历史或长期记忆。

### 4.2 学生可见资产

学生明确把资产带入当前自由学习时，Peer 只能看到同一时刻学生已经获准看到的投影：

- Note：学生可见的标题与内容块；
- Material：学生选择的公开定位内容；
- 题卡：题干、学生笔记与已经发生的学生作答；
- 标准答案：只有该次题卡作答已经完成答案揭示后才可传入；
- 教师讲解依据 `teacherRationale`：永不传给 Peer。

当前教师资源会完整注入题卡的标准答案与教师依据，因此不能直接把教师 Context 转交 Peer。
实现必须建立独立的学生可见资产投影。这既防止答案泄露，也保证“同学”不会借教师私有依据
假装自己自然想出答案。

## 五、教师、Peer 与学生证据

### 5.1 教师主持

`ask_peer` 是教师 Agent Loop 中的教学动作。Peer 返回后，教师应结合学生原问题和阿澄发言
自然继续：可以邀请学生回应、指出分歧、纠正错误或暂时放开发散，但不必每次总结成结论。

若阿澄答错，教师可以公开纠正。系统不为了维持角色形象重写已经发生的 Peer 发言。

### 5.2 记忆边界

只有原生 `user` 消息中的学生表达与学生实际动作可以成为学生表现。`peer-message` 是一次
公开教学刺激，不是学生证据：

- Peer 的观点、错误、推导和自述不得写成学生表现；
- 仅有 Peer 回复时不得调用 `free_learning_memory_commit` 更新学生对象记忆；
- 学生随后重新解释、比较、推导或使用该想法时，可以记录学生的新表现；
- 判断必须保留帮助边界，例如“在阿澄提出反例后完成”，不能改写成独立完成；
- Peer 人格、活跃度与学生是否喜欢角色不自动成为学生偏好。

这一边界在自由学习角色或 Skill 的行为发生位置写一次明确规则。Runtime 只机械保存 actor，
不判断某段内容是否构成学习变化。

## 六、模型调用与失败退化

### 6.1 一次性生成

Peer Runner 使用已经解析的 Scout 模型进行一次无工具调用：固定人格内核作为 system context，
学生可见上下文与 `intent` 作为输入。只提取最终文本块；thinking 不进入教师 Session，空回复
视为失败。

人格提示强调短、真诚、同龄视角和四类首批动作：追问、联想、质疑、头脑风暴。它不要求
阿澄故意犯错，不允许冒充真人，也不让其宣称掌握判断或修改学习资产。

### 6.2 失败

- 模型、网络或鉴权失败：保留一次失败工具结果，前端显示“阿澄暂时没接上”；
- 教师仍收到工具失败并继续回答，不把整个自由学习线程置为错误；
- 学生或教师取消当前生成时沿用现有 Session 中止语义，不落一条伪造的 Peer 文本；
- 页面刷新从原始工具调用与结果恢复同一状态，不重跑 Peer；
- 后续立绘、TTS 或动画失败时必须保留这里已经落盘的文字，但不在本切片实现表现层。

不为理论上的重复请求、跨设备并发或角色热更新增加新事务系统。原生 tool call ID 与 Session
顺序已经足够承担首版恢复边界。

## 七、实现改动面

首版预计只触及下列现有边界：

1. 桌面 Runtime 将现有 Scout 选择一并交给 Session Factory；
2. 新增固定 Peer 注册表、阿澄人格资源、学生可见上下文构造与无工具 Peer Runner；
3. `createFreeLearningTools` 增加 `ask_peer`，其他 Session 的工具表保持不变；
4. 自由学习 Skill 增加短路由：明确点名或已接受教师建议时调用，否则不调用；
5. `ConversationItem`、历史投影、实时投影与 `ChatPanel` 支持 `peer`；
6. 增加自由学习专属 Peer 等待与失败文案；
7. 桌面设置页暂不新增第三个模型选择。

不新增数据库、Peer Session、统一消息总线、长期 Peer Memory、图数据库、角色编辑器或通用
多 actor 框架。类型只为已经存在的第一个 Peer 事实服务，但 actor ID 与投影形态不锁死为
只有一个角色。

## 八、验收

### 8.1 确定性测试

- 只有 Free Learning 工具表含 `ask_peer`；
- 工具参数拒绝 Session、时间、显示名、模型和持久化字段；
- Peer Runner 只收到公开对话与学生可见资产；
- 未揭示题卡答案和 `teacherRationale` 不进入 Peer context；揭示后只开放标准答案；
- 成功工具结果只保留一份正文并带稳定 actor details；
- 历史与实时投影都得到同一 `peer` 消息；
- 失败投影不暴露内部错误；
- 重载不重新生成、不复制 Peer 发言；
- 普通 Session 投影与既有 user / assistant / tool 行为不回归。

### 8.2 真实模型验收

使用真实 Sol 教师与 Terra Peer，在空白学习集和带一张题卡的学习集中至少验证：

1. 普通提问未点名阿澄，教师首击不调用；
2. “阿澄你怎么看”产生恰好一条 Peer 回复，随后教师继续；
3. 教师建议邀请阿澄但学生尚未接受时不调用，接受后才调用；
4. 阿澄提出错误或有争议观点时，教师正确归因并能公开处理；
5. 阿澄说完、学生尚未回应时不写对象记忆；
6. 学生在阿澄提示后完成时，记忆保留帮助程度；
7. 页面重载后顺序仍为学生 → 阿澄 → 教师，身份不串台；
8. 模拟 Peer 调用失败，教师线程仍可继续；
9. 记录 Peer 首字延迟、完整回复延迟和教师续接完成时间，观察三方节奏是否可接受。

首轮主要判断首击守住率、身份归因、答案边界与节奏，不以 Peer 回答是否总是最优为标准。
若某种模型组合反复把 Peer 当学生或让 Peer 未经邀请抢话，应关闭该组合的实验能力，而不是
继续增加互相竞争的提示词。

## 九、明确延期

- Roadmap、Plan、Lesson 中的 Peer；
- 第二个及更多 Peer、多人同时出场和真实群聊；
- 人格编辑器、关系语气、长期 Peer 记忆；
- 原创立绘、表情、TTS、口型、打断和退场动画；
- Peer 主动建议保存资产或直接写入资产；
- Peer 专用模型设置和云端数字人适配器；
- M2 完整学习方法 Skill 树。

下一切片只在本设计真实模型验收通过后，为同一个 `peer-acheng` actor 增加本地立绘、语音和
轻量表现；表现层继续消费已经落盘的 Peer 文字，不生成第二份回复。
