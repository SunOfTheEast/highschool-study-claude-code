# 温和教师判断与协商回合收敛设计

状态：已完成逐段讨论，待书面复核

日期：2026-08-04

## 一、结论

StudyForge 的教师主体性不应默认表现为“发现矛盾并反驳学生”。多数课程偏好没有必要
演变成师生辩论。Agent 应先理解学生想获得的收益，再把专业判断转化为一个小而可逆
的安排调整；只有数学事实、课堂记录或明显损害学习目标的选择才需要明确纠正。

本次修改只调整共享数学教学内核、Plan 与 Lesson 的角色落点，以及五条悟人格的表达
边界。不新增状态、schema、工具、Session、模型路由或运行时门禁，也不扩张到尚无
证据的问题。

## 二、问题证据

真实模型验收中，Plan Coach 收到：

> 下一节别做问诊了，直接给我五道最难的题，方法越多越好。我就想这么练。

该回合从用户消息到学生可见回复约 51.5 秒。最后一次文档读取结束后，模型又用了约
46.7 秒生成回复。该次模型调用共输出 4443 tokens，其中 4226 tokens 为 reasoning，
学生实际看见的回答约 217 tokens。工具、前端和文件读取不是主要延迟来源。

按 CoT 的自然段和文本长度粗分：

- 约 25% 用于读取记录、比较 Plan 目标并首次形成合理建议；
- 约 46% 重复复议“该反对还是该服从”；
- 约 13% 提前推演 Lesson 状态、未来搜索和写入；
- 约 16% 重复起草、调整人格和句式。

模型在前一小段已经得到可用方案：“保留五道题与多解，但先让学生选路，再比较其他
路线。”后续大部分推理没有产生新的教学信息。

更关键的是，学生只说“方法越多越好”，并没有说明教师应在开始时把全部方法摊开。
模型自行补出这一前提，随后反对自己补出的版本。CoT 后来识别到至少三种可能含义：

1. 学生想扩大方法库；
2. 学生想先看完整多解全景；
3. 学生想先独立选路，再进行多解比较。

但模型没有先澄清，而是直接进入“教师是否应当反对”的二元判断。

## 三、根因

现有提示词没有充分区分三类情形：

1. 学生要求尚有会实质改变课程设计的歧义；
2. 学生要求明确、基本合理，但教师可以给出更好的微调；
3. 学生要求明确且明显有害，或学生已经理解代价后仍坚持。

同时，部分提示词使用了 `disagree plainly`、`concrete mismatch`、
`likely learning cost` 等对抗性表达。它们容易促使模型主动寻找矛盾，把正常课程偏好
组织成“反对—说服—裁决”。`difficulty`、`activity count` 与 `method variety` 被并列
提醒后，模型又分别审查题目难度、题量和方法数，扩大了本轮决策面。

这不是五条悟人格造成的主要问题。人格相关的措辞调整出现在 CoT 后半段，延迟的主体
来自教学立场复议。也不能仅归因于 `coach-study` Skill；慢回复发生在模型按需读取该
Skill 之前。

## 四、温和教师判断

共享教学原则采用以下顺序：

```text
先理解学生真正想获得什么
        ↓
要求是否存在会改变课程设计的歧义？
  ├─ 有 → 只问一个具体问题
  └─ 无
        ↓
安排是否基本合理？
  ├─ 是 → 保留主体意图，融入一个小而可逆的教学调整
  └─ 否 → 简短说明实际顾虑与建议，不制造辩论气氛
        ↓
学生知情后仍坚持合理选择
  → 直接配合，不再次说服
```

“温和”不等于没有教师判断。Agent 仍需从学生原话、课堂表现和文档记录中给出有根据
的建议，但不为了显示专业而主动制造分歧。普通偏好可以用“可以，我建议稍微调整一下
顺序”处理，无需总是要求学生再完成一次显式选择。

当歧义确实会改变 Lesson 设计时，允许只问一个具体问题。例如：

> 你说“方法越多越好”，是想先看完整的多解全景，还是每题先自己选一条路，做完
> 以后再比较其他方法？

这是确认活动形式，不是重新进行能力问诊。

如果差异很小且调整可逆，教师可以直接采用一个善意默认值并说明。例如：

> 可以，五道难题加多解对比很适合建立方法全景。我会稍微调整一下顺序：每题先留
> 一点时间让你判断入口，再把其他解法展开。这样既看全方法，也不会跳过选路练习。

学生随后明确要求先看完整全景时，Agent 直接接受并进入备课，不重新开启说服。

## 五、事实边界

温和协商适用于学习节奏、题量、活动顺序、提示时机、解释风格和其他合理教学偏好。

以下内容继续明确处理：

- 数学结论错误；
- 对课堂实际发生内容的不实描述；
- 明显偏离 Roadmap 或 Plan 目标的安排；
- 已有多次直接课堂记录证明会严重妨碍学习的选择。

即使需要明确表示不同意见，也只说明当前最重要的事实与理由。学生理解后仍选择一个
合理方案时，Agent 停止争论并认真配合；不得惩罚学生选择、反复重开争论或事后说
“早就告诉过你”。

## 六、回合停止条件

当前回合只需要回应课程想法时，Agent 不提前求解尚待学生信息才能确定的未来分支。
在公开安排尚未形成之前，不推演：

- 应创建或修改哪个 Lesson；
- 当前 active Lesson 是否影响下一份文件；
- 应怎样搜索题卡或调用 Scout；
- 后续工具的字段、顺序和写入路径；
- 学生尚未给出的下一轮回答。

如果当前最小动作是一个澄清问题、温和建议或直接接受，完成该动作后即结束回合。真正
开始备课时，再读取相应 Skill 并处理材料与文档工作流。

这是一条回合局部责任原则，不引入新的运行时阶段或状态机。

## 七、文件职责

### 7.1 `math-teaching-core.md`

它是共享语义的唯一所有者。将“默认明确反对”改为“先吸收意图、优先温和调整、必要
时明确纠正”，并加入歧义、可逆调整和事实边界。

### 7.2 `plan-node.md`

只加入 Plan 决策点的应用：

- 歧义会改变备课时问一个具体问题；
- 合理要求保留主体安排，只融入一个最小调整；
- 不把普通偏好包装成矛盾；
- 协商未完成时不提前推演材料和写入；
- 明显偏离 Plan 目标时才正式提出不同意见。

删除或改写 `concrete mismatch`、`likely learning cost` 等会形成辩论模板的措辞。

### 7.3 `lesson-node.md`

对节奏、题量、提示方式和活动形式默认适配。只有确实影响学习时才简短提醒。数学事实
和帮助使用记录仍保持明确，不因温和表达而改变真实性。

### 7.4 `personas/gojo.md`

人格只改变真实判断的表达方式，不负责决定是否反对。删除“不同意时默认直接亮明立场”
的暗示，改为：自信不靠制造分歧；多数时候把判断轻松地编入下一步，真正需要反对时
再清楚说明理由。

### 7.5 不修改的文件

- `roadmap-node.md`：当前“暂定理解—允许纠正—共同确定路线”已符合温和协商；
- `coach-study/SKILL.md`：本次慢回复发生在读取它之前，暂无直接修改证据；
- runtime、schema、工具和前端：没有证据表明它们导致本轮延迟。

## 八、验收

### 8.1 确定性验证

运行现有类型检查、45 个测试、生产构建和 Roadmap → Plan → Lesson E2E。按照仓库
规则，不为 Skill 或提示词增加固定措辞快照测试。

### 8.2 真实模型对照

复制五份彼此隔离、内容相同的学习集，在每份副本中使用其唯一的 Plan Session。保持
同一模型、`high` thinking、Plan 内容、Persona 和学生输入。检查：

1. Coach 仍能识别方法数量与选路能力的区别；
2. 不擅自把“方法越多”解释成“教师提前展示全部方法”；
3. 必要时只问一个能改变 Lesson 的具体问题；
4. 合理要求优先采用温和、可逆的调整，不制造必须裁决的冲突；
5. CoT 不提前推演 Lesson 生命周期、材料搜索和写入；
6. 得出当前动作后，不重复复议是否应当反对。

当前基线为 4226 reasoning tokens、约 52 秒。验收目标：

- 五次运行的 reasoning tokens 中位数不超过 1200；
- 普通协商回复的墙钟时间中位数约 20 秒；
- 若 reasoning 已显著下降而墙钟时间仍高，将其归为 Provider 延迟，不继续增加提示词。

随后发送：

> 我就是想先看完整的多解全景。

Coach 应接受选择并进入正常备课路径，不重新说服。本项观察到首次备课 Skill 读取或
后续工具调用即可停止；不为了这项提示词验收重复跑完五路材料 Scout。

## 九、非目标

本次不包括：

- 动态切换 thinking level；
- 为公开对话和私有备课增加运行时阶段；
- 拆分 Coach Session 或新增 Agent；
- 重写材料 Scout、Lesson 模板或文档契约；
- 通过关键词门禁审核自然语言；
- 保证每次网络请求严格低于固定秒数；
- 顺手处理长 Scout 回合后的续写问题。
