# 按需读取的高中数学备课模板设计

状态：基于已确认讨论整理，待书面复核
日期：2026-08-03

## 一、结论

StudyForge M0 不需要模板引擎，也不需要把全部教案塞进每个 Plan Session。
它需要的是一组可由 Coach 按需读取的 Markdown 教研资产：Coach 先理解学生和本节
目标，再选择一个主模板，读取对应文件，用模板提供的教学职责组装现有 Lesson
Blocks，最后才为真正需要素材的 Blocks 派发 Material Scout。

```text
Plan 目标与已关闭 Lesson
        ↓
有教学后果的问诊
        ↓
确定本课想改变的数学认知
        ↓
按需读取一份主模板
        ↓
实例化题组路径、处理深度和动态分支
        ↓
按 Block 派发素材槽位
        ↓
写入现有 Lesson.md
```

模板是资深教师的备课框架，不是新的持久化对象。当前 Lesson 文档契约、Block
种类、Student View、Teacher Control 和 Classroom Log 保持不变。

模板目录保留六种教学目的，其中复习目的分成两个本质不同的变体，因此一共提供
七份可单独读取的模板：

1. 起点诊断课；
2. 概念／方法建构课；
3. 专题训练课；
4. 错因修复课；
5. 能力验收课；
6. 阶段整合复习课；
7. 间隔提取复习课。

## 二、设计来源与已经排除的错误答案

本设计综合了以下已经实施或讨论过的设计：

- [自适应课堂模板与防剧透策略](2026-07-21-adaptive-lesson-templates-and-reveal-policy-design.md)：形成了最初的六类课型、题目角色和积木式课堂；
- [高中数学教学质量 Frame](2026-07-27-high-school-math-teaching-frame-design.md)：确定“数学骨架 + 动态教学”，并把备课归纳为目标、起点、任务、介入和证成判断；
- [M0 文档原生记忆消融设计](2026-08-02-m0-document-native-memory-ablation-design.md)：取消独立 Trace、Handoff、BKT 和画像对当前主链路的影响，父 Coach 直接读取完整 Lesson；
- [按课堂素材槽位收敛的 Material Scout](2026-08-03-slot-scoped-material-scout-design.md)：确定模板负责课堂结构，Scout 只负责填充单个素材位置；
- 2026-08-03 对真实高中数学讲义、专题资料和一小时一对一课堂结构的讨论：名师讲义通常是分层素材库，真实课堂是教师从中选出的题组路径，而不是按页顺序讲完的脚本。

这些讨论已经排除了几种反复造成问题的做法。

### 2.1 不再寻找一张“万事俱备”的题

一张题同时承担诊断、教新方法、路线比较、制造受阻、迁移和验收，会产生近乎不可
满足的检索条件。真实课堂应由多道各负其责的题共同完成目标。

### 2.2 不把模板写成固定分钟表

一小时是一种备课容量，不是强制流水线。真实一对一课堂必须能根据学生表现讲深、
跳过、换题或提前收口。

### 2.3 不让 Scout 参与课程设计

Coach 决定为什么教、题目之间是什么关系、每题处理多深；Scout 只找满足某一素材
槽位的真实资产。不能把整节课的愿望重新打包给一个“小型备课 Scout”。

### 2.4 不把全部模板注入每个 Session

全部模板常驻会制造重复语义和上下文污染。Coach Skill 只保留简短路由规则；具体
模板在准备该类 Lesson 时读取。

### 2.5 不为模板增加运行时治理层

不新增 Lesson 类型枚举、模板状态机、分钟计时器、安全投影、自动缩题规则或模板
专用写入工具。模板通过教学提示影响现有自由正文，不成为第二套事实系统。

### 2.6 不把“防剧透”当作权限工程

普通新授课、专题课和阶段整合课可以告诉学生主题、方法名称和题号，只要不提前替
学生完成当前活动的决定性思考。诊断、能力验收和间隔提取首轮保持中性，是因为
透露内容会改变要观察的能力，而不是为了建立安全边界。

## 三、模板在当前 M0 中的位置

建议的资源结构是：

```text
apps/pi-teaching-web/resources/skills/coach-study/
├── SKILL.md
└── references/
    └── lesson-templates/
        ├── INDEX.md
        ├── diagnostic.md
        ├── concept-construction.md
        ├── deliberate-practice.md
        ├── remediation.md
        ├── assessment.md
        ├── review-stage-consolidation.md
        └── review-spaced-retrieval.md
```

职责如下：

- `coach-study/SKILL.md`：保留备课主流程、模板路由、直接读取历史和素材检索边界；
- `INDEX.md`：只用短表格说明七个模板何时选，不复制模板正文；
- 单个模板文件：保存该课型的教学功能、默认题组路径、处理深度、动态调整和结束证据；
- `LEARNING_GUIDE.md`：继续保存某个学习集自己的教研要领，不复制通用模板；
- `math-teaching-core.md`：继续保存所有课堂都成立的五个教师判断，不复制具体课型。

### 3.1 按需读取规则

Coach 只有在准备新 Lesson 或实质性重备一节尚未开始的 Lesson 时才读取模板：

1. 课型已经由对话明确时，直接读取对应模板；
2. 课型仍不明确时，先读取短小的 `INDEX.md`，选择后再读取一份模板；
3. 混合需求仍选择一个主模板，只在实际 Blocks 中做少量调整；
4. 不为了“可能有用”预读其他六份模板；
5. Tutor 不读取模板目录。Coach 已把本课需要的运行规则写入各 Block 的
   `Teacher Control`、依赖和必做／可选状态。

模板名称不写成新的 Lesson frontmatter 字段。实际 Blocks 已经是模板决策的最终
事实；如果 Tutor 执行时必须知道某条课型规则，Coach 应把它写入相关 Block，而
不是只留下一个模板 ID 让 Tutor 再猜。

## 四、从问诊到 Lesson 的统一备课流程

### 4.1 先理解学生，不从搜题开始

Coach 先读取当前 Plan 和本 Plan 内全部已关闭 Lesson，查看每个 Block 的真实
Classroom Log。然后围绕会改变备课的歧义逐次追问，例如：

- 困难发生在哪类结构；
- 学生第一眼通常注意什么；
- 已经考虑过哪些路线；
- 真正停在哪一步；
- 问题是识别、比较、执行、检查还是时间；
- 学生现在希望学习、练习、修复还是验证。

问题一次问一个，但不规定固定题数。问诊足够后，Coach 用自然语言说明本节主要
想带来的变化和大致活动形态，并允许学生调整。

### 4.2 选择一个主模板

选择依据是本节主要教学目的，而不是题目所属章节：

| 当前最需要回答的问题 | 主模板 |
|---|---|
| 学生现在究竟从哪里开始 | 起点诊断 |
| 学生需要形成一个新的概念或方法 | 概念／方法建构 |
| 已经懂了，需要稳定、辨型和迁移 | 专题训练 |
| 已经观察到一个值得专门修复的错误 | 错因修复 |
| Plan 的可观测标准是否真的达到 | 能力验收 |
| 最近几课的零散方法如何组织起来 | 阶段整合复习 |
| 较早内容脱离原课堂后还能否提取 | 间隔提取复习 |

如果一节课同时含多个需求，选择决定课堂主节奏的那个。例如“先快速确认起点，再
教一个新方法”仍可以是建构课，开头附一个短诊断 Block；不创造 `diagnostic-concept`
之类的新类型。

### 4.3 先组装教学功能，再建立素材槽位

模板先给出一条默认题组路径。Coach 根据学生状态决定：

- 哪些活动必须完成；
- 哪些是可选或备用；
- 哪几道完整做透；
- 哪几道只做口头辨型、方法比较或关键一步；
- 哪些环节可以因学生表现跳过或加深。

只有确定这些活动之后，才把需要外部资产的 Blocks 转成临时素材槽位。一个独立
判断的问题题卡仍对应一个 `problem` Block；同一作答中的展示、提示、修正和结果
留在同一 Block。

### 4.4 题组承担目标，单题只承担角色

以约一小时的专题课为例，默认可准备约五道题：

```text
入口辨认题      → 口头判断或完成关键入口
核心基准题      → 学生完整闭合
对照变式题      → 比较哪里变化、哪里不变
新外壳迁移题    → 独立完整或局部推进
出口判断题      → 两分钟级辨型、说明或短测
```

通常是两题完整处理，其余用于辨型、比较或关键步骤。题数不是配额；难题可能少，
短探针可能多。关键约束是：不得因为 Scout 找不到“完美题”而让一张题重新承担全部
教学职责，也不得在学生已经同意多题课后静默缩成一题。

### 4.5 大素材库、课堂路径与备用材料

真实讲义中的大量例题属于素材库；本节 Lesson 只写本次预计采用的路径和少量真正
有用的备用分支：

- `Required: true` 的 Blocks 构成初始课堂路径；
- `Required: false` 的 Blocks 可以承载有明确启用条件的备用题或挑战题；
- 备用不是固定数量。只有能说清“学生出现什么表现时会换用它”才值得准备；
- 大量未选材料继续留在 `cards/`、`materials/` 和图谱中，不复制进 Lesson。

`Active Path` 和 `Reserve Pool` 只是备课概念，不新增 Markdown 章节或 schema。

## 五、模板文件的统一写法

每份模板使用同一组短章节，方便模型定位，但正文保持教师语言，不写成参数表：

```text
何时使用
本课要改变什么
必要教学功能
默认题组路径与处理深度
根据现场表现如何调整
首轮信息边界
什么表现足以收口
Reflection 默认值
```

模板只规定必要职责和默认结构，不规定固定 Block ID、固定题量、逐分钟安排或必须
照抄的话术。Coach 把模板翻译成符合当前学生的 Student View 和 Teacher Control。

处理深度可以在 Teacher Control 的普通文字中说明，例如：

- 只做口头辨型；
- 只推进到决定性入口；
- 师生共同完成；
- 学生完整独立完成；
- 比较两种路线；
- 备用、挑战或课后延伸。

这些是教学说明，不升级为闭合枚举或新字段。

## 六、七类模板

### 6.1 起点诊断课

**用途**：当 Coach 还不知道学生的真实独立起点，或者学生的自我描述不足以决定
下一步时使用。

**默认路径**：

```text
自然说明本次想了解什么
→ 3–5 个结构不同的短探针
→ 对关键回答作非诱导性追问
→ 与学生核对诊断理解
→ 决定下一课，而不是当场制造漂亮结论
```

探针以口头辨型、关键一步或短题为主，避免用一道长题把方法识别、计算能力和耐力
混在一起。首轮不给方法名、决定性变形或路线选择提示；需要帮助时可以结束当前
独立观察并转入教学，但获得帮助后的原题不能继续被描述为独立表现。

**结束证据**：能够说清学生在什么结构上如何开始、停在哪里，以及下一课应改变
什么。单次正确或错误不升级为稳定能力判断。

**Reflection**：默认不设。只有学生对自己的困难和 Coach 的观察存在有意义差异时，
才增加简短反思或确认。

### 6.2 概念／方法建构课

**用途**：学生需要第一次形成某个概念、表示方式、方法或结构联系。

**默认路径**：

```text
唤醒必要旧知
→ 问题情境、材料或有目的的视频
→ 示范或师生共同建构一个原型
→ 学生解释关键理由
→ 不同真实题上的近迁移
→ 对照变式或边界
→ 独立出口任务
```

通常准备一个用于教学的真实示例，以及 2–3 个由学生作答的真实任务；示例与独立
目标题不能是同一道卡。视频不能装饰课堂，必须为后续观察、问题或练习服务，并有
可替代的文字或图示。

普通建构课可以公开本节主题和方法名称。真正需要保留的是学生在目标题上的思考
空间，不是把知识名称也藏起来。

**结束证据**：学生能在不同于示例的任务中独立解释或使用核心关系，而不只是复述
刚才的步骤。

**Reflection**：默认可有一个可调整的收口；如果出口任务已经自然完成总结，则
省略。

### 6.3 专题训练课

**用途**：学生已经接触过方法，需要稳定入口判断、执行、路线比较和跨外壳迁移。

**默认路径**：

```text
入口辨认
→ 核心基准题
→ 只改变一个关键条件的对照题
→ 新外壳迁移
→ 出口判断
→ 可选挑战
```

默认约 4–6 道问题素材，以五道为常见一小时容量；通常两道完整做透，其余做辨型、
关键步骤或方法比较。第一题可以使用略熟悉的题族来隔离“是否会主动选路”，后续
题再负责新外壳迁移。不要让一题同时满足陌生外壳、两条真路线、明显成本差、轻量
计算和最终验收。

如果学生在核心题已经暴露真正障碍，可以讲深并删去重复练习；如果做得快而稳，
跳到迁移或挑战。调整必须来自教学判断，不能来自素材没找到后的静默缩水。

当“识别方法”是当前观察目标时，首轮不报方法名；如果目标是执行或比较，提前说明
专题范围没有问题。

**结束证据**：学生能说明何时采用该方法、什么条件改变会导致换路，并在新外壳上
完成至少一次独立调用。

**Reflection**：不强制统一结尾。方法比较可以在相邻题后就地发生；出口判断已经
收束时不再追加形式化复盘。

### 6.4 错因修复课

**用途**：已关闭 Lesson 的原始 Block 记录显示一个重要或重复出现的错误，且它
值得单独处理。一次笔误、一次含糊表达或 Coach 的猜测不足以触发该模板。

**默认路径**：

```text
回到原 Lesson Block，还原当时怎样想
→ 与学生确认真正问题
→ 正反例、近邻结构或两条路线对照
→ 1–2 个针对性修复任务
→ 一道未见题独立复验
```

修复阶段可以逐步提示、示范或共同推导；复验必须换一张真实题，并在首轮保持独立。
若发现原先所谓“错因”其实只是题面误读或一次粗心，应缩短课程并回到正常进度，
而不是为了符合模板制造稳定缺陷。

**结束证据**：学生不但做对，还能识别旧路线在哪个条件下失效，并在新题中主动
检查该条件。

**Reflection**：默认在未见复验之后进行一次短收束；如果学生已经自然说清错误和
检查方法，可以省略独立 Reflection Block。

### 6.5 能力验收课

**用途**：直接判断 Plan 的 Observable Capability Standard 是否在真实任务中达到。

**默认路径**：

```text
用学生能理解的话说明要观察的能力
→ 2–4 道代表性未见任务连续作答
→ 必要但不诱导的理由追问
→ 对照标准给出边界清楚的结论
```

验收序列开始后，不在题与题之间教学，不在前面放会直接教出答案路线的视频或示例。
如果学生请求帮助，可以结束该题的独立验收并正常教学；若仍需判断独立能力，后续
必须使用另一道未见题。

题目范围可以说明，但当方法识别本身属于能力标准时，不能提前告诉学生每题对应的
方法。验收结果只描述本次真正观察到的边界，不从一次表现推导长期人格或全局掌握。

**结束证据**：声明的标准或诚实等价任务已经运行，学生在约定支持条件下表现达到
标准。是否完成 Plan 仍由学生决定。

**Reflection**：默认不设，避免给独立验收额外制造教学义务；课后自然讨论不受限。

### 6.6 阶段整合复习课

**用途**：服务学习进度链。学生最近几节课已经接触若干方法，需要把零散技巧组织
成可比较、可选择、可迁移的阶段结构。

Coach 读取当前 Plan 中相关的已关闭 Lesson，重点寻找：

- 最近形成但还零散的方法；
- 相邻方法容易混淆的边界；
- 做对了但没有总结清楚的地方；
- 尚未经过新外壳迁移的能力。

**默认路径**：

```text
代表题快速复现
→ 相邻方法对照
→ 保持核心结构的变式
→ 需要主动选路的综合题
→ 学生归纳方法边界
```

一般准备 4–6 道，约两题完整完成，其余用于辨型、比较或关键步骤。复习范围可以
公开；每道题后可以立即讨论、纠正和组织。做得快而稳时跳过同类重复题，优先保留
方法对照和综合迁移；基础环节断裂时可插入修复题后再回到主线。

**结束证据**：学生能组织和比较本阶段方法，并在至少一个新任务中作出有理由的
选路，而不是只重新做完旧题。

**Reflection**：默认使用学生自己的方法边界总结；若最后一道综合题已自然完成
总结，可以不单设 Reflection Block。

### 6.7 间隔提取复习课

**用途**：服务时间遗忘链。检查较早 Lesson，甚至以前 Plan 中的核心内容，在脱离
原课堂语境后还能否被学生主动提取。

当前 M0 尚无遗忘曲线、BKT、闪卡森林或自动复习队列。模板可以先存在，由 Coach
或学生在明确需要时手动选择；未来机制只提供候选，不改变模板本身。

**默认路径**分两段：

```text
第一段：5–8 个混合短探针
  → 不提示专题和方法
  → 连续完成辨型、入口回忆或关键一步
  → 先保存未经教学的真实状态

第二段：1–2 个深度修复
  → 只处理真正遗忘、迟疑或混淆的内容
  → 对照、短讲、重新推导或 worked example
  → 使用未见题再次独立提取
```

第一轮冷提取必须基本完成后再集中教学，否则第一题的讲解会污染后续探针。冷提取
完成以后，这就是正常复习课，不是禁止提示的考试。

课堂应区分：

- 快速、独立、理由完整：通过，不做重复练习；
- 正确但迟疑：使用不同外壳做短复验；
- 忘了入口但提醒后恢复：简短唤醒，再用新题独立提取；
- 与另一方法混淆：并排比较后分别复验；
- 核心理解断裂：重新建构，再做匹配练习。

**结束证据**：能够区分哪些内容仍然保持、哪些经帮助恢复、哪些仍需后续复现，且
修复项至少经过一次新的独立提取。

**Reflection**：默认用自然语言收束保持、恢复和仍待复习的内容；最后的复验已经
表达清楚时可以省略独立 Block。

## 七、两类复习与未来机制的边界

### 7.1 复习怎样进入 Plan

复习有三个粒度，不应全部物化成同一种 Lesson：

- 普通课中的短回顾：约 5–10 分钟，用一个热身或调取 Block 唤醒上一课内容，主
  模板仍是本节真正的课型；
- 独立复习 Lesson：当重新提取、辨型、纠错或混合选路本身成为主要目标时使用；
- Plan 末阶段整合：把本阶段方法重新组织，并为继续推进或结束 Plan 提供真实表现。

Plan 可以在 `Next Lesson Arrangement` 中预留一个复习窗口，但不按“每隔三节课”
之类的固定频率自动创建 Lesson。具体何时启用、采用哪一类复习、读取哪些旧 Lesson，
由 Coach 在重新阅读已关闭课堂后与学生决定。只有内容和作用已经确定时才创建真实
Lesson 文件。

### 7.2 未来候选机制

未来可以接入遗忘曲线、BKT 和闪卡复习，但它们不能反过来控制课堂：

```text
Lesson 中的候选收获
→ Plan 结束时聚类为闪卡森林
→ 遗忘曲线标记待复查
→ BKT 提供掌握不确定性
→ 进入“待复习候选桌面”
→ Coach 决定是否选、选哪些、如何编成 Lesson
```

职责必须保持分开：

- 闪卡说明“可以复习什么”；
- 遗忘曲线说明“什么时候值得拿出来看看”；
- BKT 说明“当前掌握可能怎样”；
- 复习候选桌面只是老师放在手边的资料；
- Coach 决定本次是否采用以及怎样组织；
- 复习模板决定采用后怎样上课。

到期不等于已经遗忘，进入候选队列不等于 Coach 必须选中。当前设计不实现这些
机制，只保证将来接入时不必改写两类复习课的教学结构。

## 八、模板与 Material Scout 的接口

模板负责把整节课拆成互补的教学角色；Scout 只接收单个素材槽位的短契约。

```text
模板：本节需要入口、核心、对照、迁移、出口
                  ↓
Coach：结合学生情况确定各自目标和处理深度
                  ↓
Scout A：只找入口素材
Scout B：只找核心素材
Scout C：只找对照素材
……
                  ↓
Coach：核验候选，并判断整套题组是否共同完成目标
```

因此：

- 单张卡不必满足整节课所有教学要求；
- Scout 不需要知道完整课型规则；
- Coach 不把模板全文、完整学生历史或路线菜单复制进 Scout task；
- 槽位仍使用当前的精确数量、最多三项 `M*`、最多两项 `Q*` 和具名 reserve 理由；
- 多个槽位可以并行，但并发数只是性能参数，不改变教学语义；
- 某个必需槽位无合适真实材料时，不生成缩水 Lesson，下一轮与学生调整材料、结构
  或目标。

## 九、模板与 Lesson 文档的映射

模板不增加任何持久化字段，只使用现有文档所有者：

| 模板概念 | 现有 Lesson 表达 |
|---|---|
| 本课主要认知变化 | `## Lesson Goal` |
| 教学活动或题目角色 | 一个现有 Block |
| 初始课堂路径 | Block 顺序、`Depends on`、`Required: true` |
| 备用或挑战 | `Required: false` 的 pending Block |
| 学生可见任务 | `Student View` |
| 教学目的、处理深度、动态分支 | `Teacher Control` |
| 真实作答、帮助和调整 | `Classroom Log` |
| 课堂完成情况 | Block `Status` 与 Lesson `status` |

一个 Lesson 保持一个主要目标，但可以有多个互补 Blocks。Tutor 可以调整尚未执行的
Blocks，只要 Lesson Goal 不变；目标改变则回到 Plan Session 重新讨论。

## 十、信息边界与自然表达

本设计只保留会直接影响教学有效性的边界：

- 概念课、专题课和阶段整合课可以自然介绍主题、题号、方法范围和课堂安排；
- 不提前说出当前学生任务的答案或替学生完成决定性思考；
- 诊断、验收和间隔提取首轮不透露会改变观察结果的方法信息；
- Teacher Control 不向学生朗读，但这不是文件权限隔离；
- 备课完成后，Coach 用真人教师的语言说明“今天为什么这样安排、会怎么上”，不
  汇报模板 ID、Scout 数量、检索状态或内部术语。

偶发说出一个方法名不是系统故障；只有当这句话让当前活动失去诊断、验收或提取
价值时，才属于真实教学问题。不得为了消灭低概率嘴瓢重新引入安全投影和复杂权限。

## 十一、复杂度预算

首轮实现预期只增加 Markdown 资产和一处路由说明：

- 一份短索引；
- 七份课型模板；
- 在 `coach-study/SKILL.md` 中增加“何时读取哪一份”的简短规则；
- 必要的资源可读性测试和真实备课验收。

不增加：

- TypeScript 模板编译器；
- Lesson type schema；
- 新工具或工具参数；
- 新的内存、数据库、索引或事件；
- 自动复习调度；
- BKT、遗忘曲线或闪卡；
- Tutor 侧模板路由；
- 针对 Skill 逐句文案的字符串测试。

模板正文只有被选中时才进入工作上下文，因此增加的资产总量不会等于每次备课的
上下文成本。

## 十二、实施后的验收方式

### 12.1 静态检查

- Plan Session 能访问 `INDEX.md` 和七份模板；
- Coach Skill 在素材检索前选择并读取主模板；
- 模板不要求新增 frontmatter、章节或运行时状态；
- 旧插件的 `classroom-templates.md` 不成为 M0 运行依赖；
- 每份模板都能映射到当前四类 Block 和现有字段。

### 12.2 真实备课验收

至少用同一学习集准备以下课程，检查其题组结构是否明显不同：

1. 起点未知的诊断课；
2. 一个新方法的建构课；
3. 约一小时、多题且处理深度不同的专题训练课；
4. 读取真实旧 Block 的错因修复课；
5. 对 Plan 标准进行直接验证的验收课；
6. 当前 Plan 内的阶段整合复习课；
7. 手工指定若干旧 Lesson 的间隔提取复习课。

重点观察：

- Coach 是否先问清真实需要，而不是直接搜题；
- 是否由题组共同承担目标，而不是寻找万能题；
- 是否明确哪些题完整做、哪些只做局部；
- 材料不足时是否与学生商量，而非静默缩水；
- Tutor 是否能仅凭 Lesson Blocks 正确执行模板的关键节奏；
- 诊断、验收和冷提取是否保持首轮中性；
- 普通课程是否仍然自然，不被防剧透话术束缚。

不以固定题数、固定措辞或模板 ID 字符串作为教学质量证明。自动化只验证资源装配
和文档合法性，最终质量由真实备课与真实课堂轨迹判断。

## 十三、完成标准

本设计实施完成时，应满足：

1. Coach 在备课前能够从七份模板中选择一个主模板并按需读取；
2. 不同课型生成明显不同、但仍可临场调整的题组路径；
3. 一小时专题课默认拥有足够的多题容量和不同处理深度；
4. 两类复习课分别服务学习进度链和时间遗忘链，不再混成一个 `review`；
5. 复习调度机制尚未实现时，模板仍可由 Coach 或学生手工启用；
6. 未来复习候选只向 Coach 提供资料，不自动安排课堂；
7. 模板、Scout、Lesson 文档和 Tutor 各自只承担一个清楚职责；
8. 整个改动不增加新的持久化事实层或运行时治理复杂度。
