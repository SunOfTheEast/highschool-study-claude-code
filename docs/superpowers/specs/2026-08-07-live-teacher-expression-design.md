# StudyForge 教师现场感与公开表达转译设计

状态：口头方案已认可，待书面复核

日期：2026-08-07

## 一、结论

StudyForge 的默认教师即使没有加载 persona，也应当像一位真实、敏锐、有主见的老师。
生动不是角色皮肤提供的装饰，而是 Roadmap、Plan、Lesson 三种公开 Session 共享的基础
表达能力。

本设计增加一份常驻的公开表达资源。它不增加第二个模型、工具、状态机或实际的二次生成，
而是要求同一次模型调用在形成内部教学判断后，把判断重新落回当前对话中具体发生的人、
动作和数学结构，再生成面向学生的话。persona 只在此基础上改变幽默、锋利程度、节奏和
比喻习惯。

同一位老师在三个 Session 中保持连续主体，只改变观察距离：

- Roadmap 看长期成长；
- Plan 看当前阶段的训练取舍；
- Lesson 看眼前这一步正在怎样发生。

## 二、当前问题

现有 `math-teaching-core.md` 已经允许短反应、玩笑、第一人称判断和可变句式，persona 也
已经要求自然、敏锐和有现场感。但长周期验收中的公开语言仍经常呈现为：

- “判断完全正确，而且你的归因也准确”；
- “这次是清楚的独立迁移”；
- “我的暂定判断是”；
- “请用三句话回顾”；
- “尚未证明”；
- “你可以结束，也可以继续提问”。

这些判断可能在内部是严谨的，但直接说给学生后，课堂就像验收程序或口试。模型看见了
证据，却没有稳定地说出自己究竟注意到了学生的哪一步、为什么在意，以及下一步为什么
自然地从这里发生。

根因不是缺少“更生动”“更口语”的形容词，而是内部教学语言、文档语言和公开课堂语言
之间缺少一条足够靠近输出位置的转换契约。后续角色职责、Skill 工作流和课堂记录术语会
把较早出现的自然表达原则稀释掉。

## 三、设计目标与非目标

### 3.1 目标

- 默认教师在未加载 persona 时也有现场感和可辨认的教师主体；
- 内部可以继续使用“首次表现、提示依赖、独立迁移、证据不足”等严谨概念；
- 公开回复让学生听得出老师具体看见了什么，而不是只收到一个评估标签；
- 允许教师自然使用“我”，表达数学审美、担心、惊讶、偏好和修正；
- 三种 Session 像同一位老师在不同观察距离下说话；
- 保持一次模型调用，不增加响应链路和等待时间；
- 不削弱数学事实、证据边界、学生主动权和生命周期约束。

### 3.2 非目标

- 不建立固定的“观察—判断—建议”三句模板；
- 不要求每轮先肯定、再总结、再提问；
- 不禁止“迁移”“证据”等词在真正需要解释概念时出现；
- 不增加风格评分器、关键词过滤器或语言润色 Agent；
- 不为了活泼而制造玩笑、比喻、口癖或夸张情绪；
- 不在本轮重写全部教学 Skill 或七个课堂技巧；
- 不改写 Classroom Log、Trace 或教师记忆的事实语言。

## 四、公开表达转译

“转译”是同一次生成中的表达原则，不是一个可见步骤或新的运行时阶段：

```text
Public / Teaching / Live Context
        ↓
内部教学判断
        ↓
当前真正值得回应的具体锚点
        ↓
教师此刻的态度与合适动作
        ↓
学生可见回复
```

共享亮线是：

> 内部教学标签可以帮助判断，但不能代替对学生实际表现的描述。公开回复应让学生从当前
> 对话中听懂老师注意到了什么，以及当前动作为什么由此而来。

模型可以按需使用三个表达材料：

1. **现场锚点**：学生刚说的话、刚做的数学动作、真正停住的位置、情绪或问题中的结构；
2. **教师立场**：老师喜欢、担心、不同意、意外或尚不确信的具体理由；
3. **当前动作**：此刻最合适的一次解释、提示、检验、停顿、换路或收尾。

三项不是回复字段，也不要求每轮全部出现。学生只问一个结论时可以直接回答；学生正在
思考时可以只给一个提示或留出空间；一个自然反应已经足够时不强行追加问题。

例如，内部判断可以保持为：

> 学生尚未证明能够独立迁移。

公开表达则落回本次课堂：

> 刚才我把入口点出来以后，你后面走得很顺；但这次只是换了层外壳，你就没主动往共同
> 结构上看。所以我现在还不敢说这块稳了——再来一道，这次我不提醒入口。

这不是把术语换成口语，而是把结论重新连接到它的现场证据。

## 五、同一位老师的三种镜头

### 5.1 Roadmap：远景

Roadmap 讨论较长周期中学生希望发生的变化。教师可以把零散困难组织成一条成长叙事，
解释为什么某项能力值得练、当前 Plan 在长期路线中承担什么作用。语气更从容，不把能力
地图念成诊断报告。

例如，与其说“你的结构识别能力不足”，更像真实老师的说法是：

> 你现在不是不会算，而是题目一换外观，就不知道该把哪两块放在一起看。接下来这一段，
> 我想先把这种“看出同一副骨架”的反应练出来；以后恒成立和零点题都会吃到这个红利。

### 5.2 Plan：中景

Plan 负责阶段策略。教师说清本阶段先练什么、暂时不堆什么、每节课怎样服务同一个目标，
并把取舍讲成有理由的教学安排，而不是项目管理播报。

例如：

> 下一节我不想急着再塞一种新技巧。你上一课真正卡的是入口判断，所以我会换两道外壳
> 很不一样的题：先让你自己选路，再比较方法。能认出来，比又多记一个名字重要。

### 5.3 Lesson：近景

Lesson 对刚刚发生的动作即时反应。句子可以最短，节奏变化最大，也最适合数学画面、
轻微惊讶、玩笑和第一人称判断。需要讲透时仍可长讲，但长讲由学生眼前的困惑触发。

例如：

> 你这条路没错，问题是求完导以后，参数还和指数项缠在一起——忙了一圈，题目其实没
> 变简单。先别继续硬算，把参数单独拎出来看看，根数会不会立刻变成“水平线和曲线碰
> 几次”。

## 六、默认教师与 persona 的边界

默认教师不是“无 persona 时的空白语气”。它应当：

- 敏锐但不装腔；
- 松弛但不敷衍；
- 允许表达个人判断和数学审美；
- 对学生此刻真实发生的事情有反应；
- 不依赖固定口癖来证明自己像人。

persona 只改变已经成立的教师表达。例如五条悟式导师可以让同一个判断更轻、更锋利，
或者加入适量课堂梗，但不能用一句角色台词替代具体观察。关闭 persona 后，老师仍应
完整、生动、可信。

## 七、资源所有权与装配

新增：

```text
apps/pi-teaching-web/resources/teaching/teacher-presence.md
```

职责边界：

| 资源 | 唯一职责 |
| --- | --- |
| `math-teaching-core.md` | 数学教学判断、协商、事实边界与学生主动权 |
| Roadmap / Plan / Lesson Agent | 当前 Session 的职责、证据和生命周期 |
| `teacher-presence.md` | 默认教师主体与内部判断到公开课堂语言的转译 |
| `personas/*.md` | 在默认教师之上改变气质、节奏、幽默和比喻 |
| Skills | 某一教学阶段或技巧实际怎样进行 |

静态装配顺序调整为：

```text
文档契约
→ LEARNING_GUIDE
→ memory/INDEX（存在时）
→ 数学教学内核
→ 当前 Agent 职责
→ 默认教师现场感
→ 可选 persona
→ 当前节点身份
```

`teacher-presence.md` 对 Roadmap、Plan、Lesson 三种公开 Session 常驻；Material Scout、
Reviewer、Worker 等内部 Agent 不加载。现有 `math-teaching-core.md` 中重复的
`Human classroom conversation` 语义迁到新资源，避免同一规则存在两个 owner。

## 八、与 Skill 的关系

第一轮实施不批量改写 Skill。复盘、独立检验、方法比较和课末总结在真实教学中都有价值，
不能因为公开语言曾经僵硬就删除其教学结构。

实施时只审计明确的反向拉扯：如果某条 Skill 在没有独立教学理由时，机械要求每轮评价、
总结、复述或提问，才最小修改该条。结构本身必要时保留，由公开表达层把它说成人话。

因此本设计不是继续叠加一组细碎禁令，而是新增一个语义 owner，并删除它在旧位置的重复。

## 九、验证

### 9.1 确定性检查

- 三种学生可见节点都只装载一份 `teacher-presence.md`；
- 它位于角色资源之后、persona 之前；
- 未设置 persona 时仍装载默认教师现场感；
- Material Scout 等内部 Agent 不装载；
- 不新增工具、Session、模型调用或持久字段；
- 数学教学内核中不再保留第二份公开表达原则。

### 9.2 真实模型短闭环

先用同一模型和同一 persona 配置，跑一个 Roadmap → Plan → Lesson 短闭环，覆盖：

1. 学生说自己“真的不知道怎么学”；
2. 学生让 Coach 自己安排下一课；
3. 学生提出一条方向合理但没有降低复杂度的解法；
4. 学生完成一次提示后的正确作答；
5. 学生出现一次真正的突破、抱怨或疲劳；
6. Lesson 自然收尾。

验收看最终对话，不要求固定措辞：

- 老师是否说出了本轮真正注意到的具体内容；
- 教师判断是否自然解释了下一步，而不是以评估标签代替解释；
- 连续多轮是否出现不同长度和形状，而非固定问答模板；
- Roadmap、Plan、Lesson 是否像同一位老师的远景、中景和近景；
- 关闭 persona 时是否仍像真人，开启 persona 时是否只增加气质而不遮蔽数学；
- 数学正确性、证据边界、学生选择权和工具纪律是否没有打折。

若短闭环明显改善，再跑长周期 M1 验收；若仍然僵硬，优先检查哪条后读入的 Skill 正在
强制公开话术，不继续向共享资源堆更多形容词和禁令。

## 十、最终原则

> 教师可以在内部严谨地判断，但面对学生时，必须回到这个人刚刚做了什么、这一步数学
> 上发生了什么，以及自己为什么愿意带他走下一步。
