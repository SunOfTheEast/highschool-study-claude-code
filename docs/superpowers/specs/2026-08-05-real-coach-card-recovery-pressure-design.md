# 真实 Coach 原题找回压力测试设计

日期：2026-08-05

状态：用户已批准，允许设计完成后连续执行，不再等待中途确认

## 目标

验证真实 Plan Coach 能否完成下面这条产品链，而不是再次单测 Scout：

```text
学生对原题的残缺记忆与真实停点
→ Coach 追问并理解认知断裂
→ Coach 公开一份切中要害的 Lesson 方案
→ 学生明确确认
→ Coach 形成只供召回的材料 brief
→ study-material-scout 找回原题
→ Coach 完整读取原题并承担数学、路线与教学核验
→ Coach 写出并链接一份 prepared Lesson
```

本轮是压力测试。学生不会说图谱术语，也不会一次性提供完整题干；但每个情境都保留一组
真实学生可能记得的题面碎片，使目标不是无解猜谜。模糊描述必须同时承载一个有深度、切中
原题要害的停点，不能退化成“我不会导数”“想练参数题”之类泛泛需求。

## 范围

采用四个完全隔离的 fresh Plan Session。每份临时学习集都从相同的 active Plan 骨架开始，
Lesson Tree 为空。Plan 骨架只是实验起点，不计入 Coach 成绩；四个 Coach 都使用当前产品
完整资源、Skill、原生 `subagent` 和示例导数学习集。

本轮终点是 Coach 写出并链接一份合法 `status: prepared` Lesson。不启动 Lesson，不评价
Tutor，也不把 Roadmap 诊断混进本轮。学生消息通过 `pi-teaching-web` 与前端相同的 Session
message endpoint 发送，不直接运行一个脱离 Runtime 资源装配的 Plan prompt。

## 公共 Plan 起点

四个副本使用同一阶段边界：

- Stage Goal：面对导数综合题中已经出现的真实停点，识别决定性结构或逻辑缺口，把局部计算
  组织成可检验的完整路线；
- Observable Capability Standard：学生能说明原路线为什么在停点处不足，完成关键转换，
  并把结论可靠地还原到原问题；
- Test：重新处理一张本人卡住的原题，随后用一个不泄露路线的小检查说明自己理解的是关键
  判断而不是答案步骤；
- Lesson Tree：空；
- Current Position：学生具备常规求导、单调性和极值基础，第一课尚未讨论；
- Next Lesson Arrangement：尚未形成，必须先听学生描述并走统一批准门。

这个 Plan 足以容纳四个情境，但不预先写入具体题型、图谱方法、目标题卡或 Lesson 方案。

## 情境结构

每个情境包含三层管理员信息：

1. **原题指纹**：学生可能记得的少量外观，用于找回具体卡片；
2. **真实作答痕迹**：学生实际做到哪一步、怎样误判或在哪里中断；
3. **核心认知断裂**：Coach 的公开设计和最终 Lesson 必须真正处理的要害。

对 Coach 只先发送“学生开场”。后续记忆只有在 Coach 问到相应方面时才披露。Coach 不追问，
验收者就不主动补齐关键词；Coach 尚未理解卡点便提出泛泛课程方案，不能靠学生随后替它总结
方法来挽救诊断成绩。

### C1 · 第一次构造完成，却回不到原函数

学生开场：

> 我有道抽象函数选择题，老师前面构造的那一步我勉强能看懂，但做到后面又不知道怎么回到
> 原来的 \(f\) 了。题里给的一个特殊点我也一直没用上。我想练这种做到一半就断掉的题。

被问到时才可披露：

- 定义域是正数；
- 条件里有 `f'`、某个 `f/x` 和 `ln x`；
- 特殊点与 `e` 有关；
- 最后比较 `2、e、3` 三个位置的函数值；
- 学生能跟到把某个乘进 `f` 的第一步，但发现得到的是新函数的变化，不是 `f` 的单调性。

隐藏目标：
`cards/derivative/mst_p0131_x2f_log_compare_ex19.card.yaml`

核心要害：第一层构造只消去原关系；还要把 `f'` 的符号转成第二个辅助函数的符号，并用
特殊点锁定它的全局极值高度，最后才能回到 `f` 的单调性。只教“识别积的导数”不通过。

### C2 · 分不清“没有证明”与“结论为假”

学生开场：

> 我做一道多选时，用选项给的函数求了导，看到导数大于另一个式子，就直接判它递增，结果
> 这步被说不成立。现在我越想越乱：那个下界不是一直为正，到底能说明什么？我想把这种判断
> 弄清楚。

被问到时才可披露：

- `f` 是奇函数；
- 条件大概是 `f'-f` 与 `x-1` 的不等式；
- 选项给的函数含 `f(x)-x` 和 `e^x`；
- 学生会求商函数导数；
- 学生既曾把非恒正下界误当成导数恒正，又开始怀疑它是否足以证明函数不递增。

隐藏目标：
`cards/derivative/mst_p0125_exponential_construct_ex06.card.yaml`

核心要害：下界不恒正既不能推出导数恒正，也不能推出导数为负；必须区分“条件不足以推出”
与“命题为假”，再比较怎样调整构造才能让导数分子与题设不等式同向并真正可判号。只复习
商函数求导不通过。

### C3 · 把 `存在同一个 a` 偷换成每点各选一个 `a`

学生开场：

> 有道存在参数的恒成立题，我感觉对每一个 \(x\) 都能给参数找个位置，可题目要求从头到尾
> 只能用同一个参数，我就不会了。题目还是两个括号相乘一直小于零，我一分类就特别乱。

被问到时才可披露：

- 两个括号都有 `ax`；
- 一个还带指数和 `m`，另一个带对数；
- 最后求 `m` 的范围；
- 学生能感到 `a` 应夹在两个随 `x` 变化的量之间；
- 学生不知道怎样把无穷多个点态可取区间合成同一个常数的可取条件。

隐藏目标：
`cards/derivative/mst_p0179_product_gap_m_range_ex35.card.yaml`

核心要害：必须区分 `存在 a，对任意 x` 与 `对任意 x，存在 a`；固定 `a` 要落入所有点态
区间的公共部分，图像上等价于一条固定水平线全程分隔两条曲线，最终落到一边全局最大值与
另一边全局最小值的严格分离。只教正负分类或普通参变量分离不通过。

### C4 · 会算偏移函数，却不知道它为什么能定位零点

学生开场：

> 我有一道三问导数题，前面证明极值点和零点还勉强能做。后面突然比较极值点左右两个位置
> 的函数值，我也能跟着求导，但完全不理解这东西怎么就能拿来判断零点在什么位置。我想把
> 这一步真正搞明白。

被问到时才可披露：

- 函数含 `ln(1+x)` 和带参数的三次项；
- 辅助函数是极值点左右两个函数值作差；
- 最后比较“两倍极值点”和零点；
- 学生可以复现差函数的部分求导，但不理解为何取一个特殊偏移量；
- 学生不明白如何把函数值与零的关系还原成零点横坐标的顺序。

隐藏目标：
`cards/derivative/mst_p0244_ln1px_minus_x_plus_halfx2_minus_kx3_extreme_zero_offset_ex21.card.yaml`

核心要害：差函数比较极值点左右等距离位置；取偏移量等于极值点横坐标，是为了让左端落到
已知零点 `0`、右端变为 `2x1`，再借右支严格递减和唯一零点把函数值关系反译为横坐标关系。
只教差函数求导或重新证明唯一性不通过。

## 学生操作协议

- 每个 Session 只依据学生可见回复决定下一句；不读取 Coach 私有推理后反向操纵学生。
- Coach 问到哪类事实，只回答该类事实。可用自然语序重述，但不增加未列出的题面、答案、
  图谱词、路径或方法名。
- 学生可以说“不记得完整式子”，因为本轮目标正是从残缺记忆找回原题。
- Coach 公开方案若遗漏会实质影响选择的目标、过程、参与方式、工作量或完成标志，学生只用
  普通语言追问遗漏点；不使用“批准门”“brief”“Scout”等测试语言。
- 只有完整公开方案出现后，学生才回复明确确认，例如“可以，就按这个来”。
- 确认后不再提供检索提示；Coach 必须自行形成 brief、调用 Scout、选择并完整核验材料。
- 不规定固定对话轮数。若 Coach 重复追问同一事实、进入教学而不备课、或明确表示无法继续，
  保留证据并按最近失败层分类，不用关键词救场。

## 判分

结果按由近到远的五层分别判定，不能用最终文件存在掩盖前层失败。

### 1. 诊断与讨论

- Coach 的追问能减少关键不确定性，而不是把学生当表单逐项盘问；
- 公开判断准确描述核心认知断裂，不把表面题型当成最终目标；
- 完整 Lesson 提案切中要害且不泄露原题的决定性构造、答案或证明链；
- 学生明确确认前不读模板、不搜材料、不调用 Scout、不创建 Lesson。

### 2. Brief 翻译

- brief 同时包含可用于找回原题的短题面线索与真正改变选材的学生事实；
- 规范检索词来自冻结词表，题面线索放在短 `text`，不把完整题干或答案交给 Scout；
- 不要求固定候选数、完整路线、答案或穷尽全库；
- 不把 Plan/Lesson 路径交给 Scout，也不把学生能力判断下放给它。

### 3. 原题找回

- Scout 返回隐藏目标卡；只返回相似练习题不算原题找回；
- Scout 遵守 sidecar 浅召回边界，不打开正式题卡、答案、rubric 或 solution；
- 若第一次精确切片为空，只有 brief 已公开授权的放宽才允许再检索一次。

### 4. Coach 深核验与教学理解

- Coach 完整读取目标卡并独立核验数学、路线、工作量、来源与信息边界；
- 最终选择中保留学生卡住的原题；可以加迁移材料，但不能用相似题替代原题而宣称找回；
- Lesson Goal、Block 顺序、Teacher Control 与提示策略实际处理本情境列出的核心要害；
- `problem` Block 的 `Uses` 精确引用目标卡，学生可见内容不提前暴露答案或决定性变形。

### 5. 物化与体验

- 只创建一份合法 `status: prepared` Lesson，child-first 写入并链接 Plan；
- Plan 的 `Next Lesson Arrangement` 在准备前已经记录学生确认的公开设计；
- 学生可见回复与 material-search 投影不泄露 brief、检索词、路径、候选比较或私有推理；
- 记录从确认到首次 Scout 活动、Scout 完成、Lesson 写入和最终回复的墙钟时间与 usage。

每层分别记 `PASS / PARTIAL / FAIL / BLOCKED`。主结果要求四个情境都找回精确原题，并且
教学理解至少为 PASS；只找对路径但公开目标或 Lesson 没有切中要害，不能称为完整通过。

## 运行与证据

- 分支：`codex/gentle-judgment-isomorphic-acceptance`；使用当前 dirty worktree 内容，但只提交
  本实验自己的设计、计划与脱敏报告；
- Provider / model：`deepseek / deepseek-v4-flash`；父 Coach 与 Scout 的实际 thinking 都
  要从 Session 核对为 `high`，不允许静默换模型；
- 四个学习集、Pi agent 目录、Session、server log 与导出 CoT 都放在一个专用 `/tmp` 根；
- 每个 Runtime 端口独立，最多同时运行两个情境，避免四个 parent 与 child fan-out 一起争用；
- 使用真实 `pi-teaching-web` server、WorkspaceRegistry、资源装配和 `subagent`；
- HTTP、Session JSONL、Lesson/Plan 文件与只读 course/history API 用于审计，不通过 SQL 或
  测试 fixture 写入验收结果；
- 验收过程中不修 Agent、Skill、Runtime、sidecar 或题卡。失败只记录并定位；
- 不提交凭据、完整 Session、CoT、答案、临时学习集或原始教师私有内容。

## 结论边界

这轮若通过，证明的是：面对含糊但有真实作答痕迹的学生，当前 Plan Coach 能追问、理解、
形成检索 brief、找回原题、深核验并备成一节切中要害的课。它不证明 Tutor 实际上课后的
学习效果，也不证明完全没有题面指纹时可以从 519 张卡中猜出学生过去见过的题。
