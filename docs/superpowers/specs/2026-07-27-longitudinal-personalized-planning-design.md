# 长期学情融合与个性化 Plan 规划设计

状态：设计已通过，等待文档审阅
日期：2026-07-27

## 一、目标

StudyForge 已经具备完整的学习事实与召回链路：

- Roadmap、Plan 与 Lesson 保存学习结构；
- active Trace 保存题卡、课堂步骤、学生表现和支持程度；
- Planner Attention 聚合当前值得备课关注的方法信号；
- Lesson Summary 与 Plan Summary 压缩跨课、跨周期历史；
- `student-profile.md` 与 `teaching-profile.md` 保存经学生确认的稳定偏好；
- `LEARNING_GUIDE.md` 提供学习集自己的教研原则；
- `card_search`、`trace_search` 与来源链接支持从摘要回到原始记录。

下一阶段不增加更多记忆，而是增强 Coach 把这些材料融合成教学决策的能力。目标是：

> 在相同 Roadmap、题库和表面成绩下，不同的长期学习轨迹应使 Coach 形成不同的瓶颈判断，并推荐不同、可解释、可验证的下一 Plan。

个性化不能由“回复提到了历史”证明。规划差异必须来自真实学习记录，能够回溯到原始 Lesson、Trace 或学生原话，并在后续课堂中接受结果检验。

## 二、核心判断

当前架构已经解决：

```text
历史怎样保存
  → 怎样压缩
  → 怎样召回
  → 怎样交给下一次备课
```

缺少的是材料与决策之间的学情研判：

```text
长期记录
  → 重建能力变化轨迹
  → 比较多个原因假设
  → 回顾过去干预效果
  → 选择当前最有杠杆的瓶颈
  → 生成可证伪的下一 Plan
```

这不是新的记忆层、评分模型或规则引擎，而是 Coach 的 Plan 级教学工作流。

## 三、触发位置与角色边界

新增 `plan-next-cycle` Skill，由原 Coach 按需加载，不新增学生可见 Agent。

只在以下情景触发：

1. 当前 Plan 完成，准备选择下一 Plan；
2. 当前 Plan 持续停滞，需要重新规划；
3. 学生主动要求重新判断学习方向。

角色职责保持清晰：

| 组件 | 职责 |
| --- | --- |
| `start-or-revise-roadmap` | 首次建立或修改长期目标与 Plan 图 |
| `plan-next-cycle` | 根据长期学习轨迹建议下一 Plan 或诊断 Plan |
| `prepare-next-lesson` | 在已经选定的 Plan 内准备下一 Lesson |
| Tutor | 执行当前 Lesson、响应学生思路并写入 Trace |
| Evidence Scout | 只读查找证据、反例和来源，不决定下一 Plan |

学生继续拥有最终决定权。Coach 必须先展示研判与建议；只有学生确认后，才能写入并注册新的 Plan。

## 四、材料分工

学情融合不是把所有文件拼进一个大 Prompt。每类材料只有一种主要职责：

| 材料 | 研判作用 | 不得越权为 |
| --- | --- | --- |
| Roadmap、方法图谱 | 限定长期目标、依赖和候选路径 | 学生已经掌握的证明 |
| Plan / Lesson Summary | 展示能力变化与教学经过 | 最新原始证据 |
| active Trace | 说明学生在具体任务中实际做了什么 | 单次表现推导出的稳定结论 |
| Planner Attention | 提醒值得核查的方法信号 | 自动的下一 Plan 判决 |
| 学生画像 | 约束适合怎样学习及稳定习惯 | 掩盖能力缺口的理由 |
| 教学画像 | 约束教师如何互动与介入 | 学习内容选择器 |
| `LEARNING_GUIDE.md` | 提供本学习集的教研经验 | 学生本人表现的替代品 |
| 题卡 | 诊断、训练或验证一个假设 | 学生实际使用方法的证明 |

半年历史不整包注入 Coach。Plan Summary 提供周期索引，画像完整读取，Planner Attention 提供准备提醒；只有某条原始事实可能改变规划时，Coach 才沿链接下钻到 Lesson、Trace 或题卡。

## 五、学情研判过程

### 5.1 看变化，不看总分

Coach 首先重建纵向轨迹：

- 哪些能力从需要提示变为独立完成；
- 哪些问题跨题、跨 Plan 反复出现；
- 哪些表现只在熟悉外壳成立；
- 哪些能力经过间隔后仍能保持；
- 同类失败发生前，学生通常采用了什么判断；
- 过去采用过什么教学方式，学生怎样响应。

BKT 或 Planner Attention 可以指出“哪里值得看”，但不能替代上述语义判断。

### 5.2 比较竞争假设

Coach 对主要现象形成少量可区分的原因假设，同时查看支持证据、冲突证据、既往干预和缺失信息。

例如，同样是含参导数题连续失败，可能分别来自：

- 没有识别参数所在的结构位置；
- 已经识别结构，但方法启动依赖提示；
- 方法可以启动，真正缺口是条件与边界检查；
- 知识与策略均可用，只在时间压力下出现粗心。

模型不使用固定权重求和。若证据不能排除关键替代解释，正确输出是短诊断 Plan，而不是强行确定病因。

### 5.3 选择杠杆点

下一 Plan 不机械选择最低能力节点，而选择：

> 对 Roadmap 重要、反复阻塞后续内容、且目前最可能通过一个 Plan 改变的认知动作。

小缺口可以暂缓或随课观察；上游判断习惯可以优先于表面错误率更高的下游节点。

### 5.4 形成可证伪规划

下一 Plan 必须明确：

- 需要改变的主要认知动作；
- 为什么现在处理它；
- 采用什么教学策略；
- 学生需要在何种条件下独立表现；
- 哪些后续结果支持当前判断；
- 哪些后续结果意味着应重新规划。

## 六、直接研判与动态工作流

当最近 Plan 的结论清楚且证据一致时，Coach 直接完成研判，不启动子任务。

当历史跨越多个 Plan、证据冲突，或本次决定会明显改变 Roadmap 方向时，Coach 可以提议启动现有 Dynamic Workflow。工作流复用只读 Evidence Scout，并行回溯三个相互独立的角度：

1. **能力轨迹**：独立、提示后、迁移和保持怎样变化；
2. **认知模式**：反复出现的启动方式、错误模式和学生原话；
3. **干预反应**：过去怎样教、学生如何响应、哪些方式有效或无效。

每个任务只返回紧凑发现、支持与冲突证据、精确来源和未决问题。Evidence Scout 不给出 Plan 结论。原 Coach 结合 Roadmap 与 `LEARNING_GUIDE.md` 完成最终融合和正式写入。

前端沿用现有工作流进度，不展示子任务私有内容：

```text
回溯学习轨迹 → 核对不同解释 → 形成规划建议 → 等待学生确认
```

工作流失败时保留已经取得的来源。剩余信息足够时 Coach 可以继续；不足时只说明不确定性并建议诊断，不得补造确定结论。

## 七、Planning Basis 与疗效回看

学生确认后，`plan-next-cycle` 创建的新 Plan 必须包含一个普通 Markdown 小节：

```markdown
## Planning Basis

- 当前研判：……
- 为什么现在处理：……
- 关键来源：[…](…)、[…](…)
- 暂时排除的解释：……
- 验证与重规划信号：……
```

它不是新的 MCP 或数据库 schema，也不需要新工具。`plan_register` 继续验证并登记已经写好的 Plan。读取层把该小节视为可选，以兼容旧 Plan；但 `plan-next-cycle` 不得省略它。

Plan 开始时的 `Planning Basis` 与 Plan 结束时的现有 `Plan Summary` 组成一次完整教学试验：

```text
表现
  → 原因假设
  → 教学干预
  → 学生反应
  → 假设修正
```

Plan Summary 除了总结能力证据，还应回看：

- 初始瓶颈判断得到支持、部分支持还是被推翻；
- 本周期采用的教学方式产生了什么作用；
- 结论在哪些任务与支持条件下成立；
- 哪些迁移或延迟保持仍未验证。

未来 Coach 因此能同时读到“当时为什么这样规划”和“后来证明这种规划是否有效”，而不只是学生做过哪些题。

## 八、学生可见体验

Plan 页面增加一个简洁的“为什么这样安排”区域，读取 `Planning Basis`，展示：

- 当前阶段判断；
- 选择该方向的主要依据；
- 本阶段准备怎样验证。

来源可以继续下钻，但默认不展开内部工作流、私有教案或长篇 Trace。没有 `Planning Basis` 时隐藏该区域。

学生可以在 Coach 对话中质疑证据、补充现实约束、要求诊断、选择其他 Plan 或拒绝当前建议。未经确认的建议不写入正式 Plan。

## 九、个性化验收

### 9.1 历史互换

构造两个隔离的长期学习档案，保持以下条件一致：

- Roadmap；
- 题卡、方法图谱与材料；
- 模型、思考强度与人设；
- 当前综合正确率或表面能力水平；
- 向 Coach 发送的规划请求。

只改变长期轨迹。示例：

- 学生甲计算稳定，但在陌生外壳下无法迁移；
- 学生乙结构判断较好，但反复遗漏定义域与边界。

两名 Coach 应在主要瓶颈、Plan 目标、教学策略和验证任务上产生可由历史解释的差异。交换两份历史后，规划应随历史而交换；否则差异可能来自模板或采样噪声。

### 9.2 交叉用药

分别运行：

```text
甲 + 为甲规划的 Plan
甲 + 为乙规划的 Plan

乙 + 为乙规划的 Plan
乙 + 为甲规划的 Plan
```

每个条件运行相同数量的真实模型 Lesson，比较：

- 是否更快触及真正瓶颈；
- 所需提示量；
- 新题中的独立迁移；
- Coach 是否需要中途推翻初始判断。

只有匹配 Plan 在两个学生上都优于错配 Plan，才能说明长期记忆真正改善了教学决策。

### 9.3 结论等级

- `PERSONALIZATION_CONFIRMED`：规划随历史稳定分叉，且匹配方案明显优于错配方案；
- `PLANNING_ONLY`：规划能够随历史分叉，但尚未证明教学结果更好；
- `NO_EFFECT`：规划基本相同，或差异无法由历史解释。

## 十、最小实施范围

首版只包含：

1. Pi 与 Claude 插件中的等价 `plan-next-cycle` Skill；
2. Coach 与规划路由对该 Skill 的加载；
3. `plan-next-cycle` 创建的新 Plan 必填、读取层向后兼容的 `Planning Basis` 小节；
4. Pi 对该小节的读取和学生侧展示；
5. Plan 结束时对规划假设和教学干预的回看要求；
6. 历史互换与交叉用药真实模型验收。

明确不包含：

- 新 MCP 工具；
- 新数据库、向量库或长期记忆文件；
- 新能力分数或固定权重；
- 自动选 Plan 的规则引擎；
- 新的学生可见 Agent；
- 对 Skill 或 Agent 文案做字符串匹配的测试；
- 未经学生确认的自动 Plan 注册。

## 十一、兼容性与验证

- 没有长期历史时，Coach 根据学生陈述建立首个诊断 Plan；
- 旧 Plan 缺少 `Planning Basis` 时正常读取，前端不显示空区域；
- 结构测试只验证 Markdown 读取、API 投影、前端展示和旧文件兼容；
- Skill 行为由真实模型验收，不用脆弱的文本断言替代；
- 原始学习集、题卡、Trace 和四个 MCP 工具协议保持不变；
- 所有个性化结论必须能够回到原始来源，来源失效时明确标记未验证。

## 十二、完成标准

设计实施完成后，应同时满足：

1. Coach 能在 Plan 边界执行一次来源驱动的学情研判；
2. 证据不足时能够选择诊断 Plan；
3. 新 Plan 可解释为什么此刻选择该方向；
4. Plan Summary 能回看初始判断与教学干预效果；
5. 前端能让学生看见个性化规划依据；
6. 旧学习集和现有协议无须迁移；
7. 历史互换与交叉用药实验给出三档之一的诚实结论。
