# 按课堂素材槽位收敛的 Material Scout 设计

## 1. 目的

StudyForge 已经证明临时 Scout 可以把题卡检索过程隔离在 Plan Session 之外，
但最新真实周期暴露了明显的性能问题：三路 Scout 虽然从图谱、题面和教学适配
三个入口开始，最后仍会重复扫描同一个专题，并把“语义收敛”理解成“把同类
题卡尽量查全”。

本设计只修正检索职责和停止条件：Coach 按已经商定的 Lesson 素材槽位派发
Scout，每个 Scout 只形成足以支持一次选择的候选前沿，Coach 再完整读取最终
选中的题卡。它不增加索引、数据库、向量检索、超时、工作流状态或新的教学
事实。

## 2. 已观察到的根因

2026-08-03 的两轮多题备课共运行六个 Scout，原始 Session 显示：

- 142 个 assistant turn；
- 287 次工具调用；
- 168 次题卡读取，只涉及 59 张不同题卡；
- 两次三路 fan-out 内部分别有 46 次和 38 次重复读卡；
- 第二轮最终选中的两张题卡约两分钟时已经被读到，但对应 Scout 仍继续工作
  三至四分钟；
- 多路输出各自列出约十至三十个候选，其中包含明显不适用、已排除或同族重复
  的题卡。

Session 中多次出现“再检查剩余题卡”“补全专题块”“为了完整性再看几张”等
推理。触发这种行为的不是缺少超时，而是三项契约叠加：

1. 三个 lane 收到相同的完整教学请求，只规定不同的搜索起点，没有分割最终
   搜索空间；
2. “可变长度、不要固定上限、搜索到语义收敛”缺少面向教学选择的终止定义，
   因而被解释成专题覆盖率；
3. `pi-subagents` 为只读 Scout 推断出 `attested` acceptance，自动追加软件审计
   式验收报告，进一步鼓励 Scout 证明自己查得完整。

`thinking: medium` 会放大这个过程，但不是根因。单纯降低思考等级或更换模型
仍会保留重复搜索。

## 3. 设计约束

本次修改必须：

- 保留 Roadmap → Plan → Lesson → Block 的 M0 文档树；
- 保留一个 Plan 一个长 Session，以及父节点直接读取已关闭 Lesson；
- 保留 Plan-only 的原生 `subagent` 工具和 fresh child Session；
- 支持一节课一题、多题、视频、阅读或其他素材组合；
- 不设置 StudyForge wall-clock timeout，也不以固定候选数代表检索完成；
- 让 Coach 保留最终选材、数学核验、课堂编排和持久化权力；
- 保持学生看不到私有找题过程和未上课题目的决定性内容。

本次修改不得：

- 新增持久化题卡索引、向量库、数据库或后台索引任务；
- 恢复旧 workflow、Handoff、证据投影或安全投影；
- 用规则引擎替代教学相关性判断；
- 给 Scout 增加写工具、教学事实写入或学生能力判断；
- 用硬性 turn、tool-call 或候选数量上限掩盖错误的收敛定义。

## 4. 方案比较

### A. 只降低思考等级或换更快模型

改动最小，但三个 Scout 仍会重复读取相同题卡，父 Session 仍会接收庞大的候选
结果。它只能缩短单次推理，不能修复职责重叠，因此不作为首轮修复。

### B. 按素材槽位派发 Scout，并返回候选前沿——采用

Coach 先把已商定的 Lesson Blocks 转成临时素材槽位，再按槽位并行派发 Scout。
每个 Scout 只搜索自己的教学用途，返回能够改变 Coach 选择的非劣候选。
这沿用现有文件工具和 subagent 扩展，不增加运行时或持久化层。

### C. 增加 card catalog 或专用检索工具

预生成目录或结构化搜索工具可以进一步降低读卡成本，但会引入新的派生数据、
更新时机和工具契约。只有方案 B 经真实多题课验证后仍然明显过慢，才重新讨论
这一层。

## 5. 素材槽位

素材槽位是一次备课调用中的临时描述，不写入新的 schema。它来自学生已同意的
Lesson 活动，每个需要独立素材的 Block 对应一个槽位。例如：

```text
slot-A
用途：观察学生能否识别平移型公切线的便宜路线
素材：一张未曝光问题卡
工作量：偏轻
排除：2016 新课标Ⅱ T16 及直系克隆

slot-B
用途：观察学生是否会把公切线存在性转成恒成立
素材：一张未曝光问题卡
工作量：偏轻至中等
排除：slot-A 同族和平移型公切线
```

默认一槽位一 Scout。三道不同用途的题就是三个并行任务；一题课通常只有一个
任务。只有同一槽位的检索入口确实不明确时，Coach 才可为该槽位增加第二个不同
搜索起点，并在任务中写明第二个入口要解决的具体不确定性；不能把固定三路
fan-out 当成惯例。搜索起点只是 `graph-first` 或 `card-text-first` 的工作提示，
不允许 Scout 在完成自己的槽位后转而扫完整个专题。

原来的 `teaching-fit-first` lane 被删除。教学适配不是第三份题库搜索：Plan Coach
已经读取了学生对话、当前 Plan 和所有已关闭 Lesson，应由它把真正影响选材的
偏好、已用材料和排除条件压进各槽位简报，再对候选前沿作最终判断。

槽位只负责划分检索工作，不成为 Lesson 的新对象。最终 Lesson 仍然只保存现有
Block、Student View、Teacher Control 和 Classroom Log。

## 6. Scout 的候选前沿

Scout 不再返回“所有相关题卡”，而返回候选前沿。候选只有满足以下任一条件时
才值得保留：

- 填补了该槽位尚未满足的硬条件；
- 使用了实质不同的方法结构或题目外壳；
- 在来源陌生度、工作量或教学观察价值上形成真实取舍；
- 可作为首选核验失败后的有效替代。

如果一张新题卡与现有候选同族、教学用途相同，而且在适配性、来源或工作量上
没有任何优势，它是被支配候选，不进入结果。已知违反排除条件、明显过重或与
槽位不符的题卡也不进入 `candidates`；Scout 只在 `search_boundary` 中概括这些
已排除的家族，不为证明完整性逐张列出。

### 收敛判断

Scout 找到第一张合格候选后，应先提出一个内部问题：

> 当前还存在什么具体不确定性，足以改变 Coach 对这个槽位的选择？

只有能回答出具体不确定性时才继续搜索，例如“当前只有经典真题，需要找一道
非名题来源”或“当前候选都走同一路线，需要确认是否存在另一种外壳”。如果后续
搜索只产生同族替代品，或者不存在会改变选择的未决问题，立即结束。

这仍然是语义收敛，不是固定候选数，也不是计时截止。它把收敛对象从“专题是否
查全”改成“本次教学选择是否已经充分”。

## 7. Scout 的读取边界与输出

Scout 可以读取图谱、题卡题面、必要的元数据和任务点名的 Plan/Lesson。它不负责
把每个候选的完整答案全部核验一遍，也不为排除同族题而通读整个专题。数学正确
性和最终适配性由 Coach 对入选题卡完成完整读取后判断。

每个 Scout 返回一个无代码围栏的 JSON 对象：

```json
{
  "slot": "slot-A",
  "candidates": [
    {
      "asset_path": "cards/derivative/example.card.yaml",
      "asset_kind": "problem-card",
      "source": "2024 某校月考 T7",
      "fit": "能暴露是否先识别平移关系再设切点",
      "distinction": "与当前首选相比，来源更陌生但计算稍长",
      "risks": ["若学生熟悉平移曲线结论，诊断会变得过轻"]
    }
  ],
  "search_boundary": "已覆盖平移型公切线及一个非平移对照；继续命中均为同族题"
}
```

`candidates` 长度可变，但只包含前沿成员。输出不得包含完整题面、完整答案、决定性
变形、搜索流水账、被排除题卡清单或软件验收报告。

## 8. Coach 调用与选择流程

Coach 的备课流程改为：

```text
读取 Plan 和已关闭 Lesson
→ 与学生商定本节 Lesson 的活动结构
→ 已有明确且无需比较的素材路径：Coach 直接读取，不启动 Scout
→ 把需要独立素材的 Blocks 转成临时槽位
→ 每个槽位启动一个 fresh Scout，并行执行
→ 合并结果并按 asset_path 去重
→ 为每个槽位选一张当前首选
→ 完整读取并核验这些首选题卡
→ 写 Lesson、回读 Lesson、链接并回读 Plan
→ 只发送公开备课摘要
```

并行任务继续使用 `context: "fresh"`、`async: false`、
`includeProgress: false`、`artifacts: false` 和 `agentScope: "user"`，不设置
`timeoutMs` 或 `maxRuntimeMs`。任务数量等于本轮需要检索的素材槽位数量，而不是
固定三项；`concurrency: 3` 只是并发上限，更多槽位可以排队，不改变槽位语义。

每个任务显式关闭与只读检索无关的通用验收门：

```json
{
  "agent": "study-material-scout",
  "task": "slot=slot-A; ...",
  "acceptance": {
    "level": "none",
    "reason": "read-only candidate recall"
  }
}
```

这样 Pi 不再向 Scout 注入 `acceptance-report`。顶层调用仍保持现有七个字段；每个
task item 从 `agent + task` 变为 `agent + task + acceptance`。

如果同一路径出现在多个槽位，Coach 必须判断它是否真的能承担多个不同活动；
需要不同题目的槽位不能因去重而静默缩减。Coach 只完整读取每个槽位的当前首选。
若首选在完整核验时发现来源、数学或教学适配问题，可以从已经返回的候选前沿中
读取下一张，不重新启动整轮搜索。当前沿全部失效时，本轮不生成 Lesson，并用
普通语言告诉学生材料条件暂时不匹配。

## 9. 思考等级

首轮实现保持 `thinking: medium`，以便只验证职责分割和收敛契约这一个假设。
如果真实复测仍显示单个槽位存在冗长推理，再单独比较 `medium` 与 `low`。不得把
降低思考等级与本次契约修改捆绑，否则无法判断速度改善来自哪里、教学召回是否
受损。

## 10. 学生可见行为

学生仍只看到一个折叠的原生 subagent 活动和最终公开备课摘要。Coach 不播报
槽位、候选、搜索进度、失败卡片或内部比较。公开摘要仍可说明本节目的、来源或
题号、活动数量、工作量与互动方式，但不得提前给出决定性路线和答案。

本设计不增加安全投影。信息边界仍由 Agent/Skill 的公开与私有写作纪律实现。

## 11. 失败处理

- 一个槽位 Scout 失败，只影响该槽位；其他槽位结果仍可保留。
- 缺少任何已商定素材时，不得悄悄把多题课缩成少题课。
- 不自动重跑整个 fan-out，也不让父 Plan 回退为全库批量搜索。
- 候选首选核验失败时，优先读取同一前沿中的下一项。
- 所有前沿候选失效时，不创建 Lesson；下一轮只有在公开教学条件改变后才重新找。

## 12. 验证方法

机械验证只检查：

- Plan 仍是唯一拥有 `subagent` 的节点；
- Scout 仍只有 `read`、`grep`、`find` 和 `ls`；
- Agent、Coach Skill 和仓库说明使用一致的槽位调用契约；
- 现有类型检查、单元测试、构建和浏览器闭环继续通过。

Skill 文本不增加逐句断言测试。行为验收使用一个新 Plan Session 准备一节两题
真实课程，并与本轮基线比较：

- 是否按两个教学槽位启动任务，而不是固定三路扫描同一请求；
- 是否完全没有 `Acceptance Contract` 或 `acceptance-report`；
- 是否停止逐张枚举同族题卡；
- 是否只向 Coach 返回候选前沿；
- Coach 是否仍能选出两张真实、数学正确、教学用途不同的题卡；
- 是否保持多题数量、不剧透，并完成 Lesson/Plan 写回；
- 记录 wall time、assistant turns、工具调用、题卡读取、跨 Scout 重复读取和结果
  体积，与 142 turns、287 calls、168 reads 的基线对照。

性能验收不设置运行时强制截止。成功标准是结构性减少重复工作，同时维持或提高
最终选材质量；若仍慢，再依据新的 Session 证据决定是否降低 thinking 或引入
紧凑目录，而不是预先增加防御性机制。
