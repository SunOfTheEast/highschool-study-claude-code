# M1b 语义驱动的学习集生长设计

状态：已确认，待分阶段实施

日期：2026-08-07

## 一、M1b 解决的不是“怎么多生成几张卡”

M1a 已经让 StudyForge 能够在正式课堂结束后，根据真实 Classroom Log 更新教师可召回的
对象记忆与明确偏好，并为后续能力判断保留来源。M1b 继续回答另一个更基础的问题：一个学习集如何从几乎空白
的载体，逐渐长成学生真正使用过、理解过并能再次回到其中的学习环境。

学习集可能从三种地方出生：

1. 学生投入一本书、PDF、讲义或零散资料，系统随着真实学习需要逐步蒸馏；
2. 学生没有现成资料，只是在与教师讨论问题，讨论中逐渐形成题卡与 Note；
3. 学生复用他人公开的学习资产，但自己的课堂、作答、笔记与记忆从空白开始。

因此 M1b 不是“课程树初始化”，也不是“卡片生产流水线”。课程、原始资料、学习资产、
活动和教师记忆都只是学习集可能长出的部分。学习集本身只是承载这些事实的容器。

## 二、首要原则：只对象化必须拥有事实的东西

M1b 的关键设计不是建立一套更复杂的知识对象，而是避免过早对象化。

题卡、Note、课堂、原始作答和对象记忆必须有稳定身份，因为它们需要持久化、修订、授权、
引用和追溯。Flashcard 不是第三种顶层资产，而是 Note 中可以隐藏答案、主动翻面的回忆块。
相比之下，“导数”“绝对值”“三次函数”“极值点偏移”
“沉淀溶解平衡”“阿伦尼乌斯方程”“硫元素的性质”本身已经是含有语义的词语。它们
无需先被塞进 goal、method、structure 或预先规定的知识本体，便能同时服务于：

- 人类阅读与讨论；
- 模型联想和扩展；
- 字面检索；
- 资产召回；
- 图谱聚合与邻居发现；
- 数学、化学和其他学科的自然扩展。

整套设计遵守以下原则：

1. **一个事实，一个持久所有者。** 其他读者需要的形状使用投影，不复制真相。
2. **语义词语优先。** 平坦、人类可读的标签是跨资产与记忆的共同连接层。
3. **显式关系与派生关系分开。** 内容确实依赖某题时保存来源边；语义相近只形成可重建
   邻居。
4. **历史事实只追加，当前资产可修订。** 原生 Session、作答、课堂 Log 与对象 Learning
   History 不回写；Note、题卡内容和当前标签可以产生新 revision。旧活动继续引用当时看到的 revision。
5. **关系图是投影。** 图谱、邻居和召回索引都能从资产、记忆与标签重建，不成为第五份
   canonical truth。
6. **相关不等于掌握。** 共享标签只说明语义相关；学生学到哪里仍由有来源的教师判断
   表达。

## 三、总体分层

学生看到的是一个统一的学习集，内部则保持四类不同所有权：

| 层 | 持有的事实 | 典型内容 |
| --- | --- | --- |
| 原始资料 | 外部来源原貌与位置 | PDF、书籍、图片、讲义 |
| 学习资产 | 当前学习集中可继续阅读、修改、练习和引用的内容 | 题卡、Note、材料 |
| 学习活动 | 这个学生真实经历了什么 | 原生 Pi Session、正式课堂 Log、作答、答案查看 |
| 教师记忆 | 教师当前怎样理解学生及其认知流变 | 对象记忆、能力假设、明确偏好 |

索引、标签邻居和知识图谱是以上各层的读者投影，不单独拥有教学事实。题卡也只有一个
canonical 对象；Tutor、Scout 与学生看到不同字段，不因此产生“教师题卡”和“个人题卡”。

学生界面不要求学生理解这些层次。学生只需要做自然动作：问老师、上传资料、保存为笔记、
保存为闪卡、保存一道题、重新作答或回看过去。

## 四、Session 层级

学习集不是节点。长期课程从学习集里产生，需要一层真正的 Meta Session 负责商议。

~~~text
学习集
├── Meta Session             商议并创建 Roadmap
├── Roadmap Session          商议并创建下一个 Plan
├── Plan Session             商议并准备下一节 Lesson
├── Lesson Session           正式授课
└── 自由学习 Session         不绑定 Plan 的开放讨论（内部作用域可沿用 light-lesson）
~~~

每一层只设计自己的直接子层：

~~~text
Meta       → Roadmap
Roadmap    → Plan
Plan       → Lesson；备课中采用的自编题可在 Lesson 完成后按 7.3 确认保存
Lesson     → 课堂事实、学习资产与课末记忆
自由学习  → 学习资产与可在对话中随时形成的教师记忆
~~~

### 4.1 Meta Session

Meta Session 绑定学习集根作用域，而不是伪装成 LEARNING_GUIDE.md 节点。Pi Session 保存
商议过程，确认后的设计才进入 ROADMAP.md。

它负责：

- 听学生为什么建立学习集；
- 讨论长周期希望发生的能力变化和总体学法；
- 只在影响长期路线且谈话不足时做轻量诊断；
- 公开 Roadmap 提案；
- 等待学生明确确认；
- 使用窄结构化写入原子创建 ROADMAP.md。

它不创建首个 Plan、不搜题、不备课，也不把一次临时提问扩张成长期目标。ROADMAP.md
创建后，独立的 Roadmap Session 才讨论第一个 Plan。

当前 roadmap-dialogue 中“初次 Roadmap 会面”与“首个 Plan”混在同一 Session 的部分，
在 M1b.2 拆开：长期方向诊断进入 Meta，Roadmap 的空 Plan Tree 分支只制定首个 Plan。

### 4.2 自由学习 Session

自由学习是学习集首页上的固定入口。它可以无上下文开始，也可以由学生从资产界面选择若干
题卡、Note 或希望建立的联系后开始；允许多个线程并存。它复用 Tutor、教学核心和教学
技巧，但没有 Plan 父级，也没有预先规定的课堂目标，默认允许发散讨论。

原生 Pi Session 是自由学习中实际对话的唯一事实来源。Runtime 只需保存能够恢复该原生
Session 的身份、当前选择的上下文与生命周期；不得把同一对话再复制成自由学习
Markdown Log、Consolidated Trace 或强制 Session Summary。内部作用域名称可以沿用
`light-lesson`，但学生界面统一称为“自由学习”。

它明确没有：

- Plan 父级与课程树挂载；
- Lesson Goal；
- Blocks；
- Teacher Control；
- Classroom Log、Consolidated Trace 或课末记忆结算；
- 备课状态和 Plan 进度。

它可以用于开放讨论、重新打开题卡、概念联想、短诊断或让教师讲一道题。时长、是否形成
资产、是否发生教学都不改变 Session 类型；只有学生另行发起课程规划，才进入 Meta、
Roadmap、Plan 与 Lesson 生命周期。

自由学习不直接加载现有 block-based tutor-lesson 根 Skill。它使用独立的
tutor-light-lesson 路由 Skill，复用同一 Tutor 角色、教学核心和七个教学技巧 reference，
但只保留自由讨论、按需上下文、资产保存、记忆判断与显式结束的边界。正式 Lesson 继续只加载
tutor-lesson。这样模型不会同时受到“寻找 active Block”和“本 Session 没有 Block”两组
冲突指令，也不需要为两种课堂维护两份讲解技巧。

## 五、M1b 分阶段实施

统一设计分为四个独立验收闭环：

### M1b.1：学习集从空白生长

- 没有 ROADMAP.md 也能打开学习集；
- 开启自由学习 Session；
- 保存 Note 与题卡；Note 中可以包含可主动翻面的回忆块；
- 记录题卡作答与答案查看；
- 建立平坦标签和派生邻居图；
- 关键结论、认知转变或对象边界变化发生时即可更新 M1a 对象记忆；
- 学生重新打开资产并带着新作答再次问老师。

### M1b.2：Meta Session 让课程结构诞生

- 从学习集根开启 Meta Session；
- 商议并确认 Roadmap；
- Meta 只创建 ROADMAP.md；
- Roadmap Session 再商议首个 Plan；
- 清除现有首次 Roadmap 与首个 Plan 的职责重叠。

### M1b.3：原始资料逐步长成资产

- 上传并保留原始资料；
- 根据真实学习需要逐段蒸馏；
- 生成带来源的题卡、Note 与标签；
- 不要求一次性处理完整本书。

### M1b.4：复用、导入与分享

- 导入他人的可复用资产与词表；
- 不导入对方的作答、课堂或记忆；
- 分享同一资产的安全投影，不把学生笔记、活动和教师记忆一起发布；
- 图谱和召回索引在本地重建。

第一份实施计划只落地 M1b.1。后三个阶段在同一架构下分别设计实施计划，不把独立系统
一次绑死。

## 六、真正空白的学习集

当前 Runtime 把 ROADMAP.md 当成学习集存在的证明，NodeKind 也只有 roadmap、plan 和
lesson。这阻止了一个没有课程树的学习集工作。

M1b 将“根目录识别”和“课程是否存在”拆开：

- LEARNING_GUIDE.md 继续作为现有学习集根标志和教学契约资源；
- ROADMAP.md 变为可选教学事实；
- LEARNING_GUIDE.md 不是 Session 所有者；
- 学习资产、特征词表和原始资料目录都在第一次真实写入时懒创建；
- .studyforge 仍只保存 Runtime 状态，不承担教学语义。

M1b.1 中最小学习集可以只有：

~~~text
LEARNING_GUIDE.md
memory/
  INDEX.md
~~~

M1b.1 只显示已经实现的“问老师”“我的学习资料”和“最近的轻量课”。M1b.2 完成后再增加
“规划一下怎么学”的 Meta 入口。已有 ROADMAP.md 的学习集继续显示现有课程区域。

## 七、学习资产及其边界

M1b 需要新增定义的两种核心交互资产是：**Note** 与**题卡**。它们都是当前学习集
内可继续阅读、编辑、练习、引用和导出的内容；不再按“教师/个人”拆成两套对象，也不把
Flashcard 建成第三种顶层资产。

建议持久位置为：

~~~text
notes/
cards/
~~~

实际物理路径在实施时可以为兼容旧学习集调整，但以下语义所有权不得变化。

### 7.1 Note：正文与回忆块共享一个对象

Note 持有：

- 标题；
- 有顺序的内容块：普通 Markdown 文本块，或具有 prompt / answer 的回忆块；
- core 与 related 标签；
- 零个、一个或多个 based_on 来源引用；
- Runtime 绑定的学习集、稳定 ID、创建来源、时间、revision 与 provenance。

前端的“保存为笔记”和“保存为闪卡”仍然是两个自然动作，但都创建或更新 Note：

- “保存为笔记”通常生成可直接阅读的正文块；
- “保存为闪卡”通常生成隐藏答案、可主动翻面的回忆块；
- 一个 Note 可以混合解释正文与多个回忆块；
- 只有一个回忆块的 Note 在交互上就是一张 Flashcard。

若未来确实引入间隔重复，复习事件可以绑定稳定回忆块 ID；M1b 不预先引入 SM-2、掌握
等级、排程状态或独立 Flashcard 对象。Note 也不持有掌握判断、能力结论或教师画像。

### 7.2 题卡：一个对象，多种读者投影

一张题卡拥有完整题目事实：

- 题干；
- 学生作答后可以查看的标准答案或规范书面解答；
- 不直接投影给学生的教师讲解依据；
- core 与 related 特征标签；
- 学生自己的笔记；
- 原始资料、已有资产、备课或课堂来源；
- 稳定 ID、revision 与 Runtime provenance。

题卡只有一个 canonical 对象。读者权限决定投影：

- 学生看到题干、自己的笔记，以及满足答案门后可见的标准答案；
- Tutor 在教学需要时读取完整题卡；
- Scout 只获得可复用、无学生隐私的检索投影，不读取学生笔记、作答或教师记忆；
- 分享或导出同样使用安全投影，不因此制造第二张“公开题卡”。

教师讲解依据只保存对该题可复用的学科或教学信息。学生当时的具体错误、实际帮助与后续
表现继续属于来源 Session 或正式 Classroom Log，以及由此更新的对象记忆，不提升成题卡正文。现有
`highschool-study.problem-card.v1` 完整题卡继续受支持；新题可以使用更薄的兼容形状，
不要求模型当场填写约 9 KB 的完整教学卡字段。两种形状仍是同一种题卡语义，不是教师题卡
与个人题卡。

### 7.3 题卡的合法生成路径

题卡可以从不同教学来源产生，但最终都落成同一种对象。

**Plan 备课中的自编题：**

1. Coach 与学生先完成本节 Lesson 的讨论和备课；
2. 若备课采用自编题，Coach 在备课完成后向学生说明；
3. 学生明确确认保存后，题卡才持久化并与本 Lesson 建立准确来源关系；
4. 学生允许课堂使用但不愿保存时，题目保留为 Lesson 内联内容，不创建题卡；
5. 学生否定题目本身时，Coach 回到 Lesson 设计，而不是绕过学生保存。

Plan 生成题卡只表示教学材料已经准备，没有学生学习事实，因此不生成对象记忆或
能力判断。Worker 可以协助起草，最终学科与教学判断仍由 Coach 承担。

**Lesson 或自由学习中形成的题卡：**

- 可以来自学生拿来的一道题、教师现场自编/改编的题，或真实教学中形成的稳定题目；
- 不规定必须在进入课堂、讲解结束或收口前的某个固定时刻提出保存；
- 学生明确确认后可以在教学过程中任意合理时点写入；
- 一旦本次教学已经承诺保存题卡，Session 不得在写入成功并取得回执前虚假关闭；
- 题卡来源必须指回当前 Lesson / 自由学习 Session、原始题目或必要的已有资产；
- 正式 Lesson 的教学事实继续进入 Classroom Log；自由学习的真实过程由原生 Pi Session
  持有。二者只有在真实表现改变教师判断时才更新对象记忆，资产保存本身不触发记忆。

“内容值得以后反复使用”不是可执行门槛，也不要求 Tutor 对每次未入库问题都机械提问。
题卡是否保存来自眼前教学需要、师生自然提议与学生确认；设计只约束最终事实，不规定僵硬
话术和时机。

### 7.4 自由学习不是“造卡 Session”

自由学习的定义只有一个：学生从固定入口进入一个没有 Plan 承诺、没有预设目标的开放
Tutor 对话。它可以从空白开始，也可以带入一道新题、旧题卡、Note 或若干希望建立联系的
资产；可以短暂答疑，也可以持续较长时间发散讨论。时长、是否涉及题目、最后有没有资产，
都不改变它的类型。

- 重开已有题卡时通常只记录新作答和教学，不重复建卡；
- 概念讨论可以形成 Note，也可以什么资产都不形成；
- 新的未入库题目可以在确认后形成题卡；
- 一次教学也可以同时形成题卡与 Note，但不能把产物数量当作学习效果。

### 7.5 资产形态由未来怎样使用决定

原始资料、教师自编内容、学生自己的表达、师生共同讨论和导入资产都可能成为内容来源；
Session 负责确定当前责任者、来源、批准与证据边界，不把内容类型钉死。最终形态看学生以后
要怎样与它互动：

- 需要反复阅读、修改、补充和连接想法时，形成 Note 的正文块；
- 需要遮住答案主动回忆时，形成 Note 的回忆块；
- 需要独立作答、经过答案门、保留作答历史或随时“问老师”时，形成题卡；
- 同一次学习可以形成题卡、Note 正文和回忆块的组合，也可以不形成任何固定资产。

这一区分服务真实交互和前端渲染，不是为每种产物创建一套 Session 或记忆系统。

## 八、明确来源与派生邻居

Note 或题卡可以独立形成，也可以依赖一个或多个来源。唯一持久的来源方向是：

~~~text
Note / 题卡 ── based_on ──→ 原始资料或已有学习资产
~~~

`based_on` 为空表示独立内容；一个引用表示从一个来源提炼或改编；多个引用表示比较、归纳
或组合多个来源。反向的“某题有哪些 Note”“某资料派生了哪些题”由索引生成，不在来源
对象内双写。

Runtime 绑定的 `created_in` 与 `based_on` 是不同事实：前者说明资产在哪次工作或教学中
产生，后者说明内容依赖什么。Note 和题卡自己持有标签，不自动继承来源的全部标签。只有
内容确实依赖某来源时才写 `based_on`；语义相近只通过标签形成派生邻居。

Note 若来自当前讨论中的临时题，只有在学生也确认保存该题时才建立稳定题卡引用；否则
Note 保持独立，或保留当前已有的来源片段/Session 引用，不能为了让 Schema 看起来完整而
偷偷创建题卡。

### 8.1 原始资料蒸馏的责任边界

Tutor 或 Plan Coach 根据当前教学问题决定需要读取什么、希望形成什么教学输出；有界 Worker
承担耗上下文的来源阅读、定位、切片和草稿生成。Worker 不自行决定什么值得教，也不直接
提交题卡或 Note。当前负责的 Tutor / Coach 必须阅读必要来源并核验草稿的学科正确性、教学
作用和来源边界，之后再走对应 Session 的正常确认与写入流程。

Worker 返回草稿不会自动生成隐藏的“教师题卡”。Plan 中的草拟题可以保持 Lesson 内联内容；
只有满足 7.3 的说明与确认后才成为题卡。原始资料也不要求一次性完整蒸馏，而是随真实问题
和备课需求逐步生长。

## 九、平坦特征标签

新资产只使用两个相对于该资产的权重层次：

- core：没有这些标签便难以说明资产的主要内容；
- related：确实相关，但不是资产主要辨识特征。

一个资产可以有多个 core，不要求唯一 primary。标签不再被强迫归入 goal、method、
structure，也不要求保留旧 BKT 所需的 primary、secondary 或 subroute 挂载点。

Tutor 提供人类可读的标签。Runtime：

- 解析已知别名；
- 阻止同一标签在 core 与 related 中重复；
- 为 Tutor 明确提出的新词建立稳定身份；
- 维护动态 features/vocabulary.yaml；
- 不根据正文自行发明语义标签。

现有冻结的 graph/vocabulary.yaml 与 519 张旧题卡保持不动。兼容投影把旧卡的
goal.primary、分问 goal、method.primary、method.secondary、method.subroute、
structure.primary 与 structure.secondary 全部拍平成标签；不延续当前 recall index 漏掉
method.subroute 的行为。各轴 primary 与分问 goal 投影为 core，secondary 与 subroute
投影为 related；重复词去重，源文件不回写。新旧词表在查询视图中合并。

对象记忆使用一个平坦的 about_tags 列表连接同一词表，不再区分 core 与 related。标签由
Tutor 在新建对象或本次证据确实改变对象语义边界时，通过记忆提交明确给出；Runtime 只做
别名解析和稳定引用。既有 M1a 对象允许暂时没有 about_tags，不根据标题或相邻资产
自动补标签；它们在后续真实课堂再次更新时逐步进入图谱。第一次带标签的资产或对象写入时
创建 features/vocabulary.yaml。

## 十、语义关系图

第一阶段图谱的显式节点包括：

- 标签；
- 学习资产；
- 对象记忆。

显式持久边只有：

- 资产具有 core 标签；
- 资产具有 related 标签；
- 对象记忆讨论哪些标签；
- Note / 题卡 based_on 哪些来源。

以下关系全部派生：

- 标签共现邻居；
- 共享标签的相似资产；
- 题卡的反向 Note 与来源的反向派生资产；
- 对象记忆可能关联的学习资产；
- 不同学习资产之间的语义邻居。

core 共现可以比 related 共现具有更高召回权重；高频、低区分度词可在排名时降权。这些
分数只影响投影排序，不进入资产正文。

模型召回走短路线：

~~~text
精确标签组合
→ 数量不足时扩展一跳标签邻居
→ 达到调用者要求的数量后停止
~~~

这延续现有 Scout 的“找到所需数量的合格项即可”原则，不为寻找全局最优遍历题库。

共现不自动升级为先修、因果、对照或易混淆。若未来教学行为确实依赖这些关系，再由教师
确认后保存为单独的语义边。学生与标签相关也不生成“掌握”边；对象记忆继续持有有来源的
自然语言判断。

M1b.1 使用可由 read/grep 读取的薄索引和 tag-neighbors 投影，不新增 recall 工具，也不
引入图数据库。

## 十一、分读者索引与渐进式披露

共享标签语义不意味着把所有字段放进同一索引。系统保留三个不同读者入口：

1. `memory/INDEX.md`：教师记忆的常驻导航，只放认知前沿、明确偏好和对象入口；
2. 教学检索索引：材料与题卡的可复用安全投影，供 Scout、Coach 与获准的 Tutor 使用；
3. 学生资产索引：Note 与题卡的学生投影，供学生界面与当前 Tutor 使用。

同一张题卡可以同时出现在教学检索索引和学生资产索引中，但两者都只是对同一 canonical
题卡的不同投影。Scout 不接触学生笔记、作答或教师记忆；学生索引不包含教师讲解依据。
需要跨层联想时，Runtime 根据当前读者权限临时连接，不持久化一份混合私有内容的总表。

Session 上下文按以下顺序披露：

~~~text
当前 Session 身份与明确选择的上下文
→ 当前绑定资产
→ 常驻 memory/INDEX.md
→ 眼前教学动作确实需要时，才沿标签或记忆链接下钻
~~~

资产索引不常驻模型上下文。从题卡进入自由学习时，只注入当前题卡的 Tutor 允许视图、
最近作答和答案查看状态；从自由讨论进入时不预先搜索整个学习集。

正式 Lesson 的读取再遵守一条边界：`Uses` 只记录备课时明确绑定的计划内资产。课堂中若
学生主动带入某资产，或当前表现触发 Tutor 沿紧凑资产索引召回少量相关内容，Tutor 可以
按需读取并使用，不要求学生知道文件名，也不需要每次另行批准。它不修改 Lesson 目标，
不把临时召回内容补写进 `Uses`，只把真实使用以稳定引用追加到 Classroom Log。Tutor 不得
以此为由浏览整个资产目录。

## 十二、两个窄语义写入

Tutor 不使用原生 write/edit 猜 ID、路径和引用，也不获得一个字段庞杂的通用资产 CRUD。
M1b.1 提供两个窄动作：

- save_note；
- save_problem_card。

`save_note` 接受由普通正文块和回忆块组成的最终 Note；“保存为闪卡”只是前端或教师语言
选择回忆块的便捷入口，不再有 `save_flashcard`。`save_problem_card` 保存唯一的题卡对象。

语义动作由当前对资产负责的角色调用，不由资产类型反推 Session。本阶段已经确认的入口是：

- Lesson / 自由学习 Tutor 可以在学生确认后保存 Note 或题卡；
- Plan Coach 可以在备课完成、说明自编题并取得学生确认后保存题卡；
- 学生在资产页直接编辑 Note 或题卡笔记时，使用同一 Runtime 写入核心，不唤醒 Tutor；
- Scout、Reviewer 与 Worker 只承担从属的读取、召回、核验或起草任务，不能直接提交最终
  学习资产；Meta / Roadmap 当前没有已经确认的资产生成需求，不为它们预造第三套工具。

如果未来在其他 Session 中出现真实的资产生成需求，应复用同一 Note / 题卡类型、确认原则
与 Runtime 写入核心，再单独裁决该 Session 的责任边界；不能据此发明新的资产种类。

模型负责不可约语义：

- Note 的正文/回忆块，或题卡的题干、标准答案与教师讲解依据；
- core / related 标签；
- 无法从当前绑定推断的 based_on 短别名；
- 学生个人笔记。

Runtime 负责：

- 学习集、学生、责任 Session 和当前资产绑定；
- 稳定 ID、路径、时间、revision 与 provenance；
- 已知标签别名和短资产别名解析；
- 来源引用与读者隔离校验；
- 多文件原子事务；
- 同一 toolCallId 的幂等；
- 成功回执与投影重建。

现有 lesson_memory_commit 在 M1b.1 扩展对象的 about_tags 语义输入。正式 Lesson 与
自由学习共用这一字段；模型只提交标签词语，不提交图节点 ID 或边。没有新对象判断的
课堂不为图谱完整性强行更新对象。

Note 的 Skill 负责不可约的内容设计：从当前来源或讨论提炼什么、正文与回忆块如何组合、
回忆问题和答案的边界、哪些解释应始终可见，以及必要的标签和来源。Tool 只接收最终内容
形状；Runtime 不替模型生成 Note 语义，也不接受 mastery、profile、schedule 或 SRS 字段。

批准不使用脱离情境的统一话术。Plan 自编题遵守 7.3 的备课后说明与确认；教学中形成的
Note/题卡由师生自然提议，学生明确确认后保存；学生在资产页主动点击保存本身就是确认。
共同不变量是：

~~~text
形成明确的拟保存内容
→ 责任角色让学生知道要保存什么
→ 学生明确确认或主动执行保存
→ 调用一个窄写入动作
→ 成功后才说已经保存
~~~

“嗯、可以、存一下”可以构成确认；沉默、继续做题或离开页面不能推断为批准。

学生在资产页直接编辑 Note 或题卡笔记时，由当前资产绑定的 Runtime API 处理，不唤醒
Tutor，也不要求模型填写路径。

## 十三、题卡交互记录

重新打开题卡并不自动启动自由学习，也不把历次作答追加进题卡正文。原始交互由独立、
只追加的记录持有，建议位置为：

~~~text
activity/problem-attempts/<problem-card-id>.md
~~~

它记录：

- 稳定事件 ID；
- 题卡稳定 ID 与当时 revision；
- 学生实际提交的内容，或明确选择“不会”；
- Runtime 时间；
- 标准答案在这次作答之前是否已经查看；

Runtime 不写对错、掌握、能力、偏好或教学结论。答案查看本身也不是学习效果证据。

学生可以：

~~~text
打开题卡
→ 查看题干与自己的笔记
→ 提交作答，或明确选择“不会，直接看答案”
→ Runtime 追加原始事件
→ 查看标准答案
→ 直接离开，或点击“问老师”
~~~

点击“问老师”时，新建或恢复一个带该资产上下文的自由学习 Session，只提供当前题卡的
Tutor 投影、最近作答和答案查看状态。原始作答事件保持不变；新 Session 的启动上下文可以
引用它，但不能回写旧事件、预填“随后开启的对话”这种未来信息。Tutor 只有在后续真实
表现改变了教师判断时才更新对象记忆。

没有进入 Tutor 的作答仍被保留，但只是原始学习痕迹，不自动升级为长期认知判断。

## 十四、自由学习的原生对话、记忆与结束

自由学习不复用 `classroom_log_append`。正式 Lesson 需要 Classroom Log，是因为 Log 同时
服务 active Block 推进、课后复盘与课程生命周期；自由学习没有 Blocks，原生 Pi Session
已经完整、只追加地保存实际对话，因此不再复制一份 Markdown Log，也不建立 Trace。

对象记忆可以在自由学习进行中随时形成，不等待 Session 结束。唯一触发门是：

> 如果没有本次对话，未来教师对“学生现在怎样理解这个知识对象、学到哪里、边界在哪里”
> 的判断是否会不同？

会不同才写；不会不同则只保留在原生 Session。可写入的变化包括首次独立完成、暴露新的
误解或过拟合、提示依赖发生变化、旧判断被推翻、长间隔后的保持或退化，也包括学生得出
关键结论、建立重要联系或发生认知框架转变。关键结论至少要在学生的重新表达、推导、比较
或使用中出现；教师讲了一遍、学生只说“懂了”，不构成认知转变。

一次自由学习记忆更新遵守：

~~~text
真实对话产生判断变化
→ Tutor 静默提交对象目标、Learning History 变化和确实变化的快照字段
→ Runtime 绑定来源 Session 与写入时间
→ Learning History 只追加
→ Current Judgment / Evolution Overview / Boundaries 只局部更新实际变化的部分
→ 对话继续
~~~

Tutor 不填写 Session ID、时间、路径或消息 ID。对象记忆只引用整个来源 Session，不绑定
特定轮次；需要核查时从紧凑记忆下钻完整原生对话。自然语言如实说明关键结论是学生独立
得出、提示后形成还是师生共同形成，以及尚未检验的边界，不为此增加等级枚举。偏好只有
学生明确表达时才写。

Note 与记忆保持独立：

- Note 保存学生以后可以继续阅读、编辑和主动回忆的当前内容；
- 学生独立提出 Note 的核心关系，可能同时构成对象记忆证据；
- 师生共同形成时，对象 Learning History 应如实写明教师帮助；
- 教师写好、学生只选择保存时，只证明内容被保留，不证明学生理解；
- 学生在 Session 外直接编辑 Note，只产生新 revision，不自动唤醒 Tutor 或修改对象记忆。

学生显式结束只控制自由学习 Session 的生命周期，不触发强制记忆结算或强制 Summary。
学生未结束时 Session 保持可恢复，也不阻塞另开线程；Runtime 不以超时、离开页面或沉默
推断“已经学完”。结束操作使用 harness 原生、可重试的 Session 生命周期，不与正式 Lesson
的课末记忆事务绑在一起。

## 十五、对象记忆的读者边界

对象记忆的首要读者是未来的 Tutor、Coach 和 Roadmap。它不是为学生界面编写的学习报告。

它可以保存：

- Current Judgment；
- Evolution Overview；
- Boundaries / Not Yet Demonstrated；
- 带时间和来源 Session 的 Learning History；
- 暂定能力信号和需要未来证据检验的教师假设。

这些内容继续独立存在，因为它们服务于下一次教学判断。学生有权回看来时路，但不直接读取
教师内部 Markdown。

学生的“学习足迹”从学生安全来源派生：

- 正式 Lesson Summary；
- 自由学习原生 Session 的学生安全视图；
- 学生自己的作答；
- 保存或修改的学习资产；
- 时间、标签与来源 Session。

对象记忆只帮助系统把这些来源路由到同一条认知流变。每一项学生足迹都能回到真实课堂、
作答或资产，而不是展示脱离证据的能力标签。

学生直接问“我最近进步在哪里”时，Tutor 可以读取对象记忆和来源，在对话中区分已证实
变化、暂定判断和仍待检验边界。这次解释不另存为第二份“学生版对象记忆”。

## 十六、可修改资产、不可改写经历、可重建图谱

纠错遵守三种不同生命周期：

1. Note、题卡正文、标签与 based_on 是当前资产，可以修正并增加 revision；
2. 原生 Pi Session、Classroom Log、原始作答和对象 Learning History 是历史事实，只追加
   新事实或纠正，不回写旧条目；
3. 召回索引、反向链接、邻居和知识图谱是投影，源事实变化后直接重建。

题卡修正时保持稳定 ID。每次成功改变内容都生成不可变 revision；当前视图默认打开最新
revision。旧作答、课堂引用和自由学习上下文保留当时的 source revision，不能用后来修正的答案
倒推学生当时的表现。

M1b.1 只提供归档，不提供破坏历史引用的硬删除。被引用资产归档后保持可追溯；学生默认
列表可以隐藏它，历史 Session 与事件仍能解析来源。

语义重复不由 Runtime 猜测。两份相近 Note 或题卡可以同时存在；只有同一 toolCallId 重试
被视为机械重复。读者投影永远不创建第二份题卡壳。

## 十七、原子性与派生失败

一次资产提交涉及的以下事实必须同一次成功或全部不发生：

- Note 或题卡正文；
- based_on 与 provenance；
- 新标签词条；
- 当前责任作用域的稳定链接（Teaching Session 的 Saved Assets，或 Plan 所备 Lesson 的来源绑定）。

任一真实引用不存在、越权、指向错误资产类型或发生 revision 冲突时，提交不留下孤立文件。
Tutor 只有收到成功回执后才能公开声称资产已保存。

召回索引和邻居图不属于 canonical transaction。若重建失败：

- 真实资产保持成功；
- 回执明确返回 projection stale；
- 当前对话使用回执中的稳定资产入口；
- 后续读取或维护任务可从 canonical 文件重新生成投影。

这种失败不允许模型用目录扫描猜测修复，也不允许为了索引完整回滚学生刚确认保存的内容。

学生同时打开多个自由学习 Session 是正常使用方式，不新增学习集级锁文档、协调 Agent、队列
协议或新的持久状态机。canonical 写入首先依靠 harness 原生 tool 调度、原子写入和 revision
冲突：两个 Session 修改同一资产时，过期 revision 被拒绝，不自动覆盖或语义合并；互不
相关的写入可以正常并行。只有真实端到端测试证明仍会丢更新，才允许在 Runtime 内加入最小
进程锁作为实现细节。索引或图谱投影失败不回滚已成功的 canonical 写入。

题卡保存和教师记忆也不合并成一个新型大事务：Plan 生成题卡只提交题卡及 Lesson 来源，
不生成记忆；正式 Lesson 继续按课堂过程与课末反思更新对象记忆，自由学习则在真实认知
变化出现时随时独立更新。若师生已经确认当前 Session 要保存题卡，结束前必须确认该写入
已有成功回执。

## 十八、M1b.1 学生体验

无 ROADMAP.md 时，学习集首页显示：

- 问老师；
- 我的学习资料；
- 最近的自由学习。

已有 Roadmap 时，现有课程区域继续存在，不把自由学习插入 Roadmap → Plan → Lesson
树。

自由学习允许学生直接输入自然问题，不要求先选知识点或填写目标。保存成功后，Note
或题卡以可点击资产卡片内联返回。

“我的学习资料”提供：

- Note 阅读与编辑；
- Note 内普通正文阅读，以及回忆块的隐藏答案/主动翻面；
- 题卡题干、自己的笔记和作答区；
- 作答或明确选择不会后查看标准答案；
- 从资产页带上下文“问老师”；
- 以类型、最近使用和标签浏览。

标签是学生可理解的导航词，不展示内部边类型、召回分数或教师记忆字段。

## 二十、M1b.1 验收

### 20.1 确定性测试

1. 只有 LEARNING_GUIDE.md 与 memory/INDEX.md 的学习集可以启动。
2. roadmap、plan、lesson 行为不回归，light-lesson 作用域与课程树隔离；两种 Tutor
   Session 只加载各自根 Skill，共享技巧文件而不共享冲突的 Block 路由。
3. 自由学习无 Plan 父级、无 Blocks；原生 Pi Session 保存对话，可保存资产，并能在对话中
   按真实认知变化更新对象记忆，不创建 Log、Trace 或强制 Summary。
4. 两个窄保存动作验证各自合法入口、明确确认、无效引用、原子失败和幂等重试；不存在
   独立 `save_flashcard`。
5. 学生投影不含教师讲解依据；Scout 只能读取题卡安全投影，不可读取学生笔记、活动与记忆。
6. Note 的零个、一个与多个 based_on 均可解析；反向边只由投影生成。
7. 旧题卡能拍平成 core/related 查询视图，新标签能动态加入词表。
8. 精确标签召回、单跳邻居和达到所需数量后停止均可重复验证。
9. 题卡作答、明确不会、答案查看、source revision 与自由学习 Session 的顺序引用正确；旧事件
   不含未来 Session 信息。
10. 对象记忆可在自由学习中途生成，来源绑定整个 Session 而非消息轮次；结束 Session 不
    强制生成记忆，未结束 Session 不被超时伪造为已完成。
11. 资产修订后索引可重建，旧事件仍指向当时 revision。
12. 故障注入证明 canonical transaction 无半套写入，projection 失败不丢资产；并发修改同一
   资产时 stale revision 被拒绝而不是静默覆盖。
13. Lesson `Uses` 只含计划绑定；课堂按需召回的少量资产只写入 Log，不反向污染 `Uses`。
14. Note 形成过程只有在原生 Session 或正式 Classroom Log 中出现了学生重新表达、推导、
    比较或使用时才影响对象记忆；Session 外编辑不自动生成认知判断。

### 20.2 前端闭环

~~~text
空白学习集
→ 从固定入口进入自由学习 Session
→ 确认保存 Note 与题卡
→ 关键结论或认知转变发生时即时形成对象记忆
→ 学生继续讨论并显式结束
→ 重启应用
→ 从“我的学习资料”打开题卡
→ 独立作答并查看标准答案
→ 带着本次作答再次问老师
→ 新自由学习 Session 获得正确上下文
~~~

页面必须同时证明：

- 未保存前没有资产；
- 成功回执后资产立即可达；
- 教师内容未泄漏；
- 未结束的自由学习 Session 可恢复；
- 自由学习 Session 不污染课程树；
- 标签邻居能找到相关内容但不展示“已掌握”。

### 20.3 真实模型验收

使用表达自然、不会主动说系统术语的学生情境。学生可以模糊地问一个具体问题，不主动要求
系统调用工具、创建标签或写记忆。验收最终结果：

- Tutor 没把普通问题扩张为 Roadmap 或 Plan；
- 没为了产资产打断教学；
- 没有把“值得反复使用”之类模糊标准写成机械保存门；
- 学生确认前没有写入；
- Note 与标签抓住了讨论要害；
- 二次自由学习正确使用原题、个人笔记、最近作答与相关对象记忆；
- 没把标签相关、看过答案或提示后完成说成掌握；
- 全程记录模型调用、工具调用和阶段耗时；
- 保存、索引和图谱构建都是本地机械工作，不触发 Scout 或额外模型检索。

### 20.4 回归基线

在现有导数学习集上回归：

- 课程树、正式课堂、M1a 记忆和旧题卡召回继续工作；
- 不要求改写 519 张卡；
- 新学习资产和自由学习 Session 可以与旧课程并存；
- 教师、学生和 Scout 三种投影继续遵守各自证据边界。

## 二十一、M1b.1 非目标

第一阶段明确不实现：

- Meta Session 与首个 Roadmap 的物化；
- 书籍/PDF 的自动蒸馏；
- 导入、发布、社区分享或权限市场；
- 独立 Flashcard 对象、间隔重复排程和记忆算法；
- BKT、掌握分数或统一能力等级；
- 图数据库、embedding 服务或新 recall 工具；
- 先修、因果、易混淆等持久语义边；
- 自动合并语义相近资产；
- 破坏引用的硬删除；
- 把自由学习 Session 中途转换为正式 Lesson。

这些边界不否认 M1b 的整体方向，只确保第一份实施计划能够以完整学生闭环验收。

## 二十二、最终决策摘要

1. 学习集是载体；Meta、Roadmap、Plan、Lesson 分别设计自己的直接子层。
2. M1b.1 先实现“空白 → 自由学习 → 学习资产与对象记忆 → 再使用”。
3. Note 与题卡是两种核心学习资产；Flashcard 是 Note 的回忆块体验，不是独立对象。
4. 一张题卡持有题干、答案、教师讲解依据、标签和学生笔记；学生、Tutor、Scout 与分享流程
   读取不同投影，不产生教师题卡/个人题卡两份真相。
5. 原始作答由独立追加记录持有，不塞进题卡，也不自动形成掌握判断。
6. core / related 平坦语义标签取代新资产中的 goal / method / structure 强制分类。
7. based_on 保存明确内容依赖；标签邻居表达派生相关。
8. 关系图与索引可重建，并按教师、学生、Scout 读者边界分开；同一资产可出现在多个投影。
9. `save_note` 与 `save_problem_card` 两个窄写入让模型负责语义，Runtime 负责身份、引用、
   revision、原子性和投影。
10. 自由学习从固定入口开启并允许多线程；原生 Pi Session 保存对话，学生显式结束只控制
    生命周期，对象记忆可在对话中的关键结论、认知转变或边界变化发生时即时更新。
11. 对象记忆首先服务教师判断；学生来时路从真实学生安全来源派生。
12. 当前资产可修订，历史经历不可改写，图谱随源事实重建。
13. 资产类型由未来交互决定，Session 只提供责任、来源、批准与证据边界；Plan 自编题和
    Teaching Session 现场形成的题最终都是同一种题卡。
14. Note 不等于记忆：Note 保存内容，原生 Session 或正式 Classroom Log 保存形成过程，
    对象记忆以 Learning History 和当前快照保存教师判断。
