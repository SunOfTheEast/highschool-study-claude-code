# M1b：自由学习驱动的最小学习集生长设计

状态：已确认，待编写实施计划

日期：2026-08-07

## 一、版本边界

M1a 已经让正式 Lesson 能够根据真实 Classroom Log 更新教师对象记忆。M1b 只解决一个更
小、但直接决定产品可用性的问题：学生没有 Roadmap、Plan、Lesson 或预置学习资产时，能否
立刻开始学习，并让这次学习留下以后可以继续使用的内容和教师记忆。

M1b 只有一个阶段、一个验收闭环：

```text
空白学习集
→ 自由学习
→ 保存 Note / 题卡
→ 形成对象记忆
→ 再次使用资产
```

不再使用 `M1b.1`–`M1b.4` 的旧分期。

后续版本边界已经确定：

- **M1c：** 增加共享词表与语义关系、学生学习足迹、原始资料渐进蒸馏、Meta Session，
  并让空白学习与已有证据、自由学习与正式课程合流。
- **M1d：** 只在 M1b、M1c 的真实闭环验证有效后再设计；当前不预先分配功能。

导入、发布、分享、社区和权限市场也不属于 M1b；它们是否进入 M1d 或更晚版本尚未裁决。

## 二、M1b 的四个组成部分（不是四个阶段）

M1b 只新增四个相互独立、能够组成闭环的部分：

1. 固定入口、多线程的自由学习 Session；
2. Note 与题卡两种学习资产；
3. 题卡作答与答案查看记录；
4. 自由学习中直接更新 M1a 对象记忆的能力。

学习集仍只是载体。M1b 不创建课程节点，不把自由学习挂入 Roadmap → Plan → Lesson 树，也
不要求学生先解释自己要学什么。

## 三、真正空白的学习集

M1b 所说的“空白”是没有课程和学习资产，而不是没有运行契约。最小学习集可以只有：

```text
LEARNING_GUIDE.md
memory/INDEX.md
```

`memory/INDEX.md` 可以是空索引；它继续作为教师记忆的常驻入口。学习资产与活动目录只在
第一次真实写入时创建。`ROADMAP.md` 不再是打开学习集的前提。

没有 Roadmap 时，首页只需要显示：

- 问老师；
- 我的学习资料；
- 最近的自由学习。

已有 Roadmap 的旧学习集仍显示正式课程区域，但 M1b 不修改课程树、课程生命周期或正式
Lesson 的备课和授课流程。

## 四、自由学习 Session

### 4.1 产品定义

自由学习是首页固定入口，体验接近一个真正了解学生的教学对话，而不是简化版课程。

学生可以：

- 不带任何上下文，直接发散地问问题；
- 从资产界面选择一张或多张题卡、Note，再进入讨论；
- 同时保留多个互不阻塞的线程；
- 在任何时候显式结束当前 Session。

自由学习没有预设目标，不要求收敛成课程，也不因为对话变长、出现一道题或产生资产而改变
Session 类型。学生以后想建立长期课程时，由 M1c 的 Meta Session 另行处理。

### 4.2 事实所有权

原生 Pi Session 是自由学习实际对话的唯一事实来源。它已经只追加地保存消息、工具调用、
时间和分支关系，因此 M1b 不再创建：

- Light Lesson Markdown 文档；
- Classroom Log；
- Consolidated Trace；
- 强制 Session Summary。

Runtime 只负责绑定和恢复原生 Session 的身份、当前选择的资产上下文与生命周期。学生界面
统一使用“自由学习”；内部作用域名称是否沿用 `light-lesson` 属于实施细节，不能反向增加
一种教学文档。

### 4.3 上下文披露

无上下文开启时，Tutor 只获得角色、教学核心、自由学习根 Skill 和紧凑的
`memory/INDEX.md`。它不预先浏览资产目录。

从题卡或 Note 开启时，只增加学生明确选中的资产投影；从题卡“问老师”进入时，还可以
增加最近一次作答和答案查看状态。Tutor 需要历史判断时先读对象记忆，只有确实需要核查时
才下钻来源 Session。

### 4.4 结束

学生显式结束只控制 Session 生命周期，不触发强制总结或记忆结算。超时、关闭页面、沉默
或开始另一个线程都不能推断为“已经学完”。未结束的 Session 保持可恢复，也不阻塞新线程。

若师生已经明确确认要保存某项资产，Session 结束前必须取得对应写入的成功回执；除此之外，
结束不承担语义事务。

## 五、学习资产

M1b 只新增 Note 与题卡。两者都是学生以后能够打开、修改或继续使用的内容，不是教师对
学生的认知判断。

### 5.1 Note

Note 保存：

- 标题；
- 有顺序的内容块；
- Runtime 绑定的稳定 ID、revision、创建 Session 和时间；
- 零个或多个学生明确带入的来源资产引用。

内容块可以是普通 Markdown 正文，也可以是具有 prompt / answer、默认隐藏答案的回忆块。
前端保留“保存为笔记”和“保存为闪卡”两种自然动作，但底层都创建或更新 Note：

- “保存为笔记”主要产生可直接阅读的正文；
- “保存为闪卡”主要产生可主动翻面的回忆块；
- 一个 Note 可以同时含有正文与多个回忆块；
- 只有一个回忆块的 Note 在交互上就是一张 Flashcard。

M1b 不引入独立 Flashcard 对象、间隔重复、掌握等级或复习排程。

### 5.2 题卡

题卡是一个 canonical 对象，保存：

- 题干；
- 学生作答后可以查看的标准答案或规范书面解答；
- 不直接投影给学生的教师讲解依据；
- 学生自己的题内笔记；
- Runtime 绑定的稳定 ID、revision、创建 Session 和时间；
- 必要的来源资产引用。

不同读者只获得同一题卡的不同投影：

- 学生看到题干、自己的笔记，以及满足答案门后的标准答案；
- Tutor 按眼前教学需要读取完整题卡；
- Scout 继续只读取无学生笔记、作答和教师记忆的安全投影。

现有完整题卡继续受支持。自由学习中形成的新题可以使用较薄的兼容形状，不要求 Tutor
当场填写旧题卡约 9 KB 的完整字段。M1b 不为同一道题建立“教师题卡”和“个人题卡”两份
真相。

### 5.3 M1b 不建立新词表

M1b 不设计 `core` / `related` 标签、动态词表、标签邻居或知识图谱。旧题卡已有的
`goal` / `method` / `structure` 和冻结词表继续按现有路径工作，但新资产在 M1b 中不承担
建立统一语义连接层的责任。

新旧资产怎样进入共享词表、怎样形成语义邻居以及怎样与对象记忆建立标签关系，统一留给
M1c。M1b 的资产浏览只需支持类型、最近使用和直接来源关系。

## 六、资产生成与确认

### 6.1 唯一合法调用者

M1b 只为自由学习 Tutor 增加资产保存能力。正式 Lesson、Plan Coach、Meta、Roadmap 如何
生成或采用资产，属于 M1c 的自由学习—正式课程合流，不在本期顺带实现。

学生在资产页直接编辑 Note 或题内笔记时，主动保存本身就是确认，不需要唤醒 Tutor。

### 6.2 保存门

Tutor 可以在自然教学中提议“保存为笔记”“保存为闪卡”或“保存这道题”，但必须让学生
知道拟保存的内容，并等待明确确认：

```text
形成明确的拟保存内容
→ 学生知道将保存什么
→ 学生明确确认
→ 调用窄写入动作
→ 收到成功回执
→ 才能说已经保存
```

“嗯、可以、存一下”可以构成确认；沉默、继续做题或离开页面不能推断为批准。设计不使用
“内容值得以后反复使用”之类模糊门槛，也不要求 Tutor 对每次讨论机械询问是否保存。

### 6.3 两个窄写入

M1b 提供：

- `save_note`；
- `save_problem_card`。

模型只提交不可约语义：Note 内容块，或题卡的题干、答案、教师依据与学生笔记，以及无法
从当前绑定推断的来源短别名。

Runtime 负责：

- 学习集、责任 Session 和当前资产绑定；
- 稳定 ID、路径、时间、revision 与 provenance；
- 来源别名解析和读者边界；
- 原子写入、幂等重试与成功回执；
- 学生资产列表投影。

Runtime 不生成教学内容，也不接受 mastery、profile、schedule、SRS 或图节点字段。

## 七、题卡作答与答案门

重新打开题卡不自动开启自由学习，也不把作答塞进题卡正文。原始交互由只追加记录持有，
建议位置为：

```text
activity/problem-attempts/<problem-card-id>.md
```

每次事件记录：

- 稳定事件 ID；
- 题卡稳定 ID 与当时 revision；
- 学生实际提交的内容，或明确选择“不会”；
- Runtime 时间；
- 标准答案在这次作答之前是否已经查看。

Runtime 不判断对错、掌握、能力或偏好。答案查看也不是学习效果证据。

学生流程是：

```text
打开题卡
→ 查看题干与自己的笔记
→ 提交作答，或明确选择“不会，直接看答案”
→ Runtime 追加原始事件
→ 查看标准答案
→ 直接离开，或点击“问老师”
```

点击“问老师”后，新建或恢复一个带该题卡上下文的自由学习 Session。它可以获得当前题卡
投影、最近作答和答案查看状态，但不能回写旧作答事件或预填未来信息。没有进入 Tutor 的
作答仍被保留，但不会自动升级为教师长期判断。

## 八、自由学习中的对象记忆

### 8.1 直接从原生 Session 形成

自由学习不经过 Log 或 Trace。对象记忆可以在对话进行中随时形成，不等待学生结束 Session。

唯一触发门是：

> 如果没有本次对话，未来教师对“学生现在怎样理解这个知识对象、学到哪里、边界在哪里”
> 的判断是否会不同？

会不同才写；不会不同则只保留在原生 Session。

可以触发写入的变化包括：

- 首次独立解释或完成；
- 暴露新的误解、过拟合或对象边界；
- 从需要提示变为能够独立完成，或反向退化；
- 原有教师判断被新表现推翻；
- 长间隔后的保持或遗忘；
- 学生得出关键结论、建立重要联系或发生认知框架转变。

关键结论至少要出现在学生的重新表达、推导、比较或使用中。教师讲了一遍、学生只说
“懂了”，不构成认知转变。

### 8.2 追加历史，局部更新快照

一次记忆写入遵守：

```text
真实对话改变教师判断
→ Tutor 静默提交对象目标、Learning History 变化和确实变化的快照字段
→ Runtime 绑定来源 Session 与写入时间
→ Learning History 只追加
→ Current Judgment / Evolution Overview / Boundaries 只更新实际变化的部分
→ 对话继续
```

Tutor 不填写 Session ID、时间、路径、消息 ID 或轮次范围。对象记忆只引用整个来源
Session；需要核查时从紧凑记忆下钻完整原生对话。

Learning History 使用自然语言如实说明关键结论是学生独立得出、提示后形成还是师生共同
形成，以及尚未检验的边界，不增加僵硬等级枚举。偏好只有学生明确表达时才写。

### 8.3 资产不等于记忆

- 学生独立提出 Note 的核心关系，真实对话可能同时支持对象记忆更新；
- 师生共同形成时，Learning History 应写明教师帮助；
- 教师写好、学生只选择保存时，只证明内容被保留；
- 保存题卡、查看答案或保存 Note 不自动生成认知判断；
- 学生在 Session 外编辑资产，只产生新 revision，不自动修改教师记忆。

题卡保存和对象记忆是两个独立事务，不为“完整闭环”拼成一个大工具调用。

## 九、读取与再次使用

下一次自由学习的最小上下文顺序是：

```text
自由学习根契约
→ 学生本次明确选择的资产
→ memory/INDEX.md
→ 需要历史判断时读取相关对象记忆
→ 仍需核查时下钻来源 Session
```

从“我的学习资料”再次打开资产时，学生可以：

- 阅读和编辑 Note；
- 主动翻看 Note 中的回忆块；
- 查看题卡题干与自己的笔记；
- 再次作答并在答案门后查看标准答案；
- 带着当前资产和最近作答重新“问老师”。

M1b 不通过标签搜索、邻居图或资料蒸馏扩大上下文；这些能力进入 M1c。

## 十、原子性、并发与恢复

资产正文、revision、来源和创建 Session 必须同一次成功或全部不发生。列表投影若重建失败，
canonical 资产保持成功，并能从源文件重建投影；Tutor 不扫描目录猜测修复。

多个自由学习 Session 可以并行。不同资产正常写入；同一资产的 stale revision 被拒绝，
不静默覆盖或自动语义合并。首先依靠 harness 原生 tool 调度和原子写入，只有真实端到端
测试证明仍会丢更新时，才增加最小 Runtime 进程锁。

原生 Pi Session、自主作答和对象 Learning History 都是只追加事实。Note 与题卡正文可以
通过新 revision 修正，但旧作答和旧 Session 继续指向当时看到的 revision。

## 十一、验收

### 11.1 确定性测试

1. 只有 `LEARNING_GUIDE.md` 与空 `memory/INDEX.md` 的学习集可以启动，无需 ROADMAP.md。
2. 多个自由学习 Session 可以创建、恢复、显式结束，且不出现在课程树。
3. 自由学习只使用原生 Pi Session，不生成 Light Lesson 文档、Classroom Log、Trace 或强制
   Summary。
4. 无上下文与选中一个或多个资产两种启动方式都能恢复正确上下文。
5. `save_note` 与 `save_problem_card` 在学生确认前拒绝写入；成功后返回稳定资产入口。
6. Note 正文块、回忆块和混合形态均可读取；不存在独立 Flashcard 对象。
7. 学生题卡投影不泄漏教师讲解依据；Scout 不读取学生笔记、作答或记忆。
8. 作答、“不会”、答案查看和 source revision 按发生顺序只追加，旧事件不含未来信息。
9. 对象记忆可以在 Session 中途写入；结束 Session 不强制生成记忆。
10. Learning History 绑定来源 Session 与 Runtime 时间，不要求消息级引用；快照只修改提交的
    语义字段。
11. 保存资产、查看答案和 Session 外编辑都不会自动生成认知判断。
12. stale revision、重复 toolCall、投影失败和应用重启不会产生孤立文件或重复事实。

### 11.2 前端闭环

```text
空白学习集
→ 从固定入口开始自由学习
→ 讨论中确认保存 Note 与题卡
→ 关键结论或认知转变出现时形成对象记忆
→ 学生显式结束
→ 重启应用
→ 从“我的学习资料”打开题卡
→ 独立作答并查看标准答案
→ 带着本次作答再次问老师
→ 新自由学习 Session 获得正确资产与记忆上下文
```

### 11.3 真实模型验收

学生只使用自然语言，不主动要求系统调用工具或写记忆。验收最终结果：

- Tutor 不把普通问题扩张成 Roadmap、Plan 或正式 Lesson；
- 没为了产资产而打断教学；
- 学生确认前没有保存资产；
- 保存的 Note 或题卡抓住了讨论要害；
- 没把漂亮资产、看过答案、教师讲解或“懂了”说成掌握；
- 学生真正得出关键结论或发生认知转变时，能够形成有边界的对象记忆；
- 没有认知变化的长对话不会被过度记录；
- 二次自由学习能够正确使用资产、最近作答和相关对象记忆；
- 全程记录模型调用、工具调用和阶段耗时。

### 11.4 回归基线

- 现有 Roadmap、Plan、Lesson 与 M1a 正式课堂记忆不回归；
- 现有完整题卡、冻结词表和 Scout 召回继续工作；
- 新自由学习与资产不污染课程树；
- 其他未进入 M1b 的功能不出现半成品入口。

## 十二、明确非目标

M1b 不实现：

- Meta Session、Roadmap 创建或首个 Plan 物化；
- 自由学习与正式 Lesson 的资产、记忆或生命周期合流；
- 新资产共享词表、`core` / `related` 标签、语义邻居与知识图谱；
- 面向学生的聚合学习足迹；
- 书籍、PDF、讲义或图片的上传与渐进蒸馏；
- 导入、发布、分享、社区和权限市场；
- 图数据库、embedding 服务或新 recall 工具；
- 间隔重复、SRS、BKT、掌握分数或统一能力等级；
- 自动合并语义相近资产；
- 把自由学习中途转换为正式 Lesson。

其中 Meta Session、课程合流、共享词表与语义关系、学习足迹和资料蒸馏属于已经确认的
M1c 方向；其他功能由后续设计单独裁决，不提前塞进 M1d。

## 十三、最终决策摘要

1. M1b 只有一个阶段：空白 → 自由学习 → Note / 题卡 → 对象记忆 → 再次使用。
2. 自由学习是固定入口、无预设目标、允许多线程的原生 Pi Session，不创建教学文档、Log、
   Trace 或强制 Summary。
3. Note 与题卡是两种核心资产；Flashcard 是 Note 的回忆块体验。
4. M1b 只有自由学习 Tutor 能提议保存资产，且必须等待学生明确确认。
5. 题卡作答和答案查看只追加，不自动形成掌握判断。
6. 对象记忆可在自由学习中途直接形成，只绑定来源 Session，不绑定消息轮次。
7. Learning History 追加变化，当前快照只局部更新实际变化的字段。
8. 资产保存与记忆写入互相独立；内容存在不证明学生理解。
