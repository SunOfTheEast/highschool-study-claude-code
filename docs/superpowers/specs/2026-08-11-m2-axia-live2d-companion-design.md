# StudyForge M2 阿夏 Live2D 长伴随设计

**状态：** 页面内形态已实施；后续由桌宠设计替代其挂载位置
**日期：** 2026-08-11  
**范围：** 自由学习中的 `peer-axia` 专属 Live2D 模型与 Session 内长伴随  
**上位设计：** `2026-08-11-m2-local-peer-embodiment-design.md`

与“三档图片嘴型作为首版终点”的决定；上位设计关于消息事实、Peer 身份、TTS、公式口播、
中断、隐私和失败退化的边界继续有效。

> 第五、六节关于“只在自由学习页面挂载、离开页面即卸载”的位置与生命周期决定不再作为

## 一、目标

现有 M2 薄切片已经建立了阿夏的独立 Peer 消息、自动 TTS、静态立绘、音量驱动嘴型和中断
节奏。本切片只替换并增强表现层：制作一套能辨认出本人特征的日系 Live2D 专属模型，并让
阿夏在一段自由学习 Session 内安静长伴随。

成功形态是：学生进入自由学习后，阿夏一直位于页面边缘；平时只有克制的呼吸、眨眼和轻微
转头，被现有 `ask_peer` 邀请时进入思考与说话状态，结束后回到安静陪伴。她的存在不新增
Agent、模型调用、记忆读取或云端视频服务。

本切片优先验证私人环境中的真实体验。公开仓库和公共 DMG 不包含可识别本人身份的模型素材，
也不把 Live2D 作为 StudyForge 核心教学闭环的前置条件。

## 二、承重边界

### 2.1 发言事实不变，Live2D 只是派生表现

`ask_peer` 的成功 `toolResult` 仍是阿夏发言的唯一事实。Live2D 模型、表情参数、嘴型、待机
动作和播放状态都只是这条消息与当前页面状态的派生表现：

```text
同一条 peer-message
→ 原有 Markdown / KaTeX 文字
→ 原有 TTS 音频
→ Cubism 模型表情与嘴型
```

Live2D 不生成、改写或重复持久化消息，不进入学习记忆、足迹、Note、题卡或 Material。

### 2.2 长伴随的是形象，不是后台 Agent

安静陪伴期间不调用模型、不合成语音，也不额外读取对话。只有教师按既有语义边界调用
`ask_peer` 时，Peer Runner 才真正生成阿夏的发言。常驻形象不能被解释为阿夏持续监听、
持续推理或拥有一条并行 Session。

### 2.3 Live2D 是可选渲染器

现有静态头像继续作为完整退路。Cubism 运行库、模型或任一动作加载失败时，表现层退回静态
阿夏；文字 Peer、TTS、教师续接和原生 Session 均不受影响。Live2D 不反向成为自由学习的
运行前提。

## 三、专属模型资产

### 3.1 画风与构图

模型采用已经确认的日系 Live2D 方向：清晰线稿、柔和赛璐璐上色、适度二次元化，同时保留
本人可辨认的眼形、脸部比例、鼻唇特征、发色与中分发型。模型为正面头部至胸口构图，服务于
页面边缘的同桌陪伴，不制作全身和复杂手势。

已生成的画风样张只作为视觉基准，不直接硬拆为模型。正式原画需要重新生成或修绘成适合绑定
的正面稿，保证完整头部、双肩和干净轮廓，并为会发生位移的部件补画被遮挡区域。

### 3.2 克制分层

只拆真正需要独立运动的部件：

- 后发、脸与耳朵、前发及少量独立发束；
- 左右眉毛；
- 左右眼睫、眼白、虹膜与高光；
- 上下唇、口腔、牙齿与舌头；
- 鼻部、脖子、上身衣物与项链。

具体图层数量由真实遮挡和动作需要决定，不以“图层越多越专业”为目标。眼睛、嘴和头发需要
补足运动后会露出的隐藏部分；不会独立运动的装饰不拆成无效图层。

### 3.3 私人与运行时资产

保留三层交付物：

1. 分层 PSD：继续修绘和重新导入的源资产；
2. `.cmo3`：继续调整绑定、参数和物理的 Cubism 工程；
3. `.moc3`、`model3.json`、纹理、表情、物理和动作文件：StudyForge 只读运行时包。

三层私人资产均放入固定但不受 Git 管理的 `actors/peer-axia/live2d/` 本地角色槽位。公开源码、
公共 DMG、测试夹具和截图不得包含本人照片、分层稿、可编辑工程或可识别身份的导出模型。

## 四、绑定与动作

第一版只绑定实际会在页面边缘看到的运动：

- 轻微的头部横向、纵向与倾斜；
- 左右眼眨眼、视线与基础眉形；
- 嘴巴开合和嘴形；
- 呼吸与轻微上身运动；
- 头发和项链的小幅物理摆动。

不接摄像头，不做人脸追踪，也不复刻 VTuber 主播的全套控制参数。阿夏由对话状态与当前音频
驱动，而非真人实时操纵。

制作时优先使用 Cubism Editor 已有的自动网格、自动 Deformer 与自动面部 XY 动作生成，随后
只手工修正真实预览中不自然的眼睛、嘴、轮廓、头发和物理表现。自动生成是起点，不替代最终
视觉判断。

`question / association / challenge` 继续稳定映射为好奇、平静与审视三种表情。它们是同一
模型上的眉眼和嘴形参数组合，不再存储三张完整立绘。TTS 的真实音频包络驱动
`ParamMouthOpenY`；停顿回到闭嘴，中断立即停止嘴部运动。首版不增加音素识别或逐字 viseme。

## 五、Session 内长伴随

### 5.1 生命周期

```text
进入自由学习
→ 加载阿夏并进入 calm
→ ask_peer 开始：thinking
→ Peer 文字完成、TTS 播放：speaking
→ 播放完成或中断：回到 calm
→ 离开自由学习：卸载模型
```

阿夏不跟随到学习首页、资产页、Roadmap、Plan 或 Lesson。长伴随的范围恰好是一段自由学习
Session。

### 5.2 页面表现

模型沿用已经确认的页面边缘位置，不常驻独立面板、不挤窄对话正文。`calm` 状态只有低频
眨眼、呼吸和轻微转头；`thinking` 可以有克制的注意力变化；`speaking` 才启用当前表情和
嘴型。动作始终服从阅读页面，不能把角色变成比教学内容更醒目的主体。

学生静音或停止语音后，阿夏保留安静形象并立即闭嘴。页面进入后台时暂停动画与帧更新，重新
可见后从 calm 恢复，不补播历史动作或旧语音。

## 六、应用内渲染

在现有 actor 表现层下增加一个薄的 Cubism 渲染器。它只消费现有数据：

- 当前 `PeerConversationItem`；
- 已确定的 `PeerMove / expression`；
- 现有 TTS 播放阶段与音频包络；
- 当前自由学习路由是否仍然有效。

渲染直接运行在 Tauri WebView 的 WebGL 画布中，不依赖 VTube Studio、摄像头、云 GPU、视频
流或额外常驻应用。当前 Peer Runner、Session 投影、MiMo TTS、公式口播、播放中断与教师续接
顺序不因 Live2D 改写。

私人开发环境从固定本地资源槽位加载 Cubism Core 与阿夏模型。公共构建在这些资源缺失时只
启用静态渲染器。Cubism Core 不提交到公开 Git；任何启用 Live2D 的公开发行版都必须在发行前
按官方对 AI / Chatbot 与可扩展应用的分类重新确认 Publication License，不把私人验证自动
解释为公开发布授权。

## 七、失败退化

- Cubism Core 缺失或初始化失败：使用静态阿夏；
- 模型清单、纹理、物理或动作缺失：本次不启用 Live2D，不能半加载破图；
- WebGL 上下文丢失：停止动画并回退静态形象，不重跑 Peer 或 TTS；
- TTS 失败：保留文字与安静模型，不伪造嘴型；
- 学生中断：停止音频和嘴型，保留已经落盘的 Peer 文字；
- 页面刷新或历史恢复：重新进入 calm，不自动重播旧发言；
- 私人模型不存在：公共占位与原有文字三方对话照常工作。

## 八、验收

验收以真实使用感受为中心：

1. 静止时第一眼能认出是阿夏，不像通用模型只换了发色；
2. calm 状态具有存在感，但呼吸、眨眼和转头不抢正文注意力；
3. thinking、speaking 与 calm 之间没有闪烁、重新加载或突然跳姿势；
4. 嘴型随真实 TTS 音频自然开合，停顿闭嘴，中断立即停止；
5. 好奇、平静和审视三种表情能辨认，但不夸张表演；
6. 连续完成一段真实自由学习后仍流畅，不持续涨内存或让桌面端明显发热；
7. 路由离开、页面后台、刷新和重新进入不会留下僵尸动画或重播历史；
8. 移除 Cubism 或私人模型后，静态头像、TTS、文字 Peer 与教师续接全部可用。

最终判断权保留给用户本人：参数齐全、测试通过或技术上能运行都不能替代“是否像她、是否
愿意让她长期待在页面边缘”的真实体验判断。

## 九、明确不做

- 全身模型、手势库、舞蹈或摄像头追踪；
- VTube Studio 外挂和第三方常驻桌面程序；
- 云端神经视频、实时数字人或按分钟渲染；
- 音素级精确口型；
- 角色编辑器、用户上传任意 Live2D 模型或通用插件市场；
- 教师数字人和正式课程中的长伴随；
- 将视觉常驻误写成 Peer 持续推理或监听；
- 在公开仓库或公共安装包中分发私人模型与未经确认的 Cubism 运行库。

## 十、Skill 固化边界

现阶段不声称已有一个能自动产出 `.moc3` 的 Live2D Skill。第一版使用现有图像生成能力、
Cubism Editor 官方自动功能与人工视觉修正完成。只有在分层 PSD、绑定、导出和 StudyForge
预览真实走通后，才把已经验证的步骤、图层约定、检查脚本和失败案例固化为
`live2d-model-production` Skill。

这样得到的是可复用的真实工作流，而不是根据名词拼出的制作说明。
