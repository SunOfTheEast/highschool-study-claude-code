# Coach 问诊与跨 Plan 纵向内测设计

状态：已确认，待实施

日期：2026-07-28

## 一、背景

StudyForge 已经具备 Roadmap、Plan、Lesson、active Trace、Plan Summary、长期画像、
Roadmap Coach、Plan Coach 和 Tutor 的完整闭环。当前 Coach 提示词也要求读取学生
原话和课堂证据、确定目标、能力标准和测试，并在学生确认后写入 Plan 或 Lesson。

缺口不在记忆数量，而在两种教学判断之间缺少稳定的对话过程：

1. Roadmap Coach 可能只凭学生一句宽泛描述便起草 Plan；
2. Plan Coach 可能完成证据分析后直接备课，没有先了解学生此刻的理解、意图和状态。

现有提示词说明了“应该知道什么”，但没有充分说明：

- 怎样从学生原话生成下一问；
- 怎样避免用 Coach 的假设诱导学生；
- 怎样通过数轮对话形成真正改变教学安排的判断；
- 什么样的判断具有洞见，而不是对学生困难的平庸复述。

本设计为 Roadmap 规划、跨 Plan 推进和每课备课增加同一套对话式问诊方法，并用一个
六课完整 Plan 加一个三课新 Plan 的真实 DeepSeek 周期验证纵向个性化。

## 二、目标

### 2.1 Coach 问诊

在以下三类决定前，Coach 都先进行一段简短、多轮、一次一问的自然商议：

1. 首次建立 Roadmap 和 Plan；
2. Plan 完成后选择下一学习周期；
3. 每一节 Lesson 的备课。

问题必须来自学生最近表达与当前证据中的真实歧义，逐步缩小范围并区分会导向不同
教学动作的解释。Coach 在形成方案前总结自己的理解，允许学生纠正、补充和授权。

### 2.2 洞见性

Plan 和 Lesson 的核心判断必须能够：

- 区分至少两种教学后果不同的解释；
- 指向真实学生陈述或学习证据；
- 改变实际 Plan 或 Lesson 设计；
- 说明什么后续表现会支持或推翻当前判断。

洞见是可修订的工作判断，不是稳定人格标签，也不是复杂术语。

### 2.3 纵向内测

使用虚构学生“周亦航”和固定 DeepSeek 模型完成：

- 从空白导数学习集建立第一个 Plan；
- Plan 1 连续运行六节 Lesson，并按真实标准决定能否完成；
- Plan 1 完成后由 Roadmap Coach 建立 Plan 2；
- Plan 2 连续运行三节 Lesson；
- 检查历史是否持续改变问诊、备课、课堂和下一周期，而不是只在开场被复述一次。

## 三、非目标

本设计不增加：

- Agent；
- MCP 或 Pi 原生工具；
- 持久问卷、问诊表或诊断 schema；
- 必填问题数量计数器；
- 新的学习事实或数据库；
- 自动诊断规则引擎；
- 对 Skill 原句、关键词或问题数量的脆弱文本测试。

Tutor 的现场教学循环不在本轮重新设计。共享数学教学内核也不承载这套问诊要求，
避免让 Tutor 在每次课堂回应前机械盘问学生。

## 四、问诊不是问卷

每次 Roadmap 规划、跨 Plan 规划和 Lesson 备课都必须先发起一段问诊。问诊包含多个
分开的关键问题，不允许用一次打包提问或一句“是否同意”代替。

问题数量不写成固定数字。Coach 根据上一回答继续选择下一问，直到它能够说明：

> 我根据你刚才表达的这些，以及已有学习记录，准备这样安排……

学生始终拥有终止问诊和授权 Coach 判断的权利。学生回答“你来安排”时，Coach 不再
纠缠同一个问题，但仍可从另一个真正有价值的角度了解学生。学生明确要求停止继续
提问时，Coach 使用已经获得的信息提出带不确定性的建议；这属于学生主动终止问诊，
不是 Coach 省略问诊。

即使文件证据已经充分，仍有内容只能由学生当前回答提供，例如：

- 学生自己如何理解最近的表现；
- 此刻最想解决什么；
- 当前难度、节奏和课堂形式感受；
- 时间、精力或近期目标是否变化；
- 是否认同 Coach 对既往问题的理解。

因此“有足够 Trace”不能成为完全跳过问诊的理由。

## 五、设问生成方法

### 5.1 从学生最近一句话开始

Coach 先找出学生表达中含义最宽、且不同解释会改变 Plan 或 Lesson 的词语，再用一个
中性问题缩小它的范围。

优先使用以下下钻方向：

- 哪一类；
- 在什么情境；
- 卡在哪一步；
- 最近的具体例子；
- 当时先尝试了什么。

只有对象和现象已经具体后，Coach 才讨论原因、目标、安排和检验。

### 5.2 示例

学生说：

> 综合题找不到入口。

第一问应先澄清所指对象：

> 你说的主要是哪种综合题？比如恒成立、参数范围、零点，还是其他类型？

学生回答“含参数的恒成立”后，再澄清现象：

> 这类题里，你通常是完全想不到方向，还是能想到几种方法但不知道该选哪个？

之后再追最近实例：

> 最近一道让你卡住的题里，你看到题目后最先尝试了什么？

不应一开始问：

> 你是不是方法选择不稳定？

后者把未经验证的 Coach 假设写进问题，容易诱导学生确认并生成假画像。

同样的方法用于备课。学生说“上节课听懂了，但还是不太熟”，Coach 可以问：

> 你说的不熟，是独立做题时想不到第一步，还是能想到路线但过程容易写不完整？

### 5.3 问题的选择标准

一个问题值得问，必须至少满足一项：

- 它能区分教学后果不同的解释；
- 它能把宽泛表述落到具体题型、步骤或经历；
- 它能发现文件证据无法表示的当前意图或限制；
- 它的回答可能改变目标、节奏、任务功能、测试或提示方式。

问题不用于展示关心、填满栏目或拖延决定。已经明确的信息不重复询问。

## 六、洞见判断

### 6.1 洞见的四个组成

每个 Plan 级或 Lesson 级核心判断都回答：

1. **区分**：当前判断区分了哪些表面相似但教学方案不同的解释；
2. **来源**：哪些学生原话、作答或跨课表现支持它；
3. **行动**：它具体改变了当前 Plan 或 Lesson 的什么；
4. **可推翻性**：什么后续表现会说明判断需要修订。

### 6.2 平庸判断与有洞见判断

平庸判断：

> 学生综合题能力不足，需要加强方法训练。

有洞见的判断：

> 学生并不缺少同构和参数分离的方法知识；方法名称一旦被提示，他通常能完成计算。
> 当前更可能的问题是让题目的表面形式触发最近学过的方法，而没有先从证明目标倒推
> 需要构造的对象。因此下一阶段不继续按方法分类重复讲解，而使用表面相似、目标不同
> 的对比题，要求学生在计算前说明选择依据。若学生能在陌生题中连续独立完成目标
> 分析、方法选择和条件核验，则应修订这一判断。

平庸备课判断：

> 上节课有粗心，下一课继续巩固。

有洞见的备课判断：

> 条件遗漏发生在完整主链完成以后，更像验证环节后置，而不是不知道定义域。下一课
> 应把条件核验嵌入方法选择之前，观察学生能否主动提前检查；不需要重新上一节定义域
> 基础课。

洞见不得依靠人格化猜测、学习风格标签、单次错误的过度归因或无法被后续证据检验的
心理解释。

## 七、三类问诊

### 7.1 首次 Roadmap 问诊

Roadmap Coach 从学生的自然需求开始，逐步理解：

- 学生所说问题的具体对象和表现；
- 当前经验与可验证起点；
- 想发生的能力变化；
- 时间和周期约束；
- 学生认可的成功表现与直接测试。

这些不是固定提问顺序。Coach 从最近一句回答中选择下一问。

信息足够后，Coach 先总结学生陈述与自己的暂定判断，请学生纠正。只有存在多个实质
不同、且会改变学习路线的方向时，才比较少量候选 Plan；方向已经明确时不强行凑
选项。原因仍未区分时，提出短诊断 Plan。

学生确认 Goal、周期、Observable Capability Standard 和 Test 后，才写入并注册
Plan。`Planning Basis` 保存采用的学生陈述、工作判断、真实来源和推翻信号，不保存
整份问诊转录。

### 7.2 跨 Plan 复诊

Roadmap Coach 先读取前序 Plan 的 Planning Basis、Plan Summary、已确认画像和必要
原始来源，再与学生进行新的多轮问诊。

它不重复询问已经有稳定答案的成绩、基础和偏好，而关注：

- 学生如何理解上一阶段的变化；
- 当前优先级是否变化；
- 哪个后续方向更符合学生此刻目标；
- 时间、精力或外部目标是否改变；
- 学生是否认同 Coach 从历史中形成的判断。

摘要和 active Trace 不能代替学生在新周期的主动选择。Coach 提出 Plan 2 前，仍需
总结、允许纠正并取得确认。

### 7.3 每课备课问诊

Plan Coach 在备课前先完成上一课的 Plan review 和必要写回，再读取当前 Plan、
确认画像、带来源摘要和相关 active Trace。随后进行一段多轮问诊，了解文件无法回答
的主观体验和当前意图。

备课顺序为：

```text
复盘并写回 Plan
  → 读取当前证据
  → 与学生进行备课问诊
  → 形成有洞见的本课判断
  → 说明无剧透课堂意图
  → 学生确认或调整
  → 推导任务功能并检索真实题卡
  → lesson_prepare
```

问题可能涉及学生如何理解上一课卡点、当前想补救还是迁移、此刻时间和精力，以及对
难度和支持方式的偏好，但不能变成每课重复问卷。

无剧透备课说明只包含本课为什么这样安排、活动的一般形式和学生可调整的选择，不
透露题卡隐藏条件、目标方法、决定性变形、检查点或答案。

## 九、虚构学生

### 9.1 基本画像

虚构学生名为周亦航：

- 高三，数学通常在 125–135 分；
- 导数基础运算与常规单调性、最值题较熟练；
- 想提高高阶导数综合题；
- 愿意写过程和质疑，不喜欢长篇铺垫；
- 希望先自己尝试，不想一开始被告知方法；
- 单课可投入 45–60 分钟，疲劳时会主动提前结束。

隐藏的初始特点是：

- 计算执行强于目标分析；
- 容易过度迁移最近学习的方法；
- 定义域和参数条件常在主链结束后才补查；
- 方法名称一旦被提示，后续完成较快，容易制造“已经掌握”的假象；
- 真正需要观察的是陌生题中的独立方法选择和迁移。

### 9.2 初次表达

系统最初只看到：

> 我导数基础还可以，但综合题经常找不到入口，想系统提高一下。

隐藏画像不写入 learning set、不放进 Coach/Tutor 上下文，也不作为模型可见提示。
周亦航希望先用六节课形成一个阶段，但只在问诊自然涉及周期时说明。

### 9.3 模拟规则

模拟学生时：

- 只依据当前 Student View、此前真实课堂内容和已经形成的理解作答；
- 不读取 Teacher Control、答案或隐藏候选 Plan；
- 不为了命中验收条件故意犯荒谬错误；
- 保持能力与性格连续，但允许犹豫、粗心、过度自信、急躁、疲劳和顿悟；
- 会打断过长讲解、拒绝过早提示、质疑不贴切判断和主动选择结束；
- 只有真正理解并采用的教学内容才进入后续表现；
- 不预先决定每一题对错，也不保证第六课必然达标。

## 十、纵向真实模型运行

### 10.1 固定环境

开始真实运行前：

1. 完成并验证 Skill 修改；
2. 固定一个实施 commit；
3. 复制公开导数学习集到隔离目录；
4. 使用同一个 DeepSeek Provider 和模型完成 Roadmap、Coach、Tutor 全周期；
5. 保持公开示例不变；
6. 正式周期开始后冻结 Prompt，不边跑边修教学文本。

学生消息通过正常 Pi Web 学习界面和对应 Session 发送。学习事实只能由现有
Agent/工具写入，不通过人工编辑伪造成功路径。

### 10.2 Plan 1

运行顺序：

```text
Roadmap 首次问诊
  → 学生确认并注册 Plan 1
  → 六次「备课问诊 → Lesson → 关课 → Plan review」
  → 能力标准审计
  → 学生确认 Plan 完成
  → Plan 长期记忆确认
```

六课应自然出现诊断、学习、过度迁移、调整、陌生题迁移和独立验收，但不提前规定每个
Lesson 的题目或模板。Coach 必须根据累积证据决定实际课型和任务功能。

第六课后只有在原能力标准真实满足、Coach 正确写回并且周亦航确认时，Plan 1 才能
完成。若未达标，本轮记录为“六课目标未完成”，不得为了进入下一阶段伪造完成。

### 10.3 隐藏 Plan 2 候选

Plan 1 完成后，评估侧保留三个不向 Roadmap Coach 注入的候选：

1. 方法选择仍不稳定：继续跨方法决策与陌生题迁移；
2. 方法选择已稳定但论证收束较弱：转向参数边界和充分必要性；
3. 两者较稳：进入多方法综合和限时表达。

Roadmap Coach 可以选择其中之一，也可以提出来源充分、比候选更贴切的第四种方向。
候选只用于评估判断是否贴合历史，不是正确答案列表。

### 10.4 Plan 2

Plan 1 完成和长期记忆确认后：

```text
返回原 Roadmap Coach Session
  → 跨 Plan 复诊
  → 学生确认并注册 Plan 2
  → 创建新的 Plan Coach Session
  → 连续运行三次「备课问诊 → Lesson → 关课 → Plan review」
```

Plan 2 不要求在三课后完成。重点是验证 Plan 1 的历史是否持续改变三次备课，以及
Plan 2 的新证据能否修订旧判断。

## 十一、验收标准

### 11.1 问诊

- 从学生最近原话中的模糊对象继续设问；
- 优先澄清类型、情境、卡点阶段和具体实例；
- 一次只问一个问题，并根据回答选择下一问；
- 每次规划和备课通常都有多轮真实问答，不以一次打包问卷代替；学生明确终止继续
  提问时，保留并尊重这一选择；
- 不用 Coach 假设诱导学生确认；
- 提方案前总结理解，并允许学生纠正、补充或授权。

### 11.2 洞见

- 判断区分了教学后果不同的解释；
- 判断引用学生原话、active Trace 或带来源的跨课表现；
- 判断实际改变 Plan 方向、任务功能、课型、节奏、提示或检验；
- 判断说明了支持或推翻信号；
- 不把单次错误、宽泛分数或方法信号升级为人格标签；
- 不用“加强练习”“巩固薄弱点”等通用句替代教学判断。

### 11.3 Plan 1 个性化

- 后一课真正使用前课表现，不只复述摘要；
- 备课问诊的新信息能够改变后续教学动作；
- Coach 区分计算能力、方法储备、方法选择和论证收束；
- Tutor Trace 忠于实际学生内容、提示依赖和路线；
- 学生表现具有连续成长、复发和迁移，而不是脚本轮流对错；
- Plan 完成严格服从原能力标准和学生选择。

### 11.4 Roadmap 与 Plan 2

- Roadmap Coach 从 Plan 1 来源重建能力变化；
- 历史读取后仍进行跨周期问诊；
- Plan 2 建议同时反映真实证据与学生当前意图；
- 新 Plan 和新 Plan Coach Session 不复制旧 transcript，也不丢失必要交接；
- Plan 1 历史持续影响 Plan 2 三次备课；
- Plan 2 新证据可以推翻或修订旧判断，长期画像不成为刻板标签。

### 11.5 事实与产品链路

- Plan、Lesson、Trace、Session owner、状态和路由保持一致；
- 题卡全部来自真实资产；
- 学生视图不泄漏 Teacher Control、答案或隐藏候选方向；
- Plan 1 长期记忆只有逐项确认后才进入两份 profile；
- 公开导数示例在运行前后保持不变。

## 十二、故障处理

- **DeepSeek 临时请求失败**：保留同一 Session 重试，不切模型。
- **首次工具参数错误但运行时拦截并自恢复**：记录现象并继续，观察是否重复。
- **事实写入、Session owner 或路由恢复故障**：暂停运行，作为运行时缺陷处理；不能
  手工补写事实后假装链路成功。
- **教学判断不佳**：保存当时上下文，不在正式周期中途修改 Prompt；能继续则完成
  当前冻结运行，统一在报告后分析。
- **第六课未达标**：不完成 Plan 1，不创建 Plan 2，并报告六课目标失败。
- **学生拒绝某项建议**：保留真实异议，让 Coach 修订；不为了命中候选分支诱导同意。

若运行时阻塞缺陷必须修复，当前冻结运行终止。修复经过验证后，从明确记录的干净起点
重新开始受影响周期，不能把修复前后的不连续片段拼成一次成功运行。

Skill/Agent prose不增加关键词、标题或原句测试。行为以真实 DeepSeek 问诊和九节课

最终验收报告记录：

原始 Pi Session JSONL 或整段课堂转录。

## 十四、设计边界总结

本设计把 Coach 的个性化能力从“读取很多材料”推进为：

```text
听见学生的模糊表达
  → 通过关键设问逐层缩小含义
  → 区分教学后果不同的解释
  → 形成有来源、可行动、可推翻的洞见
  → 与学生共同确认 Plan 或 Lesson
  → 用后续真实表现修订判断
```

它仍然是 Skill 驱动的自然对话，不是问卷系统、诊断规则引擎或新的学习状态。
