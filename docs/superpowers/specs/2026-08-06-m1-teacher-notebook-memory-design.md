# StudyForge M1 记忆系统设计：教师备课本（事实登记 + 可撤回判断层）

**状态：** 草案（数据核心与消费契约四节已在讨论中逐节确认，全文待审阅）

**日期：** 2026-08-06

**实施路线：** `memory/` 登记目录 + 所有权层级写入 + 按需读取永不注入；分四阶段实施

## 1. 背景与核心判断

M0 的文档原生记忆消融建立了一个干净基线：课堂事实只写在 Lesson Block，父 Agent
直接读原始 Markdown，没有任何派生记忆。消融设计同时留下一条**记忆阶梯**（M1 来源
索引 → M2 局部压缩 → M3 跨 Plan 长期记忆 → M4 能力聚合），并规定每次升级必须
"先在至少两节真实课堂中观察到相同缺口"。

M1 阶段包含两个独立子项目：学习集生产与记忆系统。本设计只覆盖**记忆系统**。

为回答"第一级记忆到底该是什么"，我们对 M0 终验运行（2 Plan / 5 Lesson，模拟学生）
的全部 8 个 pi-agent Session 转录做了逐线分析（见第 4 节）。核心发现：

> 实证缺口的形状**都不是索引**。缺口是"根本没记"（学生侧身事实零持久化）、
> "记了就丢"（函数级覆盖史在摘要压缩中静默丢失）和"承重集中"（全部跨课记忆压在
> Coach 手工收口文本上）。索引解决"记得但找不到"，而我们的证据是另外三种病。

因此 M1 的第一层记忆是**登记（registries）**，不是阶梯原设想的索引。阶梯各级本来就是
"候选方向，不是预先承诺的功能"——现在真实证据到了，阶梯顺序被证据改写。

系统的外部形态是**教师备课本**：一个教了几十节课的老师脑子里对学生的那幅活画像——
会什么、不会什么、掌握哪些方法、知道哪些知识点、哪个忘了几次、哪个记住了几次、
做过哪些题。备课本分两层：

- **事实层**：append-only 的登记（做过什么题、提取检验结果、学生说过什么），
  永不压缩、只登记不判断；
- **判断层**：教师当前对学生的看法（会/不会、方法掌握、知识点状态），每条带证据
  引用、注明日期、**可撤回**——撤回不删除历史。

这两层的划分守住愿景文档的铁律：课堂 Event 是不可改写的原始事实；知识点状态、
趋势、误区与掌握只能是可撤回的聚合判断，不能反过来覆盖原始事件。

## 2. 目标

1. 建立学习集级 `memory/` 登记目录，修复三个已实证缺口：学生侧身事实零持久化、
   函数级覆盖史静默丢失、收口文本单点承重。
2. 判断层以结构化记录承载"教师对学生的当前看法"，每条带引用、带日期、可撤回；
   写入走所有权层级（Tutor 事实 → Coach Plan 级判断 → Roadmap 跨 Plan 判断）。
3. 消费契约：登记内容永不自动注入（唯一开口是 INDEX.md 指针地图）；Coach 出题前
   必查覆盖登记；判断继续经 lesson 文档烘焙服务 Tutor 冷启动。
4. 机械事实（时间戳、间隔天数）由 Runtime 负责，不让模型猜。
5. 备课本对学生可见、可指正（学生决策权在记忆层的同构）。
6. 以加长的模拟学生长周期验收（10–15 课 / 3+ Plan）证明：重复构造消失、偏好不再
   蒸发、判断层被真实决策使用、撤回机制真实运转。

## 3. 非目标

- 不做向量库、图数据库、embedding 检索（外部调研确认：对数十节课规模是负资产）；
- 不做 BKT 或任何"能力真相"投影（判断层是教师的当前看法，不是系统认定的真相）；
- 不做算法调度器（遗忘曲线自动排期是 BKT 幽灵的方向）；
- 不做记忆内容的自动注入（INDEX.md 指针地图是唯一例外，见 8.1）；
- 不让 Tutor 读取或写入 `memory/`（冷启动纯洁性不动）；
- 不做后台自动派生判断（sleep-time 式独立策展角色是候选后续方向，不进首版）；
- 不做教学 Skill 的模型自改（模型只提变更建议，人审入库）；
- 不修改教学契约：Roadmap/Plan/Lesson 生命周期、Block 契约、Session 恢复不动；
- 不做跨学习集记忆（单学习集作用域）；不做多用户与权限；
- 不与学习集生产子项目设计接口（两个子项目独立演进）。

## 4. 证据基础

### 4.1 A 层：当前撑得住的（不要动）

- Roadmap 跨 Plan 决策：终验全程 0 次读 lesson 原文，决策质量无损——PLAN.md 的
  Current Position 聚合层在 2 Plan / 5 课规模够用；
- Plan 内课际记忆：每课完整重读上一课（约 50KB/课），Lesson 003 设计对前两课
  零事实错误；
- Tutor 单课执行：冷启动 + 文档驱动，零幻觉、零重复教学。

### 4.2 B 层：已实证缺口（本轮就发生）

**B1 学生侧身事实"根本没地方记"**（三条转录线独立确认）：学生说"晚上最多做一道、
不想留作业"——Tutor 口头接住但一字未写；不在 Classroom Log、PLAN.md、ROADMAP.md
任何一处；Coach 不知情地给下一课排了 5 任务/50–60 分钟；没出事纯属模板默认恰好
免作业（运气不是机制）。Plan 002 Coach 自行推断"不设强制作业"写入 PLAN.md——
推断碰巧正确，但机制无原则。情绪状态同样零持久化。

**B2 跨 Plan 函数级事实"静默丢失"**：Plan 002 Coach 自拟题 `q(t)=1/t−t+2ln t` 与
Plan 001 Lesson 002 学生已独立完成过的 `s(x)` 函数相同、导数相同。信息在系统里，
Coach 按设计看不到（Skill 明文："目录中未链接的文件不是该学生的历史"）。Reviewer
偶然自己读了学习集才抓到，而第二次 reviewer 的 prompt 明确禁止读学习集——唯一的
校验网只存在过一次。重复进了课堂，收口文本还把"独立完成辅助函数"当正向证据引用、
未标注 reviewer 警告：**错误证据沿 PLAN.md → ROADMAP.md 上浮**。

**B3 收口文本单点承重**：全部跨课记忆压在 Coach 手工写作的保真度上。它有损（帮助
粒度、中间判断、偏好全丢）、只留最新版（中间摘要被整节覆盖）、无 Schema 约束。
本轮写得保真所以无缝；写粗一次，系统性退化。

### 4.3 C 层：规模可预见爆发（5–20 课）

1. 学生跨课引用（"上次那道题"）→ Tutor 被迫在装失忆与编造之间二选一；
2. 复发模式盲：同一提醒给过 3 次、同一错误第 4 次复发，无人感知；
3. 间隔真实性："隔了三天"靠学生自报（墙钟实际 5 分钟），无法核验；
4. 逐跳压缩：函数级事实在摘要链上必然丢失，30 课后 Coach 对"学生做过什么构造"
   只剩几段梗概。

### 4.4 缺口性质与机制映射

| 缺口 | 性质 | 机制 |
| --- | --- | --- |
| 学生侧身事实 | 根本没地方记 | 新存储位置（登记），不是索引 |
| 函数级覆盖史 | 静默丢失 | 不压缩的覆盖登记，备课必查 |
| 收口单点承重 | 承重集中 | 判断层结构化 + 校验脚本加固 |

### 4.5 外部系统校准

对 9 个主流系统（MemGPT/Letta、sleep-time、A-MEM、Mem0、Zep/Graphiti、Generative
Agents、LangMem、ChatGPT memory、Claude MEMORY.md）与 2026 新爆项目（claude-mem、
MemPalace、GBrain、Hindsight、supermemory、cognee、OpenViking、Memori 等）及学术
前沿（TOKI、EvoMem、Anthropic Dreams 等）的调研结论：

1. **"可撤回的聚合判断"曾是全行业缺口**（九家里只有 Zep 做到），2026 年已成为学术
   前沿正式问题（TOKI 的写时并发控制与审计行、EvoMem 的撤回裁决）——本设计的
   supersedes 机制既有差异化又有学术对应物；
2. **append-only 原文 > 写入时有损压缩**已有公开数据证据（MemPalace 逐字模式
   96.6% 被独立复现，其压缩模式掉 12.4 分）；
3. **判断与事实分库存放**的最佳现成模板是 Hindsight 的 Opinion Network：判断 =
   {主张, 置信度, 证据引用, superseded_by}；
4. **整合/撤回机制必须落在可执行代码与校验脚本，不能只写在提示词里**——GBrain 的
   三大特性被独立审查判定为"Markdown 指令而非代码"，上线即坏；
5. **小索引常驻 + 细节按需**（Claude MEMORY.md 的 200 行/25KB 上限）是唯一接近
   本设计读取哲学的产品先例；
6. **后台整理 + 人审闭环**（Anthropic Dreams：写入独立输出仓、人审后接受/丢弃、
   原仓不受触碰）验证了判断层写入的未来形态；
7. **机械事实绕过 LLM 推断**（AWS strictly consistent metadata）与本设计的
   Runtime 时间戳同构；
8. **教育长周期"证据轨迹 + 可撤回 + 真实课堂"是确认空白**——DeepTutor/LOOM/
   IntelliCode 全是画像式记忆，本方向无竞品填位。

## 5. 总体架构

~~~text
事实层（append-only，只登记不判断）
  memory/coverage.md        覆盖登记：题目、构造、方法、帮助等级
  memory/retrieval.md       提取事件：计划/实际间隔、结果
  memory/student-facts.md   学生侧身事实：负担、情绪、偏好（带出处，可撤回）
       ▲ Coach 课后复盘逐课登记（Tutor 只写 Classroom Log，不碰 memory/）
判断层（profile 模式，可撤回）
  memory/judgments.md       当前判断区 + supersedes 历史区
       ▲ Coach 收口写 Plan 级判断；Roadmap 回流写跨 Plan 判断
消费层
  memory/INDEX.md           ≤50 行指针地图（注入 Coach/Roadmap 静态资源）
  Coach 备课读登记 → 烘入 lesson 文档 → Tutor 冷启动执行
  Roadmap 排期读 INDEX + judgments + PLAN.md 阶段总结
  学生经 Memory 页只读查看、可提出指正
~~~

### 5.1 与已消融旧 memory/ 的区别

本设计在学习集根新建 `memory/`。消融文档曾删除同名目录，必须讲清区别：

| 维度 | 旧 memory/（已消融） | 新 memory/（本设计） |
| --- | --- | --- |
| 内容 | 派生画像（BKT、能力投影、planner-attention） | 带出处的事实 + 可撤回判断 |
| 读取 | 编译注入上下文 | 永不注入（INDEX 指针地图除外） |
| 写入 | 多工具多路径 | 序列化角色 + 校验脚本硬规则 |
| 语义 | 判断=真相（陈旧投影污染决策） | 判断=可撤回的当前看法，历史永存 |

消融删除的是派生记忆；本设计加入的是登记与可撤回判断——消融文档的记忆阶梯本来就
预告了逐层加回，这不是反复，是按阶梯的证据规则履约。

## 6. 事实层

### 6.1 写入路径

- **Tutor 永远不碰 `memory/`**：它不知道 memory/ 存在。非任务事实的捕获靠扩展
  Classroom Log 写入纪律——负担、情绪、暂停请求、偏好**必须**记录进 lesson.md
  的 Classroom Log（B1 的修复点，tutor-lesson Skill 契约改动）。
- **登记发生在 Coach 课后复盘**：Coach 本来就会重读每节关闭的 lesson（终验实证），
  复盘时把事实提升到登记文件——**逐课登记，不等收口**，事实永远不经过收口的有损
  压缩。
- 写者按生命周期序列化（单用户、单激活节点），无并发写入。

### 6.2 `memory/coverage.md`（覆盖登记，append-only）

~~~text
- [2026-08-05] plans/plan-001/lessons/lesson-002.md#block-004 | 任务: 内联·ln(1+x)≤ax 商函数 | 构造: s(x)=1/x−x+2ln x | 方法: 参数分离、二次求导 | 帮助: 轻提示 | 结果: 完成
~~~

- **函数级构造必须写出**——q(t)≡s(x) 事件的直接修复；
- 方法、结构等术语必须来自 `graph/vocabulary.yaml`（可 grep、可被 lint 校验）；
- 帮助等级枚举：独立 / 轻提示 / 实质提示；结果枚举：完成 / 未完成；
- 任务为题卡时记录题卡 ID；内联题记录短签名。

### 6.3 `memory/retrieval.md`（提取事件，append-only）

~~~text
- [2026-08-05] plans/plan-001/lessons/lesson-003.md#block-001 | 内容: 条件检查族 | 计划间隔: 3d | 实际间隔: 3d | 结果: 独立
~~~

- 结果枚举：独立 / 轻提示 / 实质提示 / 失败；
- 实际间隔由 lesson frontmatter 的时间戳算出（见 6.5），lint 可重算校验；
- 非间隔检验的普通课次不产生本文件条目。

### 6.4 `memory/student-facts.md`（学生侧身事实，append-only，可撤回）

~~~text
- [2026-08-05] 晚间最多再做一道题、不接受成套作业 — 来源: plans/plan-001/lessons/lesson-002.md#block-006 | 学生陈述
~~~

- 每条必须带来源（lesson#block）与性质：学生陈述 / 教师观察 / 学生确认；
- 作废 = 追加一条新条目并标注 `supersedes:` 加旧条目的日期与原文引用（不设条目
  ID，避免事件级官僚化），旧条目永不删除；
- 只记侧身事实（负担、情绪、偏好、生活约束），不做能力判断——那是 judgments.md
  的职责。

### 6.5 机械时间戳

lesson frontmatter 增加 `started_at` / `closed_at`，由 Runtime 在生命周期切换时
自动盖写。模型拿不到"猜日期"的机会；"隔了三天"从学生自报变成机械事实。

## 7. 判断层

### 7.1 `memory/judgments.md` 结构

**当前判断区**（按 vocabulary.yaml 术语组织）：

~~~text
### 条件检查（method: condition-checking）
- 状态: 稳定
- 判断: 能在陌生中档题中独立执行端点/符号/参数方向检查
- 证据: [plans/plan-001/lessons/lesson-002.md#block-002, 2026-08-03] [plans/plan-001/lessons/lesson-003.md#block-003, 2026-08-05]
- 记录于: 2026-08-05 · 观察期: 2026-08-03 → 2026-08-05
~~~

状态枚举：稳定 / 形成中 / 脆弱 / 未见。

**历史区**（supersedes 日志，append-only）：被撤回的旧判断移入此处，每条以"术语
标题 + 记录日期"指向被撤回对象，附撤回理由与新证据。旧判断永不删除。

### 7.2 五条硬规则（全部落在校验脚本，不是提示词）

1. **无引用禁止入库**：每条判断必须引用至少一条事实（lesson#block 或登记条目），
   memory-lint 拒绝裸判断；
2. **更新 = 新判断 + 历史区追加撤回记录**，禁止就地编辑；
3. **双时态**：每条判断记"何时为真（观察期）"与"何时记录"两个日期；
4. **判断不复制事实**：只引用，不转述（杀重复语义）；
5. **写者序列化**：Coach 写 Plan 级判断（收口时，把现有 Current Position 散文负担
   重构为结构化记录），Roadmap 写跨 Plan 判断（回流时）；卫生检查只做 supersedes
   链维护与去重，不新写判断。

### 7.3 问题契约

备课本必须能回答的教师问题清单及其回答方式：

| 教师的问题 | 回答来源 |
| --- | --- |
| 学生会什么、不会什么 | judgments.md 状态字段 |
| 掌握哪些方法、知道哪些知识点 | judgments.md 按词表组织 |
| 哪个忘了几次、记住了几次 | retrieval.md 统计 |
| 做过哪些题目 | coverage.md |
| 学生有什么负担/偏好/边界 | student-facts.md |

## 8. 读取与消费契约

### 8.1 `memory/INDEX.md`（常驻小索引）

- ≤50 行硬上限（lint 强制）；只放：每个登记文件的一句话说明 + 当前进行判断的
  **指针**（如"当前脆弱项"清单，只指路不囤内容）；
- **INDEX.md 注入 Coach 与 Roadmap 的静态资源**——它是地图不是记忆内容，这是
  "永不注入"原则的唯一开口（Claude MEMORY.md 先例）；
- 四个登记文件永不注入；Tutor 永远拿不到 INDEX.md 与 memory/。

### 8.2 各角色读取规则

- **Coach 备课**：INDEX → 按需读登记文件；**出题前必查 coverage.md**（契约级规则）；
- **Roadmap 排期**：INDEX + judgments + 各 PLAN.md 阶段总结（现状已验证有效）；
- **Tutor**：不读 memory/；
- **学生**：本地直接读 Markdown，或经 Memory 页（第 9 节）。

### 8.3 烘焙机制

Coach 把相关判断与事实烘入 lesson 文档（Student View / Teacher Control）——M0 已
验证的机制，Coach 的信息源从"重读原文"升级为"读备课本"。Tutor 依然冷启动、没有
记忆，但 lesson 文档携带更准确的上下文。

### 8.4 Reviewer 规则（B2 修复）

- 任何 reviewer 的 prompt **不得禁止读学习集**（q/s 事件中第二次 reviewer 被禁读
  是事故）；
- reviewer 结论必须在 lesson 文档与收口证据条款中**显式处理**（吸收或反驳）——
  斩断错误证据上浮链路。

### 8.5 与现有文档的边界（每类信息只有一个家）

- **PLAN.md Current Position**：保留阶段总结（本阶段证明了什么——Plan 作用域真理），
  瘦身：学生状态判断不再展开，引用 judgments.md；
- **ROADMAP.md**：长期编排不变；学生状态引用 judgments.md；
- **Classroom Log**：课堂事实唯一原位（含扩展后的非任务事实）；
- **memory/**：跨课事实登记与学生状态判断的唯一位置。

### 8.6 提取调度

- Runtime 提供机械事实（时间戳、间隔天数）；
- Coach 备课读 retrieval.md 与覆盖日期 → 决定检验安排（何时检、检什么、独立还是
  提示），烘入 Teacher Control；
- Roadmap 在 Plan 边界安排长期间隔检验（正面回应它已记录的"长间隔保持"未知）；
- 无算法调度器。

### 8.7 卫生检查

- 触发：用户手动或 Plan 完成时；
- 职责：supersedes 链完整性、去重、判断引用存活检查（指向的事实仍存在）、INDEX
  刷新；
- 只维护不新写判断；v1 即 memory-lint 手动执行，自动化为后续候选。

## 9. 前端：Memory 页（学生可见）

M0 因不存在独立长期记忆而隐藏 Memory 页；本设计分阶段恢复：

- **只读视图**：学生/家长可看到备课本（判断、事实、覆盖史）；
- **指正入口**：学生可对某条判断或事实提出指正——指正成为 student-facts.md 的
  新条目（性质：学生陈述），不直接改记录；
- Course/Knowledge 页面结构不变；
- 这是学生决策权在记忆层的同构（ChatGPT memory summary 的教育版）。

## 10. Runtime 改动点

1. lesson frontmatter 增加 `started_at` / `closed_at`，生命周期切换时自动盖写；
2. Coach / Roadmap 静态资源装配增加 INDEX.md（Tutor 无）；
3. 新增 `memory-lint` 校验脚本：无引用拒绝、supersedes 链完整性、INDEX 行数上限、
   日期格式、词表术语有效性、间隔重算；
4. tutor-lesson Skill 契约：Classroom Log 写入纪律扩展（非任务事实必须记录）；
5. Coach / Roadmap Skill 契约：备课必查 coverage、判断写入规则、Reviewer 规则；
6. 测试夹具扩展 memory/ 样例；
7. Memory 页只读视图与指正入口。

不改：Session 种类、NodeKind 生命周期、教学文档契约、Session 恢复机制。

## 11. 错误处理

保持 M0 直接风格：

- memory-lint 校验失败：报告文件、行、原因，不自动修复；
- 判断引用失效（指向的事实被移动）：卫生检查报告，不静默；
- `memory/` 缺失或损坏：**教学路径不受影响**（Tutor 本来就没有它），Coach/Roadmap
  明示降级回 M0 纯文档模式——既有学习集（如 derivative-m0）无需迁移即可继续运行，
  初始化空 memory/ 后自动获得新能力；
- 不静默降级、不提供兼容适配器。

## 12. 测试

- 夹具：`tests/fixtures/` 学习集增加 memory/ 样例（四文件 + INDEX）；
- memory-lint 全规则单元测试（无引用拒绝、supersedes 链、INDEX 行数、日期格式、
  词表有效性、间隔重算）；
- 写入纪律契约测试：Tutor 资源装配不含 memory/ 任何东西，Coach/Roadmap 含 INDEX；
- frontmatter 时间戳自动盖写测试；
- Memory 页只读渲染与指正入口测试；
- `bun run check` 保持全绿。

## 13. 验收（模拟学生长周期）

比 M0 终验更长：10–15 课 / 3+ Plan，隐藏画像模拟学生，隔离运行根，安全停止条件，
不可改写证据。判据：

1. Coach 查 coverage 后**零重复构造**（对照 q/s 事件）；
2. 负担偏好类事实**不再蒸发**（student-facts 可查、被后续备课实际使用）；
3. 间隔检验按 retrieval 历史调度，实际间隔有机械记录；
4. 判断层被真实决策引用（备课提案、排期讨论中出现 judgments 引用）；
5. 至少一次撤回真实发生且 supersedes 链完整；
6. 污染检查：Session 转录中无任何登记文件内容被注入（INDEX 除外）；
7. "摘要代替原文"受控：Coach 读登记而非重读全部原文时，备课决策质量不降。

## 14. 实施阶段

1. **阶段 1：事实层**——三个登记文件 + Runtime 时间戳 + Classroom Log 纪律扩展 +
   memory-lint 骨架；
2. **阶段 2：判断层**——judgments.md + 五条硬规则校验 + INDEX.md 与静态资源注入；
3. **阶段 3：消费契约**——Coach/Roadmap 读取纪律、coverage 必查、烘焙升级、提取
   调度 + Memory 页只读视图与指正入口；
4. **阶段 4：模拟长周期验收**——按第 13 节执行并出报告。

每个阶段独立制定实施计划；阶段间依次依赖。

## 15. 与其他车道的协调

- 本设计与学习集生产子项目、开源硬化车道都触碰 `apps/pi-teaching-web`（硬化后将
  改名 `apps/studyforge`）的静态资源装配、Skill 契约、前端。实施前确认各车道状态，
  约定先后，避免并行改同一文件；
- 任何学习集可由本设计的初始化步骤建立空 memory/；既有学习集降级运行直至初始化；
- 与学习集生产子项目无接口：化学学习集是否带 memory/ 由本设计的初始化决定，不依赖
  生产 spec。

## 16. 已确认决策

- M1 的记忆系统与学习集生产为两个独立子项目，各自走 spec → plan → 实施循环；
- **两层全设计**：事实层 + 判断层 + 消费契约进入同一份 spec，实施分四阶段；
- **所有权层级写入**：Tutor 登记事实（经 Classroom Log）、Coach 写 Plan 级判断、
  Roadmap 写跨 Plan 判断，卫生检查只维护不新写；不新增独立策展角色；
- **提取调度 = 机械事实 + Coach 判断**：Runtime 盖时间戳与算间隔，Coach 备课做
  调度判断，Roadmap 管长期间隔；不做算法调度器；
- **文档拓扑 = memory/ 目录**：coverage.md / retrieval.md / student-facts.md /
  judgments.md + INDEX.md，每文件独立纪律与写者；
- **Tutor 完全不碰 memory/**，登记全走 Coach 课后复盘；
- **五条硬规则落在校验脚本**，不是提示词；
- **判断不复制事实，只引用**；
- **INDEX.md 注入 Coach/Roadmap 静态资源**是"永不注入"的唯一开口；
- **Memory 页恢复为只读视图 + 指正入口**（学生可见备课本）；
- 第一层记忆是**登记**而非阶梯原设想的索引——阶梯顺序被终验证据改写；
- 四节设计（事实层、判断层、消费契约、工程面）已在讨论中逐节确认。
