# StudyForge M1 记忆系统设计：认知建模网络（知识点痕迹与状态 + 认知特征 + 偏好）

**状态：** 草案（第四版。前三版的完备性机器——Log 条目 ID、covers 新鲜度体系、双端
引用、INDEX、待复核队列、Memory 页——已按"系统必须比它解决的问题小"原则拆除；
保留三轮审阅确认的所有权与事实纪律）

**日期：** 2026-08-06（第四版重写于 2026-08-07）

## 1. 核心判断

老师讲课时关心的只有三块东西：

1. **针对某个知识点的对象记忆和学习痕迹**——这个点上学生做过什么、错过什么、
   检验过什么、现在会到什么程度；
2. **学生自己的认知特征**——跨知识点的稳定模式（例如"面对陌生题立即展开、
   机械分类""把听懂当掌握"）；
3. **偏好建模**——负担、节奏、情绪、生活约束。

**整个备课过程就是在这张认知建模网络上行走**：从本课目标知识点出发，走到相关
节点，读痕迹与状态，带着特征与偏好做决策，再把决策烘进 lesson 文档。本设计只做
这一件事，不做保证一致性的机器。

现实约束（决定文档厚度）：本地单用户、一个学生、当前真实运行 5 节课。这个现实里，
新鲜度、并发、一致性几乎都是伪问题；**真实风险是维护成本超过使用价值，系统被悄悄
荒废**——与被消融的旧系统同一种死法。因此本设计只保留"纪律 + 文件"，校验机器
从零开始，哪个错误真实出现两次再为它写校验（沿用记忆阶梯的证据规则）。

底层证据不变（终验 8 Session 转录分析）：学生侧身事实零持久化（B1）、函数级覆盖史
静默丢失（B2）、收口文本单点承重（B3）；外部调研结论不变（可撤回判断、append-only
原文、机制不落提示词而落可执行处——但"可执行处"首先是 Runtime 的两个机械时间戳
与文件结构，不是 lint 帝国）。

## 2. 目标

1. 建立学习集级 `memory/`，以**知识点为锚**组织痕迹与状态，外加认知特征与偏好
   两个横切模型；
2. 课堂事实唯一原位仍是 Lesson Block；非任务事实（负担/情绪/暂停/偏好）必须被
   Tutor 记录（B1 修复）；
3. 痕迹含函数级构造，Coach 出题前必查（B2 修复）；
4. 状态/特征/偏好是**可撤回的判断**，每条带 Log 引用、带日期（B3 与愿景铁律）；
5. 备课与回流两条路径把这张网真正用起来。

## 3. 非目标

- 不做 Log 条目 ID 体系、不做快照版本头、不做新鲜度/陈旧检测、不做重建工作流、
  不做 INDEX、不做待复核队列、不做 `corrects:` 链（前三版的完备性机器，全部拆除）；
- 不做 lint（v1 用纪律与评审；哪个错误真实出现两次再为它写校验）；
- 不做 Memory 页（学生查看与指正推迟到独立小 spec）；
- 不做向量库/图数据库/embedding 检索、不做 BKT 能力真相、不做算法调度器；
- 不做任何常驻注入；Tutor 不读不写 `memory/`；
- 不修改教学契约与生命周期；不与生产子项目设计接口。

## 4. 认知建模网络

### 4.1 锚点

知识点节点沿学习集图谱词汇组织（`graph/vocabulary.yaml` 存在时用其术语；无图谱
学习集用自由主题词，化学早期同此）。节点之间的前置/相似/迁移关系沿学习集图谱；
无图谱时在条目里一句话注明（"相似：×××"），不建关系数据库。

### 4.2 每个知识点节点承载两样

- **学习痕迹**：这个点上做过什么——任务、函数级构造、帮助等级、检验事件（含
  "检验什么、隔了几天、结果"），每条带 Log 引用；
- **当前状态**：这个点上学生现在会怎样——证据量、趋势、模式（看见什么决定性
  结构知道可用）、反模式（知道什么近邻情形不能照搬）、触发条件、反证、引用。

### 4.3 两个横切模型

- **认知特征**：跨知识点的稳定模式，每条 = 模式描述 + 证据引用 + 观察次数；
- **偏好建模**：负担、节奏、情绪、生活约束，每条 = 内容 + 来源引用 + 性质
  （学生陈述/教师观察/学生确认）。

## 5. 文档与所有权（每样东西恰好一个家）

| 内容 | 位置 | 写者 | 性质 |
| --- | --- | --- | --- |
| 课堂原始事实（含非任务事实） | Lesson Block · Classroom Log | Tutor | append-only 事实 |
| 本 Plan 阶段判断 | PLAN.md Current Position | Coach | 自包含，不经 memory/ |
| 知识点学习痕迹 | `memory/traces.md` | Coach（逐课复盘重写） | 当前快照，不存历史 |
| 知识点当前状态 | `memory/knowledge.md` | **仅 Roadmap**（回流时） | 可撤回判断 |
| 认知特征 | `memory/traits.md` | **仅 Roadmap** | 可撤回判断 |
| 偏好建模 | `memory/preferences.md` | **仅 Roadmap** | 可撤回判断 |

**写入纪律：**

- Tutor：非任务事实必须进 Classroom Log（tutor-lesson Skill 契约）；永远不碰
  `memory/`；
- Coach：每节课关闭后的复盘（它本来就重读该课）中，把本课相关知识点节点的痕迹
  **整体重写**进 traces.md（快照式重写本身就是新鲜度机制，无需检测）；PLAN.md
  Current Position 照 M0 现状自包含书写；
- Roadmap：Plan 完成回流时更新 knowledge/traits/preferences——先读 Plan 总结，
  **引用什么读到什么**（引用哪条 Log 就必须实际下钻读到哪条）；更新 = 新判断 +
  撤回记录（撤回历史保留在各文件内，旧判断永不删除）；
- Coach 对 Roadmap 的三个文件**只读**；
- 引用格式为 `plan-00X/lesson-00X#block-00X`（M0 的 Block 坐标，不建 ID 体系；
  引用真断了再修）。

## 6. 消费：备课与回流两条路径

**备课路径（Coach）**：确定本课目标知识点 → 沿图谱找相关节点 → 读 knowledge.md
状态 + traces.md 痕迹 + traits/preferences → **出题前必查 traces 中的已有构造**
（q/s 事件修复）→ 决定教什么/复习什么/怎么支架 → 烘入 lesson 文档（Student View /
Teacher Control）。间隔检验由 Coach 依据 traces 中的检验记录与 lesson 日期判断
（无算法调度器）。

**回流路径（Roadmap）**：Plan 完成 → 读 PLAN.md 总结 → 按需下钻 → 更新三个模型
文件 → 写 ROADMAP.md 编排。

**纪律**：无任何常驻注入；Coach/Roadmap 在备课、收口、排期、回流等决策点主动读取
（Skill 契约承载纪律）；Reviewer prompt 不得禁止读学习集，reviewer 结论必须在
lesson 文档与收口证据条款中显式处理（吸收或反驳）。

**Runtime 只做两个机械字段**：lesson frontmatter 的 `started_at` / `closed_at`
（生命周期切换时自动盖写）——"隔了三天"从学生自报变成可计算事实。

## 7. 降级与错误

- `memory/` 缺失或损坏：教学路径不受影响（Tutor 本来就没有它），Coach/Roadmap
  明示降级回 M0 纯文档模式；PLAN.md 自包含使降级是结构性的；既有学习集无需迁移；
- traces.md 损坏：Coach 重读 Log 重写即可（快照可重生成）；
- 判断/痕迹引用断：读到时顺手修；不建检测系统；
- 不静默降级、不提供兼容适配器。

## 8. 测试

- 夹具：`tests/fixtures/` 学习集增加 memory/ 四个文件样例；
- 时间戳机械盖写测试（模型无法伪造）；
- 资源装配契约测试：Tutor 不含 memory/ 任何东西；Skill 文本含备课/回流读取纪律；
- `bun run check` 保持全绿；
- 无 lint 测试——v1 没有 lint。

## 9. 验收（模拟长周期，观察制）

10–15 课 / 3+ Plan，隐藏画像模拟学生，隔离运行根。**观察而非判据清单**：

1. Coach 备课是否真的沿着这张网走（读状态/痕迹/特征/偏好的证据在转录中）；
2. 旧构造是否被识别为复习/检验而非首次独立证据（对照 q/s 事件）；
3. 偏好类事实是否不再蒸发（Log 有捕获、备课有使用）；
4. Roadmap 回流是否真实更新了状态/特征/偏好，撤回是否发生过且历史保留；
5. **维护成本是否超过使用价值**（Coach 复盘重写痕迹的耗时与 token；这是本设计
  最现实的风险，必须量化记录）；
6. 无任何 memory/ 内容被常驻注入。

## 10. 实施阶段

1. **阶段 1：事实纪律**——Tutor 非任务事实写入契约 + Runtime 两个时间戳；
2. **阶段 2：痕迹**——traces.md + Coach 复盘重写工作流 + 出题必查纪律；
3. **阶段 3：模型**——knowledge/traits/preferences + Roadmap 回流更新 + Coach
   备课读取路径；
4. **阶段 4：模拟长周期观察**——按第 9 节执行并出报告。

每阶段独立实施计划。阶段 1 单独就有价值（B1 修复不依赖后面任何阶段）。

## 11. 与其他车道的协调

同前：本设计与生产子项目、开源硬化车道都触碰 `apps/pi-teaching-web`（硬化后改名
`apps/studyforge`）的 Skill 契约、Runtime、前端，实施前确认各车道状态、约定先后；
任何学习集可初始化空 memory/，既有学习集降级运行直至初始化。

## 12. 已确认决策

- **记忆系统的本质是三块**：知识点对象记忆与学习痕迹、学生认知特征、偏好建模；
  备课过程就是在这张认知建模网络上行走（用户原话定稿）；
- **系统必须比它解决的问题小**：本地单用户、一个学生、当前 5 节课的现实里，
  一致性机器是伪需求，维护成本超使用价值才是真实风险；
- **Lesson Block 唯一事实原位**；Tutor 记录非任务事实是 B1 的唯一修复点；
- **每样东西恰好一个家**：阶段判断在 PLAN.md（Coach，自包含）、痕迹在 traces.md
  （Coach 重写）、状态/特征/偏好在 memory/ 三文件（Roadmap 独占，Coach 只读）；
- **可撤回判断**：更新 = 新判断 + 撤回记录，旧判断永不删除，引用必须指到 Log
  （引用什么读到什么）；
- **痕迹含函数级构造，出题前必查**（B2 修复）；
- **快照整体重写即新鲜度**，不建版本头与检测系统；
- **Runtime 只做机械字段**（两个时间戳）；无 Log ID 体系，引用用 M0 的 Block 坐标；
- **无常驻注入**，决策点主动读取；Reviewer 规则保留；
- **v1 无 lint**：纪律与评审先行，错误真实出现两次再写校验（证据规则）；
- **Memory 页推迟**到独立小 spec；
- 前三版拆除清单（供未来读者理解为什么这些不存在）：Log 条目 ID、covers 头部与
  新鲜度 lint、陈旧判定与重建工作流、双端引用与间隔重算、INDEX.md、待复核队列、
  corrects: 链、五条硬规则 lint。
