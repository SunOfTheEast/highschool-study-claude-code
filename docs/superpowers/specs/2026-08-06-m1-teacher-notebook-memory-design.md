# StudyForge M1 记忆系统设计：教师备课本的语义蓝图

**状态：** 第五版语义蓝图，已完成教学语义与 Session 生命周期讨论；物理文件结构、
检索索引和 Runtime 工具契约等待开源记忆插件调研后另行定稿。

**日期：** 2026-08-06（第五版重写于 2026-08-07）

## 1. 核心判断

StudyForge 的记忆不是聊天记录摘要，也不是一份给学生贴标签的静态画像。它是教师在
备课和上课时使用的**认知建模网络**，回答三类问题：

1. **针对某个知识对象的学习痕迹与对象记忆**：学生在这里实际做过什么，现在学到
   哪里，哪些边界已形成，哪些仍未证明；
2. **学生自己的能力假设**：同一学习模式跨不同知识对象反复出现后，对学生怎样识别、
   迁移、检查和修正的暂定解释；
3. **偏好建模**：学生明确表达或多次确认的互动需求，包括负担、节奏、情绪状态和
   生活约束。

教师备课的过程，就是从当前需求出发，在这张网络上按需行走：先找相关对象，再读压缩
痕迹与当前状态；确有必要时才展开能力假设、偏好或原始证据。记忆最终服务于教学判断，
而不是为了把学生描述得尽可能完整。

持久记忆采用**学习集内的人类可读 Markdown**。Markdown 是可检查、可版本控制、可迁移
的事实与判断载体；未来即使加入数据库、embedding 或索引，它们也只能是可重建的检索
投影，不能成为唯一真相。

## 2. 五个语义边界

下面五个判断是整个系统的分类契约。

### 2.1 学习痕迹

**直接发生、可以复述的表现，是学习痕迹。**

例：

> 这道同构题中，提醒比较两个式子的共同结构后完成。

学习痕迹记录具体任务、首次表现、实际帮助、修正和结果。提示后完成不能润色成独立
完成，后来的成功也不能覆盖早先的错误。

### 2.2 对象记忆

**只回答某个知识对象学到哪里，是对象记忆。**

例：

> 能在明确提示下完成同构变形，尚未证明能自主识别。

“尚未证明”是一等状态。对象记忆不为了看起来完整而补满结论，也不从一次表现外推稳定
能力。

知识对象不只限于教材知识点，也可以是方法或结构，例如参数分离、端点与内点、同构
识别、三次函数结构。具体词汇由学习集决定。

### 2.3 能力假设

**跨不同知识对象反复出现、并用于解释学习方式的模式，才是能力假设。**

例：

> 题目表面形式变化后，不容易主动寻找不变量；经过对照后迁移较快。

同一对象内反复出现的模式仍属于对象记忆。一次 Lesson 可以提出能力信号，但不能凭一个
对象宣判长期能力。

### 2.4 偏好

**学生明确表达或多次确认的互动需求，是偏好。**

例：

> 近期不接受成套作业，希望每晚最多一道。

“使用对照讲解后学得更快”只是教学效果观察，不能自动写成“学生喜欢对照讲解”。只有
学生明确表达这种需求，才构成偏好事实。

偏好保留学生原话中的时间与适用范围：“今天”不升级为长期特征，“最近”不升级为永久
习惯。学生后来改变需求时，原始表达仍保留，当前适用的偏好可以更新。

### 2.5 教学待办

**教师打算以后怎样处理，是教学待办。**

例：

> 下节课用外观不同的结构做独立检验。

教学待办不是学生认知特征，不进入记忆模型。Plan 内待办属于 `PLAN.md` 的下一课安排，
跨 Plan 待办属于 `ROADMAP.md`。

## 3. 三层披露，不是三份真相

### L2：原始证据

课堂中发生的作答、帮助、修正和决定，按发生顺序进入 Lesson Classroom Log；Plan 或
Roadmap 对话中出现的新事实，则保留其真实 Session 来源。原始事实永不改写，只能追加
后续事实或纠正。

信息发生在哪个 Session，就绑定哪个 Session 的来源；不再把所有学生信息伪装成 Lesson
Log。

### L1：压缩记忆

压缩记忆包括：

- 能指回原始证据的学习痕迹；
- 某个对象当前学到哪里的对象记忆；
- 跨对象能力假设；
- 仍在适用范围内的偏好。

它保存当前教学真正需要的轨迹、边界和待检验点，而不是复制课堂流水。

### L0：召回线索

L0 是检索时先看到的一句话线索，用来判断某条 L1 是否值得展开。它是面向读者的投影，
不是另一份可独立修改的事实。

L0 是否物化为 Markdown 索引，还是由 L1 按需生成，等待开源记忆插件调研后决定。

## 4. 记忆形成的时间尺度

“生成记忆”包含三种不同动作：现场记录、课末固化和跨对象聚合。

| 内容 | 首次形成时机 | 后续变化时机 |
| --- | --- | --- |
| 原始课堂事实 | 课堂中发生时立即追加 | 永不修改，只追加后续事实或纠正 |
| 学习痕迹 | 每节 Lesson 课末反思后固化 | 新检验发生后延长认知轨迹 |
| 对象记忆 | 每节 Lesson 课末根据新痕迹更新 | 该对象出现新证据后更新 |
| 能力信号 | Lesson 课末可以提出候选 | 等待其他对象上的证据 |
| 工作能力假设 | 同一模式跨不同对象出现后，由 Plan 内 Coach 形成 | Plan 内修正，跨 Plan 再校准 |
| 长期能力假设 | Roadmap 回流时跨 Plan 巩固 | 强化、改写、削弱或撤回 |
| 偏好 | 学生明确表达或多次确认时 | 学生改变、确认或撤回时更新 |
| 教学待办 | 课后复盘或规划时 | 留在 Plan / Roadmap，不进入记忆 |

Roadmap 不是所有记忆的首次生成者。对象记忆必须在每节 Lesson 后形成，否则同一 Plan 的
下一节课无法利用上一节课的变化；Roadmap 负责更长时间尺度的再聚合。

## 5. Lesson：唯一一次课末反思与最小充分固化

### 5.1 正常课堂闭环

每节 Lesson 只进行一次正式课末反思，并且发生在 Tutor Session 内：

1. 课堂任务完成后，Tutor 根据已有证据做自然短回顾；
2. 学生说明哪里真正顺了、哪里仍不踏实，以及当下负担或需求；
3. Tutor 结合课堂事实形成有边界的判断；
4. Tutor 静默完成本课记忆固化；
5. Tutor 用正常教学语言公开简短总结，学生可以自然纠正；
6. 学生若纠正，Tutor 追加新事实并修订刚形成的判断；
7. 学生通过界面关闭 Lesson。

学生看到的是教师对本课的自然理解，不是“学习痕迹 / 对象记忆 / 能力信号”表单。这里
不增加正式批准门；但内部写入不得比公开总结作出更强的学生判断。

### 5.2 一次固化允许产生什么

只产生本课证据真正支持的内容：

- 值得未来找回的学习痕迹；
- 本课涉及对象的当前状态更新；
- 很有解释力、但仍待跨对象验证的能力信号；
- 学生明确表达的偏好事实及其适用范围。

一次固化不产生：

- 下一课安排；
- 教学待办；
- 跨对象能力定论；
- Roadmap 级长期判断。

没有任何类别配额。多数 Lesson 可能只有少量痕迹和一两个对象更新；没有能力信号或偏好
事实就不写。它是**最小充分固化**，不是课后报告。

### 5.3 当前 Session 只写不回读

Lesson 课末固化面向未来上下文。Tutor 写完后不把刚形成的记忆再次注入当前 Session；
学生纠正时依据当前对话与原始事实直接修订。记忆在跨 Session、上下文压缩后恢复或真实
教学需求触发时才被读取。

异常关闭时怎样补偿、怎样表示本课尚未完成固化，属于 Runtime 生命周期设计，等待结构
调研后定稿；异常路径不得阻塞学生结束课堂。

## 6. Plan：消费课堂记忆并共同决定下一课

### 6.1 学生决定何时继续

Lesson 关闭后，界面回到原 Plan，并显示“本课已经结束，课堂记忆已整理”。学生可以立即
点击“继续讨论下一课”，也可以隔一段时间再回来。

关闭 Lesson 不自动触发 Coach，也不隐含学生批准立即规划下一课。点击入口后，Runtime
只用结构化生命周期事件唤醒原 Plan Session并定位刚关闭的 Lesson；事件不携带记忆正文。

### 6.2 课后消费流程

学生选择继续后，Coach：

1. 读取本课固化结果；
2. 必要时读取相关对象的既有记忆、能力假设与偏好；
3. 形成教师判断并向学生公开；
4. 与学生讨论下一步真正需要解决的问题；
5. 学生确认下一课方案后，才更新 Plan 并准备下一 Lesson。

Plan 不再默认读取完整 Lesson，也不再例行询问一遍“哪里顺、哪里不踏实”。只有固化结果
缺失、内部冲突、学生提出具体纠正，或者高影响判断取决于帮助前后的细节时，才下钻原始
Lesson 或提出一个针对性问题。

Plan 的职责是**消费已经形成的课堂记忆、公开阶段判断，并与学生共同决定下一步**，不是
重新采访学生或重建整堂课。

### 6.3 Plan 内能力聚合

当相同模式已经跨不同知识对象出现时，Coach 可以在 Plan 内形成或修订工作能力假设，
使它立即服务后续 Lesson；证据仍只来自一个对象时，不得升级。

`PLAN.md Current Position` 继续保存本阶段决策所需的自包含总结。能力假设保存可跨 Plan
复用的认知模式及证据。二者服务不同生命周期，不互相替代，也不复制课堂流水。

## 7. Roadmap：跨 Plan 校准，而不是垄断记忆

Plan 完成回流时，Roadmap：

1. 先读取已完成 Plan 的阶段总结；
2. 查看该 Plan 中发生变化的对象记忆、能力假设和偏好；
3. 只有高影响判断或证据冲突时才下钻 Lesson；
4. 综合跨 Plan 表现，强化、改写、削弱或撤回长期能力假设；
5. 用这些判断与学生讨论下一个 Plan。

Roadmap 不重做每节课已经完成的痕迹提取与对象更新，也不是所有对象记忆、能力判断和偏好
的唯一写者。它处理的是跨 Plan 的时间尺度。

## 8. Lesson 课堂中的按需召回

Lesson 开始时默认只使用 Coach 已经烘入 Teacher Control 的本课条件，不常驻注入完整
学生画像。

学生出现预案外的典型错误或停点时，Tutor 按下面顺序处理：

1. 先判断当前课堂证据是否已经足够；
2. 不足时，按当前知识对象或错误表现检索记忆线索；
3. 先读相关对象记忆和学习痕迹；
4. 只有能力假设确实会改变眼前动作时才展开；
5. 只有压缩记忆不足以核查关键差异时才下钻原始证据；
6. 回到当前课堂，做一个与学生眼前表现成比例的教学动作。

旧记忆不能覆盖当前表现，也不能因为“以前犯过类似错误”就认定这次原因相同。记忆用于
选择讲解、对照或检验方式，不必把内部画像说给学生。本次新表现照常进入课堂记录，并在
课末参与下一次固化。

## 9. 偏好形成与更新

偏好事实可以发生在 Lesson、Plan 或 Roadmap。信息发生在哪里，就保留哪里的来源，并在
该 Session 的自然收口点进入记忆；不强行写回某个 Lesson。

偏好模型保留学生表达的真实作用范围：

- “今天”只控制当日安排；
- “最近”或“这个阶段”是有边界的阶段需求；
- 明确长期表达或多次确认，才形成较稳定偏好；
- 没有时间范围时，不擅自解释为永久人格特征。

原始表达永不删除。学生后来改变需求时，更新当前适用判断，并保留旧表达作为认知流变的
历史证据。

## 10. 语义所有权

| 内容 | 语义责任 |
| --- | --- |
| 原始课堂事实 | Tutor 在 Lesson 中按发生顺序记录，后续不能改写 |
| 其他 Session 新事实 | 发生它的 Plan / Roadmap Session 保留来源 |
| Lesson 学习痕迹 | Tutor 在唯一课末反思后固化 |
| 对象记忆 | Tutor 按本课新证据更新；后续证据可以修订当前状态 |
| 能力信号 | Tutor 可以提出候选，但不能从单对象升级为能力定论 |
| 工作能力假设 | Coach 在跨对象证据成立后形成并维护 |
| 跨 Plan 能力校准 | Roadmap 在回流时巩固、削弱或撤回 |
| 偏好事实 | 发生它的 Session 保留来源；模型只保留仍适用的解释 |
| 教学待办 | Coach / Roadmap 写入现有 Plan / Roadmap 位置，不进记忆 |
| 学生纠正 | 追加为新事实，并触发相关当前判断修订 |

角色名本身不是写入权限。实际工具应由 Runtime 根据当前学习集、Session、节点、时间和
来源绑定权限；模型只提交不可由 Runtime 推断的教学判断。具体 Markdown 文件归属、工具
输入和原子更新边界等待结构调研。

## 11. 修正与认知流变

- 原始 Log 和学生原话永不更新；纠正通过追加新事实表达。
- 学习痕迹保留首次表现、帮助、修正和结果，不能把链条压成只有最终成功。
- 对象记忆、能力假设和偏好都是可撤回的当前判断，不是事实本身。
- 新证据出现后，可以更新当前判断，但必须仍能回到形成它的原始证据。
- “尚未证明”不能被空白补全，也不能被一次成功自动改成“已经掌握”。
- 当前表现优先于旧模型；旧模型与新表现冲突时先保留冲突，再设计负责的检验。

物理上怎样表示修订历史、稳定引用和跨文件关系，等待插件调研；这里先固定不可违反的
语义。

## 12. 与现有上下文机制的统一

当前 Roadmap、Plan、Lesson 是独立 Session；Plan Session 会跨多节 Lesson 持续存在。
记忆正好承担 Session 与压缩边界之间的状态交接：

```text
Lesson 内产生事实
        ↓
唯一课末反思后固化记忆
        ↓
当前 Tutor Session 只写不回读
        ↓
学生明确选择继续后，Plan 按需读取
        ↓
新 Lesson 只获得本课需要的 Teacher Control
        ↓
现场出现新需求时再按需召回
        ↓
Plan 与 Roadmap 在不同尺度继续聚合
```

因此记忆是 checkpoint，不是自动注入层：

- 不把 memory 常驻注入任何角色；
- 不在刚写完的 Session 中自动回读；
- 不同时默认读取压缩记忆与它对应的完整 Lesson；
- 新 Session、上下文压缩恢复或真实决策需求出现时才披露；
- 原始 Lesson 只在冲突、高影响判断或压缩不足时下钻。

在这条主线上，不需要先发明 `Lesson delta`、披露 epoch 或自动去重账本。

## 13. Markdown 方向与结构调研边界

已经确认：持久记忆使用 Markdown，位于学习集内，能够被人直接阅读、版本控制和迁移。

尚未确认，必须先调研开源记忆插件：

- 按类型集中、按对象拆分，还是按 Lesson 情境拆分；
- L0 索引是否持久化，怎样从 L1 重建；
- 一条痕迹连接多个对象时怎样避免内容复制；
- Markdown 中的稳定引用、修订与撤回怎样表达；
- Tutor、Coach、Roadmap 的结构化工具边界；
- 异常关闭、补偿固化和幂等写入；
- compaction 后怎样恢复正在使用的记忆；
- 是否需要全文检索、embedding 或派生数据库；
- 如何观测召回内容、耗时、token 和教学效果。

调研开源插件时优先检查：Markdown / local-first 支持、渐进披露、来源引用、修订语义、
生命周期 hook、多 Agent 读写边界、可观测性，以及在无 embedding 时能否正常降级。不要
因为某个插件已有 schema，就反过来修改本设计已经确认的教学语义。

## 14. 语义验收

结构实现后，用真实长周期观察下列结果：

1. 每节 Lesson 是否只有一次正式课末反思；
2. 课末事实、偏好和首次表现是否真实进入持久记忆；
3. Tutor 是否只在真实课堂需求出现时按需召回；
4. 当前表现是否始终优先于旧模型；
5. Plan 是否消费固化结果而不是重读整课、重复采访学生；
6. 能力假设是否确实建立在跨对象证据上；
7. Roadmap 是否在跨 Plan 尺度修订判断，而不是重做逐课提取；
8. 教学效果观察、偏好、教学待办和能力假设是否保持边界；
9. 是否没有任何 memory 内容被常驻注入或在原 Session 中自动回读；
10. 维护成本与响应时间是否仍小于记忆带来的教学价值。

## 15. 已确认决策与待调研项

### 已确认

- 记忆的三块核心是对象记忆与学习痕迹、能力假设、偏好建模；
- 五个语义边界按 §2 执行；
- 持久记忆使用学习集内的人类可读 Markdown；
- 每节 Lesson 只有一次正式课末反思；
- Tutor 在反思后进行最小充分固化，并公开自然总结供学生纠正；
- 当前 Session 只写不回读；记忆是跨 Session 与 compaction 边界的 checkpoint；
- Lesson 关闭后由学生选择是否点击“继续讨论下一课”；
- Plan 读取固化记忆，不默认重读 Lesson，也不重复询问学生整堂课；
- 对象记忆逐 Lesson 更新，能力假设在跨对象证据成立时形成；
- Roadmap 负责跨 Plan 校准，不垄断所有记忆判断；
- Tutor 可在预案外错误出现时按需召回，当前表现优先；
- 偏好保留学生表达的时间范围，教学效果观察不能冒充偏好；
- 教学待办留在 Plan / Roadmap，不进入学生记忆；
- 不需要 `Lesson delta`、披露 epoch 或自动去重账本作为设计前提。
