# StudyForge M1 记忆系统设计：教师备课本（唯一事实原位 + 可重建投影 + 可撤回判断）

**状态：** 草案（已经两轮用户审阅并修订：投影化、去注入、快照化、判断字段重构、词表条件化、验收门修正）

**日期：** 2026-08-06

**实施路线：** Lesson Block 唯一事实原位 + `memory/` 可重建登记投影 + 可撤回判断层；分四阶段实施

## 1. 背景与核心判断

M0 的文档原生记忆消融建立了一个干净基线：课堂事实只写在 Lesson Block，父 Agent
直接读原始 Markdown，没有任何派生记忆。消融设计同时留下一条**记忆阶梯**（M1 来源
索引 → M2 局部压缩 → M3 跨 Plan 长期记忆 → M4 能力聚合），并规定每次升级必须
"先在至少两节真实课堂中观察到相同缺口"。

M1 阶段包含两个独立子项目：学习集生产与记忆系统。本设计只覆盖**记忆系统**。

为回答"第一级记忆到底该是什么"，我们对 M0 终验运行（2 Plan / 5 Lesson，模拟学生）
的全部 8 个 pi-agent Session 转录做了逐线分析（见第 4 节）。核心发现：

> 实证缺口的形状**都不是索引**。缺口是"根本没记"（学生侧身事实零持久化）、
> "记了就丢"（函数级覆盖史在摘要压缩中静默丢失）和"承重集中"（全部跨课记忆压在
> Coach 手工收口文本上）。

但第一轮设计（登记文件直接保存事实内容）在审阅中被证明会重新制造两份事实：登记
一旦保存构造、帮助等级、结果，上游 Classroom Log 被更正后，登记与判断层的旧结论
就会继续上浮——与被诊断的污染同构。因此本设计的根本所有权规则是：

> **Lesson Block 是唯一原始事实。`memory/` 不保存第二套事实——它是可重建的当前
> 快照投影（帮模型找到事实）与可撤回的 judgment（教师对学生的当前看法）。判断
> 必须最终指回具体 Classroom Log 条目。**

系统的外部形态是**教师备课本**：一个教了几十节课的老师脑子里对学生的那幅活画像——
会什么、不会什么、掌握哪些方法、知道哪些知识点、哪个忘了几次、哪个记住了几次、
做过哪些题。备课本分两层（都建立在唯一事实原位之上）：

- **投影层**：可重建的当前快照（做过什么题、提取检验结果、学生说过什么），
  每条指回 Log 条目，负责**找**，不负责**是**；投影不保存自己的历史——全部历史
  已经在 append-only Classroom Log 中；
- **判断层**：教师当前对学生的看法（会/不会、方法掌握、知识点状态），每条带证据
  引用、注明日期、**可撤回**——撤回不删除历史，判断的撤回历史是备课本中唯一的
  append-only 区。

这两层守住愿景文档的铁律：课堂 Event 是不可改写的原始事实；知识点状态、趋势、
误区与掌握只能是可撤回的聚合判断，不能反过来覆盖原始事件。

## 2. 目标

1. Classroom Log 承重条目获得 Runtime 机械绑定的稳定 ID 与时间，使跨课引用有
   可靠坐标（模型不填写机械字段）。
2. 建立学习集级 `memory/` 投影目录，修复三个已实证缺口：学生侧身事实零持久化、
   函数级覆盖史静默丢失、收口文本单点承重——投影可重建，不成为第二套事实。
3. 判断层以结构化记录承载"教师对学生的当前看法"，每条引用 Log 条目、带日期、
   可撤回；写入走所有权层级（Tutor 事实 → Coach Plan 级判断 → Roadmap 跨 Plan
   判断）。
4. 消费契约：记忆内容零常驻注入；Coach 出题前必查覆盖投影；判断继续经 lesson
   文档烘焙服务 Tutor 冷启动。
5. 机械事实（时间戳、条目 ID、间隔天数）由 Runtime 负责，不让模型猜。
6. 备课本对学生可见、可指正（学生决策权在记忆层的同构）。
7. 以加长的模拟学生长周期验收（10–15 课 / 3+ Plan）证明：旧构造不被误判为首次
   独立证据、偏好不再蒸发、判断层被真实决策使用、撤回与重建真实运转。

## 3. 非目标

- 不让 `memory/` 成为第二套事实（投影必须可重建、指回 Log 条目）；
- 不做向量库、图数据库、embedding 检索（外部调研确认：对数十节课规模是负资产）；
- 不做 BKT 或任何"能力真相"投影（判断层是教师的当前看法，不是系统认定的真相）；
- 不做算法调度器（遗忘曲线自动排期是 BKT 幽灵的方向）；
- 不做记忆内容的任何常驻注入（静态资源注入会随长缓存 Session 过期；改为决策点
  主动读取，见 8.1）；
- 不让 Tutor 读取或写入 `memory/`（冷启动纯洁性不动）；
- 不做后台自动派生判断（sleep-time 式独立策展角色是候选后续方向，不进首版）；
- 不做教学 Skill 的模型自改（模型只提变更建议，人审入库）；
- 不修改教学契约：Roadmap/Plan/Lesson 生命周期、Block 契约、Session 恢复不动；
- 不做跨学习集记忆（单学习集作用域）；不做多用户与权限；
- 不与学习集生产子项目设计接口（两个子项目独立演进）。

## 4. 证据基础

### 4.1 A 层：当前撑得住的（不要动）

- Roadmap 跨 Plan 决策：终验全程 0 次读 lesson 原文，决策质量无损——PLAN.md 的
  Current Position 聚合层在 2 Plan / 5 课规模够用；
- Plan 内课际记忆：每课完整重读上一课（约 50KB/课），Lesson 003 设计对前两课
  零事实错误；
- Tutor 单课执行：冷启动 + 文档驱动，零幻觉、零重复教学。

### 4.2 B 层：已实证缺口（本轮就发生）

**B1 学生侧身事实"根本没地方记"**（三条转录线独立确认）：学生说"晚上最多做一道、
不想留作业"——Tutor 口头接住但一字未写；不在 Classroom Log、PLAN.md、ROADMAP.md
任何一处；Coach 不知情地给下一课排了 5 任务/50–60 分钟；没出事纯属模板默认恰好
免作业（运气不是机制）。Plan 002 Coach 自行推断"不设强制作业"写入 PLAN.md——
推断碰巧正确，但机制无原则。情绪状态同样零持久化。

**B2 跨 Plan 函数级事实"静默丢失"**：Plan 002 Coach 自拟题 `q(t)=1/t−t+2ln t` 与
Plan 001 Lesson 002 学生已独立完成过的 `s(x)` 函数相同、导数相同。信息在系统里，
Coach 按设计看不到（Skill 明文："目录中未链接的文件不是该学生的历史"）。Reviewer
偶然自己读了学习集才抓到，而第二次 reviewer 的 prompt 明确禁止读学习集——唯一的
校验网只存在过一次。重复进了课堂，收口文本还把"独立完成辅助函数"当正向证据引用、
未标注 reviewer 警告：**错误证据沿 PLAN.md → ROADMAP.md 上浮**。

**B3 收口文本单点承重**：全部跨课记忆压在 Coach 手工写作的保真度上。它有损（帮助
粒度、中间判断、偏好全丢）、只留最新版（中间摘要被整节覆盖）、无 Schema 约束。
本轮写得保真所以无缝；写粗一次，系统性退化。

### 4.3 C 层：规模可预见爆发（5–20 课）

1. 学生跨课引用（"上次那道题"）→ Tutor 被迫在装失忆与编造之间二选一；
2. 复发模式盲：同一提醒给过 3 次、同一错误第 4 次复发，无人感知；
3. 间隔真实性："隔了三天"靠学生自报（墙钟实际 5 分钟），无法核验；
4. 逐跳压缩：函数级事实在摘要链上必然丢失，30 课后 Coach 对"学生做过什么构造"
   只剩几段梗概。

### 4.4 缺口性质与机制映射

| 缺口 | 性质 | 机制 |
| --- | --- | --- |
| 学生侧身事实 | 根本没地方记 | Log 捕获纪律 + 学生事实投影 |
| 函数级覆盖史 | 静默丢失 | 覆盖投影（函数级、指回 Log），备课必查 |
| 收口单点承重 | 承重集中 | 判断层结构化 + 校验脚本加固 |

### 4.5 外部系统校准

对 9 个主流系统（MemGPT/Letta、sleep-time、A-MEM、Mem0、Zep/Graphiti、Generative
Agents、LangMem、ChatGPT memory、Claude MEMORY.md）与 2026 新爆项目（claude-mem、
MemPalace、GBrain、Hindsight、supermemory、cognee、OpenViking、Memori 等）及学术
前沿（TOKI、EvoMem、Anthropic Dreams 等）的调研结论：

1. **"可撤回的聚合判断"曾是全行业缺口**（九家里只有 Zep 做到），2026 年已成为学术
   前沿正式问题（TOKI 的写时并发控制与审计行、EvoMem 的撤回裁决）——本设计的
   supersedes 机制既有差异化又有学术对应物；
2. **append-only 原文 > 写入时有损压缩**已有公开数据证据（MemPalace 逐字模式
   96.6% 被独立复现，其压缩模式掉 12.4 分）；
3. **判断与事实分库存放**的最佳现成模板是 Hindsight 的 Opinion Network：判断 =
   {主张, 置信度, 证据引用, superseded_by}；
4. **整合/撤回机制必须落在可执行代码与校验脚本，不能只写在提示词里**——GBrain 的
   三大特性被独立审查判定为"Markdown 指令而非代码"，上线即坏；
5. **小索引常驻 + 细节按需**（Claude MEMORY.md）曾是接近本设计读取哲学的产品先例；
   但静态注入会随长缓存 Session 过期，本设计进一步改为决策点主动读取（见 8.1）；
6. **后台整理 + 人审闭环**（Anthropic Dreams）验证了判断层写入的未来形态；
7. **机械事实绕过 LLM 推断**（AWS strictly consistent metadata）与本设计的
   Runtime 时间戳/条目 ID 同构；
8. **教育长周期"证据轨迹 + 可撤回 + 真实课堂"是确认空白**——DeepTutor/LOOM/
   IntelliCode 全是画像式记忆，本方向无竞品填位。

## 5. 总体架构

~~~text
唯一事实原位（append-only，Runtime 机械绑定 ID 与时间）
  Lesson Block · Classroom Log
       │ 引用（log entry ID）
       ▼
投影层（可重建的当前快照，负责"找"不负责"是"）
  memory/coverage.md        覆盖快照：题目、构造、方法、帮助等级 → 指回 Log 条目
  memory/retrieval.md       提取事件快照：计划/实际间隔、结果 → 指回 Log 条目
  memory/student-facts.md   学生事实快照：负担、情绪、偏好 → 指回 Log 条目
       │ Coach 复盘提取，Runtime 原子替换；上游更正时陈旧段先重建再读
       ▼
判断层（profile 模式，可撤回）
  memory/judgments.md       当前判断区（快照式更新）+ supersedes 历史区（append-only）
       │ 引用 Log 条目（投影帮助定位，永远不作为引用对象）
       ▲ Coach 收口写 Plan 级判断；Roadmap 回流写跨 Plan 判断
消费层（零常驻注入）
  memory/INDEX.md           ≤50 行指针地图（当前快照），决策点主动读取
  Coach 备课读投影 → 烘入 lesson 文档 → Tutor 冷启动执行
  Roadmap 排期读 INDEX + judgments + PLAN.md 阶段总结
  学生经 Memory 页只读查看、可提出指正
~~~

### 5.1 与已消融旧 memory/ 的区别

本设计在学习集根新建 `memory/`。消融文档曾删除同名目录，必须讲清区别：

| 维度 | 旧 memory/（已消融） | 新 memory/（本设计） |
| --- | --- | --- |
| 内容 | 派生画像（BKT、能力投影、planner-attention） | 可重建投影（指回 Log）+ 可撤回判断 |
| 与事实关系 | 派生物即真相（第二套事实） | 事实唯一在 Log；投影可重建，判断可撤回 |
| 读取 | 编译注入上下文 | 零常驻注入，决策点主动读取 |
| 写入 | 多工具多路径 | 序列化角色 + 校验脚本硬规则 |
| 语义 | 判断=真相（陈旧投影污染决策） | 判断=当前看法，历史永存 |

消融文档"不建立事件 ID"一条在此修订：承重 Classroom Log 条目由 **Runtime** 在写入
时机械绑定稳定 ID 与时间（模型不填），因为投影与判断现在需要耐久的引用坐标——
这不是恢复事件级官僚化，机械字段不经模型。

## 6. 投影层（可重建的当前快照）

三个投影文件都是**当前可重建快照**：不保存自己的历史（全部历史已在 append-only
Classroom Log 中），每次逐课提取或卫生检查由 Runtime **原子替换**（复用
`mutateDocumentAtomically` 原语）。这消除一个致命组合——若投影 append-only 又允许
陈旧，grep 会永远新旧同召回，旧结论沿读取结果再次上浮。

**快照头部契约**（每个投影文件）：

~~~text
---
generated_at: 2026-08-05T19:30:00Z
covers:
  plan-001/lesson-001: e7
  plan-001/lesson-002: e5
  plan-001/lesson-003: e4
---
~~~

`covers` 按课记录本快照覆盖到的最后 Log 条目 ID。lint 对比头部与 Log 现状即可
**机械判定**哪些课的段落已陈旧（该课出现了头部之后的新条目或更正条目）——不需要
模型判断。一条 lesson-002 的更正只让源于该课的投影段陈旧，不错杀全文件。

### 6.1 事实捕获与快照生成

- **Tutor 永远不碰 `memory/`**：非任务事实的捕获靠扩展 Classroom Log 写入纪律——
  负担、情绪、暂停请求、偏好**必须**记录进 lesson.md 的 Classroom Log（B1 的修复
  点，tutor-lesson Skill 契约改动）。Log 是唯一事实原位。
- **快照更新发生在 Coach 课后复盘**：Coach 本来就会重读每节关闭的 lesson（终验
  实证），复盘时把承重事实提取进投影——逐课提取，由 Runtime 原子替换文件并刷新
  头部 `covers`。
- 每条投影条目必须引用来源 Log 条目 ID；lint 校验引用可解析。
- 写者按生命周期序列化（单用户、单激活节点），无并发写入。

### 6.2 `memory/coverage.md`（覆盖快照）

~~~text
- [2026-08-05] log:plan-001/lesson-002#block-004:e3 | 任务: 内联·ln(1+x)≤ax 商函数 | 构造: s(x)=1/x−x+2ln x | 方法: 参数分离、二次求导 | 帮助: 轻提示 | 结果: 完成
~~~

- **函数级构造必须写出**——q(t)≡s(x) 事件的直接修复；
- 方法、结构等术语：**学习集含 `graph/vocabulary.yaml` 时**必须取自词表（lint
  校验）；**无图谱学习集**允许自由术语，lint 降级为只校验格式（化学学习集早期、
  极简学习集因此可用）；
- 帮助等级枚举：独立 / 轻提示 / 实质提示；结果枚举：完成 / 未完成；
- 任务为题卡时记录题卡 ID；内联题记录短签名。

### 6.3 `memory/retrieval.md`（提取事件快照）

~~~text
- [2026-08-05] log:plan-001/lesson-003#block-001:e1 | 内容: 条件检查族 | 计划间隔: 3d | 实际间隔: 3d | 结果: 独立
~~~

- 结果枚举：独立 / 轻提示 / 实质提示 / 失败；
- 实际间隔由 lesson frontmatter 的时间戳算出（见 6.5），lint 可重算校验；
- 非间隔检验的普通课次不产生本文件条目。

### 6.4 `memory/student-facts.md`（学生事实快照）

~~~text
- [2026-08-05] log:plan-001/lesson-002#block-006:e2 | 晚间最多再做一道题、不接受成套作业 | 学生陈述
~~~

- 每条必须引用来源 Log 条目 ID，并标注性质：学生陈述 / 教师观察 / 学生确认；
- 只投影侧身事实（负担、情绪、偏好、生活约束），不做能力判断——那是 judgments.md
  的职责；
- 快照条目**不建 supersedes 链**：更正发生在上游 Log（append-only 更正条目），
  快照经陈旧判定与重建反映更正（见 6.6）。

### 6.5 机械字段：条目 ID 与时间戳

- Runtime 在 `classroom_log_append` 写入时为每条 Log 条目机械绑定**稳定 ID**（格式
  实施时定，如 `<block>#e<seq>`）与**时间戳**；模型不填写；条目 ID 在 lesson 内
  唯一，跨学习集的完整引用为 `log:<plan>/<lesson>#<条目ID>`（lesson ID 只在父
  Plan 内唯一，lint 按此规则校验引用可解析、无歧义）；
- lesson frontmatter 增加 `started_at` / `closed_at`，生命周期切换时自动盖写；
- Log 更正条目必须引用被更正条目 ID（`corrects:` 约定，模型声明，lint 校验存在性）。

### 6.6 上游更正 → 快照陈旧判定与重建

- lint 对每个投影文件做新鲜度检查：某课在 Log 中出现了快照头部 `covers` 之后的
  新条目或更正条目 → 源于该课的投影段**判定陈旧**；
- **陈旧段不得进入普通读取结果**。决策点读取协议为机械三步（写在 Coach/Roadmap
  Skill 契约里，由 lint 强制执行，不靠 Agent 自觉跳过）：lint 新鲜度检查 →
  陈旧段先重建 → 再读；
- 重建 = Coach 重读相关课的 Log、重新提取，Runtime 原子替换快照并刷新头部；重建
  不触碰 Log；
- 判断层引用的 Log 条目被更正时，相关判断进入"待复核"（卫生检查报告），由 Coach
  或 Roadmap 在下一个决策点处理——撤回或确认。

## 7. 判断层

### 7.1 `memory/judgments.md` 结构

**当前判断区**（按主题组织；词表存在时按词表术语）：

~~~text
### 条件检查
- 证据量: 多次（跨 3 课）
- 趋势: 稳定
- 模式: 看见端点/除式/参数方向等决定性结构，知道必须先检查再计算
- 反模式: 内点极值条件不能照搬到端点（边界：定义域含端点时）
- 触发条件: 含参数的不等式与根数问题
- 反证: 无
- 引用: [log:plan-001/lesson-002#block-002:e4, 2026-08-03] [log:plan-001/lesson-003#block-003:e2, 2026-08-05]
- 记录于: 2026-08-05 · 观察期: 2026-08-03 → 2026-08-05
~~~

字段分轴：**证据量**（未见 / 单次 / 多次）与**趋势**（形成中 / 稳定 / 脆弱）分开，
不混在一个枚举里；**模式**（看见决定性结构知道可用）与**反模式**（知道近邻情形
不能照搬及决定性差异）对齐愿景 §4.2 的掌握两方向；**触发条件**与**反证**显式成
字段，不埋在散文里。

**历史区**（supersedes 日志，append-only）：被撤回的旧判断移入此处，每条以"主题
标题 + 记录日期"指向被撤回对象，附撤回理由与新证据。旧判断永不删除。**这是
memory/ 中唯一的 append-only 区**——判断不可重建（它们是教师的判断而非事实的
视图），其撤回史本身就是证据；三个投影快照与 INDEX.md 都是当前快照，不保存历史。

### 7.2 五条硬规则（全部落在校验脚本，不是提示词）

1. **无引用禁止入库**：每条判断必须引用至少一条 Log 条目 ID，lint 拒绝裸判断，
   也拒绝以投影条目为引用对象（投影只帮助定位）；
2. **更新 = 新判断 + 历史区追加撤回记录**，禁止就地编辑；
3. **双时态**：每条判断记"何时为真（观察期）"与"何时记录"两个日期；
4. **判断不复制事实**：只引用，不转述（杀重复语义）；
5. **写者序列化**：Coach 写 Plan 级判断（收口时，把现有 Current Position 散文负担
   重构为结构化记录），Roadmap 写跨 Plan 判断（回流时）；卫生检查只做 supersedes
   链维护与去重，不新写判断。

### 7.3 问题契约

备课本必须能回答的教师问题清单及其回答方式：

| 教师的问题 | 回答来源 |
| --- | --- |
| 学生会什么、不会什么 | judgments.md（证据量/趋势/模式/反模式） |
| 掌握哪些方法、知道哪些知识点 | judgments.md 按主题组织 |
| 哪个忘了几次、记住了几次 | retrieval.md 统计 |
| 做过哪些题目 | coverage.md |
| 学生有什么负担/偏好/边界 | student-facts.md |

投影负责把这些问题**指回** Log 原文；回答的引用对象永远是 Log 条目。

## 8. 读取与消费契约

### 8.1 `memory/INDEX.md`：决策点主动读取，零常驻注入

静态资源只在 Session 打开时加载，而 Plan/Roadmap Session 长期缓存——INDEX.md 若
作为静态资源注入会迅速过期。因此：

- **INDEX.md 不注入任何 Session**；"记忆内容零常驻注入"无例外；
- INDEX.md 保持 ≤50 行硬上限（lint 强制），只放每个投影文件的一句话说明与当前
  进行判断的指针（只指路不囤内容）；
- **读取纪律由 Skill 契约承载**（纪律不是记忆内容）：Coach 在备课、收口前，
  Roadmap 在排期、回流前，必须先读 INDEX.md 并按需读投影与判断；
- Tutor 永远拿不到 INDEX.md 与 memory/。

### 8.2 各角色读取规则

- **Coach 备课**：读 INDEX → lint 新鲜度检查 → 陈旧段先重建 → 按需读快照与判断；
  **出题前必查 coverage.md**（契约级规则）；
- **Roadmap 排期**：INDEX + judgments + 各 PLAN.md 阶段总结（现状已验证有效）；
- **Tutor**：不读 memory/；
- **学生**：本地直接读 Markdown，或经 Memory 页（第 9 节）。

### 8.3 烘焙机制

Coach 把相关判断与事实烘入 lesson 文档（Student View / Teacher Control）——M0 已
验证的机制，Coach 的信息源从"重读原文"升级为"读备课本投影与判断"。Tutor 依然
冷启动、没有记忆，但 lesson 文档携带更准确的上下文。

### 8.4 Reviewer 规则（B2 修复）

- 任何 reviewer 的 prompt **不得禁止读学习集**（q/s 事件中第二次 reviewer 被禁读
  是事故）；
- reviewer 结论必须在 lesson 文档与收口证据条款中**显式处理**（吸收或反驳）——
  斩断错误证据上浮链路。

### 8.5 与现有文档的边界（每类信息只有一个家）

- **Classroom Log**：课堂事实唯一原位（含扩展后的非任务事实；承重条目有稳定 ID）；
- **memory/**：跨课定位投影与可撤回判断的唯一位置（不是第二套事实）；
- **PLAN.md Current Position**：保留阶段总结（本阶段证明了什么——Plan 作用域
  总结），瘦身：学生状态判断不再展开，引用 judgments.md；
- **ROADMAP.md**：长期编排不变；学生状态引用 judgments.md。

### 8.6 提取调度

- Runtime 提供机械事实（时间戳、条目 ID、间隔天数）；
- Coach 备课读 retrieval.md 与覆盖日期 → 决定检验安排（何时检、检什么、独立还是
  提示），烘入 Teacher Control；
- Roadmap 在 Plan 边界安排长期间隔检验（正面回应它已记录的"长间隔保持"未知）；
- 无算法调度器。

### 8.7 卫生检查

- 触发：用户手动或 Plan 完成时；
- 职责：supersedes 链完整性、快照与判断引用的存活检查、新鲜度复算（上游更正后
  的陈旧判定与待复核清单）、去重、INDEX 刷新；
- 只维护不新写判断；v1 即 memory-lint 手动执行，自动化为后续候选。

## 9. 前端：Memory 页（学生可见）

M0 因不存在独立长期记忆而隐藏 Memory 页；本设计分阶段恢复：

- **只读视图**：学生/家长可看到备课本（判断、投影、覆盖史）；
- **指正入口**：学生可对某条判断或投影提出指正。指正由 Runtime 暂存为待处理条目
  （带 ID 与时间），下一次 Coach 或 Roadmap 决策点时作为学生陈述读入并处理
  （更新投影/判断，或安排课堂讨论）；指永不直接改记录；
- Course/Knowledge 页面结构不变；
- 这是学生决策权在记忆层的同构（ChatGPT memory summary 的教育版）。

## 10. Runtime 改动点

1. `classroom_log_append` 写入时为 Log 条目机械绑定稳定 ID 与时间戳；lint 校验
   `corrects:` 引用存在性；
2. lesson frontmatter 增加 `started_at` / `closed_at`，生命周期切换时自动盖写；
3. 新增 `memory-lint` 校验脚本：快照/判断引用可解析、无裸判断、supersedes 链
   完整性、INDEX 行数上限、日期格式、词表有效性（词表存在时）、间隔重算、
   快照头部 `covers` 新鲜度检查；
4. tutor-lesson Skill 契约：Classroom Log 写入纪律扩展（非任务事实必须记录）；
5. Coach / Roadmap Skill 契约：决策点读取纪律（备课/收口/排期/回流先读 INDEX）、
   出题前必查 coverage、判断写入规则、Reviewer 规则；
6. 学生指正暂存与读出（Memory 页配套）；
7. 测试夹具扩展 memory/ 样例；
8. Memory 页只读视图与指正入口。

不改：Session 种类、NodeKind 生命周期、教学文档契约、Session 恢复机制、静态资源
装配清单（无 INDEX 注入）。

## 11. 错误处理

保持 M0 直接风格：

- memory-lint 校验失败：报告文件、行、原因，不自动修复；
- 快照或判断引用失效：卫生检查报告并列入待复核，不静默；
- `memory/` 缺失或损坏：**教学路径不受影响**（Tutor 本来就没有它），Coach/Roadmap
  明示降级回 M0 纯文档模式；既有学习集（如 derivative-m0）无需迁移即可继续运行；
- 快照损坏时可从 Log 重建——**可重建性是错误恢复手段**，这是快照化相对"第二套
  事实"的额外收益；
- 不静默降级、不提供兼容适配器。

## 12. 测试

- 夹具：`tests/fixtures/` 学习集增加 memory/ 样例（三个快照文件 + judgments +
  INDEX）与带条目 ID 的 lesson 样例；
- Log 条目 ID/时间戳机械绑定测试（模型输入无法伪造）；
- memory-lint 全规则单元测试（引用可解析、无裸判断、快照不得作为判断引用对象、
  supersedes 链、INDEX 行数、日期格式、词表有效性与无词表降级、间隔重算、
  头部 `covers` 新鲜度判定）；
- 快照原子替换测试（复用 `mutateDocumentAtomically`，替换后无旧条目残留）；
- 写入纪律契约测试：Tutor 资源装配不含 memory/ 任何东西；
- 决策点读取纪律的契约测试（Skill 文本与装配：lint 新鲜度检查 → 重建 → 再读）；
- Memory 页只读渲染与指正暂存测试；
- `bun run check` 保持全绿。

## 13. 验收（模拟学生长周期）

比 M0 终验更长：10–15 课 / 3+ Plan，隐藏画像模拟学生，隔离运行根，安全停止条件，
不可改写证据。判据：

1. **旧构造不被误判为首次独立证据**（备课记录与 reviewer 结论显示：重复构造被
   识别为复习/检验而非首次——零重复构造不是目标，间隔复习本来就需要重复）；
2. 负担偏好类事实**不再蒸发**（Log 有捕获、投影可查、被后续备课实际使用）；
3. 间隔检验按 retrieval 历史调度，实际间隔有机械记录；
4. 判断层被真实决策引用（备课提案、排期讨论中出现 judgments 引用）；
5. 至少一次撤回真实发生且 supersedes 链完整；
6. **上游更正链路真实运转**：一次 Log 更正 → lint 判定陈旧 → 快照重建与判断
   复核 → 读取结果中无陈旧内容；
7. 污染检查：Session 转录中无任何记忆内容常驻注入；
8. "摘要代替原文"受控：Coach 读快照而非重读全部原文时，备课决策质量不降。

## 14. 实施阶段

1. **阶段 1：事实原位加固**——Log 条目 ID/时间戳机械绑定、frontmatter 时间戳、
   Classroom Log 纪律扩展、memory-lint 骨架；
2. **阶段 2：投影层**——三个快照文件、Coach 复盘提取工作流、原子替换与头部
   `covers` 新鲜度校验；
3. **阶段 3：判断层与消费契约**——judgments.md、五条硬规则校验、INDEX 决策点
   读取纪律、coverage 必查、烘焙升级、提取调度 + Memory 页只读视图与指正入口；
4. **阶段 4：模拟长周期验收**——按第 13 节执行并出报告。

每个阶段独立制定实施计划；阶段间依次依赖。

## 15. 与其他车道的协调

- 本设计与学习集生产子项目、开源硬化车道都触碰 `apps/pi-teaching-web`（硬化后将
  改名 `apps/studyforge`）的静态资源装配、Skill 契约、前端。实施前确认各车道状态，
  约定先后，避免并行改同一文件；
- 任何学习集可由本设计的初始化步骤建立空 memory/；既有学习集降级运行直至初始化；
- 与学习集生产子项目无接口：化学学习集是否带 memory/ 由本设计的初始化决定，不依赖
  生产 spec。

## 16. 已确认决策

- M1 的记忆系统与学习集生产为两个独立子项目，各自走 spec → plan → 实施循环；
- **Lesson Block 是唯一原始事实**；`memory/` 不保存第二套事实（第一轮审阅的
  根本修正）；
- **三个投影文件是当前可重建快照，不保存历史**（全部历史已在 append-only
  Classroom Log 中）；每次逐课提取或卫生检查由 Runtime 原子替换；快照头部按课
  记录覆盖到的 Log revision，陈旧由 lint 机械判定；**陈旧段不得进入普通读取
  结果**——决策点协议为"lint 新鲜度检查 → 陈旧段先重建 → 再读"（第二轮审阅的
  根本修正，消灭 grep 新旧同召回的旧结论上浮）；
- **判断的撤回历史是 memory/ 中唯一的 append-only 区**（判断不可重建，其撤回史
  本身就是证据）；
- **承重 Classroom Log 条目由 Runtime 机械绑定稳定 ID 与时间**，模型不填写机械
  字段；消融文档"不建立事件 ID"一条据此修订；
- **判断必须最终指回具体 Log 条目**；快照只负责帮助定位，永远不作为引用对象；
- **记忆内容零常驻注入**：INDEX.md 不注入（静态注入随长缓存 Session 过期），
  读取纪律由 Skill 契约承载，决策点主动读取；
- **所有权层级写入**：Tutor 事实（经 Classroom Log）、Coach Plan 级判断、Roadmap
  跨 Plan 判断，卫生检查只维护不新写；
- **提取调度 = 机械事实 + Coach 判断**；不做算法调度器；
- **Tutor 完全不碰 memory/**，快照生成全走 Coach 课后复盘；
- **五条硬规则落在校验脚本**，不是提示词；
- **判断字段分轴**：证据量与趋势分开，模式/反模式/触发条件/反证显式成字段；
- **词表校验条件化**：词表存在时强制，无图谱学习集自由术语降级；
- **验收门修正**：目标不是"零重复构造"（间隔复习需要重复），而是"不把旧构造
  误判为首次独立证据"；
- **Memory 页恢复为只读视图 + 指正入口**（学生可见备课本，指正经暂存由 Agent
  处理，不直接改记录）。
