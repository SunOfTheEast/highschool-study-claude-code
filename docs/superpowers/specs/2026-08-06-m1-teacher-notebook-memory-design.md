# StudyForge M1 记忆系统设计：教师备课本的语义蓝图

**状态：** 第六版设计定稿，已确定教学语义、Session 生命周期、Markdown 物理结构、
原生文件召回与索引维护边界；异常关闭补偿、图数据库加速与可观测性留待实施设计。

**日期：** 2026-08-06（第六版定稿于 2026-08-07）

## 1. 核心判断

StudyForge 的记忆不是聊天记录摘要，也不是一份给学生贴标签的静态画像。它是教师在
备课和上课时使用的**认知建模网络**，回答三类问题：

1. **针对某个知识对象的学习痕迹与对象记忆**：学生在这里实际做过什么，现在学到
   哪里，哪些边界已形成，哪些仍未证明；
2. **学生自己的能力假设**：同一学习模式跨不同知识对象反复出现后，对学生怎样识别、
   迁移、检查和修正的暂定解释；
3. **偏好建模**：学生明确表达或多次确认的互动需求，包括负担、节奏、情绪状态和
   生活约束。

教师备课的过程，就是从当前需求出发，在这张网络上按需行走：先找相关对象，再读压缩
痕迹与当前状态；确有必要时才展开能力假设、偏好或原始证据。记忆最终服务于教学判断，
而不是为了把学生描述得尽可能完整。

持久记忆采用**学习集内的人类可读 Markdown**。Markdown 是可检查、可版本控制、可迁移
的事实与判断载体；未来即使加入数据库、embedding 或索引，它们也只能是可重建的检索
投影，不能成为唯一真相。

## 2. 五个语义边界

下面五个判断是整个系统的分类契约。

### 2.1 学习痕迹

**直接发生、可以复述的表现，是学习痕迹。**

例：

> 这道同构题中，提醒比较两个式子的共同结构后完成。

学习痕迹记录具体任务、首次表现、实际帮助、修正和结果。提示后完成不能润色成独立
完成，后来的成功也不能覆盖早先的错误。

### 2.2 对象记忆

**只回答某个知识对象学到哪里，是对象记忆。**

例：

> 能在明确提示下完成同构变形，尚未证明能自主识别。

“尚未证明”是一等状态。对象记忆不为了看起来完整而补满结论，也不从一次表现外推稳定
能力。

知识对象不只限于教材知识点，也可以是方法或结构，例如参数分离、端点与内点、同构
识别、三次函数结构。具体词汇由学习集决定。

### 2.3 能力假设

**跨不同知识对象反复出现、并用于解释学习方式的模式，才是能力假设。**

例：

> 题目表面形式变化后，不容易主动寻找不变量；经过对照后迁移较快。

同一对象内反复出现的模式仍属于对象记忆。一次 Lesson 可以提出能力信号，但不能凭一个
对象宣判长期能力。

### 2.4 偏好

**学生明确表达或多次确认的互动需求，是偏好。**

例：

> 近期不接受成套作业，希望每晚最多一道。

“使用对照讲解后学得更快”只是教学效果观察，不能自动写成“学生喜欢对照讲解”。只有
学生明确表达这种需求，才构成偏好事实。

偏好保留学生原话中的时间与适用范围：“今天”不升级为长期特征，“最近”不升级为永久
习惯。学生后来改变需求时，原始表达仍保留，当前适用的偏好可以更新。

### 2.5 教学待办

**教师打算以后怎样处理，是教学待办。**

例：

> 下节课用外观不同的结构做独立检验。

教学待办不是学生认知特征，不进入记忆模型。Plan 内待办属于 `PLAN.md` 的下一课安排，
跨 Plan 待办属于 `ROADMAP.md`。

## 3. 三层披露，不是三份真相

### L2：原始证据

课堂中发生的作答、帮助、修正和决定，按发生顺序进入 Lesson Classroom Log；Plan 或
Roadmap 对话中出现的新事实，则保留其真实 Session 来源。原始事实永不改写，只能追加
后续事实或纠正。

信息发生在哪个 Session，就绑定哪个 Session 的来源；不再把所有学生信息伪装成 Lesson
Log。

### L1：压缩记忆

压缩记忆包括：

- 能指回原始证据的学习痕迹；
- 某个对象当前学到哪里的对象记忆；
- 跨对象能力假设；
- 仍在适用范围内的偏好。

它保存当前教学真正需要的轨迹、边界和待检验点，而不是复制课堂流水。

### L0：召回线索

L0 是检索时先看到的一句话线索，用来判断某条 L1 是否值得展开。它是面向读者的投影，
不是另一份可独立修改的事实。

L0 是一个常驻在当前角色上下文中的紧凑路由索引。它只提供“这里有什么、为什么可能值得
展开、去哪里读取”的线索，不携带 L1 判断正文或 L2 原始证据。L0 是可从 L1 重建的投影，
不是另一份真相。它物化为学习集内的 `memory/INDEX.md`：教学角色在自然收口点局部维护
受影响的路由，Runtime 只在新 Session 启动或 compaction 恢复后注入该文件，不生成其中
的教学语义。

## 4. 记忆形成的时间尺度

“生成记忆”包含三种不同动作：现场记录、课末固化和跨对象聚合。

| 内容 | 首次形成时机 | 后续变化时机 |
| --- | --- | --- |
| 原始课堂事实 | 课堂中发生时立即追加 | 永不修改，只追加后续事实或纠正 |
| 学习痕迹 | 每节 Lesson 课末反思后固化 | 新检验发生后延长认知轨迹 |
| 对象记忆 | 每节 Lesson 课末根据新痕迹更新 | 该对象出现新证据后更新 |
| 能力信号 | Lesson 课末可以提出候选 | 等待其他对象上的证据 |
| 工作能力假设 | 同一模式跨不同对象出现后，由 Plan 内 Coach 形成 | Plan 内修正，跨 Plan 再校准 |
| 长期能力假设 | Roadmap 回流时跨 Plan 巩固 | 强化、改写、削弱或撤回 |
| 偏好 | 学生明确表达或多次确认时 | 学生改变、确认或撤回时更新 |
| 教学待办 | 课后复盘或规划时 | 留在 Plan / Roadmap，不进入记忆 |

Roadmap 不是所有记忆的首次生成者。对象记忆必须在每节 Lesson 后形成，否则同一 Plan 的
下一节课无法利用上一节课的变化；Roadmap 负责更长时间尺度的再聚合。

## 5. Lesson：唯一一次课末反思与最小充分固化

### 5.1 正常课堂闭环

每节 Lesson 只进行一次正式课末反思，并且发生在 Tutor Session 内：

1. 课堂任务完成后，Tutor 根据已有证据做自然短回顾；
2. 学生说明哪里真正顺了、哪里仍不踏实，以及当下负担或需求；
3. Tutor 结合课堂事实形成有边界的判断；
4. Tutor 静默完成本课记忆固化；
5. Tutor 用正常教学语言公开简短总结，学生可以自然纠正；
6. 学生若纠正，Tutor 追加新事实并修订刚形成的判断；
7. 学生通过界面关闭 Lesson。

学生看到的是教师对本课的自然理解，不是“学习痕迹 / 对象记忆 / 能力信号”表单。这里
不增加正式批准门；但内部写入不得比公开总结作出更强的学生判断。

### 5.2 一次固化允许产生什么

只产生本课证据真正支持的内容：

- 值得未来找回的学习痕迹；
- 本课涉及对象的当前状态更新；
- 很有解释力、但仍待跨对象验证的能力信号；
- 学生明确表达的偏好事实及其适用范围。

一次固化不产生：

- 下一课安排；
- 教学待办；
- 跨对象能力定论；
- Roadmap 级长期判断。

没有任何类别配额。多数 Lesson 可能只有少量痕迹和一两个对象更新；没有能力信号或偏好
事实就不写。它是**最小充分固化**，不是课后报告。

### 5.3 当前 Session 不回读本次新写入

Lesson 课末固化面向未来上下文。Tutor 可以继续使用本 Session 开始时已经常驻的 L0 快照，
但写完后不把刚形成的 L0 更新或 L1 记忆再次注入当前 Session；
学生纠正时依据当前对话与原始事实直接修订。记忆在跨 Session、上下文压缩后恢复或真实
教学需求触发时才被读取。

异常关闭时怎样补偿、怎样表示本课尚未完成固化，留待 Runtime 实施设计；异常路径不得
阻塞学生结束课堂。

## 6. Plan：消费课堂记忆并共同决定下一课

### 6.1 学生决定何时继续

Lesson 关闭后，界面回到原 Plan。学生可以立即继续对话，也可以隔一段时间再回来；
关闭 Lesson 不自动触发 Coach，也不隐含学生批准立即规划下一课。

学生在 Plan 中开口后，Coach 沿 Lesson Tree 状态自行定位刚关闭的 Lesson，再按 §6.2
消费固化结果。「继续讨论下一课」入口、关闭后的结构化生命周期事件与「记忆已整理」
确认留待实施设计（见 §15）；先用现有纯文本回流，长周期观察 Coach 定位是否出错后
再决定是否补齐。

### 6.2 课后消费流程

学生选择继续后，Coach：

1. 读取本课固化结果；
2. 必要时读取相关对象的既有记忆、能力假设与偏好；
3. 形成教师判断并向学生公开；
4. 与学生讨论下一步真正需要解决的问题；
5. 学生确认下一课方案后，才更新 Plan 并准备下一 Lesson。

Plan 不再默认读取完整 Lesson，也不再例行询问一遍“哪里顺、哪里不踏实”。只有固化结果
缺失、内部冲突、学生提出具体纠正，或者高影响判断取决于帮助前后的细节时，才下钻原始
Lesson 或提出一个针对性问题。

Plan 的职责是**消费已经形成的课堂记忆、公开阶段判断，并与学生共同决定下一步**，不是
重新采访学生或重建整堂课。

### 6.3 Plan 内能力聚合

当相同模式已经跨不同知识对象出现时，Coach 可以在 Plan 内形成或修订工作能力假设，
使它立即服务后续 Lesson；证据仍只来自一个对象时，不得升级。

`PLAN.md Current Position` 继续保存本阶段决策所需的自包含总结。能力假设保存可跨 Plan
复用的认知模式及证据。二者服务不同生命周期，不互相替代，也不复制课堂流水。

## 7. Roadmap：跨 Plan 校准，而不是垄断记忆

Plan 完成回流时，Roadmap：

1. 先读取已完成 Plan 的阶段总结；
2. 查看该 Plan 中发生变化的对象记忆、能力假设和偏好；
3. 只有高影响判断或证据冲突时才下钻 Lesson；
4. 综合跨 Plan 表现，强化、改写、削弱或撤回长期能力假设；
5. 用这些判断与学生讨论下一个 Plan。

Roadmap 不重做每节课已经完成的痕迹提取与对象更新，也不是所有对象记忆、能力判断和偏好
的唯一写者。它处理的是跨 Plan 的时间尺度。

## 8. Lesson 课堂中的按需召回

Lesson 开始时默认使用 Coach 已经烘入 Teacher Control 的本课条件，以及紧凑、可重建的
L0 路由索引；不常驻注入 L1 对象记忆、能力假设、偏好正文或完整学生画像。

学生出现预案外的典型错误或停点时，Tutor 按下面顺序处理：

1. 先判断当前课堂证据是否已经足够；
2. 不足时，先沿 `memory/INDEX.md` 或分桶索引找到相关条目；索引没有直接线索时，才用
   原生 `Grep` 搜索稳定对象名、别名或短关键词；
3. 用原生 `Read` 先读相关对象记忆和学习痕迹；
4. 只有能力假设确实会改变眼前动作时才展开；
5. 只有压缩记忆不足以核查关键差异时才下钻原始证据；
6. 回到当前课堂，做一个与学生眼前表现成比例的教学动作。

旧记忆不能覆盖当前表现，也不能因为“以前犯过类似错误”就认定这次原因相同。记忆用于
选择讲解、对照或检验方式，不必把内部画像说给学生。本次新表现照常进入课堂记录，并在
课末参与下一次固化。

## 9. 偏好形成与更新

偏好事实可以发生在 Lesson、Plan 或 Roadmap。信息发生在哪里，就保留哪里的来源，并在
该 Session 的自然收口点进入记忆；不强行写回某个 Lesson。

偏好模型保留学生表达的真实作用范围：

- “今天”只控制当日安排；
- “最近”或“这个阶段”是有边界的阶段需求；
- 明确长期表达或多次确认，才形成较稳定偏好；
- 没有时间范围时，不擅自解释为永久人格特征。

原始表达永不删除。学生后来改变需求时，更新当前适用判断，并保留旧表达作为认知流变的
历史证据。

## 10. 语义所有权

| 内容 | 语义责任 |
| --- | --- |
| 原始课堂事实 | Tutor 在 Lesson 中按发生顺序记录，后续不能改写 |
| 其他 Session 新事实 | 发生它的 Plan / Roadmap Session 保留来源 |
| Lesson 学习痕迹 | Tutor 在唯一课末反思后固化 |
| 对象记忆 | Tutor 按本课新证据更新；后续证据可以修订当前状态 |
| 能力信号 | Tutor 可以提出候选，但不能从单对象升级为能力定论 |
| 工作能力假设 | Coach 在跨对象证据成立后形成并维护 |
| 跨 Plan 能力校准 | Roadmap 在回流时巩固、削弱或撤回 |
| 偏好事实 | 发生它的 Session 保留来源；模型只保留仍适用的解释 |
| 教学待办 | Coach / Roadmap 写入现有 Plan / Roadmap 位置，不进记忆 |
| 学生纠正 | 追加为新事实，并触发相关当前判断修订 |

角色名本身不是写入权限。写入责任由当前 Session 类型、节点路径和自然收口时机共同限定；
Tutor、Coach、Roadmap 只在各自已经确认的生命周期位置使用原生 Markdown 编辑能力。
Runtime 提供当前学习集、Session、节点和时间上下文并负责注入 `memory/INDEX.md`，但不
新增通用记忆读写工具，也不替模型生成教学判断。

## 11. 修正与认知流变

- 原始 Log 和学生原话永不更新；纠正通过追加新事实表达。
- 学习痕迹保留首次表现、帮助、修正和结果，不能把链条压成只有最终成功。
- 对象记忆、能力假设和偏好都是可撤回的当前判断，不是事实本身。
- 新证据出现后，可以更新当前判断，但必须仍能回到形成它的原始证据。
- “尚未证明”不能被空白补全，也不能被一次成功自动改成“已经掌握”。
- 当前表现优先于旧模型；旧模型与新表现冲突时先保留冲突，再设计负责的检验。

物理上，学习痕迹和原始表达是追加历史，旧条目永不回写；对象的 `Current Judgment`、
能力的 `Current Hypothesis` 和偏好的 `Current Preference` 可以随新证据更新，但同一
文件中的流变概述、时间线和来源链接必须保留判断怎样变化。对象合并也不重写旧 Trace：
旧对象文件改为指向规范对象的重定向，原有引用继续有效。

## 12. 与现有上下文机制的统一

当前 Roadmap、Plan、Lesson 是独立 Session；Plan Session 会跨多节 Lesson 持续存在。
记忆正好承担 Session 与压缩边界之间的状态交接：

```text
Lesson 内产生事实
        ↓
唯一课末反思后固化记忆
        ↓
当前 Tutor Session 不回读本次新写入
        ↓
后续 Session 常驻加载紧凑 L0 路由索引
        ↓
学生明确选择继续后，Plan 按需展开 L1
        ↓
新 Lesson 只获得本课需要的 Teacher Control
        ↓
现场出现新需求时再按需展开 L1，必要时下钻 L2
        ↓
Plan 与 Roadmap 在不同尺度继续聚合
```

因此记忆是 checkpoint 加路由索引，不是正文自动注入层：

- 只把严格限额的 `memory/INDEX.md` 常驻给当前学习集中有记忆读取职责的角色；
- 不常驻注入任何 L1 判断正文或 L2 原始证据；
- 不在刚写完的 Session 中自动回读；
- 不同时默认读取压缩记忆与它对应的完整 Lesson；
- 新 Session、上下文压缩恢复或真实决策需求出现时才披露；
- 原始 Lesson 只在冲突、高影响判断或压缩不足时下钻。

在这条主线上，不需要先发明 `Lesson delta`、披露 epoch 或自动去重账本。

## 13. Markdown 物理结构与原生召回

### 13.1 唯一目录结构

```text
learning-set/
├── ROADMAP.md
├── plans/
│   └── plan-001/
│       ├── PLAN.md
│       └── lessons/
│           └── lesson-001.md  # 内含 Consolidated Learning Traces
└── memory/
    ├── INDEX.md
    ├── indexes/
    │   ├── algebraic-structure.md
    │   └── ...
    ├── objects/
    │   ├── obj-001-isomorphic-recognition.md
    │   └── ...
    ├── capabilities/
    │   ├── cap-001-invariant-search.md
    │   └── ...
    └── preferences/
        ├── pref-001-workload.md
        └── ...
```

学习集没有独立的 `memory/traces/`、单体学生画像或自动评分式的备课提醒文件。课堂事实
沿 Plan 层级留在自己的 Lesson；`memory/` 保存跨 Session 使用的当前判断、流变概述和
通向事实的路径。

### 13.2 Trace 只在来源 Lesson 保存一次

每节课完成唯一课末反思后，Tutor 在该 Lesson 末尾追加：

```md
## Consolidated Learning Traces

### trace-plan-001-lesson-001-01

- 时间：2026-08-07 20:15
- 情境：同构变形的独立识别检验
- 首次表现：没有主动比较两个式子的共同结构
- 实际帮助：提醒比较结构后继续
- 后续表现：完成变形，但尚未证明能自主识别
- 关联对象：obj-001、obj-004
- 当时的能力信号：仅在本对象中观察到外观变化后未主动寻找不变量
- 来源证据：本课 Classroom Log 中的对应记录
```

这是一条完整的教学事件摘要：保留情境、首次表现、实际帮助、后续表现、关联对象和来源，
但不复制整段课堂流水。一次事件可以关联多个对象，物理上仍只存这一份。单对象上的能力
信号也留在这条 Trace 中，不单独建立全局候选列表。

Trace 标题使用学习集内稳定的 ASCII ID。对象、能力或偏好文件直接使用相对 Markdown
链接指向来源 Lesson 的标题：

```md
- 2026-08-07
  [trace-plan-001-lesson-001-01](../../plans/plan-001/lessons/lesson-001.md#trace-plan-001-lesson-001-01)
  — 在提示比较共同结构后完成，尚未证明能自主识别。
```

Agent 使用原生 `Read` 打开来源文件，需要定位时使用原生 `Grep` 搜索 Trace ID；不维护
中央 Trace 注册表，也不使用容易随编辑失效的行号引用。

### 13.3 对象记忆：稳定文件加完整时间线

每个学习对象拥有稳定 ID 和稳定路径。对象文件至少包含：

1. `Current Judgment`：该对象当前学到哪里；
2. `Evolution Overview`：从最初状态到现在的流变概述；
3. `Trace Timeline`：按时间排列、没有缺口的相关 Trace 链接，以及每次变化对本对象的
   意义；
4. 边界与尚未证明的部分。

完整 Trace 正文仍由来源 Lesson 持有。这里的“完整时间线”是指所有相关事件都能按顺序
找到，而不是把同一事件复制进每个对象文件。需要完整流变时，读者沿时间线逐条 `Read`
来源 Trace；日常备课通常只需当前判断、流变概述和最近几条变化。

Lesson 可以创建暂定对象；Plan Coach 在看见更完整的阶段结构后确认名称、增加别名、调整
分桶或合并重复对象。重新分类只修改索引成员关系，不移动对象文件。合并时保留旧文件和
旧 ID，把它改为指向规范对象的重定向，既有 Trace 不改写。

### 13.4 能力假设：一个主题一条连续校准链

每个跨对象能力主题使用一个稳定文件，包含：

- `Current Hypothesis`；
- 适用范围和不适用边界；
- `Evolution Overview`；
- 来自不同对象的 Trace 链接；
- 冲突或反向证据；
- 追加式 `Calibration History`。

Tutor 只能在 Trace 中留下单对象能力信号。Coach 在同一模式跨不同对象出现后创建或修订
工作假设；Roadmap 在跨 Plan 回流时继续校准同一个文件。两者发生在串行生命周期中，
不拆成两份判断，也不把教学待办写进能力文件。

### 13.5 偏好：一个持续主题一个文件

每个持续偏好主题使用一个稳定文件，包含当前适用偏好、作用范围、流变概述，以及追加式
表达与确认时间线。只有学生明确表达或多次确认的需求进入这里；教学效果观察不能代替
偏好事实。

Lesson 中形成的偏好可以链接对应课堂记录。Plan 或 Roadmap 对话中形成的偏好，由偏好
文件自身保留最小充分的学生原话、时间和来源 Session；不复制完整对话，也不为了统一格式
把它伪装成 Lesson 事实。偏好过期后保留文件与历史，但从 `INDEX.md` 的活动线索中移除。

### 13.6 INDEX 是可改写的路线图，不是无限增长的清单

`memory/INDEX.md` 只保留：

- 当前学习前沿；
- 相关语义分桶的入口；
- 此刻可能改变教学动作的能力假设与偏好线索；
- 每条线索的稳定文件路径。

`memory/indexes/*.md` 按语义区域组织对象入口。分桶是多对多路由投影，不是物理所有权：
同一个稳定对象可以同时出现在“代数结构”和“函数方法”等多个索引中。根索引会随学习
前沿改写并删除过时线索；长期历史仍在对象、能力、偏好和来源 Lesson 中，因此不会丢失。

索引由当前教学角色在自然收口点局部维护：Tutor 更新本课新增或变化的对象与偏好入口；
Coach 处理对象合并、工作能力假设和当前 Plan 前沿；Roadmap 调整跨 Plan 前沿。Runtime
只负责把根索引注入具有记忆读取职责的新 Session，不根据字段自动生成教学相关性。

### 13.7 召回只使用原生文件能力

记忆读取的亮线顺序是：

```text
memory/INDEX.md
        ↓
对象 / 能力 / 偏好文件
        ↓
来源 Lesson 中的 L1 Trace
        ↓
确有必要时读取同一 Lesson 的 L2 Classroom Log
```

全程使用 Agent 已有的 `Read` 和 `Grep`。M1 不新增 `recall_memory`、`read_memory`、
`read_evidence`、全局 Trace 搜索或来源解析工具。索引足够时不搜索；当前判断足够时不展开
Trace；Trace 足够时不回读课堂流水。

未来只有在引入图数据库时，才为图查询增加专用工具。图数据库、embedding 或全文索引
仍然只能是从 Markdown 事实重建的检索投影，不能取得语义所有权。

### 13.8 旧插件架构作废

`plugins/highschool-study` 中的全局 `traces/`、`student-profile.md`、
`teaching-profile.md`、`planner-attention.md` 及其记忆 MCP 工具不再是 M1 的设计输入，
也不进入核心 App 的兼容范围。实施时不做双写、转换层或旧格式迁移；核心实现只服务
`apps/pi-teaching-web` 的 Roadmap → Plan → Lesson 层级。旧插件的代码清理由单独的实施
步骤完成，不在本设计文档中直接修改。

## 14. 语义验收

结构实现后，用真实长周期观察下列结果：

1. 每节 Lesson 是否只有一次正式课末反思；
2. 课末事实、偏好和首次表现是否真实进入持久记忆；
3. Tutor 是否只在真实课堂需求出现时按需召回；
4. 当前表现是否始终优先于旧模型；
5. Plan 是否消费固化结果而不是重读整课、重复采访学生；
6. 能力假设是否确实建立在跨对象证据上；
7. Roadmap 是否在跨 Plan 尺度修订判断，而不是重做逐课提取；
8. 教学效果观察、偏好、教学待办和能力假设是否保持边界；
9. 是否只有 L0 路由索引常驻，而 L1 / L2 没有被常驻注入或在刚写完的 Session 中自动
   回读；
10. 一条多对象 Trace 是否只在来源 Lesson 保存一次，所有对象都能沿稳定链接找到它；
11. `INDEX.md` 是否持续反映当前学习前沿，而不是随课次退化成无限增长的历史清单；
12. 召回是否只使用原生 `Read` / `Grep`，没有引入通用记忆工具或旧插件双写；
13. 维护成本与响应时间是否仍小于记忆带来的教学价值。

## 15. 已确认决策与实施边界

### 已确认

- 记忆的三块核心是对象记忆与学习痕迹、能力假设、偏好建模；
- 五个语义边界按 §2 执行；
- 持久记忆使用学习集内的人类可读 Markdown；
- `memory/` 按对象、能力、偏好拆分；学习 Trace 内联在来源 Lesson，不建立全局 Trace 池；
- 对象使用稳定 ID 和路径，重新分类只修改多对多索引，合并使用保留旧 ID 的重定向；
- 能力假设按持续主题保存在同一个文件中，由 Coach 与 Roadmap 在不同时间尺度串行校准；
- 偏好按持续主题拆分文件，保留真实表达、时间范围和流变历史；
- 紧凑、可重建、作用域明确的 L0 路由索引常驻；L1 正文按需展开，L2 原始证据极少
  下钻；
- L0 物化为 `memory/INDEX.md`，由教学角色在自然收口点局部维护，Runtime 只负责注入；
- 召回只使用原生 `Read` / `Grep` 和稳定 Markdown 链接，不新增通用记忆工具；
- 只有未来图数据库查询可以引入专用工具，图数据库仍是 Markdown 的可重建投影；
- 每节 Lesson 只有一次正式课末反思；
- Tutor 在反思后进行最小充分固化，并公开自然总结供学生纠正；
- 当前 Session 可以继续使用进入时的 L0 快照，但新写入的 L0 / L1 不在原 Session 中
  自动回读；记忆是跨 Session 与 compaction 边界的 checkpoint；
- Lesson 关闭后由学生选择是否点击“继续讨论下一课”；
- Plan 读取固化记忆，不默认重读 Lesson，也不重复询问学生整堂课；
- 对象记忆逐 Lesson 更新，能力假设在跨对象证据成立时形成；
- Roadmap 负责跨 Plan 校准，不垄断所有记忆判断；
- Tutor 可在预案外错误出现时按需召回，当前表现优先；
- 偏好保留学生表达的时间范围，教学效果观察不能冒充偏好；
- 教学待办留在 Plan / Roadmap，不进入学生记忆；
- 不需要 `Lesson delta`、披露 epoch 或自动去重账本作为设计前提；
- `plugins/highschool-study` 的旧记忆架构作废，不做兼容、迁移或双写。

### 后续设计已经解决

- 原生 Markdown 多文件写入的原子固化由
  `2026-08-07-atomic-lesson-memory-consolidation-design.md` 解决；
- 记忆已写入但 tool result、Summary 或关闭回执丢失的恢复，以及正式 Lesson / Light Lesson
  的关闭幂等，由 `2026-08-08-teaching-session-close-recovery-design.md` 解决；
- 异常退出不触发后台模型猜测式补写，学生仍可立即结束；已经成功的固化通过持久 receipt
  恢复，尚未形成的语义判断不由 Runtime 代做。

### 仍留待实施设计

- Lesson 关闭后的结构化生命周期事件、「继续讨论下一课」入口与「记忆已整理」确认；
  v1 使用现有纯文本回流，Coach 沿 Lesson Tree 状态定位刚关闭的 Lesson；
- `INDEX.md` 的常驻长度预算与不同角色的注入范围；
- compaction 后重新注入根索引的具体 Runtime 接点；
- 召回文件、耗时、token 与教学动作的可观测性；
- 旧插件代码清理、具体实施阶段和测试夹具。

图数据库、embedding 和全文检索不属于 M1 首次实现；真实长周期暴露出 Markdown 召回瓶颈
后再单独立项。
