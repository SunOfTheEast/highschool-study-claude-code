# StudyForge M0 第一阶段开源发布设计

**状态：** 已确认

**日期：** 2026-08-06

**发布路线：** 当前私有仓库继续承担可信内测；完成净化后，从白名单文件树建立全新
`studyforge` 仓库和初始提交；新仓库随后成为长期主仓库

## 1. 背景与核心判断

StudyForge M0 已经具备一个区别于普通 Chatbot 的完整产品骨架：

- Roadmap → Plan → Lesson 的三级课程周期；
- 每个节点独立、可恢复的 Pi Session；
- Markdown-first 的备课、课堂事实和父子证据读取；
- Material Scout、Lesson Reviewer 与可打印讲义；
- 一套已经经过真实长周期验收的中文教学 Skill 树；
- 可直接运行和审查的本地前端。

当前仓库却仍然保留大量研发现场：旧 Claude Code 插件、内部计划与审计、个人路径、
未完成来源治理的 519 张题卡，以及已经过时的产品说明。直接把现有仓库转为 public，
会让外部用户首先看到历史包袱，而不是 StudyForge 本身；普通删除也无法清除 Git 历史
中的数据。

因此第一阶段开源不采用“把当前仓库改成公开”的路线，而采用干净产品发布：

> 保留当前私有仓库作为内测和历史档案；从经过授权、隐私和产品核验的白名单文件树
> 创建全新的公开历史；公开后，新仓库成为 StudyForge 唯一的代码与 Skill 主仓库。

## 2. 第一阶段的定义

第一阶段发布为 **StudyForge M0 v0.1.0**。它面向：

- 教育 Agent 研究者；
- 熟悉模型配置的开发者；
- 能在 Work Agent / Coding Agent 辅助下完成环境配置的教师。

首发不要求普通学生脱离技术帮助完成一键安装。成功体验是：陌生用户克隆仓库后，
在 Agent 辅助下约十五分钟内完成依赖与模型配置，启动本地 App，并进入一条真实可用的
Roadmap → Plan → Lesson 教学链路。

“Agent 辅助安装”是正式产品入口，不是文档不足时的补救。仓库需要同时对人和 Coding
Agent 可读。

## 3. 目标

1. 让外部用户第一眼看到完整、克制、可运行的 StudyForge，而不是项目考古现场。
2. 公开 M0 Runtime、前端、Agent、Skill 树、Schema、测试和必要的架构说明。
3. 提供至少一套来源清楚、可以合法再分发的示例学习集，展示真实多课闭环。
4. 让 Work Agent 能可靠诊断环境、配置模型并启动本地服务。
5. 建立明确的代码、内容、学生数据和第三方依赖许可边界。
6. 在公开前修复本地 Web 应用最直接的跨站调用风险。
7. 以自动化检查和一次干净机器验收保证公开提交能够复现。
8. 发布后把公开仓库作为 M1 及后续产品开发的主仓库。

## 4. 非目标

第一阶段不做：

- 普通用户的一键桌面安装器；
- 云端托管、多用户账号或远程访问；
- npm、Homebrew 或应用商店分发；
- M1 长期记忆与个性化系统；
- 真人纵向数据集公开；
- 训练代码、StudentSim 或专科 Tutor 权重发布；
- 旧 Claude Code 插件的兼容或迁移；
- 完整公开全部研发审计、CoT 和内部实验历史；
- 为将来的云端威胁模型提前建设完整鉴权系统。

## 5. 仓库拓扑与切换方式

### 5.1 发布前

当前私有仓库继续承担：

- 可信内测；
- 519 张现有题卡的暂存与教学验收；
- 历史设计和审计留档；
- 公开发布所需的代码修复与净化工作。

现有题卡无需在内测阶段删除。它们默认不获得项目开源许可证，也不能仅凭“仓库当前
私有”推断为可公开再分发。

### 5.2 干净导出

公开候选树必须通过**白名单导出**创建：只复制发布清单明确允许的目录和文件。不能把
当前仓库复制后再依靠删除黑名单净化，也不能把当前 Git 历史重写成公开历史。

导出产物进入新的临时目录，在那里完成：

1. 路径与内容清单核验；
2. 密钥、个人路径、学生数据和内部材料扫描；
3. 许可证与素材来源检查；
4. 干净安装、构建、测试与真实模型烟测；
5. 人工查看 README、界面和示例学习链路。

只有导出树通过全部 Gate 后，才在该目录建立新的 Git 根提交。

### 5.3 发布后

新 `studyforge` 仓库成为代码、Skill 和公开文档的唯一主仓库。当前私有仓库作为只读
历史档案保留，不与公开仓库形成长期双向同步。

M1 在公开仓库继续开发；真人数据、未清洗材料和私域评测结果保存在公开 Git 之外。

- Pi JSONL 会话、学生课堂记录和任何真人数据；
- 个人绝对路径、邮箱、令牌、密钥和本机模型配置；
- 未通过来源检查的题卡、材料、图片和书籍页码证据；
- 使用具体动漫角色名、招式名或原作梗的人格资源；
- 与 M0 当前契约相矛盾的旧 README 和设计说明。

## 7. 许可证与数据边界

### 7.1 代码和 Skill

以下内容采用 **Apache License 2.0**：

- Runtime 与前后端代码；
- Agent 提示词和 Skill 树；
- Schema、测试、脚本和技术文档；
- 项目原创的通用配置与模板。

根 `package.json` 保持 `private: true`。仓库公开不等于首发同时发布 npm 包。

### 7.2 示例学习内容

项目原创并允许再分发的示例学习集采用 **CC BY 4.0**，在示例目录内放置独立的
`LICENSE` 与来源清单。每项内容至少记录：

- 稳定 ID；
- 作者或来源；
- 原始许可证或原创声明；
- 是否包含改写；
- 所需署名；
- 核验状态。

公共考试题、教材改写、教辅解答和图片不能因为“网上能找到”自动视为可再分发。无法
确认的内容留在私有仓库，或在公开前替换成原创等价任务。

### 7.3 真人数据

完全开源不等于发布未成年人的原始数据。第一阶段不公开：

- 原始对话；
- Lesson Classroom Log；
- Pi Session；
- 学生身份、学校、考试和时间信息；
- 可由多项记录组合恢复出的个人轨迹。

未来研究只公开合成轨迹、协议、Schema、统计结果或经过独立治理的数据产品；不能把
应用仓库当作真人数据分发渠道。

### 7.4 第三方依赖

仓库保留锁文件，在 `THIRD_PARTY_NOTICES.md` 中声明直接依赖及其许可证。当前核心依赖
主要为 MIT、Apache-2.0 和 ISC 系列许可证；正式发布时以锁文件重新生成并核验清单，
不把一次人工审计当作永久结论。

## 8. 品牌与人格

- 产品和仓库统一使用 **StudyForge** / `studyforge`；
- 旧 `highschool-study-claude-code` 名称只存在于历史档案；
- 默认人格为中性、负责的教师；
- 可选人格改写为“轻松、自信、有判断力的导师”；
- 保留节奏、幽默和教师判断，但删除“五条悟”、招式名和原作世界观引用；
- 人格仍然只影响表达，不改变教学职责、证据和生命周期。

公开页面不把 StudyForge 描述成“AI 自动替代教师”，而强调它是一个可审计、可运行的
长期教学 Agent 环境。

## 9. 本地安全与隐私基线

M0 仍然是本地单用户应用，不引入账号系统。公开前必须完成以下最小安全闭环：

1. Server 默认且仅监听 `127.0.0.1`；远程绑定不作为隐藏配置开放。
2. WebSocket `/events` 检查浏览器 `Origin`，只接受当前 App Origin 和明确的本地开发
   Origin。
3. 所有改变 Session、Plan 或 Lesson 状态的 HTTP 请求执行同样的 Origin 检查；不返回
   `Access-Control-Allow-Origin: *`。
4. 浏览器请求带有不受信任 Origin 时直接拒绝；没有 Origin 的本机测试和命令行调用按
   本地进程信任边界处理。
5. 路径解析继续限制在当前 Learning Set 内，拒绝路径逃逸和父子 ID 不一致。
6. 凭证只由 Pi 或本机环境管理；前端、日志、错误消息和示例配置不得回显凭证。
7. 默认不上传遥测、对话、题卡或运行日志。
8. 文档解释 Learning Set、Pi Session 和导出文件存在哪里，以及用户如何备份或删除。

这套基线解决 public 本地应用最直接的恶意网页访问 localhost 风险。云端、多用户和不可信
本地进程不属于 M0 威胁模型，不为它们提前建设完整鉴权。

## 10. Agent 辅助安装

### 10.1 面向 Agent 的入口

根 `AGENTS.md` 必须精确描述：

- 支持的平台与 Bun / Pi 版本；
- 允许修改的本地配置；
- 不得读取或打印的凭证；
- 环境诊断、安装、构建和启动顺序；
- 如何选择模型提供商；
- 如何确认服务真正可用；
- 常见失败的定位方式；
- 哪些动作必须由用户确认，例如写入全局配置。

README 提供一段可直接交给 Work Agent 的短提示：检查环境、运行诊断、仅修复当前仓库
范围内的问题、引导用户完成凭证配置并启动示例。

### 10.2 根命令

公开仓库至少提供以下稳定入口，具体脚本名在实施时可做机械调整：

~~~bash
bun install --frozen-lockfile
bun run doctor
bun run start:demo
bun run check
bun run test:e2e
~~~

`doctor` 只诊断并输出结构化结果，不暗中安装全局依赖或修改用户凭证。它检查：

- Bun 与平台版本；
- Pi Runtime 是否可用；
- 至少一个可用模型配置；
- 示例 Learning Set 完整性；
- 构建产物与端口占用；
- 关键目录写权限。

Agent 根据诊断结果执行普通、可逆的修复；需要改全局 Pi 配置时明确告诉用户。

### 10.3 人工兜底

Agent 辅助不是唯一入口。README 仍提供最短人工安装路径和故障排查链接，避免把另一个
闭源 Agent 变成使用 StudyForge 的硬依赖。

## 11. 公开文档信息架构

### 11.1 README

README 只承担：

1. StudyForge 是什么；
2. 它与普通聊天机器人的区别；
3. 一张 Roadmap → Plan → Lesson 心智模型；
4. 最短启动路径；
5. 可见的产品截图或短演示；
6. 当前支持范围与限制；
7. 指向架构、学习集制作、贡献和研究愿景的链接。

README 必须以当前事实为准，包括 Plan-local Lesson、Material Scout、Reviewer、课堂写入
工具、Roadmap 路由和讲义导出；不能继续描述“全局 lessons/”或“只有六个原生文件工具”。

### 11.2 架构文档

公开架构文档只保留当前承重契约：

- 三类 Session 的职责和生命周期；
- Plan-local Lesson 文件树；
- 父节点沿 Tree 读取证据的边界；
- Agent / Skill / Runtime 三层责任；
- Material Scout 与 Reviewer 的上下文隔离；
- Learning Set 最小 Schema；
- 本地数据和模型配置边界。

历史设计可以在以后整理成独立的演进文章，不混进首发的使用路径。

### 11.3 研究愿景

公开版愿景保留：认知结果 Agent、StudentSim、Skill-tree distillation、真人学习 Benchmark
和 M1 记忆方向；明确区分已经实现的 M0 与研究假设，不能把未来目标写成当前能力。

## 12. 自动化验证

### 12.1 持续集成

每次提交至少运行：

- TypeScript 类型检查；
- 单元与契约测试；
- 前端生产构建；
- Playwright M0 闭环；
- Learning Set Schema 验证；
- Markdown 链接与个人绝对路径检查；
- 许可证和敏感信息扫描。

首发优先覆盖 macOS 和 Linux。真实模型验收需要用户凭证，不进入公共 CI；它作为 release
candidate 的人工 Gate，记录模型、配置、耗时和最终结果，但不提交原始 CoT。

### 12.2 Release Candidate 验收

在一个不复用当前 `node_modules`、Pi Session 或构建缓存的临时目录中：

1. 从公开候选 Git 根重新克隆；
2. 按 README 让一名 Work Agent 协助安装；
3. 运行 `doctor`，确认问题可解释；
4. 启动示例 Learning Set；
5. 创建或进入 Roadmap Session；
6. 物化并开始一个 Plan；
7. 准备、开始并关闭至少一节 Lesson；
8. 观察公式渲染、工具活动、刷新恢复和 Plan-local Lesson；
9. 生成一次可打印讲义；
10. 确认跨 Origin 的 HTTP 与 WebSocket 请求被拒绝。

## 13. 白名单导出与公开 Gate

### 13.1 导出原则

导出脚本维护明确的路径白名单，而不是排除列表。未知顶级目录、新增二进制文件、符号链接
和未声明的大文件一律令导出失败，等待人工分类。

导出目录必须位于新建的临时目录中；脚本不能删除或改写当前仓库，也不能复制 `.git`。

### 13.2 必须通过的 Gate

公开初始提交必须同时满足：

- **产品 Gate：** `check`、E2E、真实模型闭环和前端人工验收通过；
- **数据 Gate：** 每个公开题卡和材料都有来源、许可与署名记录；
- **隐私 Gate：** 不含真人会话、学生信息、Pi JSONL 或可组合身份线索；
- **密钥 Gate：** 当前树和待发布 Git 根不含令牌、私钥、凭证或本机配置；
- **路径 Gate：** 不含个人绝对路径和私有仓库引用；
- **品牌 Gate：** 不含未经授权的角色人格和旧产品名称；
- **文档 Gate：** README、AGENTS 和架构说明与 Runtime 一致；
- **安全 Gate：** loopback、Origin 与路径边界测试通过；
- **许可证 Gate：** Apache-2.0、CC BY 4.0 和第三方声明完整；
- **历史 Gate：** 新仓库首个提交只来自核验后的导出树。

任何 Gate 失败都阻止 public，不以“先发布再修”绕过。

## 14. 发布阶段

### 阶段 A：私有发布硬化

- 修复 Origin 边界；
- 统一 StudyForge 命名；
- 收敛 README 与公开架构文档；
- 建立 Agent 辅助安装和 `doctor`；
- 建立白名单导出与自动扫描；
- 保持现有题卡和内测流程可用。

### 阶段 B：学习数据净化

- 为现有题卡建立来源与许可清单；
- 移除、原创重写或替换无法公开的内容；
- 复核题目、解答、评分细则、图片和图谱的派生关系；
- 形成可采用 CC BY 4.0 发布的示例 Learning Set。

阶段 B 可以晚于代码硬化，但必须早于公开初始提交。

### 阶段 C：干净 Release Candidate

- 从白名单生成新文件树；
- 建立全新本地 Git 历史；
- 创建新的私有 GitHub `studyforge` 仓库；
- 运行自动化和一次完整的干净机器验收；
- 修复只发生在新公开候选树或通过明确回迁发生，避免两套代码暗中漂移。

创建远端仓库、首次推送和修改可见性属于外部状态变更，实施时在动作前单独取得用户确认。

### 阶段 D：公开 v0.1.0

- 再次检查导出树与 Git 历史；
- 将仓库改为 public；
- 打 `v0.1.0` 标签并发布简短 Release Notes；
- 验证匿名用户可以读取和克隆；
- 把公开仓库声明为后续开发主仓库；
- 将当前私有仓库冻结为历史档案。

## 15. 首发验收标准

只有同时满足以下条件，才称为“第一阶段已经开源”：

1. 匿名用户可以克隆 `studyforge`，并看到 Apache-2.0 许可证。
2. 公开历史从干净根提交开始，不包含当前私有仓库的对象。
3. 仓库中每个学习内容文件都有明确的公开许可或原创声明。
4. Work Agent 能依据 `AGENTS.md` 和 `doctor` 帮助新用户在约十五分钟内启动。
5. 人工安装路径不依赖某个特定 Coding Agent。
6. Roadmap → Plan → Lesson 至少一个真实闭环可运行。
7. 课程树、公式、工具活动、刷新恢复和讲义导出正常。
