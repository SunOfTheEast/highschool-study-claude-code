# StudyForge：来源优先的学习集设计

**日期：** 2026-08-12
**状态：** 第一阶段已实现并通过确定性 E2E 与真实扫描书验收
**性质：** M1c 之上的产品主路设计，不改写既有资产与记忆所有权

## 一、要解决的问题

StudyForge 已经会自由讨论、正式上课、保存 Note / 题卡、记录教师记忆、建立语义联系并安排
复习，但这些能力尚未组成一条普通学生一眼就能理解的主路。

当前首次入口主要邀请学生“从空白开始”或“去问老师”。这适合已经知道自己想问什么的人，
却要求迷茫的学生先完成最困难的一步：自己决定学什么、从哪里开始、怎样排列。与此同时，
M1c 已经允许导入书籍并沿准确 locator 形成资产，但书在产品中仍主要表现为一份被动
Material，没有成为学习过程的来源主干。

本设计把主路改写为：

> 从一本真实资料开始，沿它原有的次序学习；让讨论形成的 Note 与题卡长在原文位置上；再用
> 语义标签把多本资料中的同类问题连接起来。

自由学习不会消失。它继续承接书外问题、临时困惑和发散讨论，只是不再承担解释整个产品
怎样使用的唯一责任。书籍主路属于发布前的开箱可用性条件：学生不应先知道自己该问什么，
才能开始使用 StudyForge。

## 二、核心定义

### 2.1 书是来源主干，不是学习集本身

一本书同时提供三样东西：

1. **内容：** 定义、例题、论证、练习与资料；
2. **编辑次序：** 编者决定先讲什么、后讲什么；
3. **固态胶水：** 动机、过渡、上下文以及“为什么此处接着讲这个”。

这些信息应保留在 Material 原文及其目录、页码和段落 locator 中。蒸馏不能只抽取“干货”后
丢弃过渡文字；教师需要时应能回到原文读取它。

书的次序是可靠的来源结构，但不是系统推断出来的先修 DAG，也不是对当前学生的唯一最优
路线。教师可以结合学生表现跳过、回补或重排，且必须公开与学生商量重大调整。

### 2.2 学习集是多来源之上的个人学习层

一个学习集可以包含零本、一本或多本 Material。它不是某一本书的复制品，而是建立在这些
来源之上的个人层：

- Note 与题卡保存学生以后会继续使用的内容；
- `sources` 固定它们真正依赖的 Material revision 与 locator；
- 平坦 `core` / `related` 标签连接跨章节、跨书出现的同类语义；
- 对象记忆保存教师对学生认知流变的判断；
- Roadmap → Plan → Lesson 在学生需要长期路径时组织教学周期；
- 复习阶梯只负责让已经进入复习的资产再次出现。

例如，第一本书在导数章出现“恒成立问题”，第二本书在三角函数导数题中出现相同结构。师生
发现联系后，可以形成一份同时引用两处原文的 Note，并用“恒成立问题”等短标签召回两边。
这份跨书 Note 才属于学习集的个人联系层；两本原书仍各自保持原貌。

### 2.3 老师站在三种排序的汇合处

| 层 | 提供什么 | 不能冒充什么 |
| --- | --- | --- |
| 来源次序 | 编者给出的章节与叙述顺序 | 当前学生的最佳路线或先修真理 |
| 教师取舍 | 根据眼前表现跳过、回补、比较与改序 | 学生已经掌握的事实 |
| 复习排程 | 已入轨资产何时再次出现 | 课程顺序、重要性或 mastery |

个人胶水来自教师对学生历史与当前表现的结合，例如“你上次在活度这里混淆过，今天先对照
这两段”。它首先存在于教学对话；只有内容本身值得学生以后阅读时才保存为 Note。教师判断
仍进入对象记忆，不能写进来源结构或语义标签。

### 2.4 同一批资产具有两种正交投影

Note 与题卡不需要复制成章节对象或图谱对象。同一个 canonical asset 可以同时出现在两种
可重建视图中：

1. **来源树：** 学习集 → 书 → 章 → 节 → 从此处形成的 Note / 题卡，回答“它从哪里长出来”；
2. **语义关系：** 标签 → 跨章节、跨书的相关资产，回答“它还和什么有关”。

来源树由资产 `sources` 与书籍索引机械投影。引用多处原文的同一份资产可以出现在多个章节
下面，但始终打开同一份 revision；没有来源的自由讨论资产进入“书外生长”，不是待清理的
异常项。语义关系仍由 `core` / `related` 标签与现有语义索引投影，不能把共享标签升级成未经
断言的因果、先修、同型或共识。

这里所说的语义索引是 `semantics/indexes/asset-recall.tsv` 及其标签投影；
`memory/INDEX.md` 继续只承担教师记忆的按需召回路由，不能参与来源树或知识关系建模。

## 三、方案选择

### 方案 A：来源优先、资产叠加——采用

保留 Note、题卡、Material、标签、来源和记忆的现有边界。书提供原文与次序，资产在真实学习
中逐渐形成，跨书联系由多来源资产与平坦标签表达。

优点是沿用现有 M1c 地基，学生看到的是书和学习结果，而不是图谱维护工具；缺点是需要补齐
目录、原文导航、反向来源与“从这一节开始学”的产品入口。

### 方案 B：先增加 Flashcard、错题本、学生作品和套卷等对象——暂不采用

这些学习动作可能需要更好的交互，但当前 Note 已有回忆块，题卡已有学生笔记、作答活动和
标签。现在新增四套 schema 会过早复制内容、来源、revision、复习与前端逻辑。

先验证现有两类核心资产在来源主路中能否承接真实学习。只有某种动作无法由 Note / 题卡加
活动投影自然表达时，再为它单独设计新对象。

### 方案 C：整本书自动拆卡并生成知识图——不采用

批量生成会把“导入资料”错误变成“已经形成大量学习资产”，制造审核负担与复习洪峰，也容易
丢失原文胶水。关系图若先行持久化，还会重新制造需要双写的知识真相。

自动能力只能帮助建立可搜索文本、可追溯目录候选和蒸馏草稿；未经真实使用或明确复核的结果不
进入 canonical Note、题卡、记忆或复习轨道。

## 四、三条供给通道

### 4.1 跟着自己的书学

学生导入教材、教辅、讲义或其他合法持有的资料。Runtime 先保存不可变 Material revision 并
尽快返回，再按学生实际打开的位置渐进建立物理页清单、可搜索文本、目录和 locator。文本型
PDF 优先使用可靠的原生文本；扫描、公式密集、图表密集或文本质量异常的页面使用视觉读取。
学生从目录或当前位置选择一节，与老师开始自由学习；以后也可由正式课程读取同一来源。

这条路径的价值是与学校教学同序：StudyForge 不抢学校课堂的方向盘，而是在相同来源上补断、
比较、练习和复习。

### 4.2 使用精选学习集

精选学习集以可复制目录包进入学生本地世界。它可以包含原创或已获授权的学习材料、Note、
题卡、标签、来源关系和可选课程结构。导入后得到个人副本：

- 既有资产不会因为复制而自动产生 `enrolled` 事件；
- 学生的本地 revision、作答、记忆和课程进度不回传，也不被更新覆盖；
- 后续版本以新版本或可审阅差异进入，不能静默改写个人副本；
- 精选集必须包含可读的讲解脉络或合法来源，不能只是去掉胶水的题卡包。

当前“导数示例”的复制路径已经证明目录级供给可行；未来 Commons 负责更多精选集的发布、
来源与许可，不需要为首个精选入口先建账号或中心数据库。

### 4.3 没有资料时由模型编写学习材料

学生没有书时，模型可以在专门的编写 Skill 中把世界知识组织成有章节、正文、例子、过渡和
练习的学习材料。它在产品形态上仍是一份 Material，而不是第四种学习资产。

这条通道不能把模型自己的话伪装成真书或已校对来源。开放前必须另行设计：

- 生成者、模型、时间和版本的 provenance；
- “AI 生成 / 教师已复核”的公开状态；
- 内容修订和错误纠正怎样影响已经引用它的资产；
- 是否以及怎样补充外部来源。

因此模型编写是北极星中的完整供给通道，但不属于第一阶段实施。

## 五、来源骨架与语义联系

### 5.1 来源骨架

来源骨架只回答“内容来自哪本资料、哪一章、哪一节、哪个位置”。它的根事实仍是 Material
revision 与原始内容。

第一版支持文本型与扫描型常见 PDF，不把“文件恰好自带可读目录”设为开箱门槛。目录来源按
可靠性依次为：

1. PDF bookmarks、Markdown 标题等原文件自带结构；
2. 精选学习集随授权来源提供的编者目录；
3. 从清晰目录页通过视觉读取形成的目录投影。

每个 Material revision 只增加一份可重建的**书籍索引投影**，不新增 Book、Chapter 或
OCR Document 等 canonical 资产。索引可以渐进形成，包含：

- 完整物理页清单、物理页序号与 PDF 页标签；
- 每页尚未处理、原生文本、视觉读取或失败的处理状态；
- 可搜索正文及其物理页或物理页段锚点；
- 目录节点、印刷页提示、可选物理页段和目录来源；
- 使用的读取方式、模型与版本等 provenance。

原 PDF 始终是唯一原文事实。OCR 文本只是方便搜索和模型读取的派生内容，不能覆盖原件；
目录也只负责导航，不能冒充先修关系、课程承诺或学生最佳路线。视觉目录识别错误时可以删除
重建，既有 Note / 题卡仍通过 `Material revision + physical page / page range` 打开原文，不依赖
易变化的章节节点 ID。没有可识别目录时保留原件并退化为页码导航，不静默编造 canonical
章节树。公式、图像、表格或题目版式参与含义时，教师必须能直接查看渲染后的原页证据；不能把
OCR 转写当作唯一证据。像素区域或裁剪框定位不属于第一版，页与连续页段已经足够形成稳定来源。
连续页段沿现有 `page-NNNN` 语法增加 `pages-NNNN-NNNN`；它由 Runtime 根据已核验的页面选择
机械生成，模型不手写页码字符串。非连续来源继续写成多个 `sources`，不发明复合 locator。

扫描目录中的“第 37 页”通常是书的印刷页码，不一定等于 PDF 的第 37 个物理页面。因此目录
识别可以先保存标题、层级、印刷页提示与 provenance，而把物理页段标为尚未定位。视觉模型
的目录提示词可以要求它在同时看见目录末页和带可见印刷页码的首张正文时，提出
`printedPageOffset` 候选；这是语义读取结果，不由 Runtime 根据目录长度猜测。学生首次打开
该节点时，Runtime 只在该候选附近的有限窗口内查找并核验章节标题，成功后才持久化物理页段；
失败则展示候选页并允许按页浏览，不能把未经核验的页码偏移写成准确 locator。

#### 渐进式处理

首个导入事务只负责以适合大文件的方式复制原件、记录便宜的文件元数据并返回。书籍主页随后
发起一个明确、可见的索引请求，读取页数、bookmarks 和必要的封面或目录候选页；它不是隐藏的
整书后台任务。学生选择某一节后，再处理该页段与完成当前理解所必需的邻页。第一版不在空闲时
自动预处理相邻章节，也不引入通用作业队列。中断后从已持久化页状态继续，不重复支付已经完成
的视觉读取。

视觉模型设置提供两种路径：

- 默认“自动”：当前主模型明确支持图像输入时，复用同一 provider / model；
- 可选覆盖：学生单独配置更便宜或更适合资料读取的视觉模型。

即使复用主模型，视觉读取也运行在独立资料处理任务中，不继承教师会话、学生记忆、课程上下文
或教学 Skill。主模型不支持视觉且没有单独配置时，界面明确引导配置，不伪造 OCR 结果。

#### 实施前置地基

当前实现只有同步 PDF 文本提取，且 HTTP 导入会把整个文件读进内存并受 32 MB 上限约束；它
还没有原页阅读器、页图渲染接口、逐页状态或后台作业系统。第一版实施必须先补四项地基：

1. 桌面端按路径或流式复制大文件，不再要求真实扫描书先整体进入 FormData / `arrayBuffer()`；
2. 可打开原 PDF 的阅读页，以及可供视觉模型读取的受控单页渲染接口；
3. 由 Material revision 键控、可逐页恢复的书籍索引状态；
4. 同时支持单页与连续物理页段的 locator 语法、读取与回跳。

模型目录还必须把“是否支持图像输入”暴露给 StudyForge，资料任务在发送页图前再次校验能力。
这四项是 OCR 与来源树成立的前提，不应被包装成提示词问题。

### 5.2 跨书语义联系

第一阶段不新增持久化的“前置 / 同型 / 易混 / 对比”边。跨书联系使用已经成立的两种表达：

- 多个资产具有相同或相关的平坦语义标签；
- 一份 Note 或题卡直接引用多个来源位置。

标签共现只能表述为“共享这些词”，不能自动叫作相似、因果、先修或共识。同一个词在多本书
反复出现，可以帮助召回和发现候选，但出现次数不自动代表重要性、考试频率或课程优先级。

本设计所说的“多书共识”必须表现为一份可读、可修订、引用具体来源的综合内容：由精选集
编者预先整理，或由师生在真实讨论中形成并确认保存。它是有作者和来源的 Note / 学习材料，
不是系统从标签覆盖次数机械推出来的结论。

如果真实使用证明“共享标签”无法保存师生明确提出的关系，再为显式关系单独设计事实主人、
作者、修订和纠错闭环；不能借图谱投影先写一套不可追责的关系事实。

来源树与语义视图可以组成跨书路径：

```text
书 A 的章节 → 从此处形成的资产 → 语义标签
             → 书 B 的相关资产 → 书 B 的原文章节
```

正式备课默认允许一次紧凑的跨书召回。第一版只走已经存在的资产通道：Scout 从当前页段、
教学目标和必要的学生记忆得到少量短检索词，查询 `asset-recall.tsv`，返回要求数量的 Note / 题卡
候选；备课教师再沿候选资产已经固定的 `sources` 读取少量原文，判断是否用于对照、迁移、诊断
或练习。自由学习只在当前讨论确实需要联想时触发同一条路径。

未形成资产的原始书页不会因为目录标题或语义猜测而进入跨书召回。第一版不为搜索候选临时 OCR
其他书，也不声称已经对所有书页建立语义索引；如果真实使用以后证明资产中介召回明显漏掉高价值
联系，再单独设计原文页段索引及其成本边界。

### 5.3 类型只是阅读与操作投影

Note、题卡和 Material 的类型决定页面怎样呈现、可以做什么动作，但不构成另一棵知识骨架。
学生可以按类型筛选；系统不需要把“类型轴”持久化为知识关系。

## 六、事实所有权

| 事实 | 唯一主人 | 可重建投影或消费者 |
| --- | --- | --- |
| 书的原始内容 | Material revision | 阅读页、Search / Read、文本投影 |
| 页清单、OCR 文本与视觉目录 | 由 Material revision 键控的书籍索引 projection | 来源树、搜索、渐进处理状态 |
| 原文件自带目录 | 原始 Material 内容 | 章节树 projection |
| Note / 题卡内容 | 资产 revision | 学生、Tutor、Scout 的安全投影 |
| 资产直接来自哪里 | 资产 revision 的 `sources` | 反向来源、章节下资产列表 |
| 资产涉及什么语义 | tag sidecar | 搜索、邻居与跨书候选 |
| 学生实际作答与看答案 | activity event | 最近状态与学习足迹 |
| 学生在对象上学到哪里 | 对象记忆 | Tutor / Coach 按需读取 |
| 正式课程承诺 | Roadmap / Plan / Lesson | 课程页面与 Session |
| 复习是否入轨及何时到期 | review event history | 日历与复习入口 |

必须保留的边界：

- 导入、下载、打开、滚动或生成内容都不创建认知判断；
- 导入或复制资产不等于加入复习；
- 章节覆盖、资产数量和标签数量不等于读完、理解或掌握；
- 资产来源修订后，旧 revision 仍固定到当时来源，不能漂移到最新版；
- 学生和教师的本地改写不覆盖原始书籍或精选包的上游版本。

## 七、第一阶段最小闭环

第一阶段只验证“来源主路能否成立”，不同时实现精选市场、整书批量资产蒸馏与模型造书。

```text
创建或打开一个学习集
→ 导入一本真实 PDF，包括扫描版
→ 建立页清单，并从书签或目录页渐进形成书籍索引
→ 打开书籍主页，同时看见目录和静态的起点引导
→ 选择一节“和老师学这里”
→ 渐进处理该节正文，必要时调用视觉模型
→ Free Learning 只携带该 Material revision + locator
→ 真实讨论形成 Note 或题卡草稿
→ 学生确认后保存准确 sources
→ 在原文章节看到由它形成的资产
→ 从资产一键回到对应原文
```

### 7.1 学生界面

- First Run 增加“从一本书开始”，底层仍先创建标准学习集，再进入 Material 导入；
- 导入完成进入书籍主页：目录可见，页面以老师口吻静态提示“你可以从现在学到的位置开始；
  不知道时我也可以帮你找起点”；只有学生选择章节或回应引导后才创建 Session 和调用模型；
- 处理进度以学生能理解的“正在整理目录 / 正在读取这一节 / 可以开始”呈现，不暴露模型、任务
  ID 或内部状态枚举；
- 首页在存在书籍时把“继续读这本书 / 从目录选择”提升为主行动，同时保留“问老师”；
- Material 页面首先是能查看真实 PDF 页面的阅读器，并展示可追溯目录、当前位置、上一节 /
  下一节和“和老师学这里”；尚未完成物理页定位的目录节点在首次打开时显示“正在定位这一节”；
- Note / 题卡来源使用人类标题与章节位置，一键回原文，不暴露 canonical locator；
- Material 章节页由反向来源索引列出“从这里形成的 Note / 题卡”；
- 学习资料提供“沿书学习”和“知识之间”两种视图：前者显示来源树，后者保留现有跨书语义
  关系；学生不需要拖节点或维护图结构；
- 设置页提供可选的资料视觉模型覆盖项，默认自动复用明确支持图像输入的主模型。

#### 已确认的桌面端视觉基准

静态预览位于 `apps/pi-teaching-web/preview/source-first/`，是生产实现的布局基准，不是另一套
产品表面。五个界面的职责固定为：

1. **第一次见面：** “从一本书开始”占主位；空白学习、已有学习集和示例是安静的次入口；
2. **学习首页：** “继续读这本书”是有书时的主行动，“问老师”仍在同页但降为便道；
3. **书籍概览：** 封面、书名与来源状态构成扉页；目录承担主工作区，静态起点引导和从本书
   长出的资产位于页边；
4. **原文阅读：** 桌面端采用“目录 / 原 PDF 页 / 学习边栏”三栏；原页占据最大面积，目录只
   负责定位，右栏只放“和老师学这里”、本节资产与相邻位置；
5. **学习资料：** “沿书学习”按书 → 章 → 资产展示来源树，并与按类型、学习足迹和“知识之间”
   并列；同一 canonical asset 在多处只作投影，不复制内容。

视觉继续沿用当前留白新中式主题：纸色为底、墨色建立层级、墨绿表达来源与当前定位、朱砂只
用于品牌章和关键学习行动。界面不能退化成卡片仪表盘或文件管理器；不增加拖拽建图、章节进度
百分比和未经证据支持的学习状态。书籍概览与原文阅读是唯一新增的核心构图，其余三屏是在现有
First Run、Home 和 Assets 上改造。

### 7.2 Agent 行为

- 资料处理任务只负责页图、文字、目录与 locator，不做教学判断，也不写资产、记忆或课程；
- 进入对话时只注入选中章节的紧凑来源身份和必要正文，不整本书塞入上下文；
- Tutor 可以按需向前后读取原文胶水，也可以读取相关对象记忆；
- Prepare 可以通过 Scout 查询跨书语义候选，但路线级核验和教学取舍仍由 Prepare 承担；
- Tutor 先帮助学生学习，不为尽快“蒸馏”而机械提问是否保存；
- 保存仍走公开草稿 → 学生自然确认 → 原子写入 → 成功回执；
- 书序只是默认路线。需要明显跳章、长期重排或建立课程时，分别交给学生决定、Meta 与课程周期。

### 7.3 验收情境

使用一本真实扫描版《化学反应原理》或同类教材完成，不能只用程序生成的单页 PDF：

1. 导入一份超过当前 32 MB 限制的真实资料，原件以流式或路径复制完成，不整体驻留内存；
2. 导入后立即看见书名和处理进度，不等待全书 OCR；
3. 可以在原页阅读器中查看公式、表格、图像和复杂版式，视觉模型读取的是渲染页而非空文本；
4. 主模型支持视觉时自动复用；主模型仅文本时可改用单独配置的视觉模型；
5. 从扫描目录页形成目录投影；在印刷页码与 PDF 物理页有偏移的情况下，首次打开并核验后才
   固定“沉淀溶解平衡”的物理页段；
6. 从 Ksp 附近一段开始自由学习，只处理当前页段与必要邻页；
7. 教师按需读取前文，讲清固体活度为何进入常数；
8. 学生形成一份带回忆块的 Note 或一张题卡；
9. 保存后的资产显示准确书名、章节和页码或页段；
10. 从资产返回原文，再从原文章节看见该资产；
11. 更新 Material 后，旧资产仍打开旧 revision 的准确位置；
12. 全程没有自动创建 Roadmap、记忆、复习 enrollment 或“已学会”状态。

补充一个跨书验收：导入第二份资料，形成一份同时引用两处原文的 Note；来源树在两处显示
同一资产，语义视图显示共享标签和准确来源。随后准备一节相关课程，Scout 能从当前章节召回
第二本书中的候选，Prepare 只深读实际采用的少量材料；系统不生成“先修”或“共识”等未经
断言的关系，也不为了召回而处理完整本书。

## 八、失败与降级

- **大文件复制失败：** 不留下可打开但内容不完整的 Material revision；报告可理解的原因并允许
  从原文件重试；
- **目录提取失败：** 保留原 Material，退回页码 / 文本定位；不伪造章节树；
- **目录页尚未映射到物理页：** 保留印刷页提示，首次打开时在有限窗口内定位；仍失败则展示
  候选页或退回按页浏览，不写假 locator；
- **视觉能力未配置：** 原件与书签仍可打开；需要读取扫描页时引导配置支持图像输入的主模型
  或独立视觉模型；
- **单页读取失败：** 保留原页并允许重试或更换视觉模型，不把一页失败扩大成整本导入失败；
- **目录识别错误：** 允许重新选择目录页或更换模型重建书籍索引，不修改原件与既有资产；
- **处理过程被关闭：** 从已持久化页状态继续，不重复处理已经成功的页面；
- **来源位置失效：** 资产内容继续可读，来源显示“原位置暂不可用”，不静默换到最新 revision；
- **精选包更新冲突：** 保留学生个人副本，以新版本或可审阅差异另行进入；
- **模型编写中断：** 不留下半本 canonical 材料；草稿可恢复但不进入资产与复习投影；
- **图或索引损坏：** 从 Material、sources 与 tags 重建，不影响 canonical 内容；
- **Agent 想整书扫描：** 由受管读取边界阻止，只读取当前章节、相邻胶水与精确召回命中的位置。

## 九、明确不做

第一阶段不做：

- 新建 Flashcard、错题本、学生作品或套卷 schema；
- 把书序持久化成先修 DAG；
- 自动按多书覆盖度决定重要性或课程优先级；
- 一键把整本书批量生成几百张 canonical 卡；
- 导入后无条件全书 OCR，或为了备课寻找“最优材料”而遍历所有书；
- 为首版引入通用后台作业队列，或空闲时自动预处理未打开章节；
- 给所有原始书页建立跨书语义索引；跨书召回先只沿已形成资产及其来源进行；
- 像素级区域框选与裁剪标注；首版来源定位止于物理页和连续页段；
- 用打开章节或资产数量生成“读完 60%”与掌握结论；
- 让学生拖节点、维护复杂关系或兼任图书管理员；
- 模型生成书、精选学习集市场、云端同步与自动更新；
- 完整 MarginNote 式批注编辑器。

这些边界保证第一阶段验证的是“书能否成为学习主路”，而不是一次性重造内容管理平台。

## 十、产品定位

面向学生的第一句话可以收敛为：

> 把你的书放进来，老师陪你一节一节学；学过的内容会长成自己的笔记、题卡和联系。

完整供给承诺是：

> 有一本书，就沿着它学；有多本书，就把它们连起来；没有书，也可以先问老师，以后再形成
> 自己的学习材料。

第三句暂不承诺“立刻给你写一本”，直到模型编写来源的审稿、标注与纠错闭环独立成立。

StudyForge 与 MarginNote 的共同点，是保留原文、来源结构、资产与回溯；关键区别不是“AI
替学生整理一切”，而是教师承担教学取舍，系统继承书已有的结构，学生把注意力留给学习。
骨架对学生可见，但不要求学生维护。
