# StudyForge 真实学习纪录录屏 HTML 设计

## 目标

用一次真实的“同构变形识别与迁移”学习周期，直观展示 StudyForge 如何根据学生的实际表现连续备课。最终产物是一份专门用于录屏的本地静态 HTML，以及由它录制出的约 12–15 分钟演示视频。

这不是正式产品功能，也不是通用回放系统。

## 展示内容

真实学习周期包含：

1. Coach 与学生讨论方向并建立 Plan；
2. Lesson 001 诊断学生当前路线；
3. Coach 根据课堂 Trace 调整 Lesson 002；
4. Lesson 002 建立同构原型；
5. Lesson 003 更换函数外壳，检查迁移；
6. Lesson 004 使用未见综合题验收；
7. Coach 完成 Plan 复盘；
8. 学生确认可进入长期记忆的学习偏好。

学生由 Codex 持续扮演：基础微积分与代数能力可靠，遇题习惯先计算，不故意犯错，也不预知教学目标。Coach 可以依据真实表现调整后续课的题目、难度与顺序，但四课学习周期保持不变。

## 制作方式

采用“真实课程数据 + 手工精选编排”的方式：

- 先在正式本地运行时跑完完整四课周期；
- 保留原始 Plan、Lesson、题卡、课堂对话、active Trace、能力投影与 Plan 复盘；
- 人工选取最能说明教学调整的时刻；
- 将选出的真实内容整理为一份静态演出数据；
- 本地 HTML 按固定时间轴自动切换章节、逐字显示对话并更新右侧说明；
- 使用屏幕录制工具捕获 HTML，再输出 2 倍速成片。

HTML 不回写任何学习事实，不新增教学协议，也不成为第二份课程真相来源。

## 画面结构

录屏画面固定为 16:9，沿用当前前端的墨绿、暖米色与低饱和金色主题。

### 顶栏

显示案例名称、当前章节和演出时间。它只承担定位作用，不模拟正式产品导航。

### 左侧章节栏

依次显示：

- 起点与目标；
- 诊断：会算；
- 原型：看结构；
- 换壳迁移；
- 综合验收；
- 复盘与记忆。

完成、当前和未开始章节使用不同的低干扰状态。

### 中央课堂区

中央是视觉主体，显示当前题目、Tutor 与学生的真实对话，以及必要的课堂节点。内容按演出脚本逐条出现，保留学生自然思考的停顿感。

画面不展示内部工具调用、原始 JSON、系统提示词或虚构的学习数据。

### 右侧解释栏

右栏只解释“这一刻为什么影响下一步”，包括：

- 学生当前采用的实际路线；
- 对应的学习印记与方法节点；
- 能力判断为什么保持、上调或继续观察；
- Coach 如何据此调整下一节课。

它不宣告超过现有事实的信息，也不把单次正确作答包装成稳定掌握。

### 底部时间轴

用连续时间轴串联 Coach 定向、四节 Lesson 和 Plan 复盘，突出这是一段持续学习，而不是四段互不相关的聊天。

## 演出节奏

完整 HTML 按正常速度演出约 12–15 分钟：

- 30–45 秒交代学生起点与 Roadmap；
- 每节课约 2 分钟，聚焦一个关键转折；
- 每次课间用 20–30 秒展示 Trace 如何改变下一课；
- 最后约 90 秒展示综合验收、Plan 复盘和长期记忆确认。

录屏后整体以 2 倍速发布，成片约 6–8 分钟。重要题目、学生回答和 Coach 调整需要保留足够停留时间，确保加速后仍可读。

## 文件边界

实现只需要一份自包含的本地 HTML：样式、演出脚本和人工整理的真实课程素材全部内嵌，不依赖网络资源。可以另附一份简短的本地录屏说明。

不建设：

- 通用 Plan 回放路由；
- 自动视频对齐；
- 正式产品入口；
- 新数据库、schema 或 MCP 工具；
- 面向任意学习集的回放生成器。

## 降级处理

- 某段真实对话不适合公开时，删除整段或做明确的匿名化处理，不补写伪造对话；
- 某个能力变化没有足够 Trace 支撑时，只展示“继续观察”；
- 页面脚本失效时，所有章节仍能通过键盘或底部时间轴手动推进；
- 字体或动画加载失败时，核心文字与布局仍可阅读和录制。

## 验收标准

1. HTML 可在本地浏览器直接打开并稳定完成一次全程演出；
2. 所有教学事实都能回溯到真实 Plan、Lesson、题卡、Trace 或 Session；
3. 观众无需理解内部架构，也能看懂“上一课的表现如何改变下一课”；
4. 中央课堂始终是主角，右侧解释不会演变为数据仪表盘；
5. 录制并按 2 倍速播放后，关键文字仍有足够阅读时间；
6. HTML 不修改正式运行时，也不引入通用产品能力。
