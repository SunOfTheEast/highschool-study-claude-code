# StudyForge 节点专属教学 Skill 树总设计

日期：2026-08-04

## 结论

Roadmap、Plan 与 Lesson 是三个独立 Session。它们面对的时间跨度、教学问题和学生
对话深度不同，不能共享一个通用“讨论 Skill”。资源装配改为五个顶层 Skill：

```text
Roadmap Session
├── roadmap-dialogue
└── prepare-approved-plan

Plan Session
├── plan-dialogue
└── prepare-approved-lesson

Lesson Session
└── tutor-lesson
```

Roadmap 讨论整个学习集中的长期能力、总体学法和下一个 Plan；Plan 讨论一个阶段在
多节课中的推进和下一课设计；Lesson 只处理当前课堂中的理解、作答、帮助和结束。

这是一份持续扩展的总设计文档。各模块先经过真实学习情境讨论并逐段确认，再追加到
同一文件；全部模块收束后统一生成实施计划和真实模型验收方案。当前已细化“初次
Roadmap 会面”，跨 Plan 复诊、Plan 对话和 Lesson 特殊教学技巧在后续章节继续设计。

## 资源分层原则

常驻 Agent、按需 Skill、Skill reference 与学习集文件承担不同职责：

```text
Agent：我是谁、负责哪一层、拥有什么权限、必须经过什么批准门
Skill：当前正在完成哪一种工作、怎样完成、产出什么交接
Reference：遇到某类具体情境时采用什么专业方法
学习集文件：当前学习集提供什么内容与学科教学边界
Roadmap / Plan / Lesson：学生已经确认或课堂真实发生了什么
```

具体归属如下：

- `math-teaching-core.md` 保存所有节点常驻的教师底色，例如自然交流、有依据的暂定
  判断、不制造分歧、尊重学生选择、承认误判和诚实区分独立与受帮助表现。
- `roadmap-node.md`、`plan-node.md`、`lesson-node.md` 只保存各节点身份、尺度、权限、
  禁止事项、批准门和 Skill 路由，不保存低频教学流程。
- 五个顶层 Skill 保存对应工作流的稳定主干与 reference 路由。
- 初次诊断、现场短探针、跨 Plan 复诊、Plan 周期、Lesson 模板和特殊讲解技巧等
  条件分支放进相应 Skill 的 references，只在命中真实情境时读取。
- `LEARNING_GUIDE.md` 保存学习集有什么、适合谁及其学科特有教学姿态。通用 Skill
  不硬编码“同构”“跨阶”等特定学习集内容，也不假设存在独立课程目录。

关键批准边界采用调用端与接收端分别守卫：Roadmap Agent 不得在学生确认前进入 Plan
准备，`prepare-approved-plan` 则拒绝物化没有已确认公开设计的输入。两者约束不同的
责任点，不复制整段工作流。

## 批准边界

Roadmap 与 Plan 都采用“先讨论、后实施”的教育版 Superpowers 工作流：

```text
公开讨论与教师方案
→ 学生明确确认或修正
→ 把最终设计写入父节点现有正文
→ 调用对应 prepare Skill
```

学生说“你来安排”只是授权教师提出方案，不是批准尚未公开的 Plan 或 Lesson。
即使学生的初始要求很具体，Coach 也先呈现完整设计并等待确认。学生对方案作出明确的
“接受并修改”后，修改后的表达可以构成最终确认，不增加第三次形式化审批。

## 节点交接

- Roadmap 通过一个已确认并写入的 Plan 文件向 Plan Session 交接。
- Plan 通过一个已确认并写入的 Lesson 文件向 Lesson Session 交接。
- Lesson 通过 Block Classroom Log 和关闭后的 Lesson 文件把课堂事实交还给 Plan。
- Plan 完成后通过 Plan 原文与 Handoff 回到 Roadmap；跨 Plan 证据的进一步设计另议。

不新增批准状态、schema、数据库、Session 类型或运行时状态机。确认后的公开设计使用
现有 Roadmap/Plan 自由正文表达。

## 渐进展开

五个顶层 Skill 只保存稳定职责、对话边界、批准门和按需引用入口。细节后续逐步加入：

- Roadmap 诊断、跨 Plan 复诊和能力地图作为 `roadmap-dialogue` 的 references；
- Plan 周期原型作为 Roadmap/Plan 对话可共享的 references；
- Lesson 模板与材料准备只属于 `prepare-approved-lesson`；
- 特殊讲解、提示、对照、修复和路线比较技巧作为 `tutor-lesson` 的 references；
- 学习集特有的数学教学方法继续来自 `LEARNING_GUIDE.md`。

五 Skill 骨架阶段只完成 Runtime 装配与确定性测试；本总稿从该骨架继续逐段细化教学
内容，但每次只展开已经与学生情境共同确认的模块。

## 初次 Roadmap 会面

### 目标与尺度

第一次 Roadmap 会面不是填写学习档案，也不是立即挑一个知识点开课。它是一段真实的
初次接诊：学生用自然语言描述愿望、困扰和最近经历；Roadmap 教师负责把这些材料解释
为一条暂定的长期能力方向、总体学法和下一个有边界的 Plan，再交还学生确认。

Roadmap 同时回答两个问题：

1. 学生希望经过较长周期后获得什么能力；
2. 学生准备采用怎样的总体学习方式获得它。

前者是“爬到哪里”，后者是“怎样爬整栋楼”。Plan 再把总体方针结合当前数学内容与
最近证据，翻译成这一层的具体学法；Lesson 只负责脚下这一个台阶。

### 渐进加载结构

初次会面的具体方法不常驻于 Roadmap Agent，也不增加第六个顶层 Skill：

```text
roadmap-dialogue/SKILL.md
└── references/diagnosis/
    ├── INDEX.md
    ├── first-roadmap.md
    └── live-diagnostic-probes.md
```

- Roadmap Agent 常驻允许“有边界的现场短诊断”，同时禁止把它扩展成未建档 Lesson、
  宣布掌握或替代正式课堂。
- `roadmap-dialogue` 保存首次会面触发条件、共同收敛流程和 reference 路由。
- `first-roadmap.md` 保存短介绍、自然问诊、教师解释、总体学法与首个 Plan 提案方法。
- `live-diagnostic-probes.md` 只在学生明显无法描述问题，且决策性不确定性无法靠继续
  交谈区分时加载。

### 自然对话而非固定问卷

进入干净学习集时，教师先根据 `LEARNING_GUIDE.md` 做足以让学生开口的短介绍，再听
学生的自然诉求；不先倾倒完整能力地图或假想课程目录。学生可以只说：

- “我想学点高级技巧。”
- “导数题我经常没有思路。”
- “我也不知道自己应该怎么学。”

不能要求学生自己说出“我缺少结构识别能力”或选择教育学术语。教师内部逐渐形成四个
判断，但对外始终保持自然对话：

1. 学生希望长期发生什么变化；
2. 哪些具体经历支持当前理解；
3. 整体更适合怎样学；
4. 哪个首个 Plan 最值得尝试。

这些判断不构成四道必问题，也不要求全部确定。每轮最多处理一个真正会改变长期路线的
问题，让学生的上一轮回答决定下一步。学生说“你帮我安排”表示停止继续盘问，由教师
承担提出方案的责任；它不是批准尚未公开的 Roadmap 或 Plan。

停止追问不以填满字段为标准。满足以下条件即可提出方案：

```text
教师能够提出一条有理由、可调整的长期路线
＋能够说明为什么先选当前 Plan
＋知道什么后续表现可能推翻判断
＋学生已经能够理解并确认或修正
```

### 现场短诊断

只有同时出现以下条件时，才从自然问诊切换为现场短探针：

- 学生无法稳定描述自己的问题，或说法互相矛盾；
- 教师已有两种以上会导向不同 Plan 的合理解释；
- 继续语言追问难以负责地区分这些解释。

教师先自然解释原因并取得轻量同意，例如：“我们再靠说可能也说不清，要不看两道很短
的题？我主要看你第一步会想到什么。”学生拒绝时，不强迫诊断；教师可以保留明确的
不确定性，提出一条可逆路线或建议以后使用正式诊断 Plan。

短探针允许两种材料来源：

- 优先使用学习集中已有且未曝光的可靠题目；
- 只需区分一个小变量时，允许教师临时编制短题。

题目应短而互补，每道主要区分一个解释，观察学生看见什么、怎样开始、在哪里停住以及
哪一级帮助使其恢复。不要用一道综合大题同时混合计算、结构识别、选路、耐力和提示
依赖，也不要为了“完整了解学生”无限扩题。

帮助采用“先保留首次状态，再正常帮助”的方式：

```text
学生先独立开始
→ 保留第一步和真实停止点
→ 必要时给最小提示
→ 观察哪种帮助改变了表现
→ 必要时换平行短题复验独立表现
```

可以解释题意，但首次尝试前不泄露正在诊断的决定性方法。学生主动求助时可以帮助；
提示后的成功用于判断什么支持有效，不能改写为独立完成。如果当前讲解会污染后续
探针，则暂缓完整讲解。诊断目的达到后，返回 Roadmap 判断与 Plan 提案，不顺势在
Roadmap Session 中上完一堂课。

原始作答保留在 Roadmap Session。`ROADMAP.md` 只写经学生确认的暂定解释、依据、
不确定性和推翻信号，不创建课堂 Trace，也不把一次短探针升级为稳定能力或永久标签。

若问题需要较多题、多轮复验、正式课堂记录或跨 Session 观察，则停止现场探针，公开
提议一个短诊断 Plan，并继续遵守 Plan 批准门。

### 公开 Roadmap 方案

初次讨论收敛后，采用“长期弧线公开、未来方向暂定、一次只批准并物化一个 Plan”的
粒度。公开方案需要让学生理解：

- 教师目前怎样理解他的愿望和具体情况；
- 这段长期学习希望产生什么能力变化；
- 总体准备怎样学，例如快速建立全景、逐层建构或难题探索；
- 基于当前学习集与学生情况推导出的暂定能力方向；
- 为什么先做当前 Plan；
- 哪些后续表现会改变路线、顺序或总体学法。

下一个 Plan 才详细到 `Stage Goal`、`Observable Capability Standard`、`Test` 和公开的
多课初始弧线。未来阶段只作为 Roadmap 正文中的暂定方向，不创建文件、不加入
`Plan Tree`。学生明确确认或修正最终方案后，`prepare-approved-plan` 一次只物化这
一个 Plan。

## 后续共同设计的模块

以下内容明确保留在同一总设计文档中继续讨论，不在初次 Roadmap 切片中预判答案：

- Roadmap 的跨 Plan 复诊与跨 Plan 课程记忆；
- Plan 首次阶段解释、课后复盘和下一 Lesson 讨论；
- `prepare-approved-plan` 与 `prepare-approved-lesson` 的完整交付核验；
- Lesson 中的特殊讲解、提示、纠错、路线比较和课堂适应技巧；
- 各模块组合后的端到端长周期验收。

## 验收

装配测试必须证明：

- Roadmap 只获得 `roadmap-dialogue` 与 `prepare-approved-plan`；
- Plan 只获得 `plan-dialogue` 与 `prepare-approved-lesson`；
- Lesson 只获得 `tutor-lesson`；
- 旧 `roadmap-study`、`coach-study` 与 `plan-next-cycle` 不再成为运行时入口；
- Plan 周期、Lesson 模板和材料准备 references 仍完整存在于新的归属位置。

骨架搭建阶段不进行教学话术验收；每个 Skill 细化后再使用真实学生情境分别做
RED/GREEN 验证。

### Skill 行为验收方法

Skill 修改遵循 RED—GREEN—REFACTOR。每个模块先在当前提示词上运行干净学习集和真实
模型，保留原始 Session、工具调用、公开对话和 CoT 作为 RED；确认失败形态后才修改
对应 Agent、Skill 或 reference。GREEN 使用相同学习集、模型、学生输入和判断标准，
不把预期答案写进学生话术或模型上下文。

初次 Roadmap 至少并行覆盖四种学生情境：

1. **目标较清楚的优秀学生**：“我想学点导数高级技巧，综合题经常没思路。”
2. **真的不知道怎样学**：“我也不知道该学什么，最近数学越来越乱。”
3. **明显糊涂的学生**：描述含糊或互相矛盾，需要轻量同意后的现场短探针。
4. **把决定权交给老师的学生**：“我说不清，你帮我安排吧。”

验收关注行为，不检查固定话术：

- 是否短介绍后进入具体经历，而不是倾倒课程目录；
- 是否让学生用自然语言说话，由教师承担专业解释；
- 是否在已有足够信息时停止追问；
- 是否只在决策性不确定性确实存在时启动短探针；
- 是否区分首次独立表现、提示后表现和后续平行复验；
- 是否在 Roadmap 中停止授课并返回长期判断；
- 是否公开长期能力、总体学法、暂定方向、下一个 Plan、依据与推翻信号；
- 是否在学生确认前不创建 Plan，并且一次只物化一个 Plan。

全部模块设计完成后，再补充跨节点组合场景和端到端长周期验收，不让单模块测试代替
完整 Roadmap → Plan → Lesson 学习过程。
