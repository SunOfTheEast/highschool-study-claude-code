# StudyForge 节点专属教学 Skill 树总设计

日期：2026-08-04

## 结论

Roadmap、Plan 与 Lesson 是三个独立 Session。它们面对的时间跨度、教学问题和学生
对话深度不同，不能共享一个通用“讨论 Skill”。资源装配改为五个顶层 Skill：

```text
Roadmap Session
├── roadmap-dialogue
└── prepare-approved-plan

Plan Session
├── plan-dialogue
└── prepare-approved-lesson

Lesson Session
└── tutor-lesson
```

Roadmap 讨论整个学习集中的长期能力、总体学法和下一个 Plan；Plan 讨论一个阶段在
多节课中的推进和下一课设计；Lesson 只处理当前课堂中的理解、作答、帮助和结束。

这是一份持续扩展的总设计文档。各模块先经过真实学习情境讨论并逐段确认，再追加到
同一文件；全部模块收束后统一生成实施计划和真实模型验收方案。当前已细化“初次
Roadmap 会面”“Roadmap Session 中的 Plan 制定”以及“已确认 Plan 的首次进入与草案式
共同备课”“课后复盘与后续 Lesson 共备”“Plan 阶段结束与父级回读”以及“Lesson 课堂
执行与适应”以及”已批准设计的 Plan/Lesson 准备交付”；并经 2026-08-04 校正审计并入
“约束负荷与决策点原则”和”Plan Session 的阶段路由”。Lesson 特殊教学技巧已根据
60 次真实模型运行收缩为四个按需 reference，并补入 Lesson Session 的证据、公开输出、
生命周期与日志边界。第一次长周期验收又证明通用 `edit` 不能稳定承担高频 Lesson
结构写入，因此按 M0 预留的失败退路补回两个像原生 `edit` 一样使用、但由 Runtime 绑定
事实与保证原子性的课堂工具；这不恢复旧 Trace、Handoff 或工具化教学工作流。长期跨
Plan 复诊、连续受挫学生、作业闭环与长间隔回归的具体 reference 在后续章节继续设计。
同一次验收还暴露了材料 Scout 的长等待：后续设计据此把 Scout 收缩为“规范特征召回与
浅核验”，把路线级深核验归还 Coach，并直接复用原生 `subagent` 事件向学生投影安全的
实时进度、向开发验收导出完整负担数据。

## 资源分层原则

常驻 Agent、按需 Skill、Skill reference 与学习集文件承担不同职责：

```text
Agent：我是谁、负责哪一层、拥有什么权限、必须经过什么批准门
Skill：当前正在完成哪一种工作、怎样完成、产出什么交接
Reference：遇到某类具体情境时采用什么专业方法
学习集文件：当前学习集提供什么内容与学科教学边界
Roadmap / Plan / Lesson：学生已经确认或课堂真实发生了什么
```

具体归属如下：

- `math-teaching-core.md` 保存所有节点常驻的教师底色，例如自然交流、有依据的暂定
  判断、不制造分歧、尊重学生选择、承认误判和诚实区分独立与受帮助表现。
- `roadmap-node.md`、`plan-node.md`、`lesson-node.md` 只保存各节点身份、尺度、权限、
  禁止事项、批准门和 Skill 路由，不保存低频教学流程。
- 五个顶层 Skill 保存对应工作流的稳定主干与 reference 路由。
- 初次诊断、现场短探针、跨 Plan 复诊、Plan 周期、Lesson 模板和特殊讲解技巧等
  条件分支放进相应 Skill 的 references，只在命中真实情境时读取。
- `LEARNING_GUIDE.md` 保存学习集有什么、适合谁及其学科特有教学姿态。通用 Skill
  不硬编码“同构”“跨阶”等特定学习集内容，也不假设存在独立课程目录。

关键批准边界采用调用端与接收端分别守卫：Roadmap Agent 不得在学生确认前进入 Plan
准备，`prepare-approved-plan` 则拒绝物化没有已确认公开设计的输入。两者约束不同的
责任点，不复制整段工作流。

## 约束负荷与决策点原则

Skill 与 reference 的篇幅不是主要风险；同一决策点上同时生效的克制条件数量才是。
模型更可能在"同一时刻要同时忍住多件反本能的事"时失守，而不是被文档总长度压垮。
因此：

- 每个决策点尽量只保留一条亮线：一个明确的动作顺序或一条单一规则。多从句条件门
  （"若 A 且 B 则 C，除非 D"）改写成顺序、路由，或在批准范围内的一句话询问。
- 应优先优化门的形态，再考虑增加门的数量。这是一条设计启发，不是实验结论；现有
  真实模型对照没有同时控制模型与提示词变量，不能推出模型档位之间的约束预算比例。
- 教师拿不准的分类，只有当分支会改变 Session 层级、批准范围、课程目标或明显影响
  学生体验时，才用一句自然语言问学生；普通教学判断（笔误还是概念错、先比较哪条
  路线等）仍由教师承担，用可逆的小调整落实。
- 一条规则必须写在对应行为实际发生的那个 Skill 与阶段中；只写在其他节点的规则
  等于没有。
- 同一失败安全方向全局一致：拿不准就停止并回到对话，各 Skill 引用同一措辞，不换
  说法重复。

## 批准边界

Roadmap 与 Plan 都采用“先讨论、后实施”的教育版 Superpowers 工作流：

```text
公开讨论与教师方案
→ 学生明确确认或修正
→ 把最终设计写入父节点现有正文
→ 调用对应 prepare Skill
```

学生说”你来安排”只是授权教师提出方案，不是批准尚未公开的 Plan 或 Lesson。
即使学生的初始要求很具体，Coach 也先呈现完整设计并等待确认。学生对方案作出明确的
“接受并修改”后，修改后的表达可以构成最终确认，不增加第三次形式化审批。

每个 Dialogue Skill 的核心各自完整保存本层的批准流程（Roadmap 侧在
`roadmap-dialogue`，Plan 侧在 `plan-dialogue`）；阶段 references 只引用它，不重复
改写。这不取消双端守卫：`prepare-approved-plan` 与 `prepare-approved-lesson` 仍独立
检查当前对话确有明确确认、且父节点已记录最终方案，才允许物化。

## 节点交接

- Roadmap 通过一个已确认并写入的 Plan 文件向 Plan Session 交接。
- Plan 通过一个已确认并写入的 Lesson 文件向 Lesson Session 交接。
- Lesson 关闭后，Plan Session 重新读取这个真实 Lesson；只有当前判断需要时才查看其中
  相关 Block 与 Classroom Log。
- Plan 完成后，Roadmap Session 重新读取这个真实 Plan；只有制定下一阶段确实需要时，
  才沿其 Lesson Tree 下钻到相关 Lesson 与 Block。
- 不生成独立 Handoff，也不把子节点事实复制到父节点。Tree 中的真实链接是唯一回读
  路径；未链接文件、目录扫描结果和孤立节点都不是该父节点的课程证据。

不新增批准状态、schema、数据库、Session 类型或运行时状态机。确认后的公开设计使用
现有 Roadmap/Plan 自由正文表达。

## 渐进展开

五个顶层 Skill 只保存稳定职责、对话边界、批准门和按需引用入口。细节后续逐步加入：

- Roadmap 诊断、跨 Plan 复诊和能力地图作为 `roadmap-dialogue` 的 references；
- Plan Session 的首次进入、课后复盘与 Plan 收口工作流作为 `plan-dialogue` 的结构
  触发 references，不在根 Skill 常驻；
- Plan 周期原型作为 Roadmap/Plan 对话可共享的 references；
- Lesson 模板与材料准备只属于 `prepare-approved-lesson`；
- 特殊讲解、提示、对照、修复和路线比较技巧作为 `tutor-lesson` 的 references；
- 学习集特有的数学教学方法继续来自 `LEARNING_GUIDE.md`。

五 Skill 骨架阶段只完成 Runtime 装配与确定性测试；本总稿从该骨架继续逐段细化教学
内容，但每次只展开已经与学生情境共同确认的模块。

## 初次 Roadmap 会面

### 目标与尺度

第一次 Roadmap 会面不是填写学习档案，也不是立即挑一个知识点开课。它是一段真实的
初次接诊：学生用自然语言描述愿望、困扰和最近经历；Roadmap 教师负责把这些材料解释
为一条暂定的长期能力方向、总体学法和下一个有边界的 Plan，再交还学生确认。

Roadmap 同时回答两个问题：

1. 学生希望经过较长周期后获得什么能力；
2. 学生准备采用怎样的总体学习方式获得它。

前者是“爬到哪里”，后者是“怎样爬整栋楼”。Plan 再把总体方针结合当前数学内容与
最近证据，翻译成这一层的具体学法；Lesson 只负责脚下这一个台阶。

### 渐进加载结构

初次会面的具体方法不常驻于 Roadmap Agent，也不增加第六个顶层 Skill：

```text
roadmap-dialogue/SKILL.md
└── references/diagnosis/
    ├── INDEX.md
    ├── first-roadmap.md
    └── live-diagnostic-probes.md
```

- Roadmap Agent 常驻允许“有边界的现场短诊断”，同时禁止把它扩展成未建档 Lesson、
  宣布掌握或替代正式课堂。
- `roadmap-dialogue` 保存首次会面触发条件、共同收敛流程和 reference 路由。
- `first-roadmap.md` 保存短介绍、自然问诊、教师解释、总体学法与首个 Plan 提案方法。
- `live-diagnostic-probes.md` 只在学生明显无法描述问题，且决策性不确定性无法靠继续
  交谈区分时加载。

### 自然对话而非固定问卷

进入干净学习集时，教师先根据 `LEARNING_GUIDE.md` 做足以让学生开口的短介绍，再听
学生的自然诉求；不先倾倒完整能力地图或假想课程目录。学生可以只说：

- “我想学点高级技巧。”
- “导数题我经常没有思路。”
- “我也不知道自己应该怎么学。”

不能要求学生自己说出“我缺少结构识别能力”或选择教育学术语。教师内部逐渐形成四个
判断，但对外始终保持自然对话：

1. 学生希望长期发生什么变化；
2. 哪些具体经历支持当前理解；
3. 整体更适合怎样学；
4. 哪个首个 Plan 最值得尝试。

这些判断不构成四道必问题，也不要求全部确定。每轮最多处理一个真正会改变长期路线的
问题，让学生的上一轮回答决定下一步。学生说“你帮我安排”表示停止继续盘问，由教师
承担提出方案的责任；它不是批准尚未公开的 Roadmap 或 Plan。

停止追问不以填满字段为标准。满足以下条件即可提出方案：

```text
教师能够提出一条有理由、可调整的长期路线
＋能够说明为什么先选当前 Plan
＋知道什么后续表现可能推翻判断
＋学生已经能够理解并确认或修正
```

### 现场短诊断

只有同时出现以下条件时，才从自然问诊切换为现场短探针：

- 学生无法稳定描述自己的问题，或说法互相矛盾；
- 教师已有两种以上会导向不同 Plan 的合理解释；
- 继续语言追问难以负责地区分这些解释。

教师先自然解释原因并取得轻量同意，例如：“我们再靠说可能也说不清，要不看两道很短
的题？我主要看你第一步会想到什么。”学生拒绝时，不强迫诊断；教师可以保留明确的
不确定性，提出一条可逆路线或建议以后使用正式诊断 Plan。

短探针允许两种材料来源：

- 优先使用学习集中已有且未曝光的可靠题目；
- 只需区分一个小变量时，允许教师临时编制短题。

题目应短而互补，每道主要区分一个解释，观察学生看见什么、怎样开始、在哪里停住以及
哪一级帮助使其恢复。不要用一道综合大题同时混合计算、结构识别、选路、耐力和提示
依赖，也不要为了“完整了解学生”无限扩题。

帮助采用“先保留首次状态，再正常帮助”的方式：

```text
学生先独立开始
→ 保留第一步和真实停止点
→ 必要时给最小提示
→ 观察哪种帮助改变了表现
→ 必要时换平行短题复验独立表现
```

可以解释题意，但首次尝试前不泄露正在诊断的决定性方法。学生主动求助时可以帮助；
提示后的成功用于判断什么支持有效，不能改写为独立完成。如果当前讲解会污染后续
探针，则暂缓完整讲解。诊断目的达到后，返回 Roadmap 判断与 Plan 提案，不顺势在
Roadmap Session 中上完一堂课。

原始作答保留在 Roadmap Session。`ROADMAP.md` 只写经学生确认的暂定解释、依据、
不确定性和推翻信号，不创建课堂 Trace，也不把一次短探针升级为稳定能力或永久标签。

若问题需要较多题、多轮复验、正式课堂记录或跨 Session 观察，则停止现场探针，公开
提议一个短诊断 Plan，并继续遵守 Plan 批准门。

### 公开 Roadmap 方案

初次讨论收敛后，采用“长期弧线公开、未来方向暂定、一次只批准并物化一个 Plan”的
粒度。公开方案需要让学生理解：

- 教师目前怎样理解他的愿望和具体情况；
- 这段长期学习希望产生什么能力变化；
- 总体准备怎样学，例如快速建立全景、逐层建构或难题探索；
- 基于当前学习集与学生情况推导出的暂定能力方向；
- 为什么先做当前 Plan；
- 哪些后续表现会改变路线、顺序或总体学法。

下一个 Plan 才详细到 `Stage Goal`、`Observable Capability Standard`、`Test` 和公开的
多课初始弧线。未来阶段只作为 Roadmap 正文中的暂定方向，不创建文件、不加入
`Plan Tree`。学生明确确认或修正最终方案后，`prepare-approved-plan` 一次只物化这
一个 Plan。

## Roadmap Session 中的 Plan 制定

### 所属 Session 与触发时机

“制定一个 Plan”发生在绑定 `ROADMAP.md` 的 Roadmap Session 中，而不是绑定某个既有
Plan 的 Plan Session 中。二者不能因为都谈到“下一步”而混为一谈：

- Roadmap Session 选择并共同制定当前学习集的第一个 Plan，或一个既有 Plan 结束后的
  下一个 Plan；
- Plan Session 接受已经由 Roadmap 确认的阶段边界，结合本 Plan 中真实发生的 Lesson
  调整阶段内的推进，并共同制定下一节 Lesson；
- Plan Session 可以把新的证据和建议交还 Roadmap，但不能越权替学生决定下一个 Plan。

首次 Roadmap 会面不一定要把所有长期方向讨论得同样细。Plan Tree 为空、且长期方向和
总体学法已经足够支持当前选择时，就详细制定第一个 Plan。后续 Plan 只在 Plan Tree 中
最新已链接 Plan 自身的 frontmatter 已为 `completed` 时制定。学生在 `prepared` 或
`active` Plan 中主动转向，或现有证据表明阶段目标可能选错时，先回当前 Plan Session
讨论“选择结束”与收口；学生通过界面完成当前 Plan 后，Roadmap 才复诊并制定后继。

### Plan 的定义与粒度

Plan 不是教材章节名、若干知识点的容器，也不是一节课要完成的小任务。它是一个有边界
的中期能力周期：多节 Lesson 围绕同一个阶段目标积累证据、根据表现调整教学，最后用
一个能直接检验该目标的任务作出有意义的阶段判断。

判断粒度时不按 Lesson 数量机械切分，而检查三个关系：

1. 这些 Lesson 是否共同服务一个连贯的 `Stage Goal`；
2. 各课证据是否会进入同一个能力判断与调整循环；
3. 完成这个循环后，是否值得回到 Roadmap 重新选择下一阶段方向。

如果内容只需要一次小活动或一次局部修复，通常属于 Lesson；如果其中包含多个彼此独立
的阶段目标、检验和教学循环，则应拆成多个 Plan。反过来，一张内容清单看起来很长，
也不自动意味着必须拆分；只要它们共同构成同一个能力循环，就可以保留在一个 Plan 中。

每个 Plan 至少需要形成四个相互对齐的锚点：

- `Stage Goal`：学生经过这一阶段要发生什么能力变化；
- `Observable Capability Standard`：届时学生能够独立表现出什么；
- `Test`：用什么直接而有意义的任务检验，不以“上完内容”代替；
- `Current Position`：为什么现在这样安排，包括已知证据、合理假设与仍然存在的不确定性。

这四项用于约束课程设计，不要求学生以字段或教育学术语逐项回答。

### 第一个 Plan 与后续 Plan

第一个 Plan 从学生初次会面的真实诉求、总体学法、`LEARNING_GUIDE.md` 声明的学习集
范围和当前可支持的判断中推出。Roadmap 不为此枚举或读取具体卡片、材料和知识图谱；
具体材料选择属于后续备课。没有证据时可以保留假设，但不能为了让 Plan 显得完整而发明
学生的薄弱点。
当关键不确定性会导向完全不同的首个阶段时，可按前述规则进行现场短探针，或先共同建立
一个正式诊断 Plan。

后续 Plan 不是按预设目录自动播放。Roadmap 教师需要回看 Roadmap 中已链接的既有 Plan
及足以支持判断的课堂证据，结合学生此刻的目标、时间和主观感受，说明：

- 上一个阶段实际建立了什么，哪些仍需支持；
- 为什么当前最值得进入这个方向；
- 还有哪些合理方向，以及选择当前方向的主要代价；
- 什么新表现可能使这项建议需要改变。

既有 Plan 是专业建议的证据，不是替学生自动决定下一阶段的指令。课程证据只能沿当前
Roadmap 已链接的节点取得；目录中未链接的文件不能被当作该学生的历史。完成一个 Plan
后，Roadmap 先重读该 Plan，再只为当前决策按需沿 Lesson Tree 下钻。怎样在多个历史
Plan 间长期压缩、复诊和形成更长周期记忆，仍留给后续专门模块设计。

### 逆向制定流程

Roadmap 教师先从阶段结束时希望看见的能力反推课程，而不是先凑 Lesson 清单：

1. 说明这个 Plan 为什么现在值得做，并区分证据、推断和未知；
2. 收敛一个有边界的 `Stage Goal`；
3. 把目标翻译成可观察的独立表现，并设计与之直接对齐的 `Test`；
4. 判断学生的当前位置与目标之间最关键的学习变化；
5. 选择合适的阶段推进方式，并形成一条可调整的多课初始弧线；
6. 标出会促使教师加快、放慢、补支架、改变顺序或返回 Roadmap 的证据；
7. 给出明确的专业建议、主要理由与代价，交给学生确认或修改；
8. 只有学生确认后，才记录最终设计并调用 `prepare-approved-plan`。

Plan 周期原型可以帮助教师思考推进方式，但它是按需加载的专业参考，不是要让学生选择
的模板名，也不应作为持久化字段。公开对话应呈现教师对这个学生的具体建议，而不是
暴露内部模板或把一组选项原样推给学生。

### 教师建议与学生决策权

Roadmap 教师不能把决策责任伪装成“尊重学生”，只给出一排中性选项。教师必须根据已有
证据明确推荐最值得做的 Plan，解释为什么现在做、会得到什么，以及暂时不选其他方向的
影响。学生保留路线和节奏的最终决定权。

如果学生选择另一条仍然合理的路线，教师应把最重要的代价或风险解释一次；学生理解后
仍然选择它，就按学生的选择重新形成方案。学生的选择可以改变未来学习安排，不能改写
过去证据，也不能偷偷降低已经公开的能力标准。若学生的选择会使原目标无法成立，教师
需要公开指出冲突并共同改写 Plan，而不是保留一个名不副实的测试。

### 动态 Lesson 数量与初始弧线

Plan 的 Lesson 数量取决于学生在真实课堂中的独立表现、提示依赖、迁移速度和可用时间。
制定 Plan 时尚未发生这些课堂，因此只能估计工作量，不能承诺一个固定课次。曾讨论的
“五到六节一小时一对一课”只是一种可能的估量示例，不是默认值、字段、状态或结束条件；
真实 Plan 可以更短，也可以更长。

如果学生关心时间投入或现实约束会影响选择，Roadmap 教师可以给出暂定范围，同时说明
估算依据和可能改变它的表现；否则优先讲清学习弧线，不为了显得精确而编造课次。公开的
初始弧线描述各阶段要解决的问题与相互关系，不预先创建所有未来 Lesson。

进入 Plan Session 后，可以在不改变已确认 `Stage Goal`、能力标准和 `Test` 的前提下，
依据每节课证据调整后续 Lesson 的数量、顺序、支架和练习重心。学生提前达到标准时不为
凑课次继续上课；需要更多时间时也不为遵守初始估算仓促结课。如果证据表明阶段目标本身
选错、需要拆分或应当换方向，则应带着证据回到 Roadmap 重新讨论，不能在 Plan 内静默
换成另一个目标。

### 化学反应原理校准示例

学生说“我想预习化学反应原理”时，Roadmap 可以建议采用“先建立模型和框架，再用少量
代表性问题检验迁移”的总体学法。第一个 Plan 可以围绕能量账本、热化学方程式与盖斯
定律形成一个连贯的阶段能力周期，而不是把整本书一次列成课程目录。

完成首个 Plan 后，第二个 Plan 可以把反应速率的定量表示、图像与数据、浓度温度催化剂
的微观解释、实验控制和迁移任务放进同一个循环。这里不因知识点数量或预计课次数量自动
拆分；如果它们共同服务“从证据表征到机制解释再到实验与迁移”的阶段判断，就可以是
一个 Plan。只有当学生情况使其中出现相互独立的目标、检验和适应循环时，才建议拆分。

### 批准与物化边界

Roadmap 教师最终需要公开一个完整但可调整的 Plan 提案，让学生看懂当前依据、阶段目标、
结束标准、直接检验、初始学习弧线、可能的调整信号，以及在需要时给出的暂定工作量。
学生可以接受、修改或拒绝。“你来安排”只要求教师承担完整提案，不能代替对这个已公开
提案的确认。

确认后，最终设计写入 Roadmap 的现有正文，再由 `prepare-approved-plan` 一次物化一个
Plan 并连接到 `Plan Tree`。未来 Plan 只能保留为 Roadmap 中的暂定方向，不预先创建空
文件；Lesson 也要到相应 Plan Session 逐节讨论、确认和准备。

## Plan Session 的阶段路由

`plan-dialogue` 根 Skill 只保存职责尺度、以下路由和统一批准门；各阶段工作流住在
结构触发的 references 中，只在命中对应文档状态时读取：

```text
Lesson Tree 为空且没有当前 Lesson
→ 首次进入（references/first-entry.md）

最新 Lesson 已 closed，且没有 prepared/active 的下一课
→ 课后复盘（references/post-lesson-review.md）

学生主动提出结束，或教师在复盘后认为已有达标可能
→ Plan 收口（references/plan-closure.md）

已有 prepared/active Lesson
→ 不创建另一课
```

路由只依据 Plan 与 Lesson Tree 的既有结构状态，不新增 phase 字段。"证据接近标准"
不是结构触发条件，而是教师在复盘后作出的专业判断；收口不得由预计课次数、预设弧线
走完或教材章节讲完触发。

## 已确认 Plan 的首次进入与草案式共同备课

### 首次进入不是重新审批 Plan

学生进入绑定既有 Plan 的 Plan Session 时，该 Plan 已经在 Roadmap Session 中共同制定
并得到确认。Plan 教师先用自然语言完成一次简短交接：这个阶段为什么现在做、主要希望
发生什么变化、怎样看出阶段已经完成，以及第一课为什么可能从当前位置开始。教师可以
澄清学生的理解，但不把整个 Plan 再读一遍，也不要求学生重新批准已经确认的阶段。

如果学生此时明确反悔，或提出的目标已经超出当前 Plan，教师应解释冲突并把路线问题交
回 Roadmap；不能借第一节课备课在 Plan 内静默换掉 `Stage Goal`。如果变化只涉及阶段内
的先后、强度、学习方式或第一课重心，则可以留在 Plan Session 中共同调整。

### 教师草案先行，学生实质修订

真实家教通常不是师生面对一张白纸共同写教案。进入讨论前，教师先根据已确认的 Plan、
现有证据、初始课程弧线和专业判断形成一份暂定 Lesson 草案，再把它作为有理由的建议交
给学生讨论。这样由教师承担设计责任，也让学生面对一个可以具体回应的方案。

草案不是已经批准或物化的 Lesson，也不能因为教师已经投入时间就变成学生必须接受的
安排。教师应尽早用不泄题的方式讲清推荐内容，让学生能够实质改变它；共同备课发生在
对草案的理解、质疑、调整甚至放弃之中，而不只是记录一个偏好参数。

公开协商层可以根据当前情境讨论：

- 这一课具体要推动 Plan 中的哪一步，以及为什么先做它；
- 学生对相关内容的现有经验、主观困难和此刻准备状态；
- 本课的重点、难度、节奏、参与方式和时间约束；
- 准备采用怎样的学习活动、材料类型、课堂互动与课后负担；
- 学生到课末应能表现出什么，什么证据说明本课目标已经达到。

这些不是必须逐项盘问的表单。教师以草案为起点说明建议和真实取舍；学生可以回应、
追问、拒绝或修改，教师据此继续判断并修订。对话持续到教师能够整合一份有依据的课程
方案，且学生能够理解它将怎样进行并作出决定。不存在“最多只能问一个问题”的限制，
也不能用连续问卷把专业设计责任推回学生。

学生提出“我不想学这个”时，教师不应守着原草案继续做表面微调，而要先听清他拒绝的
对象和原因：

- 如果学生仍认可当前 Plan，只是不接受这节课的切入点、顺序或形式，就在 Plan Session
  中放弃或重写 Lesson 草案；
- 如果学生不再认可当前 Plan 的阶段目标，可以先在当前对话中把原因听清，但应停止创建
  Lesson，并回到 Roadmap Session 共同制定替代 Plan。

草案的沉没成本不能成为说服学生继续的理由。教师可以解释一次关键收益与代价，但学生
理解后仍拒绝，就重新开始共同思考，而不是把“专业建议”变成软性强迫。

专业准备层由教师承担，包括：

- 具体题目、例子、答案和材料编排；
- 提示阶梯、常见误区、诊断意图和课堂分支；
- 根据不同学生反应采取的支架、追问与备用路线；
- 为课堂记录和课末证据准备的具体观察点。

教师在形成初始草案时可以预想这些内容，以确保建议可教；会破坏诊断或学习体验的细节
不提前泄露，也不在学生确认前物化为正式 Lesson。`prepare-approved-lesson` 在公开方案
确认后完成并固化专业准备。“专业细节”不能成为偷换课程的理由：最终教案必须服务双方
已经确认的目标、重点、学习方式、负担和完成标志。

### 共同备课流程

`plan-dialogue` 承担从教师草案到确认方案的完整公开共同备课，而不只是替
`prepare-approved-lesson` 收集一个参数：

1. 根据既有 Plan 与现有证据，先形成一份可放弃的暂定 Lesson 草案；
2. 简短解释既有 Plan、当前建议起点和草案理由，不重新审批 Plan；
3. 学生围绕目标重点、学习方式、难度、负担和现实约束提出反应，教师说明取舍并修订；
4. 学生拒绝当前内容时，先理解原因：阶段内重做 Lesson，否定阶段则停止并返回 Roadmap；
5. 教师把修订结果整合成一份完整但不泄题的公开 Lesson 提案；
6. 学生明确确认、修改或拒绝该提案；
7. 只有确认后，才调用 `prepare-approved-lesson` 完成专业准备并物化当前一个 Lesson。

公开 Lesson 提案至少让学生看懂：本课为何现在进行、本课目标、与 Plan 的关系、大致
学习过程、预期参与方式、课末完成标志，以及会实质影响学生选择的负担或取舍。它不需要
公开答案、提示机关或逐分钟教案。

学生说”你来安排””都可以”或”直接开始吧”，可以终止继续追问并授权教师整合提案，
但仍不等于批准一个尚未公开的 Lesson。教师必须先呈现完整方案；学生对这个方案明确
同意或作出修改后，才能进入准备。学生在讨论中已经明确提出完整要求时，教师仍需复述并
补足关键设计边界，再取得对最终版本的确认。

连续课程中的提案可以随既定节奏紧凑，只要相同要素仍被学生看懂；”嗯、行、可以”这类
明确的语言回应可以构成确认；沉默、表情或学生的继续操作永远不得推断为批准。

### Skill 责任边界

- `plan-dialogue` 保存阶段交接、共同备课、教师建议、学生决策权和 Lesson 批准门；
- Lesson 类型、材料选择和备课方法作为 `prepare-approved-lesson` 的按需 references；
- `prepare-approved-lesson` 只能展开已确认设计，不能新增会实质改变学生体验的目标、
  负担或评价标准；
- `tutor-lesson` 在课堂中根据真实反应实施和调整，但不能把课堂适应伪装成已经提前得到
  学生批准的另一套课程。

首次进入只确定 Plan 交接与第一节 Lesson 的共同备课。后续 Lesson 如何结合上一课证据
复盘并共同调整见下一节；何时结束 Plan 仍在后续模块中单独设计。

## 课后复盘与后续 Lesson 共备

### 教师先读证据，讨论后再生成草案

一节 Lesson 结束后，Plan 教师先读取当前 Plan 及其已链接 Lesson 的课堂记录，把最初的
课程弧线与真实表现进行比较，形成对上一课的初步证据判断、仍需澄清的问题和几种可能
方向。此时不生成下一课草案：上一课后的学生体验尚未进入判断，过早形成具体课程容易让
后续讨论只剩对既有方案做微调。教师也不能沿目录枚举未链接 Lesson 作为证据。

但公开对话的顺序不同。教师先给学生一个不受教师结论锚定的表达机会，例如自然询问：
“上节课你自己感觉哪里真的顺了，哪里还不踏实？”这不是固定问卷，也不要求学生给自己
下专业诊断。学生愿意详细说时就继续听；学生说不清、只说“还行”或希望教师直接判断时，
教师不反复逼问，而是进入有依据的公开复盘。

学生的主观体验是证据的一部分，不是对能力状态的唯一裁决。课堂记录同样不能压过学生
的体验。教师公开复盘时区分：

- 课堂中实际发生的作答、停止点和帮助；
- 学生现在报告的理解感、困难、兴趣和负担；
- 教师基于两者作出的暂定解释；
- 还没有被独立表现证明的部分。

如果学生感觉“已经完全会了”，但课堂成功依赖提示，教师可以同时承认理解感有所改善，
并说明独立迁移仍需验证；如果学生觉得自己“什么都没学会”，但已经出现稳定的独立进步，
教师也应拿出具体证据帮助他校准，而不是简单附和。两类证据冲突时，保留冲突并把它转化
为下一课需要检验的问题，不能改写原始课堂事实。

师生先把“上一课实际说明了什么”和“下一步真正需要解决什么”讨论到足以设计课程，再
由教师承担整合责任，生成第一版下一课草案。这个顺序与 Plan 刚开始时不同：第一节课
缺少本 Plan 内的既往课堂经验，可以由教师依据已确认 Plan 草案先行；后续课已经有新的
师生经验，必须先把它纳入讨论，不能只拿预设弧线生成草案。

### 初始课程弧线只是可调整假设

Plan 中公开的多课弧线为教师提供方向，不是必须按顺序播放的课程目录。每完成一节课，
教师都根据独立表现、提示依赖、迁移、学生体验和现实约束判断接下来更适合：

- 按原方向继续，但更换例子或难度；
- 加快推进，提前进入迁移或检验；
- 放慢、回访前置理解或增加支架；
- 调整阶段内的先后、学习方式和课后负担；
- 暂停建课，把已经超出本 Plan 的路线问题交回 Roadmap。

这些调整可以改变 Lesson 数量和阶段内路径，但不能静默改写 `Stage Goal`、能力标准或
`Test`。已经完成某节 Lesson 也不等于对应能力已经掌握，提示后的流畅更不能被折算成
独立完成。

### 亮线顺序与 reference 路由

课后复盘的完整工作流住在 `plan-dialogue/references/post-lesson-review.md`，根 Skill
只按阶段路由进入。顺序只有一条亮线：

```text
读证据 → 先听学生 → 公开判断 → 再生成草案
```

- 读证据：读取当前 Plan 与刚关闭的已链接 Lesson；只有当前判断需要时才查看相关
  Block 与 Classroom Log。此时形成初步判断与待澄清问题，不生成草案。
- 先听学生：先给学生一个不受教师结论锚定的表达机会；学生说不清、只说”还行”或
  希望教师直接判断时，不反复逼问。
- 公开判断：区分课堂事实、学生体验、教师解释与未知，说明进展、困难和对原弧线的
  调整判断。
- 再生成草案：师生讨论出下一步需要后，教师才生成第一版草案，说明理由与主要取舍；
  学生修订或拒绝后，教师整合为完整但不泄题的公开提案，经明确确认按统一批准门写入
  `Next Lesson Arrangement` 并调用 `prepare-approved-lesson`。

在上一步完成前不进入下一步：未听学生前不公开教师结论，未讨论出下一步需要前不生成
草案，未确认前不搜索材料、不读取模板、不创建 Lesson。学生否定的是本课时在阶段内
重做草案；否定整个阶段时停止建课并返回 Roadmap。

学生说”你根据上节课看着安排”会减少不必要追问，但不跳过公开复盘、草案说明与确认。
教师也不能因为 Plan 里已经写过未来弧线，就把它当成学生预先批准了所有后续 Lesson。

### 本轮边界

课后复盘与后续 Lesson 共备的完整工作流属于 `plan-dialogue` 的结构触发 reference
（`references/post-lesson-review.md`），不在根 Skill 常驻；对不同证据组合采用何种
阶段内教学周期，可以按需读取 Plan 周期 references。`prepare-approved-lesson` 仍只在
确认后完成具体材料和专业教案，不负责替 Plan 教师决定下一课方向。

本节只设计“继续本 Plan 时怎样复盘和准备下一课”。何种证据足以建议结束 Plan、学生
怎样参与结束决定、结束后怎样回到 Roadmap，见下一节。

## Plan 阶段结束与父级回读

### 结束由双方发起，不由课次数触发

Plan 的结束讨论可以由教师或学生发起：

- 学生任何时候都可以提出停止当前 Plan 或改变方向；
- 教师在课后复盘后判断已有达标可能时，主动建议进行阶段检验或收口讨论——这是
  专业判断，不是结构触发条件；
- 预计 Lesson 数量、预设弧线已经走完或教材章节已经讲完，都不能自动触发完成。

收口工作流住在 `plan-dialogue/references/plan-closure.md`；进入收口
的路由条件只有学生主动提出结束，或教师在复盘后认为已有达标可能。

无论谁发起，Plan 教师都先重新读取当前 Plan 与相关已链接 Lesson，并与学生公开复盘
结束依据，再区分是“能力达标后完成”，还是“能力尚未充分证明但学生选择结束”。教师
要给出明确专业建议，学生保留是否继续当前阶段的最终决定权。

临时不约下一课不等于完成 Plan。本设计不新增 `paused` 状态；只有学生确实选择结束当前
阶段时，才进入完成流程。启动和完成仍由学生通过现有界面决定，Agent 不自行改写状态。

### 生命周期完成不等于能力达标

当前 M0 Plan 状态只有 `prepared`、`active` 与 `completed`。`completed` 表示这个 Plan
生命周期已经结束，不是“学生已经掌握”的机器标签。结束时必须保留两种不同结论：

1. **达标完成**：已有足够直接、独立且与阶段标准对齐的证据；
2. **选择结束**：学生决定停止或转向，但能力尚未充分证明，或现有证据明确显示仍有
   未完成部分。

学生选择可以决定未来是否继续投入，不能改变过去课堂事实，也不能把第二种结论改写成
第一种。教师同样不能因为希望课程“圆满结束”而降低原定标准。

Plan 自身只保存这一层的最终阶段判断，不复制所有 Lesson 事实。完成前，`Current
Position` 应反映：阶段目标目前达到何种程度、什么仍未证明、学生怎样理解自己的变化、
以及为什么此刻结束。`Next Lesson Arrangement` 只表达父级行动：不再准备当前 Plan 的
下一课，返回 Roadmap 讨论后续方向。详细作答、帮助和课堂过程仍由原 Lesson 与 Block
持有。

### 达标必须有直接独立证据

“达标完成”不强制额外增加一节正式考试课。证据可以来自：

- 学生执行 Plan 中原定 `Test` 时产生的真实表现；
- 已关闭 Lesson 中与 `Test` 同等直接、难度和迁移要求足以对齐的独立表现。

如果已有课堂证据完整覆盖能力标准，可以直接进入结束讨论；如果只有部分完成、熟悉题
流畅、提示后成功或教师印象，则不能宣告达标。教师应建议一节对齐 `Test` 的检验或巩固
Lesson，并继续遵守逐课讨论与批准门。学生可以拒绝该检验并选择结束，但结果只能是
“能力尚未充分证明”。

等价证据不是为了绕过原定 `Test`。教师需要公开说明它与 `Stage Goal`、可观察标准和
`Test` 怎样对齐，以及哪些边界仍然存在；无法说明时就不构成完成依据。

### 结束流程

Plan Session 按以下顺序收口：

1. 教师或学生提出可能结束当前 Plan；
2. 教师重新读取 Plan 和当前决策所需的已链接 Lesson/Block 事实；
3. 先听学生对阶段变化、负担和下一步愿望的看法；
4. 教师公开对照 `Stage Goal`、能力标准和 `Test`，区分独立表现、受帮助表现、学生体验、
   教师解释与未知；
5. 若证据不足而学生仍希望达标完成，返回后续 Lesson 共备，提议必要的检验或巩固；
6. 若准备结束，教师明确说明属于“达标完成”还是“选择结束”，并解释最重要的影响；
7. 学生确认结束结论后，教师更新 Plan 级判断与父级行动，不创建下一 Lesson；
8. 学生通过界面完成 Plan，随后在 Roadmap Session 讨论下一个 Plan。

教师可以建议下一阶段值得考虑的方向，但不能在 Plan Session 中制定或批准下一个 Plan。
Roadmap 必须重读完成后的真实 Plan，再结合学生当时的优先级重新提出建议。

### 父节点重新读取，按需沿 Tree 下钻

Plan → Lesson 与 Roadmap → Plan 使用同一递归证据规则：

```text
Plan 制定后续 Lesson
→ 重读刚关闭的已链接 Lesson
→ 当前判断需要时查看相关 Block / Classroom Log
→ 与学生复盘后形成 Plan 级判断和下一课提案

Roadmap 制定后续 Plan
→ 重读刚完成的已链接 Plan
→ 当前判断需要时沿 Lesson Tree 查看相关 Lesson
→ 必要时继续查看相关 Block / Classroom Log
→ 与学生讨论后形成 Roadmap 级判断和下一个 Plan 提案
```

父节点先使用直属子节点能够提供的最粗粒度信息；只有某项当前决策无法负责地作出时，才
继续下钻。需要比较更早阶段时，Roadmap 也只能沿自己的 Plan Tree 读取相关历史 Plan，
再按同样规则下钻。不能枚举 `plans/`、`lessons/` 或其他目录来发现“可能有关”的记录。
Tree 条目中的路径依照 M0 文档契约始终从学习集根目录解析；Lesson 链接即使写在
`plans/*.md` 中，也不能相对于 `plans/` 再拼接一次。
Roadmap 下钻到 Lesson 时只使用其中的 Block 与 Classroom Log，不沿 Block `Uses` 读取
卡片或材料；`Uses` 说明备课时安排过什么资源，资源内容本身不能证明学生实际看过、做过
或形成了何种能力。Roadmap 只从 `LEARNING_GUIDE.md` 了解学习集范围，具体资源检索留给
后续 Lesson 备课。

事实由发生它的最低真实节点持有：Block/Classroom Log 保存课堂事实，Lesson 保存本课
设计和课堂记录，Plan 保存阶段目标与 Plan 级判断，Roadmap 保存长期方向与 Roadmap 级
判断。父节点可以形成新的上层解释，但不复制一份子节点事实作为 Handoff。若子节点后来
被合法纠正，父节点下一次决策重新读取源节点，并据此修正自己的上层判断。

### 常驻不变量与按需 Skill

“只能沿 Tree 读取、不能目录扫描、父级判断不能改写子级事实”属于所有节点都必须遵守的
证据与权限不变量，应放在相应 Agent 的常驻系统设定中。以下工作流属于对应 Dialogue
Skill 的结构触发 references，不在根 Skill 常驻：

- `plan-dialogue/references/`：首次进入（first-entry）、课后复盘
  （post-lesson-review）、Plan 收口（plan-closure）；
- `roadmap-dialogue/references/`：初次会面与现场短探针（`diagnosis/first-roadmap.md`、
  `diagnosis/live-diagnostic-probes.md`）；完成 Plan 后回读、按需下钻、重新诊断并制定
  下一个 Plan（`next-plan.md`）；
- 具体怎样解释不同证据组合，可继续放在两个 Skill 的阶段复盘 references 中。

`first-roadmap.md` 与 `next-plan.md` 是互斥阶段 reference：前者在自身亮线中完成首个
Plan 的逆向制定，不再跳读后者；后者只对最新已链接 `completed` Plan 生效。Plan Tree
非空时必须先读取最新链接子节点自身的 frontmatter，不能从 Roadmap 正文猜测状态。
阶段 reference 只使用根 `roadmap-dialogue` 已声明的共享 reference 入口，不自行计算
跨目录路径；路由命中后直接读取明确路径，不通过 `find` 或 `ls` 发现 Skill 文件。

不新增 Handoff、结束原因 enum、能力状态字段或新的 Plan 状态。长期跨多个 Plan 的信息
压缩、复诊策略和更长周期记忆仍留给后续模块；本节只固定真实父子树上的直接回读边界。

## Lesson 课堂执行与适应

### 已准备 Lesson 是教学假设，不是课堂脚本

Lesson Session 只教授当前已经由学生启动的 Lesson。`Lesson Goal` 是本课保持稳定的教学
目标；Block 顺序、例题、帮助阶梯、练习数量和备用路线则是教师根据课前证据形成的可调整
假设。Tutor 先读完整 Lesson，再读取当前 Block 在 `Uses` 中引用的真实材料，根据学生
当下反应实施，而不是机械播放预设步骤。

课堂适应必须继续服务同一个 `Lesson Goal`。如果真实表现说明目标本身不再合适，Tutor
停止扩张课堂范围，保留已经发生的证据，并把目标变化交回 Plan Session 讨论；不能在
Lesson 内静默换成另一节课。Lesson 也不能编辑父 Plan 或 Roadmap。

学生已经通过界面启动 Lesson，因此开场不重新审批课程，也不固定询问“准备好了吗”。
Tutor 用一两句自然语言提醒今天要解决什么、为什么从当前起点开始，随后进入第一个合适
Block 的 `Student View`。不复述完整议程，不公开 `Teacher Control`、答案、提示机关或
诊断意图。学生可以随时打断、询问或改变节奏；若其明确否定本课目标，则停止授课并返回
Plan，而不是把异议压进原教案。

### 每轮只做一个与真实反应成比例的动作

Tutor 对每次学生回应使用同一个稳定课堂循环：

1. 理解学生实际写出或说出的内容，含义不清时先澄清；
2. 保留其中正确、有效或值得继续的部分；
3. 找到当前最重要的障碍或学习机会；
4. 选择一个与之成比例的动作；
5. 等待学生下一次真实回应，再重新判断。

这个循环禁止 Tutor 一次倾倒完整推理链，也禁止为了保持友好而回避必要的正确性判断。
教师每轮可以等待、澄清、判断一步、给提示、针对性讲解、提供对照或安排一个很小的复验，
但只选择当前最有用的一项。

帮助强度根据学生状态而不是固定采用“永远苏格拉底式”或“立即完整讲解”：

- 学生仍在有效思考时，给时间，不把停顿自动解释成求助；
- 含义、意图或方法映射不清时，先澄清，不猜测；
- 学生卡住但仍在可达范围内时，从最小方向性提示开始，按需要逐步增加具体度；
- 学生缺少必要概念、连续尝试没有产生有效变化，或明确要求教师讲解时，进行有边界的
  针对性讲解；学生明确要求完整解法时可以完整讲，但要如实记录帮助；
- 讲解之后，安排一个很小的独立关键步骤或平行问题，把行动权还给学生，并区分“听懂”
  与“自己能做”。

如果当前 Block 事先约定了明确帮助触发词或独立尝试契约，Tutor 严格遵守；“还在想”
“不确定”或未完成表达不自动构成求助。意图不明时，可以询问学生想继续想还是要提示。

### 先重建学生路线，再纠错或比较方法

Tutor 在判断错误前先重建学生的完整路线，检查它自身的逻辑、条件和适用范围：

- 局部计算或书写失误：指出最早产生影响的位置，让学生优先自行修复；
- 概念、条件或模型错误：使用有针对性的解释、对照或反例修复决定性分歧；
- 合法但不同于参考答案的路线：允许学生沿自己的路线完成，仅在确有教学价值时比较；
- 方法名称与学生真实做法无法可靠对应：用普通语言提出暂定命名并请学生澄清，不硬贴标签；
- 学生指出教师判断有误：教师重新核查，确认后直接承认，并从学生有效路线继续。

纠错之后，让学生重新完成决定性一步或做一个很小的迁移，避免教师的解释替代学生自己的
修复。方法比较服务于理解或选择，不在每条有效路线后自动追加所谓“标准解法”。

### Block 调整分为三层权限

不重新审批但保持自然沟通的课堂微调包括：更换例题、跳过已有独立表现充分覆盖的活动、
增加短支架或检查、调整相邻 Block 顺序、缩短或延长练习。Tutor 可以根据真实反应直接执行，
同时让 Block 状态和课堂记录忠实反映发生了什么。

会实质改变学生已经同意的课堂体验时，先和学生商量，例如加入较长的新活动、明显增加
作业或课堂负担、改变已约定的自主尝试与帮助契约，或用不同目的的活动替换原检测。学生
理解主要影响后仍保留选择权。任何 `Lesson Goal` 的改变都超出课堂适应权限，返回 Plan。

学生可以随时要求暂停、跳过或继续。教师可以说明某个选择对本课目标的关键影响一次；
学生理解后仍选择一条合理路径时，停止争夺控制权，在保留诚实证据的前提下继续教学。

### Classroom Log 只记录会影响后续判断的证据

`Classroom Log` 既不是逐字稿，也不是下课后为让课程显得顺利而重写的总结。Tutor 在
关键节点发生后，向当前 Block 追加简洁记录：

- 学生未经帮助的首次表现、真实路线、答案或不确定性；
- 关键错误、停止点、有效策略及其发生位置；
- 教师实际提供了什么程度的帮助，学生是否使用；
- 帮助后学生能否独立完成关键一步或小迁移；
- 会影响后续教学的主观体验、分歧和未决问题；
- 师生共同作出的继续、调整、跳过或结束决定。

普通寒暄、无决策价值的重复过程和泛泛表扬不必记录。观察事实、学生自述、教师解释与
未知必须可区分；不能把提示后流畅写成独立完成，也不在 Block 中直接宣告 Plan 级“已经
掌握”。记录采用追加方式，保留早先错误及后续修正。切换、完成或跳过 Block 前，先确保
相关关键证据已经落盘；之后由 Plan 沿 `Lesson Tree` 回读源记录并形成上层判断。

### 自适应收尾，关闭不等于掌握

Lesson 不使用固定退出问卷，也不因书面 Block 已经走完而自动结束。接近自然终点或学生
提出结束时，Tutor 根据已有证据进行短收尾：

- 已有清楚独立表现时，不为形式重复测验；
- 主要依赖提示才完成时，可以邀请学生做一个很小的无提示关键步骤或迁移题；
- 学生不想继续检验时尊重结束选择，并如实保留“尚未独立验证”；
- 条件允许时自然听取学生哪里顺了、哪里仍不踏实，并简要回顾本课真实发生的变化；
- 学生要求立即结束时不强制收尾活动，只补齐已有 Classroom Log，不再引入新任务。

下一课设计、Plan 是否达标及长期方向都不在 Lesson 中决定。学生通过现有界面控制结束，
Agent 只停止教学并完成当前记录。M0 的 `closed` 只表示 Lesson 生命周期结束，不表示
`Lesson Goal` 已掌握，更不能替代 Plan 的能力判断。

### 核心 Skill 与按需技巧的组织

不把所有教学技巧塞进一个巨型 Skill，也不把每种技巧拆成会独立注入的顶层 Skill。
Lesson 使用“常驻约束—核心工作流—本课教案—按需技巧”四层结构：

```text
lesson-node.md
└── Session 身份、权限、Lesson Goal 与生命周期边界

tutor-lesson/SKILL.md
└── 开场、逐轮判断、帮助选择、路线尊重、Block 适应、证据记录与收尾

当前 Lesson / Teacher Control
└── 本课题目、答案、观察点、提示阶梯、误区分支与备用路线

tutor-lesson/references/teaching-techniques/
├── INDEX.md
├── concept-boundary-repair.md
├── method-comparison.md
├── independent-transfer-check.md
└── frustration-and-pause.md
```

`Teacher Control` 是当前课堂的首要准备指导。Tutor 先使用核心课堂循环；只有某个按需
技巧能决定当前这一个教学动作、而 Teacher Control 与核心循环不能充分决定时，才读取
一个匹配 reference。每个 reference 经过单独 RED/GREEN 后才接入根 Skill；目录存在不
构成启用。任一 reference 都不能改变 `Lesson Goal`，也不能在同一学生回应中跳读第二个
reference。

### Lesson Session 的四条常驻系统契约

以下约束决定 Lesson Session 能看什么、能写什么以及学生实际会看到什么，必须放在
`lesson-node.md` 与 `tutor-lesson/SKILL.md` 的常驻边界中，不下放给低频技巧各自重复。

1. **证据范围**：Tutor 每轮从当前 Lesson 和当前唯一正在教授或即将激活的 Block 开始，
   只读取该 Block `Uses` 明确绑定的资源。父 Plan、Roadmap、兄弟 Lesson、未链接文件和
   目录枚举都不属于当前 Lesson 的课堂证据。现有信息不足时，向学生澄清其真实做法，
   或停止扩张并把目标问题交回 Plan；不通过 `ls`、`find`、全局 `grep` 或猜测路径补上下文。
   Lesson frontmatter 的 `parent_path` 只表达所有权，不构成读取父节点的许可。
2. **一次公开回复**：先完成当前必要的读取和日志写入，再输出一段面向学生的课堂回应，
   随后等待。工具调用段只包含工具调用，不包含“我来读取”“按路由规则”“先记录一下”
   等公开文本。M0 继续原样投影 assistant 文本，因此这个输出形态由 Lesson Agent 常驻
   契约承担；若同情境 5 次 GREEN 仍不能稳定守住，再单独设计 Runtime 缓冲或过滤，不能
   继续叠加同义提示。
3. **生命周期归 Runtime**：Tutor 可以更新 Block 状态和 Classroom Log；Lesson 顶层
   `prepared → active → closed` 只由学生界面与 Runtime 原子操作改变。学生选择暂停或
   结束时，Tutor 停止加题、补齐已有记录并把控制权交还界面。Lesson Session 不再装载
   通用 `edit/write`，Tutor 不能修改 Lesson 顶层 `status`，也不能用文字宣称已经替学生
   关闭。
4. **日志按追加顺序表达时间**：Classroom Log 使用 Markdown 列表按发生顺序追加关键
   证据；M0 的 Session JSONL 已保存真实时间，因此日志条目不要求模型生成钟点或日期。
   Tutor 不搜索其他 Lesson 模仿格式，也不猜测时间。每轮先记录学生真实表现和实际帮助，
   再产生唯一的学生可见回应。

### Lesson 结构化写入内核

#### 失败证据与恢复边界

M0 曾有意删除 `trace_append`、`classroom_update`、`lesson_close` 等旧工具，让 Agent 直接
编辑 Markdown；同时预先规定：只有真实运行证明普通编辑经常损坏文件时，才增加一个最小
确定性写入工具，不能恢复旧工具集。第一次从 Roadmap 走向完整首个 Plan 的长周期验收在
首节课命中该条件：Tutor 为当前 Block 追加第一条 Classroom Log 时，通用 `edit` 同时
删除了后续 Block；工具报告成功，但严格解析器随后发现 Lesson 结构已损坏，课堂无法关闭。

旧验收也提供了另一半证据：结构化 `classroom_update` 能稳定保护多节课堂结构，旧系统的
主要负担来自 Trace、Projection、Handoff、来源别名和调用顺序等多套语义治理，不来自
Runtime 绑定路径与执行状态转换本身。因此只恢复机械写入内核：Lesson Markdown 继续是
唯一课堂事实，教学判断继续由 Tutor Skill 和自然对话承担，不新增第二事实存储。

#### 两个像原生 edit 一样使用的工具

Lesson Session 创建时直接注册 `classroom_log_append` 和 `classroom_update`，并移除通用
`edit/write`。Roadmap、Plan、Prepare 和 Tutor 的只读工具面不在本模块中顺带改变。工具
在 Session 创建时绑定当前 `nodePath`、学习集根目录和 Lesson 所有权；模型不能填写文件
路径、Session、时间或身份。

这两个工具是 Runtime 能力，不是新 Skill、按需 reference 或教学状态机。Agent 常驻层
只声明写权限，Tutor Skill 只保留三条亮线路由：

```text
发生会影响后续判断的事实 → classroom_log_append
当前活动真正结束或需要开始活动 → classroom_update 的 start / advance
现有 pending 路线明显不再适合 → classroom_update 的适应命令
其余教学轮次 → 不调用写入工具
```

详细参数只由工具 Schema 持有，不在 Agent、根 Skill 和技巧 reference 中换词重复。模型
先正常理解学生并作出教学判断，确实需要落盘时才像调用原生 `edit` 一样自然调用；不进入
“状态管理模式”，不制定额外工具计划，也不向学生讲解内部写入。成功回执直接提供最新
游标，不要求为了仪式再次回读全文。

#### `classroom_log_append`

模型契约只有一个不可为空的自然语言字段：

```text
classroom_log_append({ note: string })
```

`note` 表达一条会影响后续判断的真实课堂事实，可以包含多句话、公式和必要换行。Runtime
自动绑定当前唯一 active Block，并把内容安全渲染为该 Block `Classroom Log` 的一个
Markdown 列表项；换行只能成为该条目的缩进续行，不能形成标题或逃出当前 Block。

Lesson 已关闭、当前没有 active Block、存在多个 active Block 或原文件本身无法解析时，
工具拒绝写入且保持文件不变。它不猜测应写入哪个 pending、completed 或 skipped Block，
不创建 Trace ID、时间字段或第二份事件记录。日志保持追加语义；早先记录有误时，Tutor
追加更正或后续证据，不润色、覆盖或删除旧记录。Runtime 不用关键词审查“掌握”“独立”
等教学语义，事实是否诚实仍由 Tutor Skill 负责。

#### `classroom_update`

`classroom_update` 使用有明确判别字段的命令分支；每个分支只暴露自身必需字段，不提供一
大组含义随命令改变的可选参数：

1. **`start`**：Lesson 没有 active Block 时，模型选择一个 pending Block。Runtime 检查
   依赖已经满足，再将它激活。
2. **`advance`**：模型选择当前 Block 的结果 `completed | skipped`，以及下一 Block ID
   或 `null`。Runtime 派生当前 active Block，在一次原子修改中结束它并按需激活合法
   后继；当前 Block 至少已有一条 Classroom Log 才能推进，日志是否充分仍由 Tutor 判断。
3. **`insert`**：模型提供新活动的标题、现有 `Kind`、`Required`、依赖、`Uses`、
   `Student View`、`Teacher Control` 及相对现有 Block 的位置。Runtime 生成新 Block ID，
   固定创建为 `pending` 并生成空 Classroom Log。
4. **`revise`**：模型完整替换一个 pending Block 的公开活动与教师控制内容；不能修改
   ID、状态或日志。完整草案代替含义不清的零碎 patch。
5. **`move`**：模型选择一个 pending Block、锚点和前后位置；Runtime 保持内容不变并
   验证依赖图。
6. **`skip_pending`**：只把尚未开始的 Block 标为 `skipped`。决定原因记录在当时 active
   Block 的 Classroom Log；没有 active Block 时不能凭空跳过，应先进入相关活动并记录
   实际决定。

模型选择目标或后继 Block，因为这是教学判断；Runtime 派生当前 Block、生成新 ID，并
验证唯一 active、状态转换、依赖存在且无环、精确 `Uses` 路径和来源边界。新插入 Block
的 `Uses` 只能取自当前 active Block 已有 `Uses`；修改 pending Block 时可以保留其原有
`Uses`，新增路径仍只能取自当前 active Block。没有 active Block 时不能引入新的 `Uses`
路径。Runtime 还检查这些精确路径确实存在且类型合法。除另一个工具向 active Block
追加 Classroom Log 外，active、completed、skipped Block 的标题和教学内容不可回写，
`Lesson Goal`、frontmatter 和其他 Block 不能发生额外变化。

本模块不恢复 `pause`、`repeat`、`delete`、Route Change 或 `lesson_close`。再次练习通过
新增 pending Block 表达，保留第一次课堂事实；跳过代替删除，保留准备路线与真实课堂的
差异。成功回执只返回新建 ID、当前 active Block 与合法后继，不形成新的持久事实。

#### Runtime 原子修改与失败语义

所有会写 Lesson 的 Runtime 路径，包括 Session ID 绑定、学生激活或关闭、上述两个工具，
共享同一个按 Lesson 串行的修改入口。一次写入依次完成：

1. 进入当前 Lesson 的写入队列并读取、解析最新文件；
2. 检查 Session 所有权、Lesson 生命周期和实时 Block 游标；
3. 在内存中产生候选文档；
4. 重新解析候选文档，并验证本次差异没有越权；
5. 写入同目录临时文件，确认操作期间的原版本没有改变；
6. 原子替换正式文件，成功后才发布界面失效通知并返回最新游标。

Lesson 已被关闭或游标已经改变时拒绝操作并返回当前状态；命令、依赖或目标非法时说明
当前可执行边界；原文件损坏时只报告解析错误，不自动猜测修复；候选验证、磁盘写入或
替换失败时正式文件保持不变。Runtime 不隐藏重试或改选另一命令，Tutor 可以像处理一次
失败的原生 `edit` 一样，根据最新状态重新判断。任何失败都只能表现为“本次没有写入”，
不能出现工具宣称成功而 Lesson 部分损坏。

### 七个候选技巧的收缩决定

2026-08-04 审计使用同一真实模型档位完成 35 次候选正向运行、10 次未命中反例和 15 次
核心对照。反例中，局部算术失误 5/5、尚未完成路线 5/5 都没有误加载技巧，说明“默认
不读 reference”的总闸门成立；但七个候选整体启用仍产生目录搜索、跨层读取、内部过程
泄露和生命周期越权。

比较过三种组织方式：继续保留七个文件会保留重叠路由与互相跳读；全部并入根 Skill 会
让低频技巧常驻并增加同一决策点的负荷；最终采用“四个按需 reference + 一条核心帮助
阶梯”。被合并或改名的旧候选路径直接删除，不保留兼容别名或互链；方法比较与独立迁移
两个保留名称的文件原地重写，不沿用旧内容。

1. **概念边界修复 `concept-boundary-repair.md`**：合并新概念讲解、首次概念误解和解释
   后仍未修复的边界分歧。文件内部先根据已经观察到的状态只选一种动作：缺概念时做
   有边界讲解；错误模型已确认时重建路线并修复决定性分歧；已有解释失败时只用一个
   对照或反例。三条分支都以学生亲手完成一个小步骤结束，不再读取其他技巧。局部计算、
   书写失误、未完成表达和仍在有效思考不命中本文件。
2. **方法比较 `method-comparison.md`**：只在学生已经完成并核验一条合法路线、比较确有
   教学价值时读取。第一轮只做“明确有效性 → 请学生说入口、关键一步和代价 → 等待”；
   收到学生复述后的新一轮，才比较最多一个替代并由学生判断取舍。路线尚未完成时继续
   原路线，不提前读取本文件。比较只使用当前 Lesson 已记录的路线；细节不足时询问学生，
   不读取 Plan、图谱、卡片或材料来猜。
3. **独立迁移检查 `independent-transfer-check.md`**：只在讲解或提示后需要区分“听懂”与
   “独立表现”时读取。优先收回支架并复用当前题的一个决定性步骤或当前 Block `Uses`
   已绑定的短任务。没有合适现成任务时，Tutor 可以现场生成一个严格位于当前 Lesson
   Goal 内、答案已自检、几步内完成的微型题；不得为此搜索父节点或目录。日志把它标明为
   教师现场微题，只把学生首次表现作为证据，不把题目来源伪装成学习集材料。
4. **挫败与暂停 `frustration-and-pause.md`**：先按学生是否已经明确要求暂停或结束分流。
   已明确停止时只接住状态、在有帮助时用一条真实课堂证据校准自我否定、记录选择并停止，
   不提供小任务或继续选项。尚未要求停止时，才采用“接住状态 → 用真实证据恢复正常感
   → 提供一个可选小入口或暂停选项 → 等待学生选择”。本文件不改变生命周期状态。

根 `tutor-lesson` 使用一条固定优先级路由，不先读取 INDEX 再分类：

1. 学生明确暂停、结束，或当下挫败已经成为本轮首要障碍 → 挫败与暂停；
2. 学生在讲解或提示后表示理解，但独立表现尚未出现 → 独立迁移检查；
3. 学生已经独立完成并核验一条合法路线，且比较确有价值 → 方法比较；
4. 已确认存在必要概念缺口、错误模型或同一解释无效 → 概念边界修复；
5. 其余情况不读取 reference，直接使用 Teacher Control 和核心课堂循环。

一次学生回应只命中第一条成立的分支。执行一个技巧动作并回应学生后立即等待；支持方式
需要改变时，只能依据下一次学生表现重新路由。`INDEX.md` 只列出已通过验收的文件与触发
摘要，Tutor 不把它作为一次额外读取步骤。

卡顿支架的“最小方向 → 更具体关系 → 具体步骤 → 有边界讲解”属于每次帮助都可能使用的
核心强度阶梯，保留在 `tutor-lesson/SKILL.md`，不再作为按需 reference。旧
`misconception-repair.md`、`new-concept-explanation.md`、`stuck-scaffolding.md`、
`contrast-and-counterexample.md` 和 `frustration-response.md` 删除；有价值的教学事实已经
合并到上述新主人，不保留会把模型拉回旧路的文件名或交叉链接。

## 已批准设计的 Plan 与 Lesson 准备交付

### Prepare Skill 是教育版 writing-plans

`prepare-approved-plan` 与 `prepare-approved-lesson` 不是新的 Session，也不承担第二轮
师生讨论。它们位于公开设计批准门之后，把已经确认的教育设计展开成可执行节点：

```text
roadmap-dialogue / plan-dialogue
≈ 讨论、形成设计并取得确认

prepare-approved-plan / prepare-approved-lesson
≈ 把已批准设计写成可执行产物

tutor-lesson
≈ 在真实课堂中执行，并依据学生反应做目标内适应
```

Dialogue Agent 与 Prepare Skill 分别守门。调用端必须先公开完整方案、取得学生明确确认，
并把最终版本写入父节点现有正文；Prepare 端同时检查当前对话确有确认，且父节点记录足以
成为唯一交接。仅有“你来安排”、学生最初请求或一段看似完整但未经确认的父节点文字，
都不能启动准备。本设计不增加 `approved` 字段、批准状态或额外 Handoff。

Prepare 不再向学生征集偏好或重新讨论方案。若输入完整，它直接承担专业实施；若缺失的
选择会改变学生已经同意的内容，则停止并返回对应 Dialogue，而不是在后台猜测后再请学生
被动接受。

### 两种 Prepare 的裁量不对称

`prepare-approved-plan` 以忠实结构化为主。Plan 的 `Stage Goal`、`Observable Capability
Standard`、`Test`、阶段学法、当前依据和公开初始课程弧线都影响学生选择，原则上已经在
Roadmap 对话中公开并确认。Prepare 可以规范表达、生成 ID、填入文档骨架和安排合法 Tree
元数据，但不能新增阶段目标、改变达标标准、替换 Test、扩张负担或选择另一种 Plan 周期。
它只创建当前一个 `status: prepared` Plan，保持 `Lesson Tree` 为空，不预建 Lesson 或
未来 Plan。

`prepare-approved-lesson` 需要更大的专业展开空间。公开确认的是本课为何现在进行、目标、
重点、活动形态、参与方式、处理深度、工作量和完成标志；具体题目、答案、材料组合、观察
点、提示阶梯、误区分支和备用路线属于教师的私有备课。Prepare 在已确认边界内自主完成
这些细节，不因每个内部选择再次打扰学生，也不提前泄露会破坏诊断或学习体验的信息。

这种自由不能反向修改公开设计。材料条件如果迫使目标、活动形态、处理深度、帮助契约、
工作量或完成标志发生实质变化，Prepare 停止并返回 `plan-dialogue`。已批准内容互相矛盾
时同样不能自行选择其中一项。只有纯执行细节不完整时，才由 Prepare 作出专业选择。

### 共享的确定性交付流程

两个 Prepare 都遵守同一个 child-first 流程：

1. 读取父节点、当前确认语境、注入的 M0 文档契约和实施所需真实来源；
2. 区分已批准的公开设计、允许自主决定的内部细节和必须返回 Dialogue 的实质缺口；
3. 从父 Tree 确定当前一个子节点的 ID 与精确路径，并确认不会覆盖既有文件；
4. 写入一份完整的 `status: prepared` 子文件；
5. 完整回读子文件，核验 frontmatter、父子关系、标题、必需章节、状态与批准设计；
6. 只有子文件合法后，才把它加入父节点 Tree；
7. 回读父节点与子节点，确认链接唯一、正文未损坏、内容仍与批准设计一致；
8. 向学生只报告已经确认的公开内容和可以从界面开始的下一步。

Plan 交付必须保留空 `Lesson Tree`；Lesson 交付至少有一个合法 Block，初始 Block 状态和
空 `Classroom Log` 符合 M0 契约。`Teacher Control`、答案和提示机关不在交付报告中公开。
两个 Prepare 都不启动节点、不教授内容、不修改 active/completed Plan 或 active/closed
Lesson，也不创建未来整串节点。

耗时准备（材料探索、Scout fan-out、文件写入与验证）期间，先在公开层给出简短回应，
并只在有意义的节点简短报进展；这不改变交付报告的内容边界。

ID 与证据发现使用不同边界：Prepare 可以根据父 Tree 生成候选 ID，并检查将要写入的精确
目标路径是否冲突；它不能枚举目录寻找可当成当前课程的既有文件。遇到精确路径已存在且
无法证明是本次尚未完成的同一产物时，停止并报告冲突，不能覆盖、改名后悄悄重建或把它
自动挂入 Tree。

### 部分失败只修复同一个产物

Prepare 不通过自动删除或更换 ID 掩盖交付失败：

- 子文件写入后验证失败时，只修复本次创建的同一个文件；合法之前绝不链接父 Tree；
- 子文件合法但父 Tree 编辑失败时，重新读取父节点，只重试链接同一个已验证子文件；
- 重试前检查父 Tree 是否已经含有该链接，防止重复条目；
- 无法安全完成时，明确报告“子文件已存在但尚未链接”的精确路径和当前状态，不宣称成功，
  不创建第二份，也不自动删除；
- 同一准备流程可以读取自己刚创建的精确路径继续恢复，但不能扫描目录猜测哪个孤立文件
  “可能属于”当前批准设计。

未链接子文件即使结构完整，也不构成父节点的课程交付或证据。Roadmap、Plan 和 Lesson
后续仍只沿 Tree 读取，因此部分失败不会让孤立文件进入学生历史；恢复目标是完成原链接，
而不是放宽证据边界。

若真实课堂 RED 持续暴露写子文件、挂 Tree、状态修改或 Markdown 编辑格式等机械失败，
应把这些动作升级为 Runtime 原子能力，而不是继续向模型叠加提示词纪律。本条是预声明
的退路，经真实证据触发后另行设计，不在本阶段实施。

## Material Scout 检索分工、实时进度与负担验收

本节记录 2026-08-05 长周期 RED 后确认的检索修复，是当前 Material Scout、Coach 选材、
学生可见进度和性能验收的权威设计。较早的
[`2026-08-03-slot-scoped-material-scout-design.md`](./2026-08-03-slot-scoped-material-scout-design.md)
保留槽位拆分和历史根因；其中与本节冲突的候选前沿、读取深度、学生可见行为、验证方法
和预计修改范围均以本节为准。

### 真实基线与问题判断

本轮五个 Scout 一共执行 162 次工具调用，其中 `read` 88 次、`grep` 41 次、`ls` 28 次、
`find` 5 次，推理量约 10.1 万 reasoning tokens。五个 Scout 共读取 59 张卡、41 张不同卡；
Coach 后续完整读取的 10 张卡均已被 Scout 读过。文件重叠本身不能证明两边做了完全相同
的推理，但说明候选内容已经跨过两层职责边界。最终返回的候选在各 Scout 结束前 97 至
205 秒已经首次读到，之后仍有明显的扩展搜索。

召回不是唯一耗时，但现有召回路径也没有被操作化：41 次 `grep` 中没有形成按字段取路径
集合、同维度取并集、跨维度取交集的检索；反而出现六次完整卡片目录 `ls` 和三次读取已经
过时的 `graph/VOCABULARY.md`。与此同时，Scout 输出包含隐零点、路线完整性、取等条件等
深层判断，Coach 随后又承担最终数学核验。真正的问题因此不是“模型不知道图谱字段”，
而是以下三件事同时存在：

1. fresh Scout 每次都要现场重新发现词表、字段和检索操作；
2. Scout 被要求在候选阶段完成本应由 Coach 承担的路线级核验；
3. “语义收敛”和“如实说明没有”把诚实解释成了近乎遍历整个题族。

这次修复不把所有延迟都归咎于关键词检索，也不把单次长 Session 归因于一个组件。采用的
顺序是先修正职责、停止边界和可观测性，再依据 A/B 结果判断是否真的需要额外索引。

### 采用方案、首轮 B 与 sidecar 启用

本轮采用现有文件工具上的混合方案：保留素材槽位和 fresh Scout；把 Scout 收缩为“规范
特征召回加题面浅核验”，把路线级深核验明确归还 Coach；复用原生 `subagent` 事件提供
学生可见进度，并从已经落盘的父子 Session 导出开发指标。

首轮 B 先只改职责和提示词。五份旧 brief 的父调用墙钟时间从 933 秒降到 704 秒，但工具
调用从 162 次变成 164 次；Scout 不再读取废弃词表，却仍枚举卡片并深读候选。旧 brief
本身带有候选数量和路线核验要求，因此又用一份符合新契约的单槽位 brief 做了三次诊断：

- 第一版用 30 次工具调用、140 秒，仍然列目录并深读；
- 收紧读取边界后用 62 次调用、92 秒，模型改成逐文件搜索；
- 把每个规范字段改成一次宽搜索后降到 15 次调用，但仍耗时 137 秒，并为了判断题型越界
  读取了答案区域；该 child 仍产生约 3.36 万 input 与 1.73 万 output tokens。

进一步检查 519 张卡发现，题面统一在第 6 行，而答案从第 7 行开始，图谱字段又位于答案和
评分细则之后。现有文件工具无法在一次安全读取中同时取得题面与图谱元数据；分字段
`grep` 虽然减少文件读取，却把长路径集合的交叉、计数和停止判断留给模型现场完成。此时
召回数据布局已经成为可复现瓶颈，因此达到原先约定的 sidecar 启用条件。

本轮据此采用轻量文件 sidecar，同时继续明确延期结构化检索工具：

- `graph/card-recall-index.jsonl` 由源题卡确定性生成并随学习集维护，一行对应一张卡；
- 每行只含卡片路径、内容修订 ID、规范 `goal` / `method` / `structure`、完整公开题面、
  选项数和小问数；不得包含答案、评分细则、解法、路线判断或教师结论；
- 行按路径稳定排序。仓库测试比较生成结果与已提交索引，卡片变化但索引未更新时直接失败；
- Scout 选择最有区分度的一个必需字段作为 anchor，对该字段的每个 OR 备选词各做一次
  字面 `grep`（通常共一次），直接在返回的完整行上核对其余字段和题面，通常不再打开
  候选题卡；
- sidecar 缺失时退回现有“字段 `grep` 取路径集合、只读前六行”的安全路径，而不是失败或
  扩大搜索；
- 非题卡、视频、阅读及非正规材料继续在 brief 指定范围内用自由文本查找，不强行进入
  题卡索引。

这仍是普通学习集文件和现有 `grep`，不新增专用 Runtime、数据库或向量检索，也不把最终
适配判断结构化。索引只把已经存在但物理上分散的公开召回字段排到同一行，Coach 仍完整
读取最终候选并承担数学和教学核验。

本轮也不同时降低 Scout 的 thinking 档位。模型档位只能在职责改造完成后作为独立变量
比较，否则速度变化无法归因。

### Coach 的检索简报

Coach 继续用自然语言说明素材槽位、教学用途、工作量、已曝光内容和排除项，同时可以增加
一组可选的“建议检索词”：

```text
建议检索词（只用于召回，不代表最终适配）：
- goal: 求参数范围
- method: 参变量分离
- structure: 指对复合结构
- text: 恒成立
```

题卡的 `goal`、`method` 和 `structure` 优先使用学习集冻结词表中的规范词；`text` 用于题面
自由文本。非题卡材料不强行伪造图谱字段，可以只给自由文本和素材类型。建议词是检索入口，
不是 Coach 提前替 Scout 宣告题目适配，也不是最终 Lesson 的持久化字段。

如果精确组合可能过窄，Coach 可以同时给出放宽顺序，例如“先去掉 `text`，再放宽
`method`”。Scout 只能按该顺序放宽；没有放宽授权时，不能自行转向邻近题族、全专题或
全库搜索。普通简报没有合适的规范词时可以不填，不能为了满足格式而编造标签。

### Scout 的唯一亮线

Scout 按下面一条顺序工作：

```text
读取当前素材类型的权威检索入口
→ 题卡图谱词用词表和别名表归一到规范词
→ 选一个最有区分度的必需字段 grep card-recall-index.jsonl
→ 在返回的完整行上核对其余字段和题面
→ 排除题面可见的不适配项
→ 返回浅候选和本次搜索边界
```

具体操作边界如下：

- 对使用图谱字段的题卡任务，学习集内 `graph/vocabulary.yaml` 是权威规范词表；存在
  `graph/aliases.yaml` 时，它只用于归一化和同义入口，不取代规范词。不得读取过时的
  `graph/VOCABULARY.md`。只含自由文本的非题卡任务不为走形式读取题卡词表。
- sidecar 存在时，只选最有区分度的一个必需字段；该字段每个 OR 备选词各召回一次完整
  JSONL 行，其他字段的 OR/AND 核对直接在这些行内完成。sidecar 缺失时，才按每个字段
  `grep` 路径集合并在本地取交集，随后只读取卡片前六行题面。
- 不先 `ls` 整个卡片目录，不把文件名清单读进上下文，也不为寻找“更优解”枚举专题。
- 命中后只使用 sidecar 的规范元数据和公开题面；可以据此判断素材类型、规范字段适配、
  明显题型、可见计算量、选项泄露或已曝光风险。Scout 不因 sidecar 已经给出路径而打开
  正式题卡；完整读取留给 Coach。
- 不读取或重推每个候选的完整答案、评分细则、完整路线、隐零点、取等条件和路线是否能
  走到底。这些判断需要解题，属于 Coach 的最终核验。

Scout 不再形成 Pareto 前沿，也不为了凑固定数量返回同族替代品。通常一个浅候选已经足够；
只有首个候选存在一个从题面或元数据可见、可能导致 Coach 淘汰它的具体风险时，才返回一项
实质不同的备用候选。`risk` 可以是 `null`，不能虚构隐藏风险来证明搜索充分。

### Scout 输出与“没有候选”的含义

Scout 返回紧凑的无代码围栏 JSON：

```json
{
  "slot": "slot-A",
  "candidates": [
    {
      "asset_path": "cards/derivative/example.card.yaml",
      "asset_kind": "problem-card",
      "metadata_fit": "structure 与 method 命中，题面工作量符合本槽位",
      "risk": null
    }
  ],
  "search_boundary": {
    "query": {
      "goal": ["求参数范围"],
      "method": ["参变量分离"],
      "structure": ["指对复合结构"],
      "text": ["恒成立"]
    },
    "matched": 5,
    "inspected": 2
  }
}
```

`matched` 是当前查询全部字段均命中的 sidecar 行数（fallback 时为文件数），`inspected`
是 Scout 实际评估过的命中行数（fallback 时为打开题面的数量）。空结果
只表示“本次特征交集命中 N 项，浅看其中 M 项后没有找到题面层适配项”。它不能被表达成
“题库里没有这种题”“整个题族已经穷尽”或“没有任何干净路线”。完整检索边界由数字和查询
本身表达，不再用长篇搜索叙述证明诚实。

### Coach 的最终核验责任

Coach 合并各槽位的浅候选并选择当前首选，然后完整读取该素材，核验：

- 数学结论和答案是否正确；
- 预期路线是否真的走得通；
- 是否存在隐零点、端点、取等或定义域问题；
- 是否泄露本课希望观察的能力；
- 实际计算量、来源陌生度和课堂作用是否符合已批准 Lesson。

首选核验失败时，Coach 才读取 Scout 已返回的备用项；没有备用项或备用项也失败时，可以在
原批准边界内依据已公开的 `search_boundary` 发出一次更明确或按授权放宽的检索。它不能把
深核验重新下放给 Scout，也不能自动重跑全库 fan-out。最终选材、数学责任、课堂编排和
Lesson 写入始终属于 Coach。

### 学生可见的实时进度

不恢复旧 `DeepWorkflowRuntime` 或 Task Rail，也不修改 `pi-subagents`。前台执行本来就会
产生：

```text
tool_execution_start → tool_execution_update → tool_execution_end
```

服务端在现有 Conversation projection 中把 `study-material-scout` 调用投影成一个只用于
界面显示的安全进度对象，再沿现有 EventHub/WebSocket、客户端状态和 ChatPanel 更新同一张
活动卡。该对象最多包含：阶段、公开活动短语、已结束任务数、总任务数、经过时间、累计
工具操作数和最终状态。它不是教学事实，不写入 Roadmap、Plan、Lesson、schema 或数据库。

学生看到的形式是活动短语加轻量数字，例如：

```text
正在查看候选材料
1 / 2 个检索任务已返回 · 1分12秒 · 23 次操作
```

内部进度映射为少数稳定短语：

- 启动阶段：`正在启动材料检索`；
- `grep`、`find` 或 `ls`：`正在筛选材料`；
- `read`：`正在查看候选材料`；
- 两次工具之间的模型判断：`正在比较候选`；
- 成功结束：`材料检索已完成`；
- 子任务失败：`材料检索遇到问题，老师正在调整`。

前端在两次 update 之间本地递增秒数，并用克制的活动动画表明任务仍在运行。检索卡活跃时，
隐藏重复的通用“老师正在思考”提示。刷新后，已经结束的调用从父 Session 持久化的
`toolResult.details` 重建最终计数和耗时。

安全投影不得包含或显示：tokens、费用、模型名、检索词、内部简报、Plan/Lesson 路径、
当前文件、卡片内容、题面、`currentToolArgs`、`recentOutput`、推理文字、部分候选、子 Session
路径或原始错误。`subagent` 的原始 arguments、partial result 和最终 result 不能继续作为
学生可展开详情；它使用专门的安全活动卡。其他普通 `read`、`edit`、`write` 工具保持现有
折叠表现。

### 开发验收侧的可观测性

父 Pi Session 的 `subagent` 最终 `toolResult.details` 已保存 `totalChildUsage`，以及每个
child 的 usage、状态、`durationMs`、`toolCount` 和 `sessionFile`；child JSONL 也已经落盘。
因此不修改 `pi-subagents`，也不为了本轮给 `run-history.jsonl` 复制第二份事实。

现有 `scripts/export-pi-cot.ts` 增加可选的子代理导出能力。对指定父 Session 和用户轮次，
报告应明确区分：

- 父调用起止之间的墙钟时间，即学生真实等待；
- 各 child 耗时之和，即并行任务支付的总计算时间；
- 各 child 的状态、usage、工具调用数和已记录的 token 分类；
- 从 child JSONL 统计的 `read`、`grep`、`find`、`ls` 等工具分布；
- 需要深入审计时附带的 child 完整 CoT、时间戳和调用记录。

不能把并行 child 耗时相加后冒充学生等待时间，也不能把父墙钟时间冒充总模型负担。字段
缺失时明确写“未记录”，不从文本长度或其他模型运行推算。child 文件缺失时仍保留父结果
中的 usage 和进度汇总，并把完整转录标为不可用。

这些开发字段不进入学生界面。学生卡片只消费上一节定义的安全投影；完整 `sessionFile`、
usage、CoT 和调用参数只存在于本地验收导出中。

### 失败与降级

- 中途 update 缺字段或暂时中断时，学生卡保留最后一个安全短语并继续本地计时，不显示
  空白卡，也不回退到原始详情。
- 一个 child 失败时仍计入“已返回”，但最终状态不伪装成成功；Coach 决定是否使用其余
  结果、发出一次新检索或返回公开讨论。
- 所有 child 都失败或没有可核验候选时，不创建缩水的 Lesson，也不自动重复整轮 fan-out。
- 旧 Session 没有足够 progress details 时，只显示可证明的通用完成状态；审计导出同样
  标明缺失，不猜测历史数据。
- 界面进度只表示后台仍在工作，不能替 Coach 宣告材料已经适合、备课已经成功或 Lesson
  已经交付。

### A/B 与长周期验收

当前五个真实选材任务作为 RED 基线。首轮提示词 B 已证实“职责边界正确但召回布局仍慢”，
不作为最终 GREEN。sidecar B 继续使用相同的学习集快照、五份槽位简报、模型、thinking
档位和并发方式；只增加确定生成的安全索引并切换 Scout 的题卡召回入口。可观测性代码
保持一致。只有能够证明旧 Session 的这些变量相同，才直接复用已有 A 日志，否则重新运行
A。另用符合当前 Coach 契约的简报验证 sidecar 本身，避免把旧 brief 的冲突要求误归因给
索引。

比较项目包括：

- 学生真实等待时间；
- child 总推理量、总计算时间和工具调用数；
- `read`、`grep`、`ls`、`find` 分布；
- 卡片读取数、完整目录读取、废弃词表读取和跨 Scout 重复读取；
- 最终候选首次被读到以后仍发生的搜索时间与调用；
- Scout 与 Coach 的读取重叠；
- 最终选材的数学正确性、路线可用性和课堂适配。

本实验不预设秒数、工具调用数或候选数硬门。B 通过需要同时满足：

1. 不再完整枚举卡片目录，不读废弃词表，不把候选答案和评分细则当作 Scout 常规输入；
2. 五个任务中至少三个明显缩短等待或调用链，且合计墙钟时间、工具调用和推理负担低于 A；
3. 每个空结果只声明本次特征切片的 `matched / inspected`，不声称穷尽整个题库；
4. Coach 仍能完成深核验并选择符合已批准 Lesson 的材料，没有以速度换取明显质量下降；
5. 学生等待期间持续看到安全的活动短语与轻量数字，刷新后能恢复最终状态且无内部泄露。

微型 A/B 通过后，使用同一模型档位和一份干净学习集跑完整长周期：

```text
制定 Roadmap
→ 讨论、确认并创建第一个 Plan
→ 动态讨论、准备并上完其中实际需要的 Lessons
→ 关闭 Lessons 并完成 Plan 收口
```

Lesson 数量仍由真实学习情况决定，不为验收硬凑五至六节。长周期除了既有结构化写入、证据
和批准边界，还要确认每次耗时选材都有可见进度，检索优化没有破坏共同备课、选材质量、课堂
自然度或 Plan 完成。最终判断以学生体验和 Roadmap、Plan、Lesson 产物为主；性能数据用于
比较和定位，不替代课程结果。

若 sidecar B 之后仍慢，先用新导出判断剩余时间在索引召回、Scout 筛选、Coach 深核验还是
父 Session 推理。只有单个 Scout 在正确边界和安全索引上仍推理冗长时，才单独比较
thinking 档位。不能因为一次总体耗时较长就同时降档并增加硬超时。

## 验收

装配测试必须证明：

- Roadmap 只获得 `roadmap-dialogue` 与 `prepare-approved-plan`；
- Plan 只获得 `plan-dialogue` 与 `prepare-approved-lesson`；
- Lesson 只获得 `tutor-lesson`；
- 旧 `roadmap-study`、`coach-study` 与 `plan-next-cycle` 不再成为运行时入口；
- Plan 周期、Lesson 模板和材料准备 references 仍完整存在于新的归属位置。

骨架搭建阶段不进行教学话术验收；每个 Skill 细化后再使用真实学生情境分别做
RED/GREEN 验证。

### Skill 行为验收方法

Skill 修改遵循 RED—GREEN—REFACTOR。每个模块先在当前提示词上运行干净学习集和真实
模型，保留原始 Session、工具调用、公开对话和 CoT 作为 RED；确认失败形态后才修改
对应 Agent、Skill 或 reference。GREEN 使用相同学习集、模型、学生输入和判断标准，
不把预期答案写进学生话术或模型上下文。

除行为是否最终正确外，每个被守护边界还要统计首击守住率：学生未提醒时，模型第一次
遇到该边界就没有剧透、没有越权改状态、没有提前备课的比例。靠学生提醒才恢复的边界
记为未守住；最终事实正确不能抵扣首击失败。

初次 Roadmap 至少并行覆盖四种学生情境：

1. **目标较清楚的优秀学生**：“我想学点导数高级技巧，综合题经常没思路。”
2. **真的不知道怎样学**：“我也不知道该学什么，最近数学越来越乱。”
3. **明显糊涂的学生**：描述含糊或互相矛盾，需要轻量同意后的现场短探针。
4. **把决定权交给老师的学生**：“我说不清，你帮我安排吧。”

验收关注行为，不检查固定话术：

- 是否短介绍后进入具体经历，而不是倾倒课程目录；
- 是否让学生用自然语言说话，由教师承担专业解释；
- 是否在已有足够信息时停止追问；
- 是否只在决策性不确定性确实存在时启动短探针；
- 是否区分首次独立表现、提示后表现和后续平行复验；
- 是否在 Roadmap 中停止授课并返回长期判断；
- 是否公开长期能力、总体学法、暂定方向、下一个 Plan、依据与推翻信号；
- 是否在学生确认前不创建 Plan，并且一次只物化一个 Plan。

Plan 制定还至少覆盖以下真实情境：

1. **首个 Plan、目标清楚**：学生准备预习一个新学科模块，教师能从总体学法推出一个
   有边界的首阶段，而不是复制教材目录。
2. **后续 Plan、有既往证据**：教师用上一个已链接 Plan 的真实表现提出明确建议，同时
   允许学生改变未来路线。
3. **学生不同意推荐**：学生理解关键代价后仍选择另一条合理方向，教师尊重选择并重新
   对齐目标、标准和测试。
4. **初始工作量估计失准**：学生进步快于或慢于预期，Plan Session 调整 Lesson 数量，
   不凑课、不赶课，也不偷偷改变阶段目标。
5. **粒度边界**：面对看似很长或很短的内容，教师按共同目标、证据循环和阶段判断决定
   合并或拆分，而不是按固定课次数量切割。

上述场景都要检查：提案前是否有足够而未捏造的依据；`Stage Goal`、可观察标准与 `Test`
是否对齐；工作量是否明确为动态估计；学生确认前是否没有新建 Plan；确认后是否只创建
当前一个 Plan，且没有预建未来 Lesson。

已确认 Plan 的首次进入还至少覆盖以下真实情境：

1. **学生愿意认真讨论**：教师带着有依据的初始草案进入对话，学生能实质改变第一课的
   目标、重点、方式和负担；既不要求学生从白纸设计，也不把草案当成定案。
2. **学生说“你来安排”**：教师停止无必要追问并承担专业设计，但先公开完整 Lesson
   提案，得到确认后才准备。
3. **学生提出学习偏好**：教师说明偏好的收益与代价，共同把它转化为适合当前 Plan 的
   课程设计，而不是只记录一个偏好参数。
4. **学生临时想换方向**：阶段内调整留在 Plan Session；改变阶段目标则明确返回
   Roadmap，不借备课越权创建新 Plan。
5. **避免泄露教学机关**：学生理解并确认课程体验与完成标准，但不会提前看到答案、
   提示阶梯或诊断题的决定性信息。
6. **学生直接拒绝草案**：教师不以备课投入施压；先理解拒绝原因，再根据拒绝的是
   Lesson 还是整个 Plan，分别重做课程草案或返回 Roadmap。

验收应区分“参与共同备课”和“承担教师工作”。教师必须主动提出初始草案、专业建议并
负责内部教案；学生必须拥有对公开 Lesson 设计的真实影响力、拒绝权与最终确认权。任何
“只问一个偏好后单方面定案”“要求学生从零设计课程”或“学生拒绝后仍围绕原草案劝服”
的表现都不合格。

课后复盘与后续 Lesson 共备还至少覆盖以下真实情境：

1. **学生感觉很好但依赖提示**：教师承认理解感的改善，同时保留“独立迁移尚未证明”，
   并在下一课草案中安排适当复验。
2. **学生感觉很差但已有进步**：教师用具体课堂事实帮助校准，不用一句“你其实会了”
   否定学生体验。
3. **学生说不清感受**：教师停止无效追问，公开自己的证据判断并继续讨论下一步；信息
   足够后才生成下一课草案，仍等待学生确认。
4. **原课程弧线不再合适**：教师依据课堂证据调整阶段内顺序、支架或 Lesson 数量，
   不机械播放预设目录。
5. **证据动摇整个 Plan**：教师不创建下一 Lesson，把事实、不确定性与建议交回
   Roadmap，而不是在 Plan 内偷偷换目标。
6. **连续多节课已有设想**：教师只提案并物化当前下一节，不把旧弧线当作学生对未来
   所有 Lesson 的预先批准。

验收应检查第一课和后续课是否采用不同顺序。后续课对话前，教师只能基于当前 Plan 证据
形成初步判断与待澄清问题，不能先生成 Lesson 草案；对话中先给学生未被锚定的表达机会，
再公开区分课堂事实、学生体验、教师解释与未知。师生讨论出下一步需要后，教师才能生成
草案；下一课仍须经过修改和明确确认，不能由课堂日志自动触发创建。

Plan 阶段结束与父级回读还至少覆盖以下真实情境：

1. **预计课次已到但证据不足**：教师不自动结课，也不降低标准；与学生讨论继续检验还是
   选择结束。
2. **原定 Test 尚未单独实施但已有等价证据**：教师能说明现有独立迁移表现怎样完整对齐
   标准，不为形式额外增加考试课。
3. **只有提示后成功**：教师建议对齐标准的检验 Lesson；学生若拒绝并结束，明确记录为
   “能力尚未充分证明”。
4. **学生主动转向**：教师解释主要影响一次，尊重学生结束当前 Plan 的决定，不把未完成
   写成达标。
5. **学生只是暂时停课**：不擅自把 Plan 标为完成，也不新增 `paused` 状态。
6. **Roadmap 制定下一 Plan**：先读完成 Plan；只有决策需要时才沿其 Lesson Tree 下钻，
   不依赖复制摘要或 Handoff。
7. **Plan 制定下一 Lesson**：先读刚关闭 Lesson，再按需查看相关 Block/Classroom Log，
   与学生讨论后才形成下一课草案。
8. **存在未链接孤立文件**：任何层级都不读取、不引用，也不把它当作该学生历史。
9. **源节点后来被纠正**：父节点重新读取真实来源并修正当前判断，不继续沿用旧复制文本。

验收应检查 `completed` 是否只表达生命周期结束，公开对话是否明确区分达标完成与选择
结束，达标结论是否由直接独立证据支持。证据读取必须从当前 Tree 的直属子节点开始，按
当前决策需要逐层下钻并及时停止；任何目录枚举、预加载整棵树或独立 Handoff 都不合格。

Lesson 课堂执行与适应还至少覆盖以下真实情境：

1. **学生仍在独立思考**：Tutor 不把停顿、未完成表达或“不确定”自动当作求助，不抢先
   给出路线；意图不清时只澄清是否需要提示。
2. **学生确实需要讲解**：缺少前置概念、重复尝试无效或明确要求教师教时，Tutor 不机械
   追问，而是针对性讲清，并用一个小独立动作恢复学生参与。
3. **局部失误与概念错误**：前者让学生定位修复，后者才使用对照、反例或直接解释，不把
   所有错误都处理成同一种提示。
4. **合法替代路线**：Tutor 先按学生路线核查并允许其完成；学生纠正教师时，教师承认并
   保留真实记录，不强行追加标准解法。
5. **课堂微调**：教师根据即时表现换例、跳过、增加短支架或调整相邻 Block，不重演批准
   仪式；明显增加负担或改变帮助契约时先和学生商量。
6. **目标已经动摇**：Tutor 停止在 Lesson 内扩张或偷换目标，保留课堂事实并把问题交回
   Plan Session。
7. **独立与受帮助表现不同**：Classroom Log 清楚记录首次表现、实际帮助和帮助后复验，
   不把日志写成逐字稿，也不把受帮助成功润色成掌握。
8. **不同收尾状态**：已有独立证据时不重复测验；只有提示后成功时邀请小复验但不强迫；
   学生立即结束时停止加题，且 `closed` 不被解释为能力达标。
9. **四个按需技巧独立接入**：概念边界修复、方法比较、独立迁移检查、挫败与暂停分别
   进行“未命中、命中、状态转变”同情境 RED/GREEN；一个未通过不能借其他技巧通过而
   整库启用。卡顿时只使用核心帮助阶梯，不读取第五个 reference。
10. **Lesson 系统契约**：所有情境都检查 Tutor 只读取当前 Lesson 与当前 Block `Uses`，
    不读取父 Plan/Roadmap、不枚举目录；必要工具结束后只产生一次学生可见回应；日志不
    猜测时间；学生要求结束后 Lesson 顶层状态仍由 Runtime 保持和转换。
11. **结构化写入近乎隐形**：普通教学轮次不多余调用工具；关键证据、Block 边界和真实
    路线调整首次就选择正确命令；Tutor 不公开谈论状态管理，也不因工具存在而提前结束
    Block、机械播放教案或增加学生等待。

### Lesson 结构化写入专项验收

第一层使用确定性 Runtime 测试覆盖两个工具的全部命令及其拒绝路径。多行日志、Markdown
标题和列表内容不能逃出当前日志项；非法状态、依赖环、来源越界、越权修改和损坏的原文件
全部拒绝；任意失败后正式文件逐字不变。Tutor 写入与学生关闭并发时只能产生一种合法
顺序，不能丢失更新。Lesson Session 必须恰有两个结构化写工具且没有 `edit/write`，其他
节点工具面保持原样；实际运行使用的模型提供方必须能接受工具 Schema，不能只通过本地
类型检查。

第二层使用短情境真实模型运行，分别观察：普通教学轮次不乱调用状态工具；出现关键证据
时首次正确追加；Block 真正结束时首次正确推进；真实反应迫使调整路线时能更新 pending
结构；学生突然停止时不越权关闭 Lesson；工具拒绝时不向学生倾倒内部过程或陷入重复
调用。这里检验的是首击行为和学生体验，不靠用户提醒模型纠正。

第三层使用这次失败时相同的模型档位和一份干净学习集，模拟真实学生，从 Roadmap 诊断、
讨论与确认开始，完成第一个 Plan 的制定、逐课共备、准备、教学、界面关闭和 Plan 收口。
Lesson 数量由真实学习情况动态决定，不为验收硬凑固定课次；过程中不允许人工编辑
Markdown、提醒模型遵守工具或替它修正状态。全程保留工作区、原生 Session 和 CoT，失败
时据此定位模型判断、工具参数、Runtime 或界面层。

长周期通过需要同时满足：每次课程快照都能被严格解析；没有模型越权改变顶层生命周期；
Classroom Log 忠实区分首次表现、实际帮助和帮助后表现；对话仍然自然，模型没有变成
状态管理员；第一个 Plan 中实际安排的 Lesson 均已由学生关闭，并完成 Plan 收口与界面
完成操作。最终判断以学生体验和 Roadmap、Plan、Lesson 产物为主，推理 token 与工具次数
只作为故障诊断材料。

四个 reference 的专项验收至少包括：

- **概念边界修复**：明确缺概念、首次确认错误模型、已有解释仍无变化各自命中正确分支；
  局部算术错和仍在形成的想法不命中；每轮只使用一个讲解、对照或反例，不跳读第二文件。
- **方法比较**：已完成合法路线时先等待学生复述，再于下一轮比较一个替代；路线未完成时
  继续当前路线，不能因参考答案不同提前比较，也不能搜索学习集补全学生路线。
- **独立迁移检查**：提示后安排一个无提示小动作，首次表现与后续帮助分开记录；现场微题
  明确是教师生成且位于当前 Goal 内，不能读取父节点、未链接卡片或材料寻找题目。
- **挫败与暂停**：表达挫败但愿意继续时提供选择；明确“今天不做了”时 5/5 不再加题、
  不修改 Lesson 顶层状态，也不把日志处理过程说给学生。

每项 wording micro-test 使用同一模型、同一学习集和同一学生输入至少 5 个独立 Session，
保留无该 reference 的对照，并人工阅读所有命中或疑似失败的 CoT。只有首击守住率达到
5/5、且没有证据越界、公开过程泄露或生命周期越权，才把该文件加入运行时 INDEX 路由。
流程形态通过不能抵消学生可见的数学错误。若通用核验边界已经明确后仍只出现个别措辞
不严谨，把它记录为模型档位的残余风险；不为单句波动继续叠加路由或工具规则。

验收关注 Tutor 是否始终根据学生当前真实反应选择一个成比例的下一动作，是否保持
`Lesson Goal` 稳定并让 Block 结构可调整，是否把关键课堂证据写回其最低真实节点。任何
机械播放教案、无差别苏格拉底追问、过早完整解答、隐藏帮助程度、Lesson 内制定下一课
或以结束状态宣告掌握的表现都不合格。

Plan/Lesson 准备交付还至少覆盖以下真实情境：

1. **只有“你来安排”或初始要求**：Prepare 拒绝创建节点，返回 Dialogue 先公开完整设计
   并取得确认。
2. **已确认 Plan**：只创建一个 `prepared` Plan，目标、标准、Test 和公开弧线忠实对应
   批准版本，`Lesson Tree` 为空，既不预建 Lesson 也不创建未来 Plan。
3. **已确认 Lesson**：只创建当前一个 `prepared` Lesson；公开体验与批准版本一致，具体
   Blocks、材料、答案、提示阶梯和备用路线由教师专业展开，初始日志为空。
4. **只缺内部实施细节**：Prepare 直接选择合适题目、材料或提示结构，不把私有备课重新
   变成学生问卷。
5. **实施条件迫使公开设计改变**：缺材料、时间或难度问题会改变目标、活动形态、处理
   深度、帮助契约或工作量时，不静默缩水，返回对应 Dialogue 重新讨论。
6. **已批准内容彼此冲突**：Prepare 不自行选择一个版本，不创建部分子节点，明确指出需
   要先由师生澄清的实质冲突。
7. **子文件验证失败**：修复同一个子文件，未合法前父 Tree 保持不变。
8. **挂 Tree 失败**：重读父节点并只重试同一链接；无法恢复时报告精确孤立路径，不删除、
   不换 ID、不创建副本，也不把未链接文件宣称为已交付。
9. **精确路径冲突**：不覆盖既有节点，不通过目录枚举把它猜成当前产物；停止并报告。
10. **公开交付报告**：学生只看到已确认的目标、活动、工作量和启动方式，Lesson 的答案、
    Teacher Control 与诊断机关继续保持私有。

验收必须检查完整顺序“写子文件—回读子文件—挂父 Tree—回读父子文件”，并确认任何
失败路径都没有 dangling link、重复 Tree 条目、静默覆盖或第二份节点。文件存在本身不算
成功；只有合法子文件已经唯一链接到正确父 Tree，才构成交付完成。

全部模块设计完成后，再补充跨节点组合场景和端到端长周期验收，不让单模块测试代替
完整 Roadmap → Plan → Lesson 学习过程。
