# StudyForge 节点专属教学 Skill 树总设计

日期：2026-08-04

## 结论

Roadmap、Plan 与 Lesson 是三个独立 Session。它们面对的时间跨度、教学问题和学生
对话深度不同，不能共享一个通用“讨论 Skill”。资源装配改为五个顶层 Skill：

```text
Roadmap Session
├── roadmap-dialogue
└── prepare-approved-plan

Plan Session
├── plan-dialogue
└── prepare-approved-lesson

Lesson Session
└── tutor-lesson
```

Roadmap 讨论整个学习集中的长期能力、总体学法和下一个 Plan；Plan 讨论一个阶段在
多节课中的推进和下一课设计；Lesson 只处理当前课堂中的理解、作答、帮助和结束。

这是一份持续扩展的总设计文档。各模块先经过真实学习情境讨论并逐段确认，再追加到
同一文件；全部模块收束后统一生成实施计划和真实模型验收方案。当前已细化“初次
Roadmap 会面”“Roadmap Session 中的 Plan 制定”以及“已确认 Plan 的首次进入与草案式
共同备课”“课后复盘与后续 Lesson 共备”；跨 Plan 复诊、Plan 阶段结束和 Lesson 特殊
教学技巧在后续章节继续设计。

## 资源分层原则

常驻 Agent、按需 Skill、Skill reference 与学习集文件承担不同职责：

```text
Agent：我是谁、负责哪一层、拥有什么权限、必须经过什么批准门
Skill：当前正在完成哪一种工作、怎样完成、产出什么交接
Reference：遇到某类具体情境时采用什么专业方法
学习集文件：当前学习集提供什么内容与学科教学边界
Roadmap / Plan / Lesson：学生已经确认或课堂真实发生了什么
```

具体归属如下：

- `math-teaching-core.md` 保存所有节点常驻的教师底色，例如自然交流、有依据的暂定
  判断、不制造分歧、尊重学生选择、承认误判和诚实区分独立与受帮助表现。
- `roadmap-node.md`、`plan-node.md`、`lesson-node.md` 只保存各节点身份、尺度、权限、
  禁止事项、批准门和 Skill 路由，不保存低频教学流程。
- 五个顶层 Skill 保存对应工作流的稳定主干与 reference 路由。
- 初次诊断、现场短探针、跨 Plan 复诊、Plan 周期、Lesson 模板和特殊讲解技巧等
  条件分支放进相应 Skill 的 references，只在命中真实情境时读取。
- `LEARNING_GUIDE.md` 保存学习集有什么、适合谁及其学科特有教学姿态。通用 Skill
  不硬编码“同构”“跨阶”等特定学习集内容，也不假设存在独立课程目录。

关键批准边界采用调用端与接收端分别守卫：Roadmap Agent 不得在学生确认前进入 Plan
准备，`prepare-approved-plan` 则拒绝物化没有已确认公开设计的输入。两者约束不同的
责任点，不复制整段工作流。

## 批准边界

Roadmap 与 Plan 都采用“先讨论、后实施”的教育版 Superpowers 工作流：

```text
公开讨论与教师方案
→ 学生明确确认或修正
→ 把最终设计写入父节点现有正文
→ 调用对应 prepare Skill
```

学生说“你来安排”只是授权教师提出方案，不是批准尚未公开的 Plan 或 Lesson。
即使学生的初始要求很具体，Coach 也先呈现完整设计并等待确认。学生对方案作出明确的
“接受并修改”后，修改后的表达可以构成最终确认，不增加第三次形式化审批。

## 节点交接

- Roadmap 通过一个已确认并写入的 Plan 文件向 Plan Session 交接。
- Plan 通过一个已确认并写入的 Lesson 文件向 Lesson Session 交接。
- Lesson 通过 Block Classroom Log 和关闭后的 Lesson 文件把课堂事实交还给 Plan。
- Plan 完成后通过 Plan 原文与 Handoff 回到 Roadmap；跨 Plan 证据的进一步设计另议。

不新增批准状态、schema、数据库、Session 类型或运行时状态机。确认后的公开设计使用
现有 Roadmap/Plan 自由正文表达。

## 渐进展开

五个顶层 Skill 只保存稳定职责、对话边界、批准门和按需引用入口。细节后续逐步加入：

- Roadmap 诊断、跨 Plan 复诊和能力地图作为 `roadmap-dialogue` 的 references；
- Plan 周期原型作为 Roadmap/Plan 对话可共享的 references；
- Lesson 模板与材料准备只属于 `prepare-approved-lesson`；
- 特殊讲解、提示、对照、修复和路线比较技巧作为 `tutor-lesson` 的 references；
- 学习集特有的数学教学方法继续来自 `LEARNING_GUIDE.md`。

五 Skill 骨架阶段只完成 Runtime 装配与确定性测试；本总稿从该骨架继续逐段细化教学
内容，但每次只展开已经与学生情境共同确认的模块。

## 初次 Roadmap 会面

### 目标与尺度

第一次 Roadmap 会面不是填写学习档案，也不是立即挑一个知识点开课。它是一段真实的
初次接诊：学生用自然语言描述愿望、困扰和最近经历；Roadmap 教师负责把这些材料解释
为一条暂定的长期能力方向、总体学法和下一个有边界的 Plan，再交还学生确认。

Roadmap 同时回答两个问题：

1. 学生希望经过较长周期后获得什么能力；
2. 学生准备采用怎样的总体学习方式获得它。

前者是“爬到哪里”，后者是“怎样爬整栋楼”。Plan 再把总体方针结合当前数学内容与
最近证据，翻译成这一层的具体学法；Lesson 只负责脚下这一个台阶。

### 渐进加载结构

初次会面的具体方法不常驻于 Roadmap Agent，也不增加第六个顶层 Skill：

```text
roadmap-dialogue/SKILL.md
└── references/diagnosis/
    ├── INDEX.md
    ├── first-roadmap.md
    └── live-diagnostic-probes.md
```

- Roadmap Agent 常驻允许“有边界的现场短诊断”，同时禁止把它扩展成未建档 Lesson、
  宣布掌握或替代正式课堂。
- `roadmap-dialogue` 保存首次会面触发条件、共同收敛流程和 reference 路由。
- `first-roadmap.md` 保存短介绍、自然问诊、教师解释、总体学法与首个 Plan 提案方法。
- `live-diagnostic-probes.md` 只在学生明显无法描述问题，且决策性不确定性无法靠继续
  交谈区分时加载。

### 自然对话而非固定问卷

进入干净学习集时，教师先根据 `LEARNING_GUIDE.md` 做足以让学生开口的短介绍，再听
学生的自然诉求；不先倾倒完整能力地图或假想课程目录。学生可以只说：

- “我想学点高级技巧。”
- “导数题我经常没有思路。”
- “我也不知道自己应该怎么学。”

不能要求学生自己说出“我缺少结构识别能力”或选择教育学术语。教师内部逐渐形成四个
判断，但对外始终保持自然对话：

1. 学生希望长期发生什么变化；
2. 哪些具体经历支持当前理解；
3. 整体更适合怎样学；
4. 哪个首个 Plan 最值得尝试。

这些判断不构成四道必问题，也不要求全部确定。每轮最多处理一个真正会改变长期路线的
问题，让学生的上一轮回答决定下一步。学生说“你帮我安排”表示停止继续盘问，由教师
承担提出方案的责任；它不是批准尚未公开的 Roadmap 或 Plan。

停止追问不以填满字段为标准。满足以下条件即可提出方案：

```text
教师能够提出一条有理由、可调整的长期路线
＋能够说明为什么先选当前 Plan
＋知道什么后续表现可能推翻判断
＋学生已经能够理解并确认或修正
```

### 现场短诊断

只有同时出现以下条件时，才从自然问诊切换为现场短探针：

- 学生无法稳定描述自己的问题，或说法互相矛盾；
- 教师已有两种以上会导向不同 Plan 的合理解释；
- 继续语言追问难以负责地区分这些解释。

教师先自然解释原因并取得轻量同意，例如：“我们再靠说可能也说不清，要不看两道很短
的题？我主要看你第一步会想到什么。”学生拒绝时，不强迫诊断；教师可以保留明确的
不确定性，提出一条可逆路线或建议以后使用正式诊断 Plan。

短探针允许两种材料来源：

- 优先使用学习集中已有且未曝光的可靠题目；
- 只需区分一个小变量时，允许教师临时编制短题。

题目应短而互补，每道主要区分一个解释，观察学生看见什么、怎样开始、在哪里停住以及
哪一级帮助使其恢复。不要用一道综合大题同时混合计算、结构识别、选路、耐力和提示
依赖，也不要为了“完整了解学生”无限扩题。

帮助采用“先保留首次状态，再正常帮助”的方式：

```text
学生先独立开始
→ 保留第一步和真实停止点
→ 必要时给最小提示
→ 观察哪种帮助改变了表现
→ 必要时换平行短题复验独立表现
```

可以解释题意，但首次尝试前不泄露正在诊断的决定性方法。学生主动求助时可以帮助；
提示后的成功用于判断什么支持有效，不能改写为独立完成。如果当前讲解会污染后续
探针，则暂缓完整讲解。诊断目的达到后，返回 Roadmap 判断与 Plan 提案，不顺势在
Roadmap Session 中上完一堂课。

原始作答保留在 Roadmap Session。`ROADMAP.md` 只写经学生确认的暂定解释、依据、
不确定性和推翻信号，不创建课堂 Trace，也不把一次短探针升级为稳定能力或永久标签。

若问题需要较多题、多轮复验、正式课堂记录或跨 Session 观察，则停止现场探针，公开
提议一个短诊断 Plan，并继续遵守 Plan 批准门。

### 公开 Roadmap 方案

初次讨论收敛后，采用“长期弧线公开、未来方向暂定、一次只批准并物化一个 Plan”的
粒度。公开方案需要让学生理解：

- 教师目前怎样理解他的愿望和具体情况；
- 这段长期学习希望产生什么能力变化；
- 总体准备怎样学，例如快速建立全景、逐层建构或难题探索；
- 基于当前学习集与学生情况推导出的暂定能力方向；
- 为什么先做当前 Plan；
- 哪些后续表现会改变路线、顺序或总体学法。

下一个 Plan 才详细到 `Stage Goal`、`Observable Capability Standard`、`Test` 和公开的
多课初始弧线。未来阶段只作为 Roadmap 正文中的暂定方向，不创建文件、不加入
`Plan Tree`。学生明确确认或修正最终方案后，`prepare-approved-plan` 一次只物化这
一个 Plan。

## Roadmap Session 中的 Plan 制定

### 所属 Session 与触发时机

“制定一个 Plan”发生在绑定 `ROADMAP.md` 的 Roadmap Session 中，而不是绑定某个既有
Plan 的 Plan Session 中。二者不能因为都谈到“下一步”而混为一谈：

- Roadmap Session 选择并共同制定当前学习集的第一个 Plan，或一个既有 Plan 结束后的
  下一个 Plan；
- Plan Session 接受已经由 Roadmap 确认的阶段边界，结合本 Plan 中真实发生的 Lesson
  调整阶段内的推进，并共同制定下一节 Lesson；
- Plan Session 可以把新的证据和建议交还 Roadmap，但不能越权替学生决定下一个 Plan。

首次 Roadmap 会面不一定要把所有长期方向讨论得同样细。只要长期方向和总体学法已经
足够支持当前选择，就详细制定第一个 Plan。后续 Plan 则在上一个阶段完成、学生主动
要求转向，或现有证据表明 Roadmap 需要重新选择阶段方向时讨论。

### Plan 的定义与粒度

Plan 不是教材章节名、若干知识点的容器，也不是一节课要完成的小任务。它是一个有边界
的中期能力周期：多节 Lesson 围绕同一个阶段目标积累证据、根据表现调整教学，最后用
一个能直接检验该目标的任务作出有意义的阶段判断。

判断粒度时不按 Lesson 数量机械切分，而检查三个关系：

1. 这些 Lesson 是否共同服务一个连贯的 `Stage Goal`；
2. 各课证据是否会进入同一个能力判断与调整循环；
3. 完成这个循环后，是否值得回到 Roadmap 重新选择下一阶段方向。

如果内容只需要一次小活动或一次局部修复，通常属于 Lesson；如果其中包含多个彼此独立
的阶段目标、检验和教学循环，则应拆成多个 Plan。反过来，一张内容清单看起来很长，
也不自动意味着必须拆分；只要它们共同构成同一个能力循环，就可以保留在一个 Plan 中。

每个 Plan 至少需要形成四个相互对齐的锚点：

- `Stage Goal`：学生经过这一阶段要发生什么能力变化；
- `Observable Capability Standard`：届时学生能够独立表现出什么；
- `Test`：用什么直接而有意义的任务检验，不以“上完内容”代替；
- `Current Position`：为什么现在这样安排，包括已知证据、合理假设与仍然存在的不确定性。

这四项用于约束课程设计，不要求学生以字段或教育学术语逐项回答。

### 第一个 Plan 与后续 Plan

第一个 Plan 从学生初次会面的真实诉求、总体学法、学习集实际提供的材料和当前可支持的
判断中推出。没有证据时可以保留假设，但不能为了让 Plan 显得完整而发明学生的薄弱点。
当关键不确定性会导向完全不同的首个阶段时，可按前述规则进行现场短探针，或先共同建立
一个正式诊断 Plan。

后续 Plan 不是按预设目录自动播放。Roadmap 教师需要回看 Roadmap 中已链接的既有 Plan
及足以支持判断的课堂证据，结合学生此刻的目标、时间和主观感受，说明：

- 上一个阶段实际建立了什么，哪些仍需支持；
- 为什么当前最值得进入这个方向；
- 还有哪些合理方向，以及选择当前方向的主要代价；
- 什么新表现可能使这项建议需要改变。

既有 Plan 是专业建议的证据，不是替学生自动决定下一阶段的指令。课程证据只能沿当前
Roadmap 已链接的节点取得；目录中未链接的文件不能被当作该学生的历史。跨 Plan 记忆
究竟读取到哪一层、怎样压缩和引用，仍留给后续专门模块设计。

### 逆向制定流程

Roadmap 教师先从阶段结束时希望看见的能力反推课程，而不是先凑 Lesson 清单：

1. 说明这个 Plan 为什么现在值得做，并区分证据、推断和未知；
2. 收敛一个有边界的 `Stage Goal`；
3. 把目标翻译成可观察的独立表现，并设计与之直接对齐的 `Test`；
4. 判断学生的当前位置与目标之间最关键的学习变化；
5. 选择合适的阶段推进方式，并形成一条可调整的多课初始弧线；
6. 标出会促使教师加快、放慢、补支架、改变顺序或返回 Roadmap 的证据；
7. 给出明确的专业建议、主要理由与代价，交给学生确认或修改；
8. 只有学生确认后，才记录最终设计并调用 `prepare-approved-plan`。

Plan 周期原型可以帮助教师思考推进方式，但它是按需加载的专业参考，不是要让学生选择
的模板名，也不应作为持久化字段。公开对话应呈现教师对这个学生的具体建议，而不是
暴露内部模板或把一组选项原样推给学生。

### 教师建议与学生决策权

Roadmap 教师不能把决策责任伪装成“尊重学生”，只给出一排中性选项。教师必须根据已有
证据明确推荐最值得做的 Plan，解释为什么现在做、会得到什么，以及暂时不选其他方向的
影响。学生保留路线和节奏的最终决定权。

如果学生选择另一条仍然合理的路线，教师应把最重要的代价或风险解释一次；学生理解后
仍然选择它，就按学生的选择重新形成方案。学生的选择可以改变未来学习安排，不能改写
过去证据，也不能偷偷降低已经公开的能力标准。若学生的选择会使原目标无法成立，教师
需要公开指出冲突并共同改写 Plan，而不是保留一个名不副实的测试。

### 动态 Lesson 数量与初始弧线

Plan 的 Lesson 数量取决于学生在真实课堂中的独立表现、提示依赖、迁移速度和可用时间。
制定 Plan 时尚未发生这些课堂，因此只能估计工作量，不能承诺一个固定课次。曾讨论的
“五到六节一小时一对一课”只是一种可能的估量示例，不是默认值、字段、状态或结束条件；
真实 Plan 可以更短，也可以更长。

如果学生关心时间投入或现实约束会影响选择，Roadmap 教师可以给出暂定范围，同时说明
估算依据和可能改变它的表现；否则优先讲清学习弧线，不为了显得精确而编造课次。公开的
初始弧线描述各阶段要解决的问题与相互关系，不预先创建所有未来 Lesson。

进入 Plan Session 后，可以在不改变已确认 `Stage Goal`、能力标准和 `Test` 的前提下，
依据每节课证据调整后续 Lesson 的数量、顺序、支架和练习重心。学生提前达到标准时不为
凑课次继续上课；需要更多时间时也不为遵守初始估算仓促结课。如果证据表明阶段目标本身
选错、需要拆分或应当换方向，则应带着证据回到 Roadmap 重新讨论，不能在 Plan 内静默
换成另一个目标。

### 化学反应原理校准示例

学生说“我想预习化学反应原理”时，Roadmap 可以建议采用“先建立模型和框架，再用少量
代表性问题检验迁移”的总体学法。第一个 Plan 可以围绕能量账本、热化学方程式与盖斯
定律形成一个连贯的阶段能力周期，而不是把整本书一次列成课程目录。

完成首个 Plan 后，第二个 Plan 可以把反应速率的定量表示、图像与数据、浓度温度催化剂
的微观解释、实验控制和迁移任务放进同一个循环。这里不因知识点数量或预计课次数量自动
拆分；如果它们共同服务“从证据表征到机制解释再到实验与迁移”的阶段判断，就可以是
一个 Plan。只有当学生情况使其中出现相互独立的目标、检验和适应循环时，才建议拆分。

### 批准与物化边界

Roadmap 教师最终需要公开一个完整但可调整的 Plan 提案，让学生看懂当前依据、阶段目标、
结束标准、直接检验、初始学习弧线、可能的调整信号，以及在需要时给出的暂定工作量。
学生可以接受、修改或拒绝。“你来安排”只要求教师承担完整提案，不能代替对这个已公开
提案的确认。

确认后，最终设计写入 Roadmap 的现有正文，再由 `prepare-approved-plan` 一次物化一个
Plan 并连接到 `Plan Tree`。未来 Plan 只能保留为 Roadmap 中的暂定方向，不预先创建空
文件；Lesson 也要到相应 Plan Session 逐节讨论、确认和准备。

## 已确认 Plan 的首次进入与草案式共同备课

### 首次进入不是重新审批 Plan

学生进入绑定既有 Plan 的 Plan Session 时，该 Plan 已经在 Roadmap Session 中共同制定
并得到确认。Plan 教师先用自然语言完成一次简短交接：这个阶段为什么现在做、主要希望
发生什么变化、怎样看出阶段已经完成，以及第一课为什么可能从当前位置开始。教师可以
澄清学生的理解，但不把整个 Plan 再读一遍，也不要求学生重新批准已经确认的阶段。

如果学生此时明确反悔，或提出的目标已经超出当前 Plan，教师应解释冲突并把路线问题交
回 Roadmap；不能借第一节课备课在 Plan 内静默换掉 `Stage Goal`。如果变化只涉及阶段内
的先后、强度、学习方式或第一课重心，则可以留在 Plan Session 中共同调整。

### 教师草案先行，学生实质修订

真实家教通常不是师生面对一张白纸共同写教案。进入讨论前，教师先根据已确认的 Plan、
现有证据、初始课程弧线和专业判断形成一份暂定 Lesson 草案，再把它作为有理由的建议交
给学生讨论。这样由教师承担设计责任，也让学生面对一个可以具体回应的方案。

草案不是已经批准或物化的 Lesson，也不能因为教师已经投入时间就变成学生必须接受的
安排。教师应尽早用不泄题的方式讲清推荐内容，让学生能够实质改变它；共同备课发生在
对草案的理解、质疑、调整甚至放弃之中，而不只是记录一个偏好参数。

公开协商层可以根据当前情境讨论：

- 这一课具体要推动 Plan 中的哪一步，以及为什么先做它；
- 学生对相关内容的现有经验、主观困难和此刻准备状态；
- 本课的重点、难度、节奏、参与方式和时间约束；
- 准备采用怎样的学习活动、材料类型、课堂互动与课后负担；
- 学生到课末应能表现出什么，什么证据说明本课目标已经达到。

这些不是必须逐项盘问的表单。教师以草案为起点说明建议和真实取舍；学生可以回应、
追问、拒绝或修改，教师据此继续判断并修订。对话持续到教师能够整合一份有依据的课程
方案，且学生能够理解它将怎样进行并作出决定。不存在“最多只能问一个问题”的限制，
也不能用连续问卷把专业设计责任推回学生。

学生提出“我不想学这个”时，教师不应守着原草案继续做表面微调，而要先听清他拒绝的
对象和原因：

- 如果学生仍认可当前 Plan，只是不接受这节课的切入点、顺序或形式，就在 Plan Session
  中放弃或重写 Lesson 草案；
- 如果学生不再认可当前 Plan 的阶段目标，可以先在当前对话中把原因听清，但应停止创建
  Lesson，并回到 Roadmap Session 共同制定替代 Plan。

草案的沉没成本不能成为说服学生继续的理由。教师可以解释一次关键收益与代价，但学生
理解后仍拒绝，就重新开始共同思考，而不是把“专业建议”变成软性强迫。

专业准备层由教师承担，包括：

- 具体题目、例子、答案和材料编排；
- 提示阶梯、常见误区、诊断意图和课堂分支；
- 根据不同学生反应采取的支架、追问与备用路线；
- 为课堂记录和课末证据准备的具体观察点。

教师在形成初始草案时可以预想这些内容，以确保建议可教；会破坏诊断或学习体验的细节
不提前泄露，也不在学生确认前物化为正式 Lesson。`prepare-approved-lesson` 在公开方案
确认后完成并固化专业准备。“专业细节”不能成为偷换课程的理由：最终教案必须服务双方
已经确认的目标、重点、学习方式、负担和完成标志。

### 共同备课流程

`plan-dialogue` 承担从教师草案到确认方案的完整公开共同备课，而不只是替
`prepare-approved-lesson` 收集一个参数：

1. 根据既有 Plan 与现有证据，先形成一份可放弃的暂定 Lesson 草案；
2. 简短解释既有 Plan、当前建议起点和草案理由，不重新审批 Plan；
3. 学生围绕目标重点、学习方式、难度、负担和现实约束提出反应，教师说明取舍并修订；
4. 学生拒绝当前内容时，先理解原因：阶段内重做 Lesson，否定阶段则停止并返回 Roadmap；
5. 教师把修订结果整合成一份完整但不泄题的公开 Lesson 提案；
6. 学生明确确认、修改或拒绝该提案；
7. 只有确认后，才调用 `prepare-approved-lesson` 完成专业准备并物化当前一个 Lesson。

公开 Lesson 提案至少让学生看懂：本课为何现在进行、本课目标、与 Plan 的关系、大致
学习过程、预期参与方式、课末完成标志，以及会实质影响学生选择的负担或取舍。它不需要
公开答案、提示机关或逐分钟教案。

学生说“你来安排”“都可以”或“直接开始吧”，可以终止继续追问并授权教师整合提案，
但仍不等于批准一个尚未公开的 Lesson。教师必须先呈现完整方案；学生对这个方案明确
同意或作出修改后，才能进入准备。学生在讨论中已经明确提出完整要求时，教师仍需复述并
补足关键设计边界，再取得对最终版本的确认。

### Skill 责任边界

- `plan-dialogue` 保存阶段交接、共同备课、教师建议、学生决策权和 Lesson 批准门；
- Lesson 类型、材料选择和备课方法作为 `prepare-approved-lesson` 的按需 references；
- `prepare-approved-lesson` 只能展开已确认设计，不能新增会实质改变学生体验的目标、
  负担或评价标准；
- `tutor-lesson` 在课堂中根据真实反应实施和调整，但不能把课堂适应伪装成已经提前得到
  学生批准的另一套课程。

首次进入只确定 Plan 交接与第一节 Lesson 的共同备课。后续 Lesson 如何结合上一课证据
复盘并共同调整见下一节；何时结束 Plan 仍在后续模块中单独设计。

## 课后复盘与后续 Lesson 共备

### 教师先读证据，讨论后再生成草案

一节 Lesson 结束后，Plan 教师先读取当前 Plan 及其已链接 Lesson 的课堂记录，把最初的
课程弧线与真实表现进行比较，形成对上一课的初步证据判断、仍需澄清的问题和几种可能
方向。此时不生成下一课草案：上一课后的学生体验尚未进入判断，过早形成具体课程容易让
后续讨论只剩对既有方案做微调。教师也不能沿目录枚举未链接 Lesson 作为证据。

但公开对话的顺序不同。教师先给学生一个不受教师结论锚定的表达机会，例如自然询问：
“上节课你自己感觉哪里真的顺了，哪里还不踏实？”这不是固定问卷，也不要求学生给自己
下专业诊断。学生愿意详细说时就继续听；学生说不清、只说“还行”或希望教师直接判断时，
教师不反复逼问，而是进入有依据的公开复盘。

学生的主观体验是证据的一部分，不是对能力状态的唯一裁决。课堂记录同样不能压过学生
的体验。教师公开复盘时区分：

- 课堂中实际发生的作答、停止点和帮助；
- 学生现在报告的理解感、困难、兴趣和负担；
- 教师基于两者作出的暂定解释；
- 还没有被独立表现证明的部分。

如果学生感觉“已经完全会了”，但课堂成功依赖提示，教师可以同时承认理解感有所改善，
并说明独立迁移仍需验证；如果学生觉得自己“什么都没学会”，但已经出现稳定的独立进步，
教师也应拿出具体证据帮助他校准，而不是简单附和。两类证据冲突时，保留冲突并把它转化
为下一课需要检验的问题，不能改写原始课堂事实。

师生先把“上一课实际说明了什么”和“下一步真正需要解决什么”讨论到足以设计课程，再
由教师承担整合责任，生成第一版下一课草案。这个顺序与 Plan 刚开始时不同：第一节课
缺少本 Plan 内的既往课堂经验，可以由教师依据已确认 Plan 草案先行；后续课已经有新的
师生经验，必须先把它纳入讨论，不能只拿预设弧线生成草案。

### 初始课程弧线只是可调整假设

Plan 中公开的多课弧线为教师提供方向，不是必须按顺序播放的课程目录。每完成一节课，
教师都根据独立表现、提示依赖、迁移、学生体验和现实约束判断接下来更适合：

- 按原方向继续，但更换例子或难度；
- 加快推进，提前进入迁移或检验；
- 放慢、回访前置理解或增加支架；
- 调整阶段内的先后、学习方式和课后负担；
- 暂停建课，把已经超出本 Plan 的路线问题交回 Roadmap。

这些调整可以改变 Lesson 数量和阶段内路径，但不能静默改写 `Stage Goal`、能力标准或
`Test`。已经完成某节 Lesson 也不等于对应能力已经掌握，提示后的流畅更不能被折算成
独立完成。

### 课后共同备课流程

后续 Lesson 采用“教师证据准备—师生先讨论—教师再出草案—学生修订确认”的顺序：

1. 教师读取当前 Plan 与已链接课堂证据，形成初步证据判断与待澄清问题，不生成草案；
2. 公开对话先邀请学生描述上一课的真实感受，不先泄露教师结论；
3. 教师综合课堂事实与学生体验，公开说明进展、困难、不确定性和对原弧线的调整判断；
4. 师生共同讨论下一步要解决的问题、学习方式与现实约束，直到足以形成课程设计；
5. 教师根据讨论生成第一版下一课草案，说明为什么这样安排及主要取舍；
6. 学生提出修改或拒绝，教师据此修订；若否定整个阶段，则停止建课并返回 Roadmap；
7. 教师整合为完整但不泄题的公开 Lesson 提案，等待学生明确确认；
8. 确认后才调用 `prepare-approved-lesson`，一次只物化当前下一节 Lesson。

学生说“你根据上节课看着安排”会减少不必要追问，但不跳过公开复盘、草案说明与确认。
教师也不能因为 Plan 里已经写过未来弧线，就把它当成学生预先批准了所有后续 Lesson。

### 本轮边界

课后复盘与后续 Lesson 共备属于 `plan-dialogue` 的稳定主干；对不同证据组合采用何种
阶段内教学周期，可以按需读取 Plan 周期 references。`prepare-approved-lesson` 仍只在
确认后完成具体材料和专业教案，不负责替 Plan 教师决定下一课方向。

本节只设计“继续本 Plan 时怎样复盘和准备下一课”。何种证据足以建议结束 Plan、学生
怎样参与结束决定、结束后怎样回到 Roadmap，留给下一模块讨论。

## 后续共同设计的模块

以下内容明确保留在同一总设计文档中继续讨论，不在初次 Roadmap 切片中预判答案：

- Roadmap 的跨 Plan 复诊与跨 Plan 课程记忆；
- Plan Session 的阶段结束与 Roadmap 交接；
- `prepare-approved-plan` 与 `prepare-approved-lesson` 的完整交付核验；
- Lesson 中的特殊讲解、提示、纠错、路线比较和课堂适应技巧；
- 各模块组合后的端到端长周期验收。

## 验收

装配测试必须证明：

- Roadmap 只获得 `roadmap-dialogue` 与 `prepare-approved-plan`；
- Plan 只获得 `plan-dialogue` 与 `prepare-approved-lesson`；
- Lesson 只获得 `tutor-lesson`；
- 旧 `roadmap-study`、`coach-study` 与 `plan-next-cycle` 不再成为运行时入口；
- Plan 周期、Lesson 模板和材料准备 references 仍完整存在于新的归属位置。

骨架搭建阶段不进行教学话术验收；每个 Skill 细化后再使用真实学生情境分别做
RED/GREEN 验证。

### Skill 行为验收方法

Skill 修改遵循 RED—GREEN—REFACTOR。每个模块先在当前提示词上运行干净学习集和真实
模型，保留原始 Session、工具调用、公开对话和 CoT 作为 RED；确认失败形态后才修改
对应 Agent、Skill 或 reference。GREEN 使用相同学习集、模型、学生输入和判断标准，
不把预期答案写进学生话术或模型上下文。

初次 Roadmap 至少并行覆盖四种学生情境：

1. **目标较清楚的优秀学生**：“我想学点导数高级技巧，综合题经常没思路。”
2. **真的不知道怎样学**：“我也不知道该学什么，最近数学越来越乱。”
3. **明显糊涂的学生**：描述含糊或互相矛盾，需要轻量同意后的现场短探针。
4. **把决定权交给老师的学生**：“我说不清，你帮我安排吧。”

验收关注行为，不检查固定话术：

- 是否短介绍后进入具体经历，而不是倾倒课程目录；
- 是否让学生用自然语言说话，由教师承担专业解释；
- 是否在已有足够信息时停止追问；
- 是否只在决策性不确定性确实存在时启动短探针；
- 是否区分首次独立表现、提示后表现和后续平行复验；
- 是否在 Roadmap 中停止授课并返回长期判断；
- 是否公开长期能力、总体学法、暂定方向、下一个 Plan、依据与推翻信号；
- 是否在学生确认前不创建 Plan，并且一次只物化一个 Plan。

Plan 制定还至少覆盖以下真实情境：

1. **首个 Plan、目标清楚**：学生准备预习一个新学科模块，教师能从总体学法推出一个
   有边界的首阶段，而不是复制教材目录。
2. **后续 Plan、有既往证据**：教师用上一个已链接 Plan 的真实表现提出明确建议，同时
   允许学生改变未来路线。
3. **学生不同意推荐**：学生理解关键代价后仍选择另一条合理方向，教师尊重选择并重新
   对齐目标、标准和测试。
4. **初始工作量估计失准**：学生进步快于或慢于预期，Plan Session 调整 Lesson 数量，
   不凑课、不赶课，也不偷偷改变阶段目标。
5. **粒度边界**：面对看似很长或很短的内容，教师按共同目标、证据循环和阶段判断决定
   合并或拆分，而不是按固定课次数量切割。

上述场景都要检查：提案前是否有足够而未捏造的依据；`Stage Goal`、可观察标准与 `Test`
是否对齐；工作量是否明确为动态估计；学生确认前是否没有新建 Plan；确认后是否只创建
当前一个 Plan，且没有预建未来 Lesson。

已确认 Plan 的首次进入还至少覆盖以下真实情境：

1. **学生愿意认真讨论**：教师带着有依据的初始草案进入对话，学生能实质改变第一课的
   目标、重点、方式和负担；既不要求学生从白纸设计，也不把草案当成定案。
2. **学生说“你来安排”**：教师停止无必要追问并承担专业设计，但先公开完整 Lesson
   提案，得到确认后才准备。
3. **学生提出学习偏好**：教师说明偏好的收益与代价，共同把它转化为适合当前 Plan 的
   课程设计，而不是只记录一个偏好参数。
4. **学生临时想换方向**：阶段内调整留在 Plan Session；改变阶段目标则明确返回
   Roadmap，不借备课越权创建新 Plan。
5. **避免泄露教学机关**：学生理解并确认课程体验与完成标准，但不会提前看到答案、
   提示阶梯或诊断题的决定性信息。
6. **学生直接拒绝草案**：教师不以备课投入施压；先理解拒绝原因，再根据拒绝的是
   Lesson 还是整个 Plan，分别重做课程草案或返回 Roadmap。

验收应区分“参与共同备课”和“承担教师工作”。教师必须主动提出初始草案、专业建议并
负责内部教案；学生必须拥有对公开 Lesson 设计的真实影响力、拒绝权与最终确认权。任何
“只问一个偏好后单方面定案”“要求学生从零设计课程”或“学生拒绝后仍围绕原草案劝服”
的表现都不合格。

课后复盘与后续 Lesson 共备还至少覆盖以下真实情境：

1. **学生感觉很好但依赖提示**：教师承认理解感的改善，同时保留“独立迁移尚未证明”，
   并在下一课草案中安排适当复验。
2. **学生感觉很差但已有进步**：教师用具体课堂事实帮助校准，不用一句“你其实会了”
   否定学生体验。
3. **学生说不清感受**：教师停止无效追问，公开自己的证据判断并继续讨论下一步；信息
   足够后才生成下一课草案，仍等待学生确认。
4. **原课程弧线不再合适**：教师依据课堂证据调整阶段内顺序、支架或 Lesson 数量，
   不机械播放预设目录。
5. **证据动摇整个 Plan**：教师不创建下一 Lesson，把事实、不确定性与建议交回
   Roadmap，而不是在 Plan 内偷偷换目标。
6. **连续多节课已有设想**：教师只提案并物化当前下一节，不把旧弧线当作学生对未来
   所有 Lesson 的预先批准。

验收应检查第一课和后续课是否采用不同顺序。后续课对话前，教师只能基于当前 Plan 证据
形成初步判断与待澄清问题，不能先生成 Lesson 草案；对话中先给学生未被锚定的表达机会，
再公开区分课堂事实、学生体验、教师解释与未知。师生讨论出下一步需要后，教师才能生成
草案；下一课仍须经过修改和明确确认，不能由课堂日志自动触发创建。

全部模块设计完成后，再补充跨节点组合场景和端到端长周期验收，不让单模块测试代替
完整 Roadmap → Plan → Lesson 学习过程。
