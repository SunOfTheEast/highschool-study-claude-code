# M1a 教师笔记式记忆验证设计

**状态：** 已逐段确认，进入实施
**日期：** 2026-08-07
**产品实现基线：** `17b7e9b`
**M0 对照基线：** `fed2a01`

## 一、目标与范围

本设计验证 StudyForge M1a 的教师笔记式 Markdown 记忆是否在真实模型长周期中成立。
它回答的不是“模型能否写出几份格式正确的记忆文件”，而是：在相同模型、课程资源和
学生经历下，持久记忆是否让后续教学更准确、更连续、更少重复询问，同时没有引入错误
建模、过度召回、证据改写、响应负担或学生决策权退化。

M1 分为两个相互关联但独立验收的阶段：

- **M1a：教师笔记式记忆。** 在已有学习集中形成、召回、修订对象记忆、能力假设和偏好；
- **M1b：学习集生命周期。** 通过独立的 Learning Set Session，让空白学习集根据学生的
  真实目标、材料和学习活动诞生并继续生长。

本轮只验证 M1a。M1b 不进入同一实验，避免学习集生成错误与记忆错误相互污染。M1a 使用
内容稳定、已经能正常上课的导数学习集。这里“空白”的只有课程历史和 M1a 记忆，而不是
静态题卡、材料与图谱。

本轮也不声称模拟学生获得了真实学习效果。隐藏学生状态只用于校准工具使用、证据判断、
教学分析和跨 Session 连续性。真实学习效果必须由后续真实学生纵向数据支持。

## 二、验证问题

M1a 需要同时回答六类问题：

1. **形成是否真实：** 对象 `Learning History`、当前状态和偏好是否忠实保存首次表现、帮助、
   结果与未知，并直接指向真实来源；
2. **边界是否克制：** 学习痕迹、对象记忆、能力假设、偏好和教学待办是否各归其位；
3. **召回是否有用：** Tutor、Plan 和 Roadmap 是否只在真实决策需要时逐级读取相关记忆；
4. **流变是否保留：** 新证据能否修订当前判断，而不改写旧 Log、旧对象历史或旧原话；
5. **长期聚合是否正确：** Plan 是否只在跨不同对象后形成工作假设，Roadmap 是否跨 Plan
   校准同一个能力链；
6. **代价是否值得：** INDEX、文件读取、token、延迟与故障恢复成本是否小于记忆带来的教学
   价值。

自动化、重放和审计只能提供事实、风险与建议判定。M1a 是否最终通过、是否允许发布，始终
由项目负责人决定。

## 三、验证总体结构

采用混合验收，而不是用单一长周期承担所有证明责任：

```text
确定性实现基线
    ↓
低成本定向机制验收
    ↓
一组完整 M0 / M1a 配对长周期
    ↓
四个关键决策点各三次独立重放
    ↓
索引增长、部分写入与真实 compaction 压测
    ↓
证据审计与项目负责人最终判断
```

定向场景负责定位单一机制；长周期负责检验组合后是否仍像真实教学；关键点重放观察首击
稳定性；真实学生内测构成下一层证据，不被本轮 StudentSim 替代。

## 四、M0 / M1a 配对边界

### 4.1 两个实验条件

| 条件 | 产品代码 | 持久记忆 |
| --- | --- | --- |
| M0 对照 | `fed2a01` | 无 `memory/`；沿原有 Roadmap / Plan / Lesson Tree 回读 |
| M1a 实验 | `17b7e9b` | 从紧凑空 `memory/INDEX.md` 开始，记忆随课堂自然形成 |

两个提交是真实执行基线，不是计划行或模拟实现。旧 `plugins/highschool-study` 不参与 M0
对照；对照只使用当时的 `apps/pi-teaching-web` 产品表面。

### 4.2 共同锁定条件

- 同一份 `examples/derivative-m0/learning-set` 静态题卡、材料、图谱和受控词表快照；
- 清空 Roadmap Plan Tree、课程节点、Session 绑定和旧课程证据；
- M1a 仅比 M0 多最小空 INDEX，不预填学生结论；
- Roadmap、Plan、Lesson 使用 `openai-codex/gpt-5.6-sol`、thinking `high`；
- Material Scout 使用 `openai-codex/gpt-5.6-terra`、thinking `high`；
- 同一隐藏学生画像、状态转移规则、现实负担和学生可见信息边界；
- 各自使用独立运行根、学习集副本、Pi 配置、端口和原生 Session；
- 两个学生驱动上下文互相看不到 transcript、课程文件和另一 Arm 的结果；
- 两边都完整完成两个 Plan，并在 Plan 2 完成后返回 Roadmap；
- 正式运行中不修改产品代码、Skill、学生画像或评分标准来挽救当前结果。

两边不必选择逐字相同的题目或课程名称。若课程方向差异过大，长周期只作为各自的完整
端到端证据；相同输入下的机制差异由关键点重放承担，不强行把不可比路径解释成因果结果。

## 五、学生驱动协议

直接继承
[`2026-08-05-m0-final-long-cycle-acceptance-design.md`](./2026-08-05-m0-final-long-cycle-acceptance-design.md)
已经验证过的“固定画像、自然应答”方案：

- 预先固定知识状态、常见错误、情绪与现实约束，但不预写逐轮台词；
- 学生每轮只根据界面真实可见信息和隐藏状态账本自然回应；
- 不让另一个自主大模型自由扮演学生并突然提高知识或元认知；
- 不读取 Teacher Control、CoT、Lesson 文件、memory 文件、答案或验收清单；
- 使用普通学生语言，宽泛问题只能得到符合画像的含糊回答；
- `stable / fragile / unseen` 状态变化必须指向学生可见课堂中的具体表现；
- 学生认真尝试，不故意破坏课堂，也不为了触发验收项主动说诊断术语；
- “听懂”和受帮助完成只进入 `fragile`；撤去支架后的新任务才能支持 `stable`；
- 明确的“嗯、行、可以”可确认已经公开的方案；沉默或继续操作不能替代确认。

### 5.1 隐藏认知主线

学生会常规求导，也能完成熟悉外壳下的单调性、极值任务。综合题中容易立即展开、机械
分类或套用刚见过的方法，不善于识别决定路线的代数或函数结构。经过对照后迁移较快，
但换壳后的独立启动仍然脆弱，也不知道如何用专业术语概括自己的问题。

学生同时承担学校里的正常学习任务，近期额外时间有限。现实负担只有在实际安排触及时
自然表达，不作为第一轮主动报出的测试字段。

## 六、主长周期

### 6.1 Plan 1：形成记忆

1. 学生以“简单的还行，复杂一点就乱了，也不知道该怎么学”进入空 Roadmap；
2. Roadmap 自然问诊并在必要时使用短探针，与学生共同确认第一个 Plan；
3. 学生在第一个知识对象上暴露表面驱动、直接展开或照搬形式的启动方式；
4. 经提示或对照后完成，但隐藏账本仍保留为 `fragile`；
5. 相似学习方式问题在另一个不同知识对象上再次出现；只有此后 Plan 才可能形成跨对象
   工作假设；
6. 学生在课程负担真正触及时自然表达“最近晚上最多再做一道，不想要成套作业”等需求；
7. 每节 Lesson 的数量由真实表现决定，不为测试固定课次；
8. 每课只进行一次正式课末反思和一次最小充分固化，没有类别配额；
9. Plan 按能力标准诚实收口并由学生确认完成。

### 6.2 Plan 1 到 Plan 2：首次长期消费

Roadmap 先读 Plan 总结与根 INDEX，再按需读取对象、能力或偏好文件。只有压缩判断不足以
负责高影响决策或存在冲突时，才沿精确链接核对来源 Block 的 Classroom Log。第二个 Plan
必须回应真实学习
前沿，但不要求采用预定名称或章节；记忆不能替代学生讨论和确认。

### 6.3 Plan 2：检验记忆而不是服从记忆

1. 在新对象中自然出现一次与旧模式相关、但备课预案没有明确预见的错误；
2. Tutor 依据当前表现判断是否需要按需召回，而不是为了展示记忆固定读取；
3. 后续撤去支架的任务中，学生出现一次真实的独立识别和主动换路；
4. 新表现与旧“脆弱”判断不完全一致，系统应缩小、修订或保留待验证边界，不能解释掉
   新证据来维护旧画像；
5. Plan 2 根据自己的能力标准完整结束；
6. Roadmap 回流后沿同一个能力文件综合两个 Plan，强化、改写、削弱或撤回当前假设；
7. Roadmap 完成本次校准后停止，不为整齐结果创建 Plan 3。

主长周期不规定必须生成多少对象、能力或偏好文件。没有足够证据时，少写比补全更好。
学生只有在公开总结确实说强了时才自然纠正；纠正能力由定向验收保证覆盖。

## 七、定向机制验收

### 7.1 最小充分固化与多对象事件

一次课堂事件同时关联两个知识对象。来源 Lesson 的 Classroom Log 只保存一份原始事实；
两个对象分别追加一条“该事件对本对象意味着什么”的历史，并直接链接同一个真实 Block。
不能复制原始事实，也不能产生无证据的能力或偏好。

### 7.2 学生纠正

学生在公开总结后说明“刚才那一步其实是你提醒后我才想到的”。系统必须追加新 Log 和
对象纠正历史，并修订当前判断；既有 Log、对象历史和学生原话保持逐字不变。

### 7.3 部分写入恢复

从“对象文件、INDEX 与成功回执的原子提交在结果返回前中断”的状态启动新 Session。系统
只能恢复同一次固化，不能重复历史条目、扫描目录猜测产物、覆盖其他记忆或制造第二份真相。

### 7.4 召回正反例

一项预案外错误确实与旧对象相关；另一项只是表面相似而原因不同。前者应沿
`INDEX → L1 → 必要时按 Lesson 路径和 Block ID 核对 Log` 逐级读取，后者应以当前表现为准
并及时停止。两个场景
共同检验召回收益与记忆负迁移。

### 7.5 能力假设门槛与反证

同一对象上的重复表现不能升级成跨对象能力假设；不同对象出现同一模式后才允许形成工作
假设。后续独立成功应校准作用范围，不得无条件强化，也不得删除历史链。

### 7.6 INDEX 生长

预填足以迫使分桶而不是逐项列举的历史对象和索引。新增记忆后，根 INDEX 仍只保留当前
前沿与桶入口，不退化为全量历史清单；旧对象仍可沿桶找到。首轮记录字节数、估算 token、
入口数量和路由命中，不先用脱离真实学习集的绝对行数替代判断。

### 7.7 原生 compaction 恢复

准备接近生产 200,000-token 阈值的真实 Plan Session，在一次成功 Lesson Markdown 写入后
触发 Pi 原生 compaction。下一轮应重新读取 `memory/INDEX.md` 并按需恢复判断，不依赖压缩
前工具结果。该压力测试与自然长周期隔离，不为触发阈值而故意拖长学生课堂。

## 八、关键点重复重放

从真实运行和定向场景提取四个最依赖模型判断的检查点：

1. 该召回还是不该召回；
2. 是否达到跨对象能力假设门槛；
3. 新证据是否正确修订旧判断；
4. Roadmap 是否正确完成跨 Plan 校准。

每个检查点在相同模型、thinking、学习集快照与可见输入边界下独立运行三次。评分只看学生
尚未提醒时的第一次行为。学生提醒后修复可以证明可恢复性，但不能抹去首击失败。

## 九、证据与可观测性

每个运行保存在仓库外的唯一目录，至少包含：

- 产品提交、dirty state、模型、thinking、运行配置和静态学习集哈希；
- 冻结的隐藏学生画像、状态账本与状态变化来源；
- 学生可见消息、生命周期操作和页面/API 响应；
- 原生 Pi Session JSONL、工具调用、文件读取路径、usage、duration 和 compaction 事件；
- 每节课结束后的 Roadmap、Plan、Lesson 与 `memory/` 快照；
- 每次固化前后的 Markdown diff；
- 每个记忆判断到来源 Lesson / Block / Log 的追溯表；
- M0 / M1a 关键决策点并排比较；
- 首次可见反馈、最终回复、读取层级、token 和最长无反馈等待；
- 每次定向测试和三次重放的独立结果，而不是只留最好的一次。

正式长周期主要通过同一真实服务的 HTTP API 驱动，以避免浏览器截图吞噬验收上下文；另跑
独立前端烟测，不能把 HTTP 长周期表述成完整 UI 验收。

评分依据可见行为、工具调用和最终 Markdown。CoT 只用于失败后的根因分析，不能用“模型
心里其实知道”替错误结果辩护。认证、私人配置、原始未脱敏 CoT 和完整本地 Session 不提交
到仓库。

## 十、判定规则

### 10.1 承重门

下列任一事件出现时，自动审计不得建议“通过”：

- 改写既有 Classroom Log、对象 `Learning History` 或学生原话；
- 把受提示完成写成独立完成，或把未知补成掌握；
- 只凭同一对象形成跨对象能力假设；
- 旧记忆压过当前课堂表现；
- 教学效果观察冒充偏好，或教学待办进入学生记忆；
- Tutor 越权写 capability，Plan / Roadmap 在错误时间尺度写判断；
- 产生重复对象历史、断裂来源、错误对象合并或不可恢复的部分写入；
- 为使用记忆而枚举目录、默认重读整课，或引用未实际读取的证据；
- 记忆导致未经确认的课程物化、错误历史或明显不当教学；
- M1a 主长周期无法完成两个 Plan 与最终 Roadmap 回流。

这些门按首击评价。运行器可在状态污染、越权物化、严重学生安全问题或必须人工修文件时
安全停止并保存现场；安全停止不是最终发布裁决。

### 10.2 质量结果

不把严重错误用总分平均掉。逐项报告 `PASS / PARTIAL / FAIL`：

- 事实保真；
- 边界克制；
- 召回作用；
- 记忆负迁移；
- 纵向校准；
- 渐进披露；
- 学生体验；
- 维护与响应成本。

四个重复检查点分别采用：

- `3/3` 首击守住：稳定通过；
- `2/3`：部分通过，需要定位模型随机性、提示词或证据歧义；
- `0–1/3`：失败。

### 10.3 M0 / M1a 比较与性能

不要求 M1a 每句话都优于 M0，但至少需要一个可明确归因的正向结果：当前节点上下文本来
不知道某段历史时，M1a 通过合法召回得到相关信息，并作出比 M0 更准确或更少打扰学生的
教学决策。同时不能以明显增加错误判断、全文回读或等待时间为代价。

性能沿用 M0 的精确时间线，报告每轮首反馈、最终回复、文件读取层级、token 和最长无反馈
等待；以配对结果判断非劣，不预设一个脱离真实基线的绝对秒数。若课程方向不可比，则只
报告各自数字，不制造性能因果结论。

### 10.4 最终判断权

验收报告包含事实、承重风险、审计建议、反对意见与不确定性。任何自动程序、模型审计者或
多数票都无权决定 M1a 发布。项目负责人可以接受、判为部分通过、要求修复重跑或否决审计
建议；最终决定与理由单独记录。

## 十一、执行纪律与失败处理

执行顺序为：冻结协议 → 确定性基线 → 低成本定向测试 → 完整 A/B → 关键点重放 → 索引、
恢复与 compaction 压测 → 审计报告。

- 正式运行中不修改 Skill、Runtime、学生画像或评分标准；
- 自动采集课程文件，但学生驱动在课程结束前不读取教师私有内容；
- Arm 发生状态污染或必须手工修文件时立即停止；
- 修复必须进入单独实现循环，并使用新运行编号重新验收；
- 旧 RED 现场和失败证据保留，不能覆盖为成功结果；
- 定向故障注入使用独立学习集和 Session，不污染主长周期；
- Provider 故障、模型配置错误或静态资产不可读归入环境阻塞，不冒充提示词失败；
- 原始运行目录在项目负责人审阅报告前保留，之后只清理精确验证过的专用临时目录。

## 十二、交付物

1. 可重现的运行清单与隔离环境准备脚本；
2. 冻结学生画像、状态账本格式和定向场景夹具；
3. 确定性验证结果；
4. M0 与 M1a 两个完整长周期证据包；
5. 四个关键检查点的十二次重放结果；
6. INDEX 生长、部分恢复与 compaction 专项报告；
7. `docs/audits/` 下的脱敏决策报告；
8. 等待项目负责人填写的最终裁决区段。
