# M2 桌宠皮套导入设计

**日期：** 2026-08-12  
**状态：** 已确认，待实现  
**范围：** macOS 桌面版；阿夏桌宠的本地 Live2D 皮套

## 1. 问题

当前 DMG 按隐私和授权边界不携带私有皮套，也不携带 Live2D Cubism Core，但 Tauri 仍然默认显示桌宠窗口。于是全新安装会看到一个“夏”字占位符：它既不是可用的桌宠，也会让用户误以为资源损坏。

现有皮套导入又只是开发者 CLI，并且首次导入依赖旧皮套目录里已经存在 Core。干净 App Home 因此无法完成第一次安装。

## 2. 产品结果

1. 没有完整可用的皮套时，桌宠窗口完全不显示；自由学习中的文字同学功能仍可正常使用。
2. 设置页明确显示桌宠状态，并提供“导入皮套”或“更换皮套”。
3. 学生通过原生选择器选择一个已解压的 VTube Studio 皮套文件夹。
4. 本机尚未安装 Cubism Core 时，再引导学生选择一次官方 SDK 中的 `live2dcubismcore.min.js`。
5. 导入成功后无需重启 StudyForge，桌宠自动刷新并显示。
6. 私有皮套与 Cubism Core 始终只存在于用户本机，不进入 Git、公开资源或 DMG。

## 3. 本阶段边界

- 第一版仅支持 macOS、单个角色 `peer-axia` 和已解压目录。
- 不支持 ZIP 解压、皮套市场、多角色管理、云同步或自动下载 Cubism Core。
- 这是内测能力。允许终端用户导入任意 Live2D 模型可能属于 Live2D 的 Expandable Application；正式公开前另行完成授权确认。
- 不改变阿夏的人格、语音、聊天触发或自由学习会话协议。

## 4. 所有权与数据位置

Runtime 已经拥有 App Home、皮套清单解析和静态资源读取，因此也拥有皮套状态判断、校验和安装。Tauri 只拥有操作系统窗口与原生文件选择器；React 只负责呈现状态和发起动作。

本地文件位置：

```text
<app-home>/
  runtime/live2d/live2dcubismcore.min.js   # 用户一次性安装的渲染组件
  actors/peer-axia/live2d/                 # 当前皮套
```

兼容现有安装：如果共享 Core 尚不存在，但旧皮套中已有有效 Core，Runtime 可在首次状态检查或更换皮套时复用它；不要求用户重新选择。

## 5. 运行状态

Runtime 对外只投影 UI 真正需要的状态：

```ts
type PeerSkinStatus =
  | { state: 'missing'; coreInstalled: boolean }
  | { state: 'installed'; coreInstalled: true };
```

损坏或不完整的目录对学生表现为 `missing`，诊断细节只进入本地日志。设置页不显示内部路径、错误码或堆栈。

Tauri 中的 companion 窗口仍作为固定 app window 声明，但初始 `visible: false`。主窗口连接 Runtime 后：

- `installed`：允许显示窗口；
- `missing`：确保窗口隐藏，并且不呈现占位符。

手动隐藏只改变窗口可见性，不改变皮套安装状态。

## 6. 导入流程

设置页的桌宠区是一条顺序流程：

1. 学生点击“导入皮套”或“更换皮套”。
2. Tauri 打开目录选择器；取消选择即安静结束。
3. 若共享 Core 已安装，React 直接请求 Runtime 导入所选目录。
4. 若 Core 未安装，页面显示“还需要安装一次渲染组件”，并提供“选择渲染组件”。学生选择 `.min.js` 文件后再提交同一次导入。
5. Runtime 在同一 App Home 内建立 staging 目录，验证 VTube Studio 清单、模型引用、显示信息、表情、动作、纹理和 Core。
6. 只有 staging 可被现有 manifest reader 完整读取后，才原子替换当前皮套。失败时当前皮套保持不变。
7. 成功后 Runtime 返回 `installed`；主窗口通知 companion 刷新皮套并显示窗口。

更换皮套只保留事务期间的回滚副本，不把无限增长的历史皮套留在 App Home。现有 `live2d.previous` 只作为旧版本兼容数据，不再成为首次或再次导入的前置条件。

## 7. 界面语言

未安装：

> 阿夏还没有皮套，所以现在不会出现在桌面上。

操作：`导入皮套`

缺少 Core：

> 还需要安装一次 Live2D 渲染组件。它只保存在这台电脑上。

操作：`选择渲染组件`

已安装：

> 皮套已经装好。隐藏后也可以从这里重新叫她出来。

操作：`显示桌宠`、`更换皮套`

用户可理解的失败：

- “这个文件夹不像完整的 VTube Studio 皮套。”
- “选择的文件不是 Live2D 渲染组件。”
- “皮套没有安装成功，原来的皮套没有变化。”

## 8. 实现切片

1. 将 companion 初始可见性改为 false，并删除无资源时的“夏”字占位符。
2. 把现有 CLI 导入逻辑提取为 Runtime 可复用模块，令 CLI 和本地 API 使用同一实现。
3. 将 Core 从皮套内部前置条件改为 App Home 级共享依赖，并兼容旧安装。
4. 增加皮套状态和导入 API；增加 Tauri 目录/Core 文件选择命令。
5. 设置页接入状态、两步导入、刷新和友好错误。
6. 让 companion 在皮套变更后重新加载表现资源并自动显示。

## 9. 验收

自动测试至少证明：

- companion 配置默认隐藏；
- 无静态头像和 Live2D 时不渲染文字占位符；
- 干净 App Home 报告 `missing`；
- 首次导入可使用单独选择的 Core；
- 已有共享 Core 时更换皮套不再要求 Core；
- 无效来源不会改变现有皮套；
- 设置页能呈现缺失、等待 Core、安装完成和友好失败；
- 打包检查继续拒绝私有模型、纹理、`.moc3` 与 Cubism Core。

真实桌面验收使用两个独立 App Home：

1. 干净 App Home 启动后看不到任何桌宠窗口；
2. 从设置页选择私有“水色小狗”目录与本机 Core；
3. 导入后桌宠立即出现，重启后仍能加载；
4. 再选择无效目录，确认当前皮套仍可用；
5. 检查 Git 与 DMG 内容，确认没有带入私有资产或 Core。
