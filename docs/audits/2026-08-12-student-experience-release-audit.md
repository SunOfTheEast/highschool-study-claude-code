# StudyForge 真实学生体验总审计

**日期：** 2026-08-12
**实现基线：** `0163fd8`
**状态：** 逐条复核完成
**用途：** 同时记录实现事实、产品判断、行为风险与发布优先级
**性质：** 角色扮演用于发现情境；代码与真实运行用于核实系统；产品判断不以真人数据为唯一许可

## 一、本轮方法校正

上一版从“把角色扮演当成事实”摆到了另一个极端：凡是没有真人证据，就只允许继续取证，
不允许作产品判断。这同样不对。

本审计现在把三件事严格分开：

1. **事实核验：** 当前系统究竟有什么、缺什么、怎样运行；
2. **产品判断：** 这个事实是否值得改变，什么边界最干净；
3. **行为判断：** 学生是否真的会停住、误解、放弃，以及影响有多大。

缺少真人数据，只限制第三层的措辞，不取消第二层。搜索框、Markdown 预览、可读字号、可点击
标签、公开保存结果这类低成本、可逆、符合第一直觉且不改变学习事实所有权的改进，可以直接纳入。
真人数据主要用于排序、校准细节和验证结果，不是每个按钮的准生证。

相反，以下决定仍需要更强证据或独立设计：引入新的持久事实、改变事实所有权、扩展 schema、
自动替学生作学习判断、跨学习集合并画像、建立高成本阅读器或移动端，以及任何学习效果声明。

### 1.1 决策门槛

| 情形 | 需要的最低依据 | 本文怎样处理 |
| --- | --- | --- |
| 可复现功能错误或设计自相矛盾 | 代码、测试或真实运行 | 直接列为缺陷并修复 |
| 低成本、可逆、不改变学习事实所有权的显然可用性改进 | 实现事实 + 清楚的产品理由 | 可以直接纳入，完成后验证 |
| 对学生行为、频率或流失的推测 | 模拟只能提出假设，真人使用才可确认 | 保留为风险，不冒充已发生事实 |
| 新所有权、schema 或高成本子系统 | 现有边界核验 + 独立设计 + 与成本相称的证据 | 不在小修中顺手扩张 |
| 掌握、迁移、提分等学习效果 | 真实学生的持续数据 | 不由界面完成或模型自评宣布 |

核心原则是：**证据约束我们怎样说，也帮助我们排优先级；它不替代产品常识。**

## 二、证据记法

| 来源 | 能证明什么 | 不能单独证明什么 |
| --- | --- | --- |
| 真人反馈 | 某位真实使用者在特定情境中的行为、原话或困难 | 普遍频率、最佳修法或学习效果 |
| 真实运行 | 当前 DMG 或真实模型链路出现过某个界面、耗时或错误 | 学生怎样理解它、是否因此流失 |
| 代码核验 | 当前实现存在或缺少某个行为、字段、入口或约束 | 某种行为影响已经发生 |
| 模拟推演 | 一个内部一致、值得测试的使用情境 | 真人已经这样做过或问题很普遍 |
| 产品判断 | 在目标用户、成本、可逆性和架构边界下作出的取舍 | 取舍已经产生预期效果 |

“小林”“小周”“念念”等角色材料仍是模拟推演；同一模型扮演多个学生也不构成多个独立真人
证据。但只要它指出的实现事实核验成立，就可以继续做产品判断，不必把所有结论退回“等待观察”。

目前唯一明确记录的真人界面反馈，是知识图谱左右区域边界对比不足；已修复，见 C-08。

## 三、总判断

StudyForge 已经形成自由学习、正式课程、学习资产、对象记忆、关系图、日历、专注和复习闭环。
当前发布收口不需要再发明一套大系统，而要完成三类工作：

1. **首日可进入、可理解、可信任：** 修复 OAuth 后模型仍为空的组合路径，公开本地保存与模型
   处理边界，真实 DMG 的失败状态不能泄露内部实现；
2. **已有能力在使用现场可见：** 资料架能直接找，保存结果说清楚，Material 不要求学生输入
   canonical locator，Note 能预览，资产关系在详情页也能进入，高阶教学方法有自然示例；
3. **两项结构债单独收口：** 复习 Session 从“批量注入全文”改为“轻量索引、按需读取”，并把
   数学教学内核拆成真正通用的核心与按需学科方法。

学生价值必须在三个时间尺度都成立，不能只承诺“三个月后老师更懂你”：

| 时刻 | 学生的问题 | StudyForge 应给出的价值 |
| --- | --- | --- |
| 第一次 | 为什么不直接问普通聊天模型？ | 找到我真正卡住的位置，讲透边界，再让我自己完成一步 |
| 下一次 | 为什么还要回来？ | 不必重新介绍，从上一次真实停下的位置继续 |
| 长期 | 为什么不问完就丢？ | 对话长成可查、可改、可联系、可复习的资产，教学判断仍能回到证据 |

第一天横评仍然要靠教学深度赢，但复核证明 Free Learning 已经能根据学生表现追问、暂定卡点、
给小检验并校正，不需要复制 Roadmap 的诊断仪式。发布门应是普通学生语言下的真实模型首击，
不是再增加一个同名诊断 Skill。高阶能力的可发现性则是独立的界面问题，应该补。

## 四、开放发现与处理结论

### E-02 【确认缺陷｜发布前修】OAuth 后推荐模型没有回填

- **实现事实：** 全新 App Home 中，OAuth 前模型目录为空；OAuth 成功后目录会刷新，但
  `ModelSettings` 的 `draft` 只在组件首次挂载时初始化，主教师与 Scout 的推荐模型不会随新目录
  回填。已连接后进入设置的路径则能正常预填；
- **产品判断：** 这是状态同步缺陷，不需要等学生真的卡住才修。OAuth 成功后应在尚未被用户
  手动修改的字段中自动填入 Sol / Terra 推荐值与 `high`，让主路径直接完成；完整模型选择继续
  放在高级设置；
- **验收：** 用全新临时 App Home 覆盖“目录为空 → 页面内 OAuth → 两项自动出现 → 完成设置 →
  进入首页”的同一条 E2E，而不是分别证明前半段和后半段。

### E-04 【明确改进｜纳入】资料架需要自己的查找与筛选

- **实现事实：** `/knowledge` 已能搜索标签、带标签 Note / 题卡标题和 519 张 legacy 题卡；因此
  “学生没有搜索”是错误表述。真正缺少的是资料架内的就地查找：`/assets` 没有关键词或标签
  筛选，Material、Note 正文和多选后的继续操作也不在图谱搜索路径里；
- **产品判断：** 学生不应先理解知识图谱，才能在自己的资料架找东西。资料架增加本地关键词与
  标签过滤是显然有用、可逆且不新增持久事实的功能，直接纳入；
- **首版边界：** 覆盖标题、可见正文、来源名与标签，保留筛选后的多选；不做语义排名、推荐流
  或用户画像。519 卡规模下要有性能回归，不能恢复首页曾经的全量重解析问题。

### E-05 【明确改进｜纳入】默认加入复习是既定语义，但保存结果必须公开

- **实现事实：** 新 Note / 题卡确认保存后，会在同一事务中加入复习并于次日首次到期；Material、
  旧 Note 和未做过的 legacy 题卡不会被批量加入。学生可以在详情页移出或重新开始；
- **边界校正：** “保存即负债”是角色对默认语义的评价，不足以推翻已经确认的 M2 设计。当前
  真正的界面缺口，是草稿、确认和成功回执都只说“保存”，没有公开同时产生的复习排程；
- **产品判断：** 保留默认加入，在成功回执中直接写明“已加入复习，明天首次出现”，并提供去
  资产详情调整的自然路径。是否以后拆成“先存着 / 以后考我”两个选择，留给真实使用数据，
  不在这次小修中改变事实语义。

### E-06 【确认架构边界｜单独收口】候选数量不应等于全文注入数量

- **实现事实：** 日历如实显示全部到期候选；当前默认勾选全部，并把所选资产全文静态注入
  Free Learning。受管上下文最多接受 12 项，因此同一学习集 13 项以上时，主行动会直接触发
  `SELECTED_CONTEXT_LIMIT_EXCEEDED`；
- **产品判断：** 不规定“每天只能五张”，也不改写原始到期事实。候选可以完整显示，学生决定
  本次处理多少；进入 Session 的应是轻量索引，教师轮到某项时再读取正文。这样队列规模与模型
  上下文规模解耦，也符合已经采用的渐进式披露；
- **仍需数据的部分：** 正常队列究竟多大、默认勾选多少最舒服，是界面调校问题。角色故事中的
  “47 张悬崖”不是实测分布，不能据此硬编码五张；
- **验收：** 13 项以上不能落入通用失败；验证索引内容足以让教师选取下一项，且正文只在需要时
  读取，不通过简单提高全文上限掩盖问题。

### E-07 【合理风险｜先做真实走查】赴约信息只对教师可见

- **实现事实：** `appointment-opened` 以 `triggerTurn: false` 进入 Session，避免仅打开页面就
  自动花费一次模型调用。约定标题、时间和时长只在教师可见 Custom Message 中；首次 Free
  Learning 可能还没有师生消息，但页面有空状态和输入提示；
- **行为假设：** “学生盯着空白十几秒”来自角色扮演，不是 DMG 事实；但在没有师生消息、教师
  不自动开口、约定信息又不可见的组合下，学生不知道是否已经进入正确约定，是合理风险；
- **产品判断：** 暂不改成自动触发教师 turn。先用真实 DMG 走查 Plan、带资产 Free Learning、
  无资产 Free Learning 三条赴约路径；如果空状态不够，优先静态投影既有约定标题和时长，而非
  引入新的 Session 行为或把“打开”记成学习。

### E-08 【确认缺口｜纳入】本地保存与模型处理边界没有说清

- **实现事实：** 学习集文件、资产、记忆与 Session 的权威副本保存在本机；学生发消息时，
  当前消息、相关 Session 历史及完成本轮回答所加载的上下文会交给所选 Provider 处理。系统不会
  因此无条件上传整个学习集；
- **产品判断：** First Run、模型授权与帮助页应该用同一套学生语言说明“什么留在本机、什么在
  对话时交给你选择的模型服务”。这是信任边界，不需要先证明学生已经误解；
- **边界：** 不承诺“内容从不离开设备”，也不误写成“整个学习集都会上传”。首次进入只给短
  说明，详细信息在帮助页展开。

### E-09 【明确改进｜先补最小人类入口】不要让学生输入 canonical locator

- **实现事实：** M1c 将 Material 定义为不可变来源资产，而不是完整阅读器；资料导入、精确
  locator 读取和带入 Free Learning 的机械闭环已经成立。当前页面却要求学生在“高级定位”中
  手工输入 `page-0062` 一类内部定位符，且没有前后翻页、打开原件或多段选择；
- **产品判断：** canonical locator 应由界面翻译和维护。首版提供人类页码/段落定位、上一处 /
  下一处和打开原件，问老师时静默绑定 canonical locator。这个判断不需要等待学生亲口要求；
- **范围边界：** 内嵌 PDF 阅读、目录、框选、批量导入与书籍蒸馏是后续独立子系统，不把它们
  混进当前小修。真实教材走查用于决定下一步先做哪一项，不用于决定是否隐藏内部定位语法。

### E-10 【拆分处理】预览、内容历史与标签治理不是同一个需求

- **实现事实：** Note / 新题卡已有不可变 revision，学生页只读最新版并显示“第 N 版”；Note
  编辑器没有同步 Markdown 预览；标签可见但只读，服务端已有写入接口；
- **A——Markdown 预览：纳入。** 编辑 / 预览切换是低成本、无新事实的编辑器基本能力，直接做，
  不等真人先保存错一次；
- **B——内容历史：纳入。** 提供按时间排列的只读旧版本与返回最新版。名称必须是“内容历史”
  或“历史版本”，不能叫“过去的我”或“认知演变”；revision 记录的是资产内容与来源，不是学生
  掌握情况；
- **C——标签治理：另立设计。** 现有标签由模型选择、Runtime 绑定，core / related 还承担检索
  语义。直接开放编辑、合并同义词或批量改写会改变责任边界，不能借已有 API 顺手暴露。先收集
  真实错误标签与同义分裂，再决定是学生纠错入口、词表建议还是归并机制；
- **结论：** 前两项不是因为“尚无证据”而搁置，第三项也不是因为“学生不懂”而永远封闭；三者
  只是成本与所有权不同。

### E-11 【明确改进｜纳入】关系能力应进入资产阅读现场

- **实现事实：** 知识图谱已经根据共享标签推导邻居并最多返回 6 项；`AssetTags` 也预留了
  `onTag`，但 Note / 题卡详情没有传入，所以标签不可点击，详情页也不投影邻居；
- **产品判断：** 标签点击后进入以该词为中心的图谱；详情页显示最多 2–3 个共享标签的相关资产。
  这是把已有关系投影到需要它的现场，不新增关系事实，也不需要等学生先迷路；
- **语义边界：** 只能说“共享 ×× 标签”或“共同出现”，不能写成相似、先修、因果、推荐或掌握。
  不在详情页重建整张图。

### E-12 【确认结构缺陷｜独立改造】常驻教学核心混入数学与 Lesson 责任

- **实现事实：** Free Learning 和课程 Session 都无条件加载 `math-teaching-core.md`。文件既有
  跨学科通用原则，也有“mathematical understanding / mathematical truth”等数学措辞，以及
  “写入当前 Lesson Block”这一只属于正式课堂的记录指令；
- **产品判断：** 这不是必须等语文学生抱怨才承认的问题。常驻核心只保留通用教学判断：看学生
  表现、最小帮助、归还独立动作、诚实记录、学生决策权。Lesson Block 写入移回 Lesson Skill；
  数学特有判断进入按需数学 Skill。其他学科先由 `LEARNING_GUIDE.md` 形成气质，以后再增加按需
  方法，不先建复杂学科枚举和路由器；
- **验收：** 同一模型分别跑数学、化学、历史材料辨析和语文文本细读，检查首击和连续对话；这
  用来验证拆分效果，不是缺陷成立的前置许可。

### E-13 【范围校正｜纳入一项】足迹应补直接复习结果，不收录一切 M2 事件

- **实现事实：** 直接翻卡会产生 canonical `reviewed` 事件，但足迹没有读取 asset review 历史；
  专注计时和赴约打开也未进入足迹；
- **产品判断：** 只补有效的直接复习结果，例如“复习了 Ksp 题卡 · 没想起 / 吃力 / 顺利”，
  并链接资产；更正事件应更新原条目。`enrolled`、移出、重启和到期管理不是学习活动，不投影；
- **明确不做：** 专注计时只能证明计时器运行，不能证明专注；赴约打开也不等于学习。它们不应
  成为独立足迹条目，后续若需要，只能作为已有 Session 的附属信息。原结论“补全全部 M2 活动”
  已撤回。

### E-14 【明确改进｜纳入】最小字号与阅读比例需要收口

- **实现事实：** 正文和教师消息大多为 16px，但 11px / 12px token 被广泛用于真实说明、状态和
  控件；应用没有标准 / 大字偏好，也没有主要页面在放大后的回归；
- **产品判断：** 正文不低于 16px，重要按钮和标签不低于 14px，辅助说明不低于 13px；11px /
  12px 只保留给可被其他信息完整替代的装饰文字。增加标准 / 大字的根级 token 比例，而不是
  `transform: scale()` 整页放大；
- **验收：** 课程三栏、知识图谱、日历、资产阅读和设置页都要在两档下完成桌面走查；对比度、
  键盘焦点与字号分开检查。角色故事中的“系统缩放已经破坏布局”仍不是实测事实。

### E-15 【明确改进｜纳入】高阶学习方法需要自然语言入口

- **实现事实：** Skill 已有头脑风暴、知识重组、结构对照、主张挑战、检索练习和论文研究，
  但 Free Learning 空状态与帮助页只给普通问答示例；路由依赖学生先表达出相应意图；
- **产品判断：** 不能要求学生主动发现一个他不知道存在的能力。空状态和帮助页加入少量普通
  说法，点击只填入输入框、不自动发送，例如“先别告诉我答案，看看我到底卡在哪”“把这个和
  以前学过的联系起来”“不要顺着我，找找哪里可能不成立”“这两个概念真正差在哪”“看看有
  没有相关研究”；
- **边界：** 不创造“攻击模式”等持久状态，不把内部 Skill 名称展示给学生，也不把每次对话
  强行拉成长流程。真人使用用于观察哪些例子有用并删减，不是增加入口的前置条件。

### E-16 【发布验收项｜不是已确认泄露】当前错误隔离已有系统性基础

- **历史事实：** 旧 DMG 曾暴露 `API_ERROR`、`ResolveMessage`、`meta:<uuid>` 和内部 Session key；
- **当前复核：** 当前代码已通过 `publicErrorText`、Session 投影清洗、工具详情隐藏和桌面状态
  映射隔离大部分内部信息。针对公开错误、主要对话入口和 Peer 投影的定向测试为 18 / 18 通过；
  本次没有找到当前版本仍会稳定泄露这些标识的路径；
- **真实缺口：** 完整 DMG 的失败状态尚未全线验收；日历创建、修改、删除和打开等异步操作没有
  统一的可见失败反馈，失败时更可能表现为“点击没反应”，而不是泄露内部错误；
- **产品判断：** 发布前按入口注入授权、网络、文件缺失、revision 冲突和 Runtime 失败，学生端
  只显示可行动的通用信息，原始细节留内部日志。失败反馈应复用统一边界，不在每个组件堆一套
  防御代码。

### E-17 【真实性能风险｜小修后测】等待进度需要去重并说真话

- **真实运行：** 一次验收中，普通教学回应约 19–38 秒、记忆固化约 57 秒、Roadmap 方案约
  112 秒、Plan 物化约 87 秒；等待期间主要重复“老师查看了相关内容”。这些是一次特定模型、
  提示词和机器的观察，不是稳定 P50 / P95；
- **产品判断：** 不建复杂进度系统。先把重复状态合并，并依据已经发生的真实阶段投影少量不同
  文案，例如“正在回看你的学习记录”“正在查找合适材料”“正在整理课程安排”；不显示虚假
  百分比，不让模型额外生成进度；
- **验收：** 固定机器与 Sol / Terra high，分别测普通问答、记忆写入、Roadmap、Plan、Lesson
  备课和 Scout 检索，记录首个有效反馈、总耗时和工具阶段。真人是否因此离开仍是待验证影响，
  但重复状态本身已经值得小修。

### E-18 【重大产品方向｜另立设计】书籍来源能力尚未成为学习主路

- **实现事实：** First Run 已有空白、复制导数示例和打开已有学习集三条入口，因此“学习集只能
  从空白生长”不成立。M1c 也已经支持导入 Material revision、精确 locator、资产 pinned sources、
  反向来源与跨来源标签，并明确写过“导入一本化学书，慢慢长成学习集”的情境；
- **真正缺口：** 这些能力仍是分散功能。书目前主要表现为可上传、搜索和定位的 Material，首页
  与首次进入没有把“沿着一本书学”解释成主路；来源目录、原文胶水、由该位置形成的资产以及
  从资产回到原文，也没有组成一条学生可见闭环；
- **产品判断：** 书是来源主干，学习集是建立在一本或多本书之上的个人联系层。原书保留内容、
  编排顺序与过渡文字；Note / 题卡通过准确 sources 生长在原文位置上；平坦标签连接跨书语义；
  教师结合记忆作个性化取舍，复习阶梯只负责保温；
- **边界校正：** 不因这项发现立刻增加 Flashcard、错题本、作品和套卷等新 schema；不把书序
  冒充先修 DAG，也不把多书重复出现冒充“共识”或重要性。现有 Note、题卡、Material、sources
  与 tags 先承担第一阶段闭环；
- **下一步：** 独立设计见
  `docs/superpowers/specs/2026-08-12-source-first-learning-set-design.md`。首个垂直验证只做“导入一本
  有可信目录的书 → 选择一节学习 → 保存带准确来源的资产 → 双向回到原文”，不阻塞当前发布
  小修，也不顺带建设完整阅读器、整书自动蒸馏或精选市场。

## 五、撤回或收窄的结论

### W-01 “自由学习没有装载诊断能力”——撤回

- **原推断：** Roadmap 有现场短诊断 reference，Free Learning 没有同名文件，所以第一晚没有
  定位学生卡点的能力；
- **复核结果：** 这是把文件名当能力边界。Free Learning 常驻教学核心与根 Skill 已要求保留
  正确局部思路、定位真实停止点、在需要时追问或给小检验，并有知识重组、主张挑战和检索练习
  支撑判别；
- **真实模型反证：** M2 的“惰性气体时总会乱，也说不清卡在哪里”情境中，模型在 3.9 秒出现
  首个回应、16.4 秒完成：先暂定总压 / 分压混淆，再以恒容 / 恒压两问缩小问题，没有读取专门
  诊断 reference，也没有强迫保存或套流程；
- **处理：** 不新增共享诊断 Skill。保留这类首击情境作为发布级教学验收。Roadmap 的独立协议
  继续负责长期路径判断、轻量同意和记录边界，不能原样搬进自由学习。

### W-02 “首页不知道今天”——撤回绝对表述，保留低优先级产品候选

- **实现事实：** 当前学习集首页已经把进行中的 Lesson 设为主行动，也列出最近自由学习；全局
  专注在页头，约定和到期复习在一级导航的日历中；
- **校正：** 因此不能把“首页没有聚合日历内容”写成“学生不知道下一步做什么”。应用级“今日”
  聚合仍可能有用，但会重复现有入口并牵涉跨学习集切换；
- **处理：** 不作为当前发布缺陷。以后可以按日常回访体验设计，不是因为没有真人证明就禁止，
  而是其边际价值目前低于 OAuth、搜索、可读性和失败反馈。

## 六、暂缓范围及其真正理由

以下事项不是“没有真人证据所以不准做”，而是当前有更具体的范围理由：

- **违背产品纪律：** 深夜主动劝睡、自动面向家长下结论、跨学习集合并认知画像；
- **独立大子系统：** 完整 PDF 阅读与框选蒸馏、批量书籍导入、音频 Material、移动端；
- **先要所有权设计：** 标签合并与批量改写、Topic / 文件夹 / 弱项夹、legacy 题卡派生编辑、
  图片或手写 Note；
- **可在后续体验迭代：** 阿夏投影既有日历 / 专注提醒、教师提议下一次约定、考试日期语境、
  面向学生本人的阶段回望和应用级“今日”聚合。

它们都可以继续讨论；只是不能借一次角色故事绕过架构边界，也不应挤占当前发布收口。

## 七、发布顺序

## 九、后续取证规则

1. **真实模型验收**只能证明当前模型与提示词组合的行为，不证明学生喜欢或学习有效；
2. **真实学生内测**优先观察行为：是否完成、在哪里停、说了什么、何时退出和是否再次回来；
3. 不把学生在引导下复述测试脚本当成自然需求；
4. 不把“模型最终纠正了”算首击通过；误诊、越权或靠学生提醒修正要单独记录；
5. 低成本、可逆的可用性改进可以先做再验证；不得把“还没做真人 A/B”写成禁止实施；
6. 新证据到来时分别更新实现事实、行为影响和优先级；只有证据推翻了产品前提时，才重开已经
   明确的边界判断；
7. 已关闭问题重新出现时，从附录移回正文，并记录新的实现基线和复现条件。
