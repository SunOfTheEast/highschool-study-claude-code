## 一、执行结论

M1a 的核心架构已经真实跑通：M0 与 M1a 都完成了
`Roadmap → Plan 1（三课）→ Plan 2（两课）→ Roadmap`，七个定向机制用例均通过，四个关键
决策点各三次独立重放的核心判断均为 `3/3`。旧 Trace 保持不可变、纠正采用追加、能力假设受
跨对象门槛约束、正负召回能够区分、INDEX 能分桶生长，原生 compaction 后也能从 INDEX 重新
恢复证据链。

记忆还产生了至少一个可明确归因的教学收益。在 DC-04 中，当前课堂本身不知道旧表现的帮助
程度；M1a 在先取得当前证据后，沿 `INDEX → 对象 L1` 读到“旧表现曾受提示”，因此把当前复现
解释为“再次出现、但尚不能称为稳定习惯”，而不是重新询问学生或误判成长期能力。表面相似但
错因不同的对照场景没有读取记忆，说明收益不是靠无差别召回获得的。

初稿曾把第三课中的“隔课”“与前课隔开”“延时混合检验”归因成 M1a 制造了时间事实；回看完整
调用顺序后，这个归因不成立。学生先明确说“今天先停在这里，下一次直接做收口检验”，Plan 也按
“下一次”准备了 Lesson；随后验收运行器在学生再次说“下一次直接开始”后仅 15.9 秒就启动了该
Lesson。也就是说，验收协议一边要求系统把它当作下一次课，一边又没有模拟真实间隔。Lesson、
Plan 和记忆继续沿用上游已经写入的时间语义，是来源继承，不足以证明记忆系统自己捏造了时间。

因此，这段证据对“延迟保持”只能判为 **NOT EVALUABLE**：它既不能证明学生经历间隔后仍保持，
也不能据此判 M1a 的记忆语义失败。真正需要修正的是验收协议——要么提供可核验的真实时间间隔，
要么把任务诚实写成紧邻 Session 的迁移检验；不能让测试程序左右互搏后再把矛盾归到记忆层。

第二项主要风险是代价。M1a 的典型首反馈没有变慢，但五次课末固化分别耗时 83.1—144.6 秒，
而 M0 的对应收尾为 9.8—22.6 秒；M1a 全周期原生 usage 的 `totalTokens` 合计高 25.1%，写工具
调用高 120.8%。机制可以工作，但当前固化路径对学生等待和运行成本都偏重。

因此，本轮应解释为：**记忆语义与恢复机制成立；真实延迟保持没有被这份协议检验；旧课末固化
路径的等待与工具扇出仍需优化。** 本报告维持 PARTIAL，是因为性能项和时间场景的证据缺口，
不是因为 M1a 已被证明会制造错误历史。

## 三、完整生命周期与终态

两条 Arm 都完成了相同的生命周期规模：

```text
空 Plan Tree
→ 与学生讨论并确认 Plan 1
→ 准备、上完、关闭 3 节 Lesson
→ 学生确认 Plan 1 完成
→ Roadmap 回流并确认 Plan 2
→ 准备、上完、关闭 2 节 Lesson
→ 学生确认 Plan 2 完成
→ Roadmap 最终校准
→ 学生选择暂不开 Plan 3
```

M1a 终态形成：5 条课末 Trace、1 个对象文件、1 个对象桶、1 个明确偏好文件、0 个能力文件。
五条课堂痕迹都被压缩进“含参数方程的表示与根数选路”这一对象；对象内部保留了从提示后完成、
紧邻迁移，到复杂任务中一次独立构造比较对象的流变。课后负担偏好只覆盖近期课后安排，没有
外推到课堂题量、长期训练量或挑战难度。

自然周期没有生成能力文件是克制的结果，而不是缺件：这些证据都被模型归为同一知识对象，按
现有门槛不能据此写跨对象能力假设。另一方面，这也暴露了仍需真实数据验证的对象粒度问题：
“含参数方程的表示与根数选路”可能是合理对象，也可能过宽到吞掉本应分开的知识对象。本轮不能
只凭文件数量替模型作出拆分结论。

终验后使用产品真实 `readCourseTree` 解析了正式 Arm、定向用例、重放及其快照中的 66 份课程树，
全部通过；记忆 Markdown 相对链接与标题锚点无断裂，单个学习集内 Trace ID 无重复。M0 终态
仍为 0 份记忆 Markdown，M1a 自然终态仍为 0 份能力 Markdown。

| 用例 | 结果 | 首击证据 | 限制或反对意见 |
| --- | --- | --- | --- |
| DC-01 一次事件关联多对象 | PASS | 一条 Trace 同时链接两个预置稳定对象；无能力、偏好或复制事实。 | 最初自然夹具被合理合并为一个复合对象，未构成正式失败；加入两个稳定对象身份后首个正式尝试通过。 |
| DC-02 学生纠正 | PASS | 追加第二条纠正 Trace，旧 Trace/Log 字节不变；对象判断改为“受提示”。 | 无承重异议。 |
| DC-03 部分写入恢复 | PASS | 新 Session 只补对象与 INDEX 路由，不重复来源 Trace，不扫描目录。 | 一次缺失对象读取和一次本地写尝试失败后在同一目标恢复。 |
| DC-04 召回正反例 | PASS | 正例先看当前步骤，再读 INDEX 与对象 L1；负例只处理当前因式分解错误，完全不读记忆。 | 正例停在 L1 而未读 Trace，原因是 L1 已足够，不是证据缺失。 |
| DC-05 能力门槛与反证 | PASS | 同对象无能力文件；两个不同对象后建一条有范围假设；第三对象独立成功后追加校准并保留两个旧提示证据。 | 前两个手工夹具的 `initial/` 快照目录误留空；原生首轮 read 和工具流仍保留输入，第三分支有完整前后快照。 |
| DC-06 INDEX 生长 | PASS | 30 个历史对象、7 个桶、2 个当前对象下，根 INDEX 846 字节、9 个链接；30 个旧对象和 6 个无关桶字节不变。 | 为判断归类额外读了一个相邻桶，但没有读历史对象或其余五桶；时间仍只能写“未记录”。 |
| DC-07 原生 compaction 恢复 | PASS | 真实产生一次 Pi compaction；下一轮重新读 INDEX、相关对象及其来源 Lesson，记忆文件保持不变。 | 上下文压力由 320,000 字符的隐藏惰性消息合成，不等同自然教学历史；单条超大消息使压缩后仍残留较高上下文。 |

DC-07 的 compaction 条目记录 `tokensBefore: 220223`，摘要长度 2,553 字符，摘要调用 usage 为
109,827 tokens。恢复轮只沿一个相关对象的来源链读取，保留了“旧表现受提示，新任务检验独立
触发”的边界。Pi 的切点仍保留了第二条超大惰性消息，使恢复轮 context usage 为 113,568；这
说明恢复语义正确，但超大单轮输入不是 compaction 能完全消除的负担。

中，M0 读取 3 份 Lesson，M1a 读取 2 份记忆文件而不读 Lesson。它说明压缩层能够减少父级为
普通决策回溯课堂全文，但由于两边写出的课程不同，只作为操作证据，不制造“记忆必然更快”的
因果结论。

### 7.2 可明确归因的收益

真正满足设计中“当前节点原本看不到历史”的对照证据来自 DC-04：

| 条件 | 当前事实 | 历史读取 | 教学判断 |
| --- | --- | --- | --- |
| 相关旧经历 | 当前再次漏写约束，且学生询问是不是反复问题 | INDEX → 对象 L1，读到旧次为提示后完成 | 说明“此前有一次提示后经历、当前再次出现”，但不升级为稳定习惯。 |
| 仅表面相似 | 当前是因式分解本身错误 | 不读取记忆 | 直接修复当前代数错误，不让旧边界记忆污染判断。 |

这组正反例共享相同初始记忆树，记忆文件前后哈希不变。收益来自合法读取到的历史帮助程度，
而不是模型在当前对话中重新猜测学生画像。

## 十一、主要缺陷与发布前建议

### 11.1 必须先解决：时间验收协议与机械记录时间

Runtime 只负责提供每条新 Trace 的机械记录时间，不替模型判断“保持”“延时”或教学意义。验收
协议则必须诚实区分两种场景：立即换 Session 只能检验紧邻迁移；真实延迟保持必须有可核验的
时间间隔。仅有新的 Session ID 或学生口头说“下次”，都不能同时充当物理间隔的证据。

后续至少重跑“立即换 Session”和“真实可核验间隔”两个分支，并检查 Lesson、对象记忆、Plan
总结和 Roadmap 是否使用同一组可见事实。这里要修的是测试输入和事件时间，不给模型叠加同义词
禁令，也不把“是否算保持”这种语义判断交给 Runtime。

### 11.2 优先优化：课末固化的工具扇出

保留模型对“写什么、边界到哪里”的判断，但把稳定的追加 Trace、更新对象、桶和 INDEX 组合成
更紧凑、可校验且可恢复的写入路径，优先考虑 Runtime 辅助的原子固化。目标不是减少必要判断，
而是避免模型为同一个已形成判断反复读取、编辑和确认多个 Markdown 目标。

优化后应重新测五次连续课末收尾，比较最终时间、工具数、usage、重复 Trace 和部分失败恢复。
当前数据不足以规定一个脱离产品体验的硬秒数，但 83—145 秒的稳定收尾成本不应被当作正常值。

### 11.3 继续观察：对象粒度与真实学习效果

下一轮应让课程自然跨到两个真正不同的知识对象，再看模型是否仍把它们吞进一个宽对象，或能在
有足够证据时建立、校准能力假设。StudentSim 只能验证工具和教学判断稳定性，不能证明学生真的
形成了长期记忆；延迟保持、迁移和学习效果仍需真实学生纵向数据。

如果时间协议得到有效复验、固化成本显著收敛，并在一次完整两 Plan 复验中不出现新的承重错误，
M1a 才具备重新评估整体 PASS 的条件。七个已经通过且未受实现改动影响的机制用例无需为了形式
全部重跑；应按实际改动面选择时间保真、固化恢复、关键召回和完整周期复验。

## 十二、证据局限与保留意见

- 两个长周期的课程方向自然分叉，不能把所有差异解释成 M1a 的因果收益；
- StudentSim 的知识变化是冻结协议下的验收状态，不是真实学生学习效果；
- 正式长周期走 HTTP/事件流，只有独立前端 E2E，不是整段浏览器操作验收；
- 自然周期没有触发 Scout，也没有触发 compaction；两者分别只能由既有 Scout 验收和 DC-07 说明；
- DC-07 使用惰性合成压力，证明原生压缩与恢复链，不证明自然 220k 教学历史的质量；
- DC-05 前两个手工夹具缺初始目录快照，虽有原生 read/tool 证据，证据完备性低于第三分支；
- 本轮没有真实等待课间，却先让学生和 Plan 把任务约定成“下一次”，随后 15.9 秒后启动新 Lesson；
  该场景只能暴露协议矛盾，不能用于评价真实延迟保持，也不能单独归因给记忆层；
- usage 合计包含 cache read，且两边回合数、题目和文件内容不同，只能作为运行负担而非价格估算；
- 原始运行证据保留在本机仓库外，没有把认证、Session ID、完整学生作答、工具载荷或 CoT 提交。
