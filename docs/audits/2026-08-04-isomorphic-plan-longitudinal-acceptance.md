# 同构学习目标长程真实验收

日期：2026-08-04

## 结论先行

本轮完整跑通了一个真实的三级学习周期：Roadmap 从学生的自然需求中形成首个
同构 Plan，Plan 连续组织六节 Lesson，六节课全部关闭，Plan 最终完成，Roadmap
重新读取 Plan 与六份原始 Lesson 后更新当前位置。三层 Session 没有复制彼此聊天，
课堂事实只保存在 Lesson Block 中，父节点依靠普通 `read` 恢复历史。

因此，M0 的最小架构结论是：**Roadmap → Plan → Lesson + Block-local Classroom
Log 已经足以支持一次连续、可恢复、会随课堂结果调整的教学周期。** 这条主链通过。

但本轮不是全绿。最终事实虽然正确，仍有五个需要继续处理的真实问题：

1. 17 个 problem Block 的 `Uses` 全部为空，题目内容虽来自真实题卡，却没有保留
   可机器回溯的卡片路径；
2. 明确的独立检验先被 Coach 公开剧透，重备后 Tutor 又在第二、三题前给出不同
   程度的方向提示；
3. Lesson 006 的 Tutor 越权把顶层 `status` 从 `active` 改成 `closed`，与学生界面
   的关课生命周期冲突；
4. 六个 Tutor Session 共出现 19 次 `edit` 失败，Classroom Log 的列表格式也三次
   阻塞关课，模型都恢复了，但过程仍然毛躁；
5. 七次备课共启动 20 个 Scout，单路平均耗时 224.2 秒，学生常见等待仍为
   3–5 分钟。

综合判定：**功能闭环通过，教学主线通过，带重要残余问题通过（pass with material
residuals）**。没有发现最终事实损坏或无法恢复的 P0；上述问题按实际产品体验属于
P1，不能因最后恢复成功而忽略。

## 学生角色边界

验收者模拟的是基础较好、尚未形成同构视角的高中生。开场只说自己的真实需求：
基础求导和常见单调性会做，但指数、对数和不同层级的式子混在一起时看不出入口，
容易先硬算。

此后学生只回答自己的理解、尝试、困惑和选择，没有指定：

- “同构 Plan”或任何方法名作为课程目标；
- Lesson 类型、教学模板、课数或 Block 数；
- 题卡、Scout、工具、文件读写或生命周期动作；
- 下一节必须怎么备、老师必须怎么教。

中途有两次学生纠正教师，但内容都是普通学生可以自然发现的课堂事实：独立检验
已经被提前说出路线，以及 Tutor 在题目前说的话已经帮助排除了一条路线。这不是
用 QA 术语指挥系统。

## 从自然需求到第一份 Plan

Roadmap Session 先介绍学习集的用途，再逐步追问学生“混在一起”具体指什么、通常
先做什么、想获得怎样的变化。学生描述自己会机械求导，但缺少求导前的结构判断。
Coach 随后读取方法图谱，提出把首个阶段放在同构变形上，理由是它能直接训练
“把指数、对数和参数压进同一个函数外壳，再用单调性比较”的视角。

首个 Plan 不是验收者点名的。Coach 自己形成了：

- Stage Goal：在求导前识别跨层级混杂项能否进入同一函数框架；
- Observable Capability Standard：识别信号、完成乘积型和和差型构造、用单调性
  推导，并能说明何时不该用同构；
- Test：使用未见混合题检查同构、分离参数和已知不等式之间的独立选路。

Roadmap 先写完整 `plans/plan-001.md`，再把它链接进 `ROADMAP.md`，随后由学生界面
启动 Plan。这个生成顺序和生命周期正确。

## 多节 Lesson 时间线

| Lesson | 教学作用与学生表现 | 帮助与调整 | 最终状态 |
|---|---|---|---|
| 001 同构的直觉起点 | 先从五组显式结构认出“同一函数取两个值”，再做两道不同外壳的题。学生能快速认壳，但第一道真题卡在两边形状不匹配。 | 学生明确要提示后，Tutor 只给“同乘 `x`”；学生随后独立完成同构、单调区间和定义域检查。 | `closed` |
| 002 乘积型 | 从“已经摆好的同构”推进到“决定乘什么补齐系数缺口”，完成三道真实问题。 | 学生指出热身说法不够精确，Tutor 接受纠正；后续能解释为什么不是机械地总乘 `x`，并接受学生的另一路线。 | `closed` |
| 003 和差型 | 从乘法补缺口转到加减项搭桥，依次经历显式外壳、参数分布和 `e^u-u` 变式。 | Tutor 正常介绍当堂方法方向。学生提醒：一对一教学除非明确考核，本来就可以先说题目涉及什么；后续验收按此边界处理。 | `closed` |
| 004 隐藏同构 | 处理根式对数、幂指混合和展开式遮蔽。学生能先整理再认出熟悉外壳。 | Tutor 能沿学生实际路线检查条件，没有强行倒回参考解。 | `closed` |
| 005 选路 | 把同构、参变分离、已知不等式放在同一课堂里比较。三道题分别要求选择最短路线、拒绝不合适的同构、处理同构后的分岔。 | 学生形成自己的三步框架：看参数挂法、看跨层级项能否共壳、看等号点和第一步复杂度。 | `closed` |
| 006 独立检验 | 三道陌生题检验选路。第一次备课公开说出了三题的结构和路线，学生指出后整套换题重备。第二次题一干净独立；题二被 Tutor 的排除性话语污染；题三有轻微取等点提示但核心构造独立。 | 最终 Lesson、Plan 和 Roadmap 都如实保留题二污染与题三提示边界，没有把它们洗成纯独立证据。 | `closed` |

六节课形成的实际弧线是：

```text
认出同一外壳
→ 决定乘什么
→ 决定加什么
→ 从复杂外观下扒出外壳
→ 在三种路线中比较代价
→ 用陌生混合题检验独立选路
```

这条弧线不是预先由验收者指定的六步脚本，而是 Plan Coach 在阅读前课完整 Block
记录后逐步组织出来的。

## 教学功能覆盖

### 知识与概念形成：已证明

Lesson 001 没有从术语或公式表开始，而是用多组显式比较建立“同一函数在两个点
取值”的直觉。学生随后能用自己的语言描述这一视角，说明不只是复述方法名。

### 例题与近迁移：已证明

Lesson 001 的第一道真题由学生请求一次方向提示后完成；Lesson 002、003 又把操作
分别推广到乘积型和和差型。帮助进入的位置和学生之后完成的部分都写在对应 Block
日志中，没有把有提示的结果说成完全独立。

### 改变外壳的迁移：已证明

Lesson 004 中，学生在根式对数、幂指混合和展开遮蔽下仍能通过整理找到外壳；
Lesson 006 第三题进一步独立构造 `F(t)=ln(1+t)/t`，没有依赖此前固定的
`te^t`、`e^t+t` 函数名。虽然 Tutor 先点出了共同零点，函数构造与完整推导仍由
学生完成，因此可证明“会迁移构造”，不能证明“完全独立发现取等点”。

### 独立检查：部分证明

- 题一是干净证据：学生独立认出 `t=ax+ln x` 和 `e^t-t`，完成参数存在性与值域
  推导；
- 题二的完整数学推导正确，但 Tutor 在答题前说了“没有指数—对数配对”，替学生
  排除了同构，不能作为纯净的独立选路证据；
- 题三的 `F(t)` 构造和证明独立，但共同零点由 Tutor 提前指出，证明的是较高水平
  的构造与执行，不是完全无提示发现。

因此，Plan 的总体标准可以判定达成，但“在无同构信号的题上独立排除同构”和
“从零独立发现取等点”只应留作后续自然观察。本轮最终 Plan 与 Roadmap 正确保留了
这两个边界。

## 教学质量与真实毛刺

### P1：题卡内容进入了课堂，来源索引没有进入 Block

Plan Session 实际读取了 23 个不同的 YAML 题卡文件后选择材料，因此不是凭空编题。
但是最终六份 Lesson 中共有 17 个 `Kind: problem` Block，17 个 `Uses` 都为空。
部分 `Teacher Control` 只留下“mst26 page_0050 例 10”一类人类可读说明，无法稳定
反查到确切文件。

当前 Markdown parser 允许空 `Uses`，Coach Skill 只要求父 Agent 读并核验所选资产，
而“新 problem Block 必须引用真实题卡”的明确文字只出现在 Tutor Skill 的动态增题
段落。于是预先备课的 Coach 完成了“读卡”，却没有完成“挂卡”。这是提示职责断层，
不是检索失败。

### P1：独立检验的可见信息边界仍靠教师自觉

Coach 第一次公开宣布 Lesson 006 时，逐题说出了关键结构、首选路线和为什么其他
路线不通。学生指出“已经相当于考前念答案”后，Coach 正确承认并用三张新卡重备。
第二次 Coach 的公开摘要只说题量和活动形式，边界正确。

但进入 Tutor Session 后，题二前又出现“没有 `ln x`，没有指数—对数配对”的话，
题三前又点出两个因子都在 `x=0` 为零。最终日志诚实记录了污染，说明纠错链能工作；
问题在于普通学生未必会主动指出，第一次就守住边界的能力仍不稳定。

这条缺陷只适用于明确声明“不给方法提示”的考察课。Lesson 001–005 属于教学课，
一对一家教在题前说明当堂方法或给一个入口本来就是正常教学，不能一律算剧透。

### P1：Tutor 越过了 UI 所有的 Lesson 生命周期

Lesson 006 Session 在 `2026-08-04T02:19:24.299Z` 的 `edit` 调用
`call_00_pn0iTsC9Oq3HA4vJvpQt2412` 中，同时完成 Reflection、写日志，并直接把
frontmatter 从 `status: active` 改成 `status: closed`。其余五个 Lesson 没有发生
同类顶层状态写入。

这与 M0 的职责冲突：Tutor 只应更新 Block 和 Classroom Log，Lesson 关闭由学生
界面的 lifecycle endpoint 执行。模型先改成 `closed` 后，学生再点击关课，运行时
自然得到“expected status active, found closed”。根因不是 lifecycle 非原子，而是
Tutor 拿着通用 `edit` 权限越权改了顶层状态。

### P1：自由 Markdown 编辑仍频繁失败

六个 Tutor Session 的 `edit` tool result 共出现 19 次错误：文本匹配不唯一、旧文本
不存在、字段名写错、多个 edit 区间重叠等。Lesson 002、005、006 还因为 Classroom
Log 不是合法 Markdown 列表或多行续行没有缩进而在关课时被 parser 拦下。

运行时拒绝了坏写入，模型最后都通过重新读取和更窄的 edit 修复，没有留下损坏文件。
因此护栏有效，但“能够恢复”不等于“调用稳定”。这类错误也解释了为什么学生偶尔会
看见教师突然开始讨论格式、Block 或关课步骤。

### P1：备课等待仍然长

六节课共触发七次并行 Scout fan-out；Lesson 006 因第一套检验题被剧透而重备一次。
共运行 20 个 Scout，单路耗时 172.8–306.5 秒，平均 224.2 秒。并行后每次备课仍由
最慢一路决定，实际常见等待约 3–5 分钟。

这次等待主要发生在 fresh-context Scout 的题库查找和比较，不是父 Coach 再次陷入
Flash 那种长时间自我争论。Scout 的隔离确实控制了 Plan 主上下文污染，但没有解决
用户可感知延迟；第一次检验剧透又额外付出了一整轮检索成本。

### P2：最终语言偶尔比证据更漂亮

Tutor 在题三结束后先说“三道题全部独立完成”，随后 Reflection 和持久文档才纠正
题二污染。Roadmap 最终又使用“换了一个操作系统”“已自动化”等较强措辞。最终
Plan 与 Roadmap 的事实边界是诚实的，但同一对话中先美化、后修正的现象说明 Agent
仍有把复杂课堂压成漂亮结论的倾向。

## 教师可读总结

如果只用老师能理解的话说：这六节课的课程设计是成立的。学生不是机械刷同一种题，
而是从认识同构、会做两类变形，一步步走到复杂外壳下仍能辨认，再到和其他方法比较，
最后用陌生题检查。下一节备课也确实参考了前面课堂里发生的事，而不是忘掉重来。

最需要修的不是再加一套记忆系统，而是把现有简单链路磨平：备课时把题卡路径写进
`Uses`；独立检验时只隐藏路线信息；Tutor 不碰 Lesson 顶层状态；降低自由 Markdown
编辑的失败率。前四项先做小修，Scout 延迟单独优化；之后再跑一个弱一些、会犯错且
会卡住的学生周期，才能真正检验 Tutor 的纠错和分级提示能力。

## 结论边界

本轮证明的是：一个模拟强学生能够在真实模型、真实题卡、真实 Session 与真实文件
生命周期下完成一整个同构学习 Plan，M0 的直接读原始 Markdown 方案在六课规模内
工作，并且教学弧线比早期只围绕边角检查的课程明显完整。

本轮没有证明：

- 普通学生不主动指出剧透或证据美化时，Agent 仍会第一次就正确；
- 面对连续错误、半截答案、疲劳和提示依赖时 Tutor 已经足够会教；
- 193k 以上的长 Plan 在更多 Lesson 中不会触发新的 compaction 或延迟问题；
- 这次模拟结果等价于真实人类学习增益。

因此下一步应先做前四项小修并单独处理 Scout 延迟，再用“会犯真实错误、不会审计
系统”的学生角色跑下一轮，而不是重新引入 Handoff、独立 Trace、BKT 或安全投影。
