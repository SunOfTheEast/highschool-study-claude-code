# Cognitive-Outcome Agent 与 StudyForge 科研愿景

状态：探索性科研愿景，更新于 2026-08-13；不是当前产品契约、效果声明或实施规格。

## 一、为什么做这件事

Coding Agent 是当前 Agent 研究与产品开发的中心方向之一，但以人的认知变化为任务结果的
Agent 尚未得到同等强度的工程投入。StudyForge 的长期愿景不是再做一个教育 Chatbot，
而是探索一类新的交互式 Agent：它的成功不由一次回答或外部交付物决定，而由使用者是否
形成持久、可独立表现的认知变化决定。

这个方向同时满足三种个人动机：

1. 它有机会成为一个足够震撼、与普通 Chatbot 明显不同的开源系统；
2. 它会迫使开发者进入 Agent runtime、长期状态、学生建模、合成环境、Benchmark、
   蒸馏、Agentic RL、真人研究与隐私治理等更完整的技术栈；
3. 它具有足够长期的现实价值和个人热情，可以支撑持续投入，而不是为了论文临时拼接的
   题目。

当前优先级明确选择工程成果：如果短期内只能选择，宁可先得到一个真实可用、具有开源
影响力的完整系统，也不为了得到一条窄论文结论而牺牲系统完整性。科研从真实系统和真实
失败中长出来，而不是反过来要求产品配合一篇预设论文。

## 二、问题类别：Cognitive-Outcome Agent

### 2.1 暂定定义

暂时把这类系统称为 **Cognitive-Outcome Agent**：

> 以人的持久内部状态变化为首要任务结果，必须在部分可观测条件下通过交互同时干预和
> 识别该状态，并依靠延迟后的独立行为间接验证成功的 Agent。

康复训练、心理治疗与行为习惯教练也可能落入这个大类；教育不是为了“显得通用”而被
硬扩张出去的一个案例，而是当前最有价值、语义搜索空间最大、最适合形成完整工程与研究
闭环的主场。

### 2.2 与 Coding Agent 的根本差异

区别不在于 Coding Agent 是否会改变用户认知。程序员当然可能从 Coding Agent 的工作中
学到东西；关键是这种改变是不是系统成功的必要目标和评价对象：

- Coding Agent 即使没有让用户学会任何东西，只要代码通过验证，任务仍然可以成功；
- 教育 Agent 即使交付了正确答案、试卷和完整课程，只要学生没有形成持久理解，任务仍然
  失败。

两类系统可以都写测试，但测试结构不同：

```text
Coding Agent
外部产物 → 可执行测试 → 快速、可重复的环境反馈

Education Agent
教学干预 → 不可直接读取的认知变化 → 延迟、迁移、解释与反模式测试
```

代码仓库可以快照、重置并重复运行；真人学生具有路径依赖，不能重置。每次诊断和考试
还会继续改变下一刻的学生。这意味着教育环境不是普通静态 Benchmark，而是一个不可完全
重复、观察本身会产生干预的长期交互系统。

### 2.3 教育中的外部产物不是终点

在学习飞轮里，一张已经做过的试卷失去大部分诊断价值，Lesson 与讲解也只是一次性
干预工具。真正持续积累的结果是使用者大脑的变化：

```text
学习 → 考试 → 暴露边界 → 再学习 → 新考试
```

因此 Roadmap、Plan、Lesson、题卡、学习证据与 Assessment 的价值，在于它们能否产生、
解释和重新检验认知变化，而不在于系统最终“交付了多少文件”。

## 三、StudyForge 是第一件核心成果

StudyForge 不是等 StudentSim、后训练和论文全部完成后才出现的 Demo。它首先是一个可
运行、可观察、可产生真实轨迹的教育 Agent 环境，也是整个科研愿景的数据起点。

### 3.1 标志性学生经历

学生进入系统时只能说：

> 简单的还行，复杂一点我就乱了，学过的方法也想不起来。我也不知道该怎么学。

普通 Chatbot 容易直接返回学习建议、知识清单或若干练习题。StudyForge 则要完成一段
具有真实状态和后果的长期关系：

1. Roadmap 先诊断长期问题，与学生共同确认一个可验证的阶段能力目标；
2. Roadmap 物化当前一个 Plan，Plan 再逐节讨论、确认和准备 Lesson；
3. Plan 备课时可委派 Scout 检索真实材料，学生端不泄露答案和决定性路线；
4. Tutor 观察学生如何启动、如何依赖提示、是否形成错误规则，而不把“听懂”冒充
   “掌握”；
5. 学生在换壳任务中再次卡住时，系统承认退步并调整支架与后续课程；
6. Plan 只沿已链接 Lesson 证据判断阶段达标或仍然脆弱；
7. 第一个 Plan 完成后，Roadmap 重读真实阶段结果，与学生共同制定第二个 Plan。

这条链路中的课程目标、学生批准权、课堂事实、材料来源、Session 归属与生命周期都存在
外部可重读环境中。模型不是连续生成“像老师的话”，而是在参与一条可持续、可审计的
学习轨迹。

### 3.2 产品成功目标

StudyForge 的长期产品目标不是让学生完全脱离所有支持，而是让它能够独立承担原本需要
真人一对一家教持续完成的工作。

它不必在所有学习效果指标上超过优秀真人家教。只要学习效果保持在可接受范围，并通过
显著降低成本、提高可获得性、扩大持续服务能力形成更好的总体效用，就已经具有替代价值：

```text
总体效用 = 学习效果 × 可获得性 × 持续性 ÷ 总成本
```

但以下条件不能拿成本交换：

- 学科正确性；
- 对证据和未知保持诚实；
- 不把听懂、受提示完成或短期熟悉冒充长期掌握；
- 不把未经确认的目标强加给学生；
- 持续失败或无把握时能够升级求助；
- 不用平均结果掩盖低频但严重的错误教学与虚假自信。

## 四、怎样定义“学生真的学会了”

### 4.1 核心结果

当前最看重的两项结果是：

1. **延迟保持**：间隔之后仍能提取并使用所学内容；
2. **原理解释**：能够说明为什么方法成立、关键条件是什么、什么时候不能用。

立即答对只能是证据的一部分。一个能解释结构、适用条件与失效边界，却在执行中出现
局部符号错误的学生，可能比一个整题做对但无法解释的学生更接近真正掌握。

### 4.2 模式与反模式

掌握一种方法至少包含两个方向：

```text
模式：看见决定性结构，知道可以使用
反模式：看见近邻情形，知道不能照搬，并能指出决定性差异
```

只会正向匹配还没有形成完整的适用边界。延迟检查可以使用一组互补探针：

- 同原理、不同外壳的正式任务，用于检查迁移；
- 外观相似、关键条件失效的轻量任务，用于检查边界。

反模式不应只来自教材预置。更有价值的路线是，Agent 从学生实际暴露的错误规则出发，
动态构造只改变关键条件的反模式。当前讨论中使用过“过拟合”描述学生根据有限正例形成
错误判定规则；它与认知科学中的“过度泛化”“边界未学全”如何严格区分，仍是待研究的
术语与测量问题，不能在没有证据时提前定论。

### 4.3 主动诊断而非静态打分

教育 Agent 不只是更准确地猜学生状态，还应知道下一步问什么，才能区分多种可能解释。

例如同一个错误可以暂时保留两个假设：

```text
H1：学生学过正确边界，但当前没有提取出来
H2：学生形成的内部判定规则本身就是错的
```

Agent 可以要求学生先回忆适用条件，再给出只差一个关键条件的微型对照。高置信度地说出
错误前提，或把只属于一道旧题的偶然触发点迁移到新题，能够支持“内部规则错误”的解释。
连续追问的价值不是逼学生承认错误，而是逐步逆向重建学生实际使用的判断条件。

诊断本身也会教学。第一轮暴露的错误规则可能在第三轮追问中已经被修复。因此系统必须
区分：

```text
怀疑存在错误规则
→ 追问后暴露
→ 当场自行修正
→ 已修复但脆弱，等待延迟验证
→ 模式与反模式均通过
→ 稳定掌握
```

当场修正不等于永久删除；后续仍要安排延迟反模式与迁移检查。

### 4.4 认知流变与原始证据

产品曾试验单独的 Consolidated Trace 层，实际只增加了重复读取和所有权负担，因此已经
删除。当前做法更直接：Lesson 保留不可改写的课堂事实，自由学习保留原生 Session；教师
对象记忆把一段变化压缩进 Learning History，并指回对应 Lesson Block 或整个自由学习
Session。需要核对时再沿来源下钻，不为每个回合建立新的中间事件层。

未来只有在真实 Roadmap、Plan 或 Tutor 决策反复因为当前粒度不足而失败时，才重新研究更
细的事件结构。知识点状态、趋势、误区与掌握始终只能是可撤回判断，不能反过来覆盖原始
课堂记录、作答或 Session。

## 五、第二学科为什么选择化学

数学首先验证结构识别、推理路线、迁移与反模式。第二验证学科选择高中化学，因为它会
向同一训练方法提出明显不同的能力要求：

- 记忆效率：在需要时提取相关事实与条件；
- 联想效率：在宏观现象、微观粒子、符号表达和既有概念之间建立有意义联系；
- 迁移效率：把关系用于新体系，同时不混淆适用边界。

一个化学学生不应只是流畅列举相关词，而要能够解释关系类型、共享原理和决定性差异。
例如理解 Ksp 时，既能把它放回化学平衡体系中，又能解释它与其他平衡常数的共同部分和
边界，并把这种关系用于没有见过的化学体系。

### 5.1 解释、比较与做题

解释最重要，但只是第一步。做题与比较是验证理解能否工作的关键：

1. 先让学生解释当前模型；
2. 用相近概念或相似体系进行比较；
3. 用必须跨概念选择的新题检验迁移；
4. 用外观相似但条件改变的任务检验反模式。

### 5.2 应试模型与科学模型

高中化学包含大量为教学和考试服务的简化表述。Tutor 不能为了理论完整，一开始就把
全部科学复杂性压给学生；也不能把有条件的近似永久教成无条件事实。

当前选择的顺序是：

```text
先形成可操作的高中应试模型
→ 在典型题中稳定使用
→ 因稳定表现、主动追问、反例冲突或后续知识依赖而触发升级
→ 揭示原模型省略的条件
→ 用更深模型重新统一已有现象
```

稳定表现、学生追问、反例矛盾和后续依赖都是合法升级触发器。模型应该在什么时候继续
巩固、什么时候揭示更深层解释，是需要进入 Skill 与训练数据的真实教学决策。

## 六、StudentSim 的责任与边界

### 6.1 为什么普通角色扮演不够

一个能够在高考中取得极高成绩的强语言模型，即使被 Prompt 要求扮演基础薄弱学生，也
只是在压制自己已经拥有的答案。它并不真的具有对应学生的知识缺口、形成过程和遗忘机制。
因此 Tutor 在这种模型身上取得的“学习增益”，不能直接作为教会真人的证据。

### 6.2 第一阶段职责

未经真人校准的 StudentSim 更适合承担交互场景与故障生成：

- 训练与测试 Tool Use、Skill 路由和异常恢复；
- 覆盖含糊表达、错误前提、拒绝、挫败、目标变化和讨答案行为；
- 检查 Tutor 是否剧透、越权、持续套用固定话术；
- 产生大量可控的成功、失败和修复轨迹。

它不能单独证明延迟保持、原理理解或真人学习增益。

### 6.3 何时可以提供学习效果训练信号

模拟学习数据不是先验无效。它能否进入 learning-effect 后训练，取决于 StudentSim 是否
经过真人数据校准，并在关键行为上达到可测的 Sim2Real fidelity。

当前最看重的是 **认知转移真实性**：给定学习历史和教师干预，StudentSim 是否能够复现
真人的误区持续、当场修复、迁移、遗忘与延迟保持，而不只是生成像学生的语言。

最低校准单位不是单轮“讲解前—讲解后”，而是包含以下内容的纵向轨迹：

- 多节课连续教学；
- 每次教学动作前后的独立表现与帮助程度；
- 一段间隔后的模式迁移；
- 反模式辨别；
- 遗忘与重新激活；
- 学生主观感受和现实负担。

StudentSim 的最终学术价值采用 instrumental validity 判断：不是它有多像学生，而是用它
产生的数据后训练 Tutor 后，真实 Tutor 策略是否更能改善真人学习。

## 七、真人数据与开放边界

### 7.1 冷启动数据来源

真人纵向数据采用两条互补路线：

1. 完善后的 StudyForge 面向自愿用户自然积累真实分布和规模；
2. 通过私域组织更小规模、过程更完整的家教，StudyForge 给真人教师打下手，获得更严格
   的多课、延迟测验和人工观察。

当前由强通用模型驱动的 StudyForge 可以成为冷启动教师。未来最理想的产品结果是，学生
逐渐不再需要真人教师每节课介入，由 StudyForge 独立承担长期教学。

### 7.2 完全开源不等于发布未成年人的原始数据

当前确认的开放边界是 A + B + D：

- 完全公开 Agent runtime、训练代码、StudentSim、评测协议和数据 Schema；
- 公开合成轨迹与使用公共教材、题库形成的合法任务环境；
- 真人纵向数据不直接发布，提供受控评测、统计结果和可复现实验协议。

StudyForge 与后训练 Tutor 作为开源项目发布。具体模型权重能否完整开放，还需受基础模型
许可证、教师数据许可和真人数据治理约束；不能用“完全开源”的口号跳过这些边界。

## 八、分层 Benchmark

研究需要三个层次，而不能用一个总分覆盖全部问题。

### 8.1 StudentSim Benchmark

给定真实学习历史和教学干预，评价 StudentSim 对后续错误、迁移、遗忘和延迟表现的预测。
它适合高频迭代，但其指标不能替代真实教学效果。

### 8.2 Tutor Agent Benchmark

让真实模型在 StudyForge 中完成诊断、Roadmap / Plan / Lesson 决策、备课、Tool Use、
授课和状态写入，评价：

- 学科正确性；
- 教学策略与学生决策权；
- Skill / Tool 调用稳定性；
- 生命周期与证据边界；
- 答案泄露；
- 响应时间、总成本和无效工具消耗；
- 跨 StudentSim 和跨任务泛化。

### 8.3 Human Learning Benchmark

真人接受不同 Tutor 策略后，评价延迟保持、原理解释、模式迁移、反模式辨别、课程持续
完成和依赖程度。这一层昂贵、慢、不能重置，但它是学习效果结论不可替代的最终 Gate。

产品目标允许与优秀真人教师之间存在一定效果差距，只要成本、可获得性与持续性优势形成
更好的总体效用；安全与事实底线不得参与交换。

## 九、研究成果与开源成果的分工

当前角色分工为：

- **StudyForge / PiEduEnv**：第一件旗舰开源产品与数据环境；
- **后训练专科 Tutor**：第二件开源产品；
- **StudentSim 与学科可迁移后训练方法**：主要论文空间；
- **纵向认知建模和 M1 记忆**：为真实产品与研究提供证据基础，但现阶段尚未形成独立
  论文主张。

最初曾把 StudentSim 本身视为论文主体。讨论进一步收敛后，更核心的长期贡献可能是：

> 领域专家用一棵可维护的 Skill 树提供教学规范；强模型在 StudyForge 中执行这些 Skill，
> StudentSim 与真人产生多样交互；训练管线把成功、失败和修复经验逐层蒸馏进一个开放的
> 27B 专科 Tutor，并使用真人学习结果验证训练方法。

这一主张仍待进一步收敛。StudentSim 是关键机制，但论文最终究竟以 StudentSim 的
instrumental validity 为核心，还是以可跨学科复用的 Skill-tree distillation recipe 为
核心，目前不能提前写死。

## 十、Skill 树是跨学科训练方法的源代码

### 10.1 领域专家真正维护什么

跨学科扩展不要求专家穷举所有教学轨迹。专家维护的是模块化 Skill 树：

- Roadmap、Plan、Lesson 的职责与生命周期；
- 学生批准门与证据边界；
- 诊断、讲解、支架、误解修复、比较、迁移与挫败处理；
- 学科模型阶梯、典型模式、反模式和升级触发器；
- 何时检索、何时停止、何时升级求助。

强教师模型将 Skill 应用于具体学生与材料，产生多样轨迹。领域专家审核 Skill 和关键样本，
不逐条手工写完训练集。

### 10.2 三层部署结构

不在“始终携带完整 Skill”与“全部蒸馏进权重”之间二选一：

| 层 | 内容 | 长期责任 |
| --- | --- | --- |
| Runtime | ID、owner、Tree、状态机、权限、原子写入 | 永远不能依赖模型记忆 |
| 外部 Skill 树 | 工作流、教学判断、承重边界、少见情形 | 可审计、可热更新的源代码 |
| 模型权重 | Tool grammar、Skill 路由、常规动作、学科推理、高频修复 | 编译后的执行熟练度 |

最终内化的定义是：模型在零 Skill 条件下也具备独立执行能力；但 Skill 树仍作为训练源代码、
审计标准和未来更新入口长期保留。Runtime 安全边界永远不蒸馏掉。

### 10.3 后训练课程

后训练由易到难分为四层。

#### 第一层：机械且可执行验证的 Agent 链路

首先训练：

```text
Plan 公开提案与确认
→ 批准内容写入父文档
→ 必要时调用 Scout
→ Lesson 合法物化并链接
```

这层可以由 Runtime 验证 Tool Use、批准顺序、状态、路径、材料绑定、停止条件和成本，是
最适合启动的蒸馏 Pilot。

#### 第二层：逐项课堂技巧

对每个课堂技巧分别生成成功、失败、学生变体和修复轨迹。先训练技巧执行，再进入复杂
路由；不能一开始要求小模型同时学会所有教学判断。

#### 第三层：技巧选择与组合

对相同表面行为设计不同隐藏原因，训练模型判断应该读取、使用或切换哪个 Skill，防止
模型把所有课堂坍缩为固定“苏格拉底式”话术。

#### 第四层：Skill dropout 与零 Skill 终验

训练初期始终提供完整 Skill，中期逐渐随机隐藏高频、低风险的说明，后期只保留 Router、
承重边界和少见工作流。最终在未见学生状态、未见题目和跨学科任务上测试零 Skill 执行。

只有公开行为、工具结果、课堂事实与教学效果均能保持，才算真正内化。

### 10.4 推荐训练步骤

1. **Skill-conditioned SFT**：按格式、Tool Use、Skill 路由、学科推理和教学行为拆分数据；
2. **On-policy correction**：让 27B 自己 rollout，再由强教师修复它实际访问到的错误状态；
3. **可执行奖励 RL**：先优化状态合法、工具成功、无答案泄露、成本和生命周期；
4. **学习效果奖励**：只有 StudentSim 经真人纵向校准后，才把其认知转移信号引入；
5. **Privileged Skill / skill dropout**：训练期使用完整 Skill 提供程序性监督，逐步测试推理
   时移除 Skill；
6. **真人 Gate**：任何 learning-effect 主张回到真人延迟表现验证。

### 10.5 跨学科模型形态

27B 参数量被视为足以承担大量专科教学行为的可行起点。与其为每个学科从头训练整个模型，
可以研究：

```text
共同 27B Backbone
+ 通用 Edu-Agent 训练：StudyForge Tool Use 与基础教学行为
+ 数学领域训练或 Adapter + 数学 Skill 树
+ 化学领域训练或 Adapter + 化学 Skill 树
```

方法的跨学科主张不是“一套权重天然会教所有学科”，而是“不同学科能够沿同一训练管线，
用各自 Skill 树、学习集、真人轨迹和验证器蒸馏出专科 Tutor”。数学是第一完整学科，化学
是检验记忆、联想、模型阶梯和迁移能力的第二学科。

## 十一、最强现实基线与效费比风险

后训练研究最危险、也最诚实的对照是：

```text
Frontier Model + 完整 StudyForge Harness
vs.
Post-trained 27B + 同一 StudyForge Harness
```

不能只用弱 Base Model 或没有 Skill 的 Chatbot 证明微调有效。更强模型可能单价更高，却
推理更短、工具错误更少、无需重复检索和真人救场，最终总成本反而更低。

应比较：

```text
获得单位真人学习增益所需的总成本
= 模型调用 + Tool / Scout + 重试 + 延迟 + 人工介入
```

如果强模型接入 StudyForge 已经以可接受成本获得很强结果，那么微调小模型可能更像用于
扩展技术栈和研究训练方法的 game，而不是产品刚需。让后训练进入产品主线，必须证明它
提供强模型加 Harness 难以替代的价值：更低总成本与延迟、本地隐私部署、开放权重、稳定
教学边界，或跨学科可复制的专科蒸馏方法。

即使 StudentSim 或后训练假设最终失败，StudyForge 仍然是独立成立的开源工程成果。这使
研究风险不会绑架产品价值。

## 十二、当前研究路线

```text
可用的 StudyForge 产品
真实学生能够沿书学习、自由讨论并完成长期课程
        ↓
纵向证据与评测定义
延迟保持、原理解释、迁移与反模式
        ↓
真人冷启动数据
自然用户 + 私域受控家教 + 延迟测验
        ↓
StudentSim
先用于场景、Tool Use 与 Skill 稳定性，再研究认知转移校准
        ↓
机械链路蒸馏 Pilot
Plan 确认到 Lesson 合法物化
        ↓
逐项课堂技巧蒸馏
        ↓
技巧路由、组合与 Skill dropout
        ↓
零 Skill 内化模型
        ↓
数学完整验证 + 化学迁移验证 + 真人最终 Gate
```

千里之行，始于足下。当前最重要的不是提前设计庞大训练集或认知 Schema，而是先让真实
学生持续使用 StudyForge，并让产品中的教学规范经受跨学科、跨周期检验。不能蒸馏一套
尚未证明能够正常教人的教学规范。

## 十三、尚未解决的问题

1. 对象 Learning History 何时不足以支持知识点、方法与认知规则的可撤回纵向聚合；
2. 怎样严格区分学生的过拟合、过度泛化、边界未学全和条件提取失败；
3. StudentSim 认知转移模型怎样从不可重置的真人轨迹中识别；
4. 怎样以受控、可审计方式提供私人真人 Benchmark，而不泄露未成年人数据；
5. StudentSim fidelity 的最低门槛和 instrumental validity 怎样共同评价；
6. Human Learning Benchmark 的成本、样本量、延迟周期和因果设计；
7. 效果略低但成本显著下降时，产品可接受边界怎样预注册；
8. Skill dropout、Privileged Skill 和完全内化之间的最佳训练配方；
9. Skill 更新后，怎样增量重新蒸馏而不破坏既有能力；
10. StudentSim 论文与跨学科 Skill-tree distillation 方法论文是否应拆开；
11. 什么实验结果足以否定 StudentSim 或小模型后训练的实际价值；
12. 基础模型、教师模型输出、题库和真人轨迹的许可证与数据治理。

## 十四、已核验的相关工作锚点

下列条目只作为当前后训练设计的原始论文锚点；它们支持部件，不证明 StudyForge 方案已经
成立。

- **Agent-FLAN，Findings of ACL 2024**：论文报告 Agent 训练数据中的格式遵循、Agent
  推理等能力具有不同学习速度，混合训练还可能带来幻觉副作用，支持把训练数据按能力
  拆分。[ACL Anthology](https://aclanthology.org/2024.findings-acl.557/)
- **Generalized Knowledge Distillation，ICLR 2024**：在学生模型自己的生成上获得教师
  反馈，以缓解固定教师序列与学生部署分布之间的错位，支持 on-policy correction。
  [ICLR Proceedings](https://proceedings.iclr.cc/paper_files/paper/2024/hash/5be69a584901a26c521c2b51e40a4c20-Abstract-Conference.html)
- **Agent Lightning，arXiv 2025 预印本**：提出把 Agent runtime 与 RL trainer 解耦，并
  将复杂执行轨迹转换为训练 transition；可作为 StudyForge runtime-to-training 接口参考，
  但不是已正式发表的教育结果。[arXiv](https://arxiv.org/abs/2508.03680)
- **Skill1，arXiv 2026 预印本**：联合训练 Skill 检索、使用和从经验中蒸馏，说明 Skill
  library 可以成为学习对象；实验仍限于通用 Agent 环境。
  [arXiv](https://arxiv.org/abs/2605.06130)
- **ADRS，2026-08-04 arXiv 预印本**：研究训练期 privileged skills 为 skill-free 轨迹
  提供 token-level credit，并保持 rollout 与推理无 Skill；它直接启发“Skill 树作为训练
  源代码、推理时逐步内化”的实验，但目前仅能视为最新方法参照。
  [arXiv](https://arxiv.org/abs/2608.03223)

形成这份愿景时使用过一份未纳入公开仓库的综述草稿。它只是一张文献地图，不等于其中
所有引用和结论已经逐篇核验。正式立项、Benchmark 与论文写作前，仍要完成主来源验证、
基线复现与数据许可审计。
