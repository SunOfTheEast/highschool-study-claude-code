# 从交付型 Agent 到认知结果型 Agent

StudyForge 的长期研究问题是：当 Agent 的交付物不是一段代码或一份答案，而是使用者大脑中可迁移、可保持、边界清楚的变化时，Agent loop 应该如何设计、评估与后训练？教育最有挑战的部分不是把知识说出来，而是持续建模一个仍在发展、表达可能含糊、会背题也会误迁移的学生，并让学生自己理解正在发生的学习决策。

这是一份研究愿景，不是学习效果声明。当前仓库实现的是 M0 工程基线；M1、StudentSim、benchmark 与后训练都仍待实验验证。

## 已实现的 M0

M0 已经把普通 chatbot 变成一个有课程尺度的 harness：Roadmap 讨论长周期能力，Plan 讨论一个动态学习周期，Plan-local Lesson 承载真实课堂，Block 保存公开任务、私有教学控制与原始课堂日志。学生明确确认后才物化子节点，并由 UI 控制生命周期。

Material Scout 与 Lesson Reviewer 把检索和风险复核隔离到一次性子上下文；Runtime 以结构化工具保证课堂写入、身份和状态不依赖提示词自觉。这个系统可以用于测试 tool-use、证据边界、Skill 路由与长周期稳定性，但尚不能证明学生学得更好。

## M1：可追溯的学生建模

M1 计划研究认知流变 trace，而不是先制造一个不可审计的“掌握度分数”。候选事件包括学生首次解释、独立动作、提示级别、迁移题表现、错误前提、过拟合触发点、延迟保持和主动修正。已经稳定掌握的结构可称为模式；仍反复诱发错误的结构是反模式。

关键难点是把事件聚合到知识与能力上，同时保留原始证据、时间、任务条件和不确定性。派生投影必须能回到对应 Lesson Block 与 Session，允许后续证据推翻，不能把一次表现永久标签化。跨 Plan 记忆也必须先从已链接课程证据生长，而不是扫描文件目录猜测历史。

## StudentSim 假设

StudentSim 可以大量生成合成互动，用于校准工具调用、状态迁移、证据记录、讲解技巧与 Skill 的首击守住率。它特别适合发现越权写入、过早剧透、无限检索、忘记确认门等协议失败。

但“扮演学生”的强模型本身可能拥有远高于目标学生的知识和表达能力，因此不能天然代表真实学习。StudentSim 的有效性必须与真实会话中的停点、错误分布、提示响应和延迟迁移对齐。只有模拟误差被量化后，合成数据才可能承担更多教学行为评估；在此之前，它不能替代真实学习效果证据。

## Tutor / Human benchmark

未来 benchmark 至少分成两层：

1. **协议与教学行为层**：是否尊重 Session 尺度、确认门、证据边界和工具权限；是否能用合适支架暴露模式与反模式。这里可以大量使用合成情境和可执行状态机。
2. **认知结果层**：真实学生能否在新题中解释原理、独立完成、比较方法、识别边界，并在延迟后保持。这里需要真实学生数据，并与有经验的人类 Tutor、通用模型基线和不同 Skill/后训练版本比较。

评价不能只看当场答对。需要包含无提示首次表现、近迁移与远迁移、错误自信、过拟合触发、延迟保持、教学时间和学生体验。化学可能成为首个后训练学科，因为它同时要求解释、做题、比较、联想效率与边界控制，例如能说明 Ksp 与其他平衡常数的联系和差异，而不是只背公式。

## 后训练路线假设

现阶段先把 Skill 树写成可运行的教师行为规范，用真实模型收集 actor trace，再由规则、Reviewer、人类 Tutor 与学习结果形成多层反馈。可探索的步骤包括：成功/失败轨迹切片、过程奖励或偏好数据、对关键课堂技巧的监督蒸馏，以及把大模型验证过的稳定策略内化到学科模型。

训练方法本身比某一个专有模型更重要：目标是让不同学科都能从可审计 Skill、真实互动和 benchmark 中蒸馏出会教学的模型。是否需要 27B 级学科模型、哪些行为能被内化、模型升级与 harness 改进各贡献多少，都必须通过真实模型和真实任务评估，不能由愿景直接推断。

## 数据治理红线

涉及未成年人的真实学习数据不会直接公开。真实数据的采集、训练与评估必须有明确授权、最小化范围、访问控制、去标识化、保留期限和退出机制。公开项目优先发布代码、Schema、Skill、合成情境、匿名聚合指标与无法回溯个体的研究结果；原始私域记录不因“开源研究”获得默认公开许可。

StudyForge 的开源价值在于让认知结果型 Agent 的 harness、行为规范和评估方法可复现，而不是把学生变成数据产品。千里之行始于 M0：先让系统像一个真正负责的老师那样工作，再证明哪些变化确实发生在学习者身上。
